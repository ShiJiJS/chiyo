# S5 — 原型还原与动效验收合同

这是开发完成条件，不是末尾的可选美化项。唯一新视觉来源是仓库内冻结的 Round09；source hash 见其 reference-manifest.json。旧 Round05/06 是旧行为参考，不得混入新布局。不得改原型、缩放截图或缩小正式软件字体来迁就实现。

## S5-V01：参照与尺寸

先按相同虚构资料、相同选择、相同主题、相同内容视口对照；HTML的100%浏览器缩放对应Flutter逻辑像素，不把包含标题栏的整窗像素误作内容视口。当前以Mac ARM64为验收平台，记录macOS版本、DPR、TextScaler、字体来源、源码/包 hash；Windows旧证据保留平台标识。1440×900 和1280×800 是必测桌面尺寸；另测实际系统DPI及200%文字可访问布局，不假称渲染倍率等于系统DPI切换。

默认1440视口：顶栏66，信息库214/300/余宽三栏；1280时后置CSS规则将两栏改为194/275。细节必须读取最终计算样式，不能只抄 base.css（后面还有三份覆盖）。详情为独立白/深色面板，有边框、内边距和圆角；正文随内容自然增长，不能全页统一巨大卡片或统一等高行。

原型字栈为 Segoe UI / Microsoft YaHei UI / Microsoft YaHei；基础14px、行高1.6，标题依视口变化。原Windows实现及字体检查保留为历史依据。Mac采用系统拉丁字体与PingFang SC字栈，#62先记录实际解析字体，并做同文本的字重、基线和换行对照；不要套旧ProductSans/Noto后把差异统称为抗锯齿，不分发Windows字体，不以字更小解决换行。

Mac对照配置放在冻结原型之外：记录原型hash，仅对字体族及系统输入标记应用明确的平台覆盖，保留覆盖清单和参考截图。布局、颜色、字号、间距及动效仍来自冻结原型。原生标题栏单独记录，不占用内容视口；HTML参考与Flutter实际必须使用同一Mac字栈，不直接拿Windows像素图作Mac逐字验收。未解释的差异仍按下述目标处理，不能借平台变化降低要求。

同尺寸下主要分栏、卡片外框、工具栏和动作区几何偏差目标≤2逻辑像素；内边距/文本基线≤2、内容换行和可见信息量应一致。抗锯齿差异单列，不设“整图差一点也算过”的总像素百分比掩盖布局。无法满足时记录实际差异和原因，不能自行降低门槛。文件真实内容自然高度、系统文件选择器及原生标题栏不按HTML逐像素比较。

## S5-V03：浮层、滚动与表单

菜单从触发器一侧展开，优先下方，空间不足整体翻到上方；限制高度后在菜单内滚动。不能将当前选项居中后同时向上下扩展。滚动触发区时按明确策略重定位或关闭，不能悬空。Escape关闭、外部点击关闭、方向键选择、关闭后焦点返回触发器；Tooltip延迟出现且不抢焦点、不遮住当前动作。

滚动轨道位于内容/按钮的右边，选中背景和点击框在轨道前结束。长名称、列表行尾操作、树缩进、弹窗关闭按钮不能与滚动条重叠。弹窗标题/底部动作固定，正文单独滚动，不双重滚动套娃。

失败提示靠近原因；提交失败留住草稿、滚动和光标；提交中按钮明确等待，重复点击不会多提交。确认操作和结果反馈有不同状态，不能先 toast 成功再等待真实写入。

Mac输入还需覆盖⌘A/C/V/X/Z等编辑操作、中文组合输入、触控板滚动和原生窗口焦点；预览菜单/查找/设置导航应正常工作。Widget注入只能证明Widget链路，实际OS输入单独记录。本人配合的检查集中于同一候选版本，未做项不勾选。

## S5-V04：动画合同

| 场景 | 原型行为 | 实现要求 |
| --- | --- | --- |
| hover/颜色/阴影 | 150ms，CSS默认ease | 统一对应曲线；不能瞬间灰块覆盖 |
| 按下按钮 | 150ms过渡，垂直1px | 只作用于控件，不使周围布局跳动；disabled不执行 |
| 切换详情 | 180ms ease-out，透明0→1，Y 3→0 | 新选中对象触发；后台刷新同对象不重播 |
| 弹窗打开 | 180ms ease-out，透明0→1，Y 7→0 | 遮罩与内容协调；焦点进入正确位置 |
| 锚定菜单 | 120ms ease-out，透明0→1，Y -3→0 | 避免闪烁/先错位后归位，翻向时保持锚定 |
| 结果 toast | 180ms ease-out，透明0→1，bottom19→25 | 不遮住主操作；业务提交完成后才出现 |
| reduced motion | 取消装饰性transition/animation | 仍有即时状态、焦点与提交反馈 |

交互关闭没有原型动画时不要擅自补弹簧/缩放。快速连续切换、打开后立刻关闭、窗口缩放和主题切换不得留下不可点遮罩或残余ticker；用可观察完成状态测，不写固定长sleep。动画时长误差目标≤一帧（60Hz）或20ms，位移按逻辑像素对照。录屏须正常速度复看；只有静态截图不能勾选动画通过。

## S5-V06：每张票的完成证据

按2026-10-25用户要求分两种票：U01–U07是正式Flutter界面的示例数据预览票，完成下面的视觉、动画及交互检查即可关闭该UI票，但必须标注未接真实服务。真实功能接入任务由F01在界面完成后重新拆分（原T02–T20仅作参考），必须补齐真实保存/权限/重启等证据，才能宣告对应功能完成。不能因UI票完成就关闭整个功能，也不能要求新后台先完成才验UI。

1. 固定源码的真实Flutter Mac界面。UI票使用独立示例数据运行实际Widget，走通入口→交互→示例结果；功能票使用真实隔离库走入口→操作→实际结果→重启/重新读取。标明示例、widget和真实原生各自范围，HTML画面只能作为reference。
2. 同尺寸reference/actual并排图和差异记录，含本票主要R状态；明暗两套、两个尺寸。共享控件可引用固定版本的已通过矩阵，票内仍查使用它的新上下文。
3. 涉及交互的短录屏及实际时序/位移证据，至少覆盖本票变动的hover、浮层、详情或提交反馈；无动效变更说明复用的token版本。
4. 空数据、长文本、错误/离线、200%文字和键盘可达检查；列表票复用200信息、50目录、100标签压力fixture，不依真实私人数据。
5. 尚有P0功能/权限错误或P1明显布局、遮挡、焦点、关键动效缺失时不关闭。剩余差异逐条列明，由用户确认的取舍才可例外；“编译通过”不等于样式通过。

Windows适配暂缓，旧检查继续保留但不替代Mac结果。UI阶段不触发个人Keychain、系统通知授权、真实凭据执行或正式库升级；这些进入F01及相关旧票的真实服务/整包验收。

旧缓存截图不得代表新源码。证据记录命令、平台、视口、fixture种子、主题、hash、时间和结果。无需逐票全量重测无关模块；核心授权/格式变更跑对应安全回归，集成发布再跑项目完整检查。
