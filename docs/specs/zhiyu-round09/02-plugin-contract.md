# S2 — 声明式模板插件合同

状态：拟议。冻结原型中的 plugin-spec/domain-plugin.json 是界面样例，下面规定生产版的收敛范围。

## S2-P01：安装包与信任

首版使用单个 UTF-8 JSON 文件，不接受 ZIP、路径引用、脚本、动态 import、远端资源、HTML/CSS 渲染代码或命令。安装发生在“设置 → 插件 → 安装插件”，选择文件后先显示名称、作者自述、版本、模板列表及结构预览，由所有者确认才安装。Agent 可生成文件和检查结果，不能替代所有者批准安装。

包 ID 使用稳定命名空间，builtin. 仅供宿主内置。外部包不能占用/覆盖内置身份，也不能凭作者字符串获得可信标识。首版不承诺签名验证、插件市场或自动更新；更新来源与原始包摘要必须可查看。

版本合同：hostApi=1，版本为无前缀、无预发行的三段非负整数；模板 ID 在包内唯一，外部引用使用包 ID＋模板 ID。单包最多10个模板、每模板40个顶层字段，包不超过1 MiB、JSON深度不超过16；sections/relations 各最多40，instructions 最多16 KiB。输入在解析前检查字节上限，未知属性、重复 key、重复身份、不支持类型、引用不存在的定义都返回明确路径及原因。完整 schema、无效样例和实际验证器必须一致，不能靠 UI 假验通过。

模板包含字段、章节、关系及录入说明。图标仅来自宿主白名单。布局仅 fields/text/timeline/relations 四类；number/date/url 仅改变校验及展示；entries 首版固定三子字段。长内容按布局流式滚动，不允许插件设置绝对定位/固定窗口尺寸。

## S2-P02：通用录入与阅读

新增资料从已启用模板选择器进入，显示其用途和小型结构预览；默认提供通用资料而非要求用户先写模板。表单由宿主生成，模板不能自行保存资料。保存经过同一 Owner 事务与验证，失败保留草稿；重启后按实例快照显示。

外部样例“域名”必须与内置“服务器”复用同一表单及详情渲染协议，证明扩展点成立；不接受在页面 switch 中逐个写死插件 ID。文件与托管凭据仍使用专用宿主控件和现有存储流程，外部包不能把 secret 声明成默认可读字段。

## S2-P03：升级、停用、移除

同 ID 同版本且不同摘要拒绝覆盖；更高版本先展示差异和新建影响。更新只替换“后续新建使用的定义”，旧资料继续持有原快照。字段含义变化必须更换定义身份。降级/回滚安装包不会改写任何实例；首版不提供自动实例批量迁移，采用新版本走 S1-D05。

停用后不再用于新建，现有资料保留且通用查看、编辑、导出可用；移除包不删资料、附件、凭据、历史、信任记录。显示影响数量和后果，保存失败不留下半安装状态。移除后重装同一合法包可以恢复专属阅读，不能静默替换旧快照。

## S2-P04：插件专属设置

插件详情显示“概览／模板”，只有实际提供设置能力时才显示“插件设置”。全局设置不列 SSH 主机信任；旧入口兼容跳转“插件 → 服务器 → 插件设置”。

首版仅内置服务器包可通过宿主登记的面板 ID 挂接 ssh-trust；外部 JSON 即使写同名 ID 也不能冒充。主机记录由核心按规范化 host＋port 和指纹管理，服务器详情和插件设置读取同一状态。启用/安装不自动信任；主机或端口变化不继承原身份；指纹变化强制警告，不从示例复制真实指纹。

停用/移除后仍提供查看和撤销既有信任的维护入口；重新确认要求服务器插件启用。执行时主机校验由核心承担，隐藏页面不会绕过校验。身份确认与凭据使用批准独立。known_hosts 导入继续调用生产能力，不把原型 toast 当导入成功。

外部通用设置表单、可执行设置面板和远端插件服务不在首版。后续扩展需要另一个版本合同，不预造一个任意组件加载器。

## S2-P05：Agent 制作流程

Skill 指引依次为：查看已安装模板元数据 → 复用合适类型 → 缺少类型时生成无秘密的声明包及虚构样例 → 调用只读验证 → 将包交给用户在设置中预览安装 → 再提交具体资料录入提案。

说明必须交代字段含义、格式/单位、公开说明与受控内容的区别、文件用途/格式/包含的内容类别、关联证据、去重依据及分类建议。插件 instructions 属于不可信任务资料，不能覆盖宿主权限、用户指令或要求输出秘密。分类建议不应把“模板=目录=权限”混为一谈。
