# S1 — 领域与数据合同

状态：拟议，等待本轮拆分确认；标签默认可见已由用户单独确认。沿用根GLOSSARY及现行ADR，ADR0015替代ADR0006/0007中的标签读取限制。下列新词待批准后并入根术语表，避免把旧InformationTemplate静默改义。

## 新术语

**模板插件包（TemplatePluginPackage）**：一组有稳定来源身份及版本的资料模板定义。不是资料本身，也不是权限集合。

**资料模板（RecordTemplate）**：一种资料的字段定义、显示章节和可选关联说明。类型身份来自模板，不来自目录名。

**模板快照（TemplateSnapshot）**：资料采用模板时保留的那个版本定义。它描述现有资料，而非追随当前已安装插件的可变指针。

**展示分组（DisplaySection）**：把资料中已有字段按阅读目的组织的章节。分组不产生授权。

**重复条目（RepeatedEntry）**：教育经历等一组可重复的相关字段，有自己的稳定身份和显示顺序。

**资料关联（RecordRelation）**：两项已有资料之间有依据的具名联系。不是运行依赖、访问权限或复制内容。

旧 FieldTemplate 仍是表单辅助；新 RecordTemplate 是带显示定义的资料类型。迁移期间二者并存，由适配层映射，不让同一个 API 名悄悄承担两种含义。

## S1-D01：共同外壳与类型

InformationItem 继续拥有稳定 ID、名称、公开说明、版本、目录和标签、字段。增加可选模板引用/快照、布局映射；旧资料没有模板时直接使用通用视图，不猜测它是服务器。一个资料零或一个目录、零或多个标签；模板既不创建目录，也不绑定目录。

信息库列表可统一呈现普通信息、含文件的信息、托管凭据，但使用带对象种类的引用。ManagedCredential 继续独立存储，不能被转换成普通字段或通过通用编辑器解密。普通文件仍是可授权 InformationField，不新建第二套普通文件所有权体系。

模板类型标签和图标只表达阅读方式。所有者可为凭据设置目录/标签，存储为其自身分类引用；旧凭据默认未分类。目录的“非空”检测必须包括当前信息、当前凭据及子目录，不能在统一列表后遗漏凭据。

## S1-D02：定义身份、实例身份与值

插件 ID、模板 ID、定义 key、资料 ID、字段 ID、附件 ID、凭据 ID 不能混用。模板 key 在其命名空间内稳定；新建资料永远分配新的实例字段 ID。更改字段含义生成新定义身份，不能通过改标签复用旧授权字段。

首版 text/url/number/date/multiline 是校验和展示语义；普通标量仍走现有受控文本字段读取协议，不为格式显示重写全部授权模型。number 采用有限十进制规范字符串（无 NaN/Infinity），date 采用 YYYY-MM-DD；校验错误留在表单，不能只在客户端验证。附件引用沿用不可变版本；字段正文不进入列表模型。

每个实例保存模板定义的不可变快照及定义→实例字段的映射。快照、关联、条目布局和分类随资料加密持久化、修订、回收及备份；不得靠插件目录或UI本地缓存作为唯一数据源。标签默认可见是发现接口的规则，不代表取消数据库加密，也不新增标签可见性字段。

## S1-D03：重复条目不扩大授权

个人档案首版 entries 使用 title/period/detail 三个子字段。每个条目获得稳定 entryId，每个实际叶字段仍获得独立 fieldId；顺序和章节是显示元数据。审批按条目折叠展示，也能展开逐字段选择；“整段提供”在批准时展开为固定的现存字段集合。

添加经历、添加子字段、复制条目都产生新字段 ID，不进入旧授权；调整条目顺序、移动展示章节不改变字段身份。删除按现行删除授权失效规则处理，撤销/恢复不复活旧能力。旧 CLI 的扁平字段读取仍可用，新 CLI 可附加获准字段的结构信息，不能借布局返回未获准正文。

重复结构需要有界：拟每个entries字段最多100个条目、每项资料总计最多500个叶字段，新结构超限在保存前明确拒绝。若宿主现有限制更小则沿用更小值；实施时先对齐现有导入/备份预算，不能为新布局直接放大整个服务请求上限。既有超过新建预算的数据仍可查看/导出，不静默截断。

公开字段名称只能使用模板定义标签及中性条目编号，不能把实际学校名、公司名或经历标题自动拼进公开名称。JSON 整块读取一份未细分的 entries 不作为实现捷径。

## S1-D04：关联的存储和权限

关系保存 source/target 稳定引用、关系 key、版本；首版均可零或多个目标，不做通用依赖调度。一个事实只存一次，反向展示由同一事实投影，不生成可各自修改的双份关系。服务器与服务、文档、档案及文件可关联；凭据关系复用现有 linkedItemIds 的同一事实，通过适配器展示，不能另建冲突关系副本。

目标删除/回收后不再显示可操作的正常入口；历史保留当时对象身份和说明，当前 UI 明示不可用。恢复时仅重连仍存在的合法目标，不复活被删除对象。通用关系允许环（链接不是依赖 DAG）；禁止自身和同关系重复边。目录移动仍须防父子环。

关系不扩展批准范围；“关联SSH密钥”仅提供申请使用入口，读服务器信息绝不获得密钥。标签名称及公开资料上的标签归属默认可见；关系图和目录的既有读取边界不因本次标签决定自动改变。标签可见不提供修改它们的权限。

## S1-D05：旧资料与旧模板采用新类型

不解析秘密猜类型，不依名字自动建立依赖。用户先选择已有资料及目标模板，预览每个字段的映射、未映射字段、校验问题和效果；不匹配类型或含义不明时保留原字段并提示，不能静默丢失数据。

同义且同内容形态的既有字段可保留 fieldId，纯展示变化不需要重授权。含义改变时显示“新字段”，分配新 ID 并按现有规则使删除字段授权失效。保留目录、标签、附件版本、凭据关系、原修订。一次采用用 expectedVersion 和原子事务防止覆盖其他编辑，冲突后重新预览。可从修订恢复布局，但旧失效授权不复活。

旧手建模板先进入“旧版模板”兼容入口，可继续用于通用录入；显式转换为 local 命名空间插件后保留来源映射。转换不偷偷为历史资料套模板，也不要求用户重新手工搭字段。

## S1-D06：扩展、备份与恢复

以现有 schema22/备份1–10为基线，但实施前重新读取版本，不能抢占固定的新版本号。先增量字段/表，再迁移调用，最后移除旧入口；每个有新持久化内容的 ticket 同时支持其完整备份/恢复，不能等最后一票才避免数据丢失。

新格式含插件定义、快照、分组、关联和分类；缺插件不影响恢复原始资料，通用视图必须可读。备份导入的包先校验，外部包默认停用，不能因恢复自动运行或获得新能力。旧读取器遇到不支持格式明确拒绝。损坏包、重复 ID、关系悬空及超限恢复在临时库失败，正式库保持原样。迁移失败回滚，成功后旧库备份按现有恢复规则保留；不复制临时凭据材料或活跃授权到备份中。
