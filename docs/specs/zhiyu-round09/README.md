## 决策优先级

用户本轮要求与已确认 Round09 外观优先于旧 Round05/06 的外观。授权、加密和执行等语义继续遵循现行 ADR；本规格明确标出的新行为经确认后才替代对应旧行为。原型演示成功不证明生产能力已完成；原型漏画某个旧操作不表示删除它。冲突需记录并修正规格，不能偷偷简化。

保留 Flutter 客户端、Dart 核心和 CLI、SQLCipher 与系统密钥保管；不改为 WebView/Electron 来绕过还原工作。当前先跑通Mac ARM64，Windows专项适配与交付后置；不含服务器同步、插件市场、可执行第三方插件或手机审批。Mac UI阶段先使用隔离示例；真实服务与安装工作由F01在界面完成后拆分。

## 当前设计范围与后续核对

1. 插件第一版只接收声明式 JSON，提供内置服务器、应用/服务、个人档案及通用资料能力；文件和凭据的安全操作始终由宿主提供。
2. 外部包先支持字段与有限布局，不支持任意插件设置表单。服务器插件设置只挂接宿主已有 SSH 主机信任面板。
3. 信息库和 Agent 查找均支持关键词＋类型＋标签；一个信息项仍能拥有多个标签。2026-10-25用户明确确认：全部标签默认对接入软件的Agent可见，不设“私人标签”或公开开关。读取正文、领取文件、使用凭据和修改标签仍分别遵循授权流程（见S4-A02）。
4. 新类型先增量接入。已有资料不自动重分类或改字段，用户在预览映射后才为选中的资料应用模板。
5. 2026-10-25用户要求先完成整套前端：界面票先以示例数据验证视觉、动画和交互；随后每个功能模块复核前端、接入本地服务、测试真实业务并复查样式。不将还原工作拖到最后，也不把界面预览完成当成功能完成。

当前开发使用隔离示例，未打开真实资料库，未复测正式应用全流程。保留原来的安全和验收结论，不用规划材料宣告通过。
