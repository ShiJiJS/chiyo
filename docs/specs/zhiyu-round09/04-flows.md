# S4 — 授权、提案、历史与设置

## S4-A01：四条授权路径保持分离

| 路径 | Agent 发现/申请 | Owner 决定 | 交付及复用 |
| --- | --- | --- | --- |
| 普通字段 | 目录元数据 → 固定字段 ID | 逐字段、按展示章节辅助选择 | 只读获准字段；当前会话及期限内复用，新增字段不加入 |
| 普通文件 | 文件字段元数据 → 指定字段/版本 | 显示文件用途、格式、版本 | 受管副本与路径，由现有交付接口领取；撤销/到期清理不承诺抹去已读副本 |
| 凭据使用 | 凭据元数据 → 使用方式/接收方/启动说明 | 批准凭据版本、方式、接收方和期限 | CLI/worker 启动进程并注入 env 或临时文件路径，或本机焦点填充；密文/明文不走普通读取 |
| 分类整理 | 私密会话申请固定资料范围 | 最长30分钟，仅所需元数据和分类写权限 | Agent 完成原子整理后只读结果；不增加第二次审批、不读改正文 |

初始命令不是整个授权期的命令白名单。使用同一凭据做多步时复用仍有效的 grant，每次操作独立 operationId、重新校验边界和记录结果；不知道执行结果时查询原操作，不能自动重放。直接在系统 shell 执行含占位符命令不会注入；只有受控 CLI 启动才替换批准的注入位置。

env、argv中的文件路径、文件路径型 env 均用结构化 launch plan。占位符只解析受支持的 token，未知/重复冲突/不匹配接收器拒绝；不做任意 shell 文本替换，不自动把秘密放进参数或日志。焦点填充独立展示目标应用、实际捕获状态和失败原因，不声称识别浏览器网页来源或防恶意 Agent。

## S4-A02：目录与新结构的可见性

Owner 的目录/标签搜索与 Agent 的普通 public catalog 是不同接口。遵循 ADR0006：不能因新原型出现 tag 菜单，就对所有会话公开私人分类和关系。Agent 首版新增可公开审阅的模板类型及字段定义，继续按公开名称/说明关键词查找、分页；私人目录/标签只在既有获批整理范围内可见。

这与原型说明里“Agent关键词、类型、标签”的方向有一个收敛：本轮先不扩大未授权标签可见性。若需要普通 Agent 按标签发现，须另确认显式公开标签的设计，不悄悄把全部私人标签公开。此选择需随本轮拆分确认。

资料关联仅帮助 Owner 导航和审批。模板说明不包含字段值；重复条目元数据不得由内容生成公开名称。普通资料、附件、凭据、Agent会话能力始终分别鉴权。

## S4-A03：审批工作台

请求用可分页收件箱浏览，按全部/待处理/已处理及关键词找请求，不按请求生成无限顶端 tabs。右侧卡片包含申请者自述、会话、用途、范围、期限、状态和决定区。申请者名称/用途标为自述，不冒充可信来源。

普通审批支持补选/减选固定字段、新类型章节/条目及文件版本；撤销、拒绝、到期、会话结束、对象被删和冲突均有清楚状态。提交中禁重按，失败保留选择。

凭据审批完整展示：哪个凭据及版本 → 注入何处 → CLI启动什么可执行程序及参数 → 允许的接收方/使用方式 → 有效期内复用。tips 在相应字段旁解释，不挤占主流程。env不显示值、文件显示占位路径说明而非实际临时路径，焦点填充显示目标应用限制。

## S4-A04：录入与修改提案

Agent 按模板提交资料草稿，Owner 查看章节化预览和字段级差异后一次确认。插件安装和资料保存是两次不同决定；安装模板不批准任何数据写入。新增、修改、删除、混合批量继续走各自既有事务和冲突语义，不只做“批准一条新增”的漂亮路径。

提案固定使用提交时定义快照/版本，模板更新后不能静默按新定义解释。禁用/缺失模板用通用预览；不兼容则提示重新生成，保留原提案。分类建议显式可审阅；附件沿用已存在的 Owner 导入流程，凭据继续使用专用录入路径。

通用提案接口不提供读取凭据正文、把凭据材料展开为普通字段或上传附件原字节的能力。普通文本是否恰好是一段秘密无法可靠自动识别，因此录入指引和Owner审阅仍必要，不能声称已实现任意文本秘密检测。

分类整理结果页只读显示哪些名称/目录/标签改变、失败或无变化；不能误显示“再次批准”。新字段、条目、关联、附件的变更须各自表达，不把整页 JSON 替换称为“修改一个字段”。

## S4-A05：授权历史

将授权与执行记录分层：一次 grant 可对应多次读取/使用/文件交付。列表按类型、状态与时间查找；详情有实际批准范围、版本、期限、撤销原因和操作结果。凭据从未有“查看使用结果中的密钥”。关联当前对象失效时仍显示历史快照，不强行跳到同名新对象。

## S4-A06：设置与完整功能保留

外观只明亮/黑暗；通知保留真实系统通知测试及点击路由；请求与记录保留期限/保留期；插件管理按 S2；目录标签管理按 S3；备份恢复保留密钥、文件选择、冲突、错误与清理；应用运行保留托盘、关闭窗口/完全退出、本机服务、材料维护、附件维护；Agent接入保留现有hooks/诊断与信任边界。

成功状态必须来自真实服务结果。原型中的备份下载、通知出现、退出、维护完成 toast 不可照搬假成功。配置保存失败保留草稿，重启读回；服务不可用时显示原因、重试入口而非空白页。

品牌改为知予，但本轮不改变旧数据库路径、DPAPI身份、CLI可执行名、协议路径、环境变量、hooks路径或 Skill ID。窗口标题、托盘、通知文案、安装展示名和桌面快捷方式可改；技术标识改名必须另做兼容方案，不混在字符串替换里。
