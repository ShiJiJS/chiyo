## S6-C02：模块职责及实际接缝

| 模块 | 拥有内容 | 不得拥有 |
| --- | --- | --- |
| 设计token与交互控件 | 色/字阶/间距/动画、浮层锚定、键盘焦点、滚动轨道 | Owner/Agent权限、业务存储 |
| 工作台状态与查询 | page/scope/query/group/sort/selection、返回快照、请求代次与过期结果丢弃 | 秘密正文、数据库对象、审批执行 |
| 资料类型渲染器 | 模板快照→章节/表单，宿主字段/附件控件组合 | 插件脚本、基于插件ID写死业务、直接读文件 |
| 模板目录与包管理 | 验证包、安装状态、版本、模板选择和快照 | 授权签发、执行秘密、主机信任规则 |
| 资料命令与关系 | 校验、expectedVersion、字段/条目映射、原子保存/采用模板 | Flutter Widget、原生对话框实现 |
| Owner/Agent服务边界 | 现有授权、提案、文件交付及凭据执行规则 | 从前端布尔值相信已批准 |
| 持久化与平台适配 | 加密事务、版本迁移/备份、文件选择、SSH/worker平台能力 | 根据当前页面猜操作权限 |

在现有包内以明确接口组织，除非实际依赖边界证明需要，不先拆成大量新package。薄页面只绑定状态与调用命令；新结构不塞入既有2000行审批页或扩大横跨页面的私有part共享状态。逐块抽出职责，不能只把一个大文件拆成共享私有变量的多个part文件。

两个实际实现用来校验接口深度：内置服务器与外部域名模板共享渲染/验证；普通信息与凭据的列表摘要适配器共享选择/分页，但敏感详情仍走各自接口。没有实际第二个实现的抽象不引入插件宿主层层转发。

接口需说明输入、稳定引用、错误、事务和生命周期。查询返回只含列表元数据的投影；详情才按需读值，文件正文/凭据正文不能被列表订阅提前加载。变化通知使缓存失效；不能靠每次导航销毁整页重建来同步，也不能维护两份权限真相。

## S6-C03：状态、错误和迁移

状态分为idle/loading/ready/empty/error与独立mutation状态，不以null和toast代表一切。取消或晚到的读取不能覆盖新选择；只保留必要页面状态，不持久化敏感详情。保存依赖expectedVersion，验证失败、冲突、未知提交结果各有稳定错误码和重试策略；未知执行结果按operationId查询，不重复执行。

旧模板模型先保留兼容适配；新模型可用后按页面/服务调用迁移，每步保持绿色。所有调用和旧数据兼容证据齐全后才移除旧手建模板主入口；遗留模板仍可查看/转为插件，不能为简化代码删数据。

修改DB前先迁移合成旧库、故障注入和备份往返；真实数据迁移放在最后交付预览确认，不访问真实资料来写测试。恢复、修订和回收不可漏掉新快照/关系/条目信息；临时grant、进程材料从不随备份恢复成活跃能力。

## S6-C06：示例数据替换为真实数据

界面阶段开始前只确定屏幕所需的请求/结果结构、稳定对象引用和可显示的失败状态，不提前开发全套数据库或服务。页面通过可注入的数据来源发起查询/操作，示例实现与正式服务实现遵守同一份界面合同。界面只依赖该合同，不直接读SQLCipher、运行CLI或访问文件；正式适配器复用已有Owner服务，避免为桌面UI凭空增加一套HTTP服务。

示例数据集中管理，包含服务器、应用、档案、文件、凭据、请求、提案和历史；不能散落成Widget中的硬编码值或到处判断isMock。需要点击后产生结果的流程使用可重置的内存状态，支持编辑、筛选、模拟保存/失败、审批状态变化、跨页跳转。异步等待、空结果和错误可确定触发，不靠随机延时偶发出现。预览重启可以回到固定初始数据，不把这叫作生产持久化完成。

预览使用明确独立的启动入口，窗口标明“界面预览·示例数据”；不读取或修改正式库、个人设置、hooks，不执行真正的密钥填充/命令，不发送真实系统通知、不替换已安装软件。实际内容区域仍使用同一套正式Widget和控制器，不能嵌入HTML、复制一份演示专用页面，也不能把图片当成界面交付。

替换真实服务时，在组装入口切换实现，页面布局、动画、菜单及导航代码原则上不变。若实际业务需要新增状态，先补其界面与合同，再实现接口；变更记录到对应模块票。正式发布入口无法启用示例成功分支，服务失败不得回退到示例数据，预览与正式存储和执行能力明确隔离。

Mac原生层也必须隔离：预览不能初始化正式ToolAccessStore、读取已保存的目录bookmark或激活security scope；Keychain、正式资料容器、hooks和真实通知不应因窗口创建而启动。菜单就绪、导航和正常退出通过最小预览接缝接通，不依赖生产服务启动。#62负责完成并证明这层隔离，单凭preview_main.dart不能宣称Mac预览已安全隔离。

每个功能模块的顺序固定为：①完成/复核该模块前端及异常状态；②接入现有服务，缺少的接口、数据库能力再补；③用真实隔离资料库和CLI验证业务，并复查接入后视觉与动画没有改变。界面阶段也做点击、排版和键盘检查；最后的测试阶段负责真实保存、重启、权限及故障，不意味着前面完全不检查。

## S6-C04：测试重点

领域测试围绕公开接口：创建→保存→重启→Owner查看/Agent申请→批准读取；新增条目不扩旧grant；插件停用/缺失可读；更新不改旧快照；关系不授予目标。实际SQLCipher与独立CLI覆盖存储及权限接缝，不能只mock所有边界。

UI测试覆盖查询/选择一致、异步竞争、保存冲突、焦点恢复、浮层和滚动；golden只能证明widget画面，原生窗口还需S5证据。动画验证时测起止、时长和取消；不要只断言一个Duration常量等于自己刚写的值。

每票跑影响范围分析/格式/测试；集成发布使用仓库完整check。缺少环境或失败写明未通过，不提高超时、跳过失败或用原型代替产品。源代码、widget、离屏、实际Mac/Windows、独立CLI、真实Codex证据分别记录。当前不运行Windows CI；旧Windows未验内容保持待办，不阻塞Mac UI。
