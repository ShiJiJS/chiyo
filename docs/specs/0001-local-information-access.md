## Problem Statement

用户保存了个人资料、服务器连接资料等信息，agent 执行工作时经常需要其中一部分。如果直接向 agent 开放整个资料目录，就难以把实际披露范围限制在本次任务需要的内容。依靠预先配置命名空间或权限等级又增加维护成本，不符合用户希望按当前需要即时授权的工作方式。

用户希望 agent 能发现有什么信息、主动提出申请，由用户在桌面软件中一次选好范围，随后在本次聊天内复用授权。资料的拆分、归类和索引应该主要在录入阶段完成，避免使用时逐层申请、反复审批。

软件需要同时照顾低操作负担和明确的访问边界：打开客户端直接使用，资料加密保存，agent 通过受控接口获取获准内容；第一版不要求限制 agent 的运行环境，也不承诺抵御已控制本机或窃取有效访问凭据的攻击者。

## Solution

提供一个后台运行的桌面应用、一套通用 CLI，以及配套 Skill 和 Codex 会话适配。应用统一管理信息项、信息字段、公开目录、访问请求、授权会话、录入提案、授权历史和访问记录。

agent 首先查询仅含允许披露的名称和说明的公开目录，再一次提交用途和候选范围。用户在桌面端可以取消字段、补选或改选信息，批准后应用签发临时访问凭据。主 agent 和子 agent 在同一聊天中复用获准范围，实际读取由本地核心服务逐次鉴权。

资料由 agent 整理为录入提案，用户批量预览和确认后入库；同时提供手动录入。第一版支持结构化字段和文本说明，以目录、标签和字段模板组织信息。授权历史关联实际访问记录，并提供撤销、回收站、修改历史及手动加密备份。

窗口关闭后应用继续后台运行；完全退出会停止服务并使当前临时授权失效。软件不设置应用主密码，数据库密钥由应用自动管理。服务器、同步传输及远程审批均不在本规格内。

## User Stories

1. 作为资料所有者，我希望信息由软件统一加密保存，以便不必把整个明文资料目录开放给 agent。
2. 作为资料所有者，我希望打开客户端即可使用，以便日常操作不需要输入应用密码。
3. 作为同时使用 Windows 和 macOS 的用户，我希望两端遵循相同的产品规则，以便换设备后仍能理解操作方式。
4. 作为资料所有者，我希望关闭窗口后软件继续后台运行，以便 agent 可以继续使用有效授权并提交新申请。
5. 作为资料所有者，我希望完全退出软件会停止访问并使临时授权失效，以便明确控制何时停止提供信息。
6. 作为资料所有者，我希望信息以目录层级组织，以便快速浏览和批量选择相关内容。
7. 作为资料所有者，我希望为信息添加标签，以便跨目录查找同一项目或用途相关的信息。
8. 作为资料所有者，我希望使用可扩展字段模板，以便在保持一致结构的同时容纳不同类型的资料。
9. 作为资料所有者，我希望按信息字段选择授权范围，以便不因需要一个地址而披露整条资料。
10. 作为资料所有者，我希望文本说明也受内容授权控制，以便公开描述不会默认暴露内部备注。
11. 作为资料所有者，我希望保留手动录入入口，以便直接补充简单信息或处理不适合交给 agent 的资料。
12. 作为资料所有者，我希望让 agent 从我指定的资料中提取和整理信息，以便减少手动录入工作。
13. 作为资料所有者，我希望批量预览 agent 的录入提案，以便一次确认多条信息并调整分类及字段。
14. 作为资料所有者，我希望修改提案展示变更差异，以便判断 agent 是否误改了已有资料。
15. 作为资料所有者，我希望公开目录的名称和描述可在录入时检查，以便在授权前只披露我允许的信息线索。
16. 作为 agent，我希望查询公开目录而不先取得内容授权，以便发现可以申请的信息。
17. 作为 agent，我希望一次提交任务用途及候选信息范围，以便用户无需经过多轮逐步缩小范围的审批。
18. 作为资料所有者，我希望审批时看到会话标识、用途及申请范围，以便判断请求是否符合当前工作。
19. 作为资料所有者，我希望可以部分批准申请，以便只提供我愿意披露的字段。
20. 作为资料所有者，我希望在审批时补选或改选正确的信息，以便不用退回让 agent 重新提交。
21. 作为 agent，我希望获知用户最终批准的范围，以便正确处理部分批准或用户调整候选项的结果。
22. 作为资料所有者，我希望新申请进入桌面待办并发送通知，以便在方便时处理。
23. 作为资料所有者，我希望 agent 查询同一申请状态不会重复通知，以便避免通知干扰。
24. 作为 agent，我希望等待审批时还能先完成独立工作，以便不让缺少资料阻塞整个任务。
25. 作为 agent，我希望 CLI 等待超时后仍可查询原申请，以便不重复创建请求。
26. 作为资料所有者，我希望待审批申请默认在 30 分钟后失效且可以调整设置，以便陈旧申请不会长期等待批准。
27. 作为资料所有者，我希望拒绝或过期的申请不会被 agent 自动反复重提，以便我的处理决定得到尊重。
28. 作为 agent，我希望用户批准后取得限定范围的临时访问凭据，以便只能通过该凭据读取获准内容。
29. 作为资料所有者，我希望授权默认最长有效期为 8 小时且批准时可调整，以便按本次工作需要控制时长。
30. 作为 agent，我希望本次聊天中重复读取获准范围无需再次审批，以便顺畅完成持续任务。
31. 作为主 agent 和子 agent，我希望共享同一聊天已取得的授权，以便内部任务分派不会触发额外授权。
32. 作为资料所有者，我希望不同聊天独立申请，以便一个任务的批准不会成为另一个任务的默认权限。
33. 作为资料所有者，我希望正常收到会话结束事件时撤销授权并取消待审批请求，以便工作结束后停止新的读取。
34. 作为资料所有者，我希望授权即使在会话结束事件缺失时也会到期，以便异常退出不会留下无限有效的凭据。
35. 作为资料所有者，我希望随时撤销有效授权，以便及时停止后续访问。
36. 作为资料所有者，我希望批准的范围固定在当时选中的信息项和字段，以便后来新增的信息不会自动被披露。
37. 作为 agent，我希望授权说明明确指出新增信息需要另行申请，以便不会误以为整个分类持续开放。
38. 作为 agent，我希望读取已授权字段的最新值，以便资料修正后可以继续使用正确内容。
39. 作为资料所有者，我希望 agent 的提交能力不自动带来读取、覆盖或批准能力，以便录入功能不会绕过授权。
40. 作为资料所有者，我希望 agent 提出的删除经过确认，以便避免未经检查的数据丢失。
41. 作为资料所有者，我希望删除的信息进入默认保留 30 天的回收站，以便修复误删。
42. 作为资料所有者，我希望删除后旧授权立即停止提供对应内容，以便删除在访问接口上及时生效。
43. 作为资料所有者，我希望恢复信息不会复活旧授权，以便恢复操作不会意外重新披露资料。
44. 作为资料所有者，我希望保留默认 30 天的修改历史，以便找回错误修改前的版本。
45. 作为资料所有者，我希望历史版本仅由我在客户端查看和恢复，以便 agent 的当前字段授权不会扩大到全部旧值。
46. 作为资料所有者，我希望以授权历史为入口查看批准范围、有效期及状态变化，以便知道曾经允许哪些会话访问什么信息。
47. 作为资料所有者，我希望授权历史关联成功和被拒绝的访问记录，以便分清批准过的范围与实际访问行为。
48. 作为资料所有者，我希望记录不包含字段值、token 或解密材料，以便历史和诊断信息不会成为另一份敏感资料副本。
49. 作为资料所有者，我希望从授权历史直接撤销仍有效的授权，以便在检查记录时立即处理。
50. 作为资料所有者，我希望手动导出加密备份，以便在设备损坏或换机时恢复资料。
51. 作为资料所有者，我希望启用备份时得到一份可另行保存的恢复密钥，以便恢复不依赖原电脑的可用性。
52. 作为资料所有者，我希望恢复密钥只用于备份恢复，以便不增加日常打开软件的步骤。
53. 作为资料所有者，我希望恢复备份不会恢复有效访问凭据或待处理审批，以便新环境从明确的授权状态开始。
54. 作为 agent，我希望 CLI 返回明确、可机器处理的状态和错误，以便区分等待、拒绝、过期、未授权和服务不可用。
55. 作为 Codex 用户，我希望适配层关联当前聊天及生命周期，以便无需手动维护每个聊天的权限配置。
56. 作为后续接入其他 agent 工具的用户，我希望 CLI 业务接口保持通用，以便更换工具时复用相同的信息与授权模型。
57. 作为资料所有者，我希望软件为同一人的多设备数据保留稳定标识和版本信息，以便后续扩展同步时不重建全部资料。
58. 作为资料所有者，我希望产品准确说明导入会话已看到原始资料、撤销不能收回已披露内容，以便理解授权机制的实际作用范围。

## Implementation Decisions

### 1. 范围、术语与已有决策

- 本规格采用项目已定义的信息项、信息字段、公开目录、访问请求、授权、授权会话、录入提案、授权历史和访问记录等术语。
- 保持“授权固定到批准时选中的信息项集合”及“第一版采用加密存储和应用层授权，不要求限制 agent 的运行环境”两项架构决策，并落实其中已明确的字段粒度。
- 第一版仅做单机；同一人多设备和手机授权确认是后续方向。未来云端优先考虑 Java + Spring Boot，服务器具体职责与实现仍延后。
- 不设置应用主密码、密码解锁或应用锁。自动管理密钥不等于提供同一操作系统用户下的强进程隔离。
- 展示形式不限定为卡片。具体视觉样式和产品名称尚未选定；客户端采用 Flutter，本地核心服务与 CLI 采用 Dart。

### 2. 模块与权限边界

| 模块 | 职责 | 必须保持的边界 |
| --- | --- | --- |
| 桌面客户端 | 浏览编辑、审批、确认提案、历史、回收站和备份恢复 | 用户管理与审批能力不暴露为普通 agent 可调用的接口。 |
| 本地核心服务 | 信息与授权用例、状态转换、逐请求鉴权、记录与保留策略 | 所有客户端共享同一套业务规则；拒绝越权不能只依赖前端或 Skill。 |
| 加密存储与密钥管理 | 加密保存、自动密钥保管、版本和备份恢复 | CLI 不直接取得全库解密密钥；首次支持真实资料前验证恢复链路。 |
| 通用 CLI | 公开目录查询、申请和等待、获准读取、提案提交 | 输出机器可读结果；不会因为可执行 CLI 而拥有审批或全库读取能力。 |
| Skill 与 Codex 适配 | 使用流程、会话关联、生命周期处理 | 会话 ID 是关联标识，不是身份凭据；异常事件由授权到期兜底。 |

本地核心服务可以随桌面应用后台运行，不要求用户单独安装或启动服务器。架构划分表达职责和权限边界，不强制每个模块成为独立进程或部署单元。

2026-10-16 确认技术方向：Flutter 开发桌面界面；独立 Dart 业务模块实现本地核心服务；Dart 独立 CLI 调用受控本机接口。业务规则独立于 Flutter 页面，数据库、密钥保管、通知和通信通过平台适配层接入；CLI 不直接打开资料库。用户接受 Flutter 学习成本，以便后续复用客户端技术开发手机授权确认功能，同时避免为本地核心再引入 Rust 或 Java 运行架构。具体 isolate 或进程划分、插件、通信和打包仍待验证；测试继续以核心服务公开接口为主。未来云端优先 Java + Spring Boot，不构成第一版依赖，也不意味着资料需上传服务器。

### 3. 信息与公开目录

- 一个信息项包含稳定身份、组织信息及可独立授权的信息字段。文本说明作为受控内容处理；对外用途描述与内部说明分开。
- 公开目录仅返回用户允许在授权前披露的名称、描述、字段说明及必要标识。全文内容、历史值、私有备注及内部搜索材料不通过此接口泄露。
- 目录、标签及模板用于组织和选择，不表示长期权限组；按目录勾选后得到的是明确的信息项和字段集合。
- 公开描述由 agent 提议、用户在录入或修改确认时检查。确认前的提案不进入正式公开目录。
- 字段拥有稳定身份。普通值修正保持身份；加入新的业务含义或新增字段不能借旧身份自动扩大授权。具体编辑约束需在实现中形成可验证的操作规则，不假设软件能自动理解所有语义变化。
- 字段级删除或替换同样不能通过复用旧身份恢复原有权限。

### 4. 领域数据模型

下表定义需要保存的领域事实，不指定物理表结构；存储实现采用 SQLite + Drift + SQLCipher。

| 对象 | 需要表达的事实 |
| --- | --- |
| 信息项 | 稳定标识、目录与标签、公开描述、当前版本、删除与恢复状态、创建及修改时间。 |
| 信息字段 | 稳定标识、所属信息项、字段定义与当前值、当前版本、是否有效；文本说明也纳入受控内容。 |
| 组织与模板 | 目录关系、标签、可扩展字段定义，均不携带自动授予内容访问的规则。 |
| 内容版本 | 所属信息及字段、版本关系、保存时间、可恢复内容、保留期限；旧值受加密保护。 |
| 录入提案 | 提交会话、拟新增或修改内容、拟公开描述、所依据的版本、用户确认结果；删除提案复用确认流程。 |
| 授权会话 | 软件内部身份、外部聊天关联、主子 agent 归属、活动或结束状态；与凭据及授权记录分离。 |
| 访问请求 | 所属授权会话、自述用途、候选范围、创建及到期时间、待审批或终态、实际处理结果。 |
| 授权 | 所属会话、源请求、批准时固定的信息项及字段集合、允许操作、生效及到期时间、撤销或结束信息。 |
| 访问凭据 | 指向授权的私密凭据及有效性控制，不等于外部聊天 ID，也不包含全库解密能力。 |
| 授权历史 | 用户实际批准的范围、有效期及后续状态变化，保留足够的历史事实以解释当时的批准。 |
| 访问记录 | 时间、会话、操作、目标信息及字段标识、处理结果和可关联的授权或请求；不记录内容值及 token。 |
| 备份 | 格式及版本、加密内容及完整性保护、恢复所需的非秘密元数据；运行中授权能力不作为可恢复权限。 |

未来同步仅要求本版不依赖本机路径充当资料身份，并保留版本、删除和恢复事实；不因此引入服务器、账户体系或同步协议。

### 5. CLI 与服务的行为契约

以下为操作语义，命令名称、传输方式和序列化细节在技术设计中确定。

| 操作 | 输入与前提 | 可观察结果 |
| --- | --- | --- |
| 检索公开目录 | 查询条件及分页信息 | 仅返回允许公开的元数据。 |
| 建立或关联授权会话 | Codex 聊天关联及客户端接入材料 | 建立本软件的会话关联，不因提交一个聊天 ID 获得已有授权。 |
| 提交访问请求 | 当前会话、用途、候选信息项及字段 | 返回可继续查询的请求标识、待审批状态及到期时间；同一请求的状态查询不创建新请求。 |
| 查询或等待请求 | 请求标识及相应私密会话关联 | 返回待处理、批准、拒绝、过期或取消等明确状态；单次等待超时保持原请求。 |
| 获取获准访问能力 | 已批准请求及创建该申请时建立的私密关联 | 返回实际获准范围、到期时间及可用于后续读取的能力；仅知道请求 ID 或聊天 ID 不足以领取。 |
| 读取信息 | 有效访问凭据、明确的目标信息项及字段 | 验证当前授权及资料状态后返回已授权字段的最新值；不默认返回整条信息。 |
| 提交录入或变更提案 | 当前会话、拟变更内容及必要的版本依据 | 返回待用户确认的提案；提交成功不等于正式写入。 |
| 用户批准或拒绝 | 可信桌面管理入口、尚可处理的请求及最终选择 | 原子地记录结果，批准时固定范围和有效期；不由 agent 自报批准。 |
| 用户确认变更 | 可信桌面管理入口、预览后的提案 | 校验版本并执行已确认的变化；过时提案不能静默覆盖新内容。 |
| 用户撤销与管理 | 可信桌面管理入口、目标授权或资料 | 后续访问按新状态生效，保留对应历史。 |

接入层需要避免把凭据写入通用日志、公开状态响应或其他聊天可按 ID 查询的缓存。私密会话关联如何安全交付和保管，需要通过 Codex 接入验证；不能用可伪造的环境变量字符串替代。

### 6. 请求与授权生命周期

- 待审批请求默认 30 分钟有效，设置可调整；到期后不能继续批准。会话结束取消尚未处理的请求。
- CLI 等待超时是一次等待操作的结果，不是申请的终态。agent 可查询原申请，不重复发通知。
- 拒绝、过期或取消后不得自动反复提交相同申请。新增真实需要可形成新请求，Skill 应清楚解释既有结果。
- 用户部分批准属于成功处理，服务明确返回最终范围。用户补选和改选以桌面最终确认为准。
- 批准后的授权默认最长 8 小时，用户在批准时可调整；重复读取不延长有效期。
- 本版以整次聊天作为授权会话。主子 agent 共享本聊天范围，其他聊天独立申请。
- 正常会话结束撤销授权；缺失结束事件依靠到期兜底。恢复聊天不复活已结束、过期或撤销的授权。
- 2026-10-16 确认 Codex 自动结束边界：已安装 hook 的私有索引仅保存对应会话的独立仅撤销凭据，服务端验证该凭据后结束会话；它不能读取、申请、批准信息或领取读取能力。用户接受伪造或延迟的本机结束事件可能使授权提前断开。主子 agent 的读取共享仍需已有私密证明，不按公开父聊天 ID 领取能力；详见 ADR 0005。
- 关闭窗口保留后台服务和有效授权；完全退出停止服务并使当前凭据失效。异常重启也不能因恢复持久化历史而悄悄复活旧凭据。
- 会话 ID、用途文字、目录名称、请求 ID 均不是内容访问凭据。有效凭据泄漏后的滥用属于已明确的安全边界，软件仍需避免自行泄露凭据。

### 7. 固定范围与当前数据

- 授权保存批准时明确选中的信息项及字段集合，不保存可自动扩张的分类查询或通配范围。
- 新信息项、新字段、模板扩展及目录移动均不扩大既有授权。CLI 返回的授权说明明确告知新增内容需要另行申请。
- 已批准字段的值更新后可直接读取最新值。旧值不随当前字段授权开放。
- 信息或字段删除后，相应已有授权停止提供该内容；恢复后不恢复旧授权。实现需保存足够的撤销或代际事实，避免仅重新出现同一个标识就恢复可读。
- 在批准、读取、修改、撤销及删除并发发生时，以核心服务中已生效的状态为准。用户看到成功撤销或删除结果后发起的新读取必须失败；已交付的数据无法收回。
- 申请到期、会话结束和用户批准之间的竞争必须产生唯一可解释的结果，不能对终态请求再次签发授权。

### 8. 录入、修改与删除

- agent 提取、归类和建立字段；用户在桌面端批量预览，确认后入库。修改展示差异，删除需要明确确认。
- 用户接受导入 agent 已接触所指定的原始资料，授权机制不尝试让其遗忘。
- 提交提案的权限不会自动赋予读取现有内容、查看历史、覆盖信息或批准提案的权限。需要现有值来整理修改时，应先取得相应读取授权。
- 变更提案应关联所依据的版本。资料已变化时向用户展示冲突或要求更新预览，不静默应用过时结果。
- 回收站与修改历史默认保留 30 天。用户在客户端查看及恢复历史，agent 的当前内容授权不包含历史版本。
- 保留期限管理针对本软件管理的活动数据和历史，不声称能够删除已经导出的离线备份或已经提供给 agent 的内容。

### 9. 桌面交互与历史

- 信息管理入口提供目录、标签、字段模板、公开描述和受控内容的编辑；不预设必须使用卡片展示。
- 待审批入口展示聊天关联、agent 自述用途、申请范围、最终选择和有效期。自述用途供用户判断，不作为可信身份依据。
- 录入提案入口支持批量预览、归类调整、差异确认及结果反馈。
- 授权历史作为主要入口，查看当时批准范围、有效期、状态变化，并关联访问记录；有效授权可以撤销。
- 访问记录包含成功、未授权及其他失败的可解释结果。服务不会为一个无凭据请求泄露目标信息是否存在或其内容。
- 2026-10-16 确认：授权历史与访问记录默认保留 90 天，可在客户端选择 30、90、180 或 365 天；缩短期限前提示将清理较早记录，用户确认后执行。记录不包含字段值、token 或密钥。这不改变回收站和内容修改历史默认保留 30 天的规则。
- 2026-10-16 确认：访问记录暂时写入失败时，暂停向 agent 返回内容并明确提示；不能先交付资料再忽略记录失败。修复记录存储后才能继续读取，不静默丢弃失败记录以恢复访问。
- 回收站、修改历史和备份恢复提供用户管理入口。功能布局可合并，不要求每项成为单独页面。
- 通知按新请求触发，同一请求状态查询不重复提醒；通知正文不携带资料值或访问凭据。

### 10. 加密、备份与恢复

- 采用 SQLite 关系型存储、Drift 数据访问层及 Dart sqlite3 绑定，以 SQLCipher 实现整库加密。正文、索引、公开目录和受控历史统一保存在加密库内；公开目录通过受控服务返回，不另建明文资料副本。字段级授权由核心服务执行，第一版不自行建立逐字段加密或独立字段密钥体系。
- 资料、受控历史和包含敏感描述的持久化记录由应用加密保存；临时文件、数据库辅助文件及错误输出不能意外形成完整明文资料副本。
- 本机数据库密钥由密码学安全随机源生成，交由操作系统保护，供应用自动获取；不能通过在公开配置或 CLI 中放置全库密钥来满足“免应用密码”。优先验证 flutter_secure_storage 平台适配，具体版本和 Windows/macOS 配置尚未锁定，不提供同用户进程强隔离承诺。
- 第一版提供手动加密备份。启用备份时生成独立于本机数据库密钥的恢复密钥，供用户另行保存，日常操作不需要输入。
- 新设备应能仅依靠有效备份和恢复密钥完成恢复，不依赖原设备仍然在线或本机密钥仍然可用。
- 备份需验证完整性和格式兼容性，错误密钥、损坏或不支持的备份不得破坏当前资料。
- 恢复后生成新设备的本机数据库密钥并重新建立系统保管；备份排除活跃临时访问凭据与待审批状态，不复活有效 token、待审批请求或原环境中的活动权限。历史记录可以作为过去事实恢复，不能转化为有效授权。
- 发布版启动时验证实际加载 SQLCipher 和加密配置；加密能力缺失时拒绝继续，不静默回退明文 SQLite，不只依赖调试断言。密钥缺失或错误时保留原资料，不覆盖旧库；临时存储采用内存策略，验证辅助文件与日志不泄露资料。
- 2026-10-16 确认完整备份目标范围：当前信息、目录、标签、模板，以及导出时仍在各自保留期内的回收站、修改版本、授权历史和访问记录。排除未确认录入或修改提案、待审批状态及所有活跃临时授权凭证。基础备份任务先交付声明的当前信息范围，完整恢复任务 #17 扩展到上述范围并验证早期格式兼容，不将尚未实现的历史支持描述为已可用。
- 已导出的离线备份不会随着应用中的保留清理自动删除旧内容；恢复历史只恢复过去事实，不恢复访问许可。授权历史与访问记录的保留时长及缩短期限提示已在第 9 节确认，不能与内容修改历史的保留策略混用。

### 11. 实现顺序与技术待定项

- 先用虚构信息完成一个可运行的申请、桌面审批、读取、撤销流程，并验证 Codex 聊天及主子 agent 关联。
- 再验证加密存储、自动密钥保管和跨设备备份恢复；这些能力验证前不迁移真实个人资料。
- 完善目录模板、提案确认、历史、回收站及跨平台安装和后台行为，完成第一版范围。
- 桌面框架及本地语言已选定为 Flutter/Dart；存储采用 SQLite + Drift + SQLCipher，随机本机密钥由系统保管，备份使用独立恢复密钥。原始规划时没有应用代码；现已集成核心、CLI和桌面代码，已有部分Windows演示，具体实现及剩余实机验收见实施状态，不将技术选择或编译视为全平台通过。
- 选择具体实现时必须保持已确认的使用体验和安全边界。若实际平台限制迫使改变这些承诺，应明确提出差异，不能静默降低标准。

### 2026-10-16 实机反馈确认：阅读式提案与限定整理任务

- 录入提案默认以只读信息卡片展示名称、说明、分类与内容，逐项“编辑”才进入独立编辑表单；编辑保存只回到预览，确认整批后才入库。保存失败保留草稿。
- 提案列表显示 Agent 自述名称、用途、聊天、提交时间、条目/内容数量及主要信息标题。旧提案未记录的属性显示未记录，不推断为已验证身份。
- 已确认提案可通过原资料 ID 只读查看当前入库资料；删除后不从提案复制旧内容。终态提案继续只保留不含字段值的凭据和描述性元数据。
- Agent 在录入时提供分类和标签建议，用户确认时原子复用或创建标签、分类并入库；默认无需用户逐项手动归类。用户可在独立编辑中调整例外；模板建议仍不自动复用旧字段身份。
- 初次确认：只向本次整理的选定聊天开放标题、公开说明和现有目录/标签名称，不提供字段值。发起方式与写入决定已由下方“整理流程更正与界面精简”替代：Agent 发起请求，一次批准后自动应用分类和标签。
- 整理任务绑定发起申请的私密授权会话及用户批准的固定信息项范围，最长 30 分钟；取消、会话结束、重启或方案提交后不能继续获取元数据。普通公开目录的可见范围保持原样。
- 整理只调整分类和标签，保留信息与字段身份、内容和已有授权；应用时整批检查基础版本，冲突不部分应用。此处旧CLI限制已由ADR0007替代：CLI可发起整理请求并在获批范围内提交原子应用，但不能自行批准。整理请求、任务和结果均不进入备份，也不因恢复而复活。

### 2026-10-16 整理流程更正与界面精简

- 整理从用户向 Codex/外部 Agent 提出要求开始，Agent 通过 CLI 提交整理请求，应用在访问审批队列列出来源、用途、具体资料及元数据/分类写入能力；用户批准前不提供目录/标签名称，也不能改分类。移除应用内手动创建整理任务和复制提示入口。
- 用户明确批准：整理请求一次批准后，Agent 可以自动应用所选资料的分类和标签，无须第二次确认。批准固定所选身份和版本，最长30分钟；不提供、修改字段值，不改变普通内容授权。任一版本冲突整批不应用，结果可只读查看；旧版未确认方案保持原确认要求。
- 请求支持等待、状态查询、缩小范围、拒绝和撤销；等待超时继续同一请求，禁止自动重复请求。结束、到期、重启或完成后无法继续获得整理能力，写入故障整批回滚。
- 资料详情在说明区域提供“编辑”，分类本身提供调整入口；历史、删除使用图标及简短提示。移除“字段内容 / 字段数 / 按字段授权”说明行，功能边界不变。
- 回收站沿用记录行与明确查看/恢复动作，去掉移动端折叠条；保留30天期限及恢复不复活旧授权。录入与变更列表的操作靠右，来源、用途、摘要、时间分层展示，不使用中点或横线拼接元数据。

## Testing Decisions

### 已确认的主要测试边界

用户已确认：主要通过桌面端和 CLI 共用的本地核心服务公开接口测试完整业务流程，再补少量真实桌面、CLI 及 Codex 接入验收。

初始规格发布时仅有文档；现在复用已集成的核心服务公开接口及测试入口，扩展受影响流程，避免为每个内部模块另建业务规则模拟层。

好测试观察输入、公开结果、实际读取范围及状态变化，不依赖私有函数、内部调用次数、特定存储表结构或界面组件实现。授权规则使用真实业务执行及临时存储验证；时间可受控以测试到期，不让测试真实等待 30 分钟或 8 小时。系统通知、密钥保管等平台交互可在主要业务测试中替换，但必须另有真实平台验证，不能据此宣称跨平台集成已完成。

### 核心服务行为测试

| 场景 | 必须观察到的结果 |
| --- | --- |
| 未授权发现信息 | 只返回允许公开的目录；字段值、私有说明、历史及未确认提案不泄露。 |
| 一次申请与用户调整 | 部分批准、补选和改选后，实际可读范围与最终用户选择完全一致。 |
| 篡改目标 | 替换信息项、字段、请求或会话 ID，无法扩大访问或领取其他会话的凭据。 |

| 请求生命周期 | 待审批、拒绝、部分批准、到期和取消可区分；等待超时不创建新请求或重复通知。 |
| 时间和结束 | 授权到期、会话结束和手动撤销后，新读取失败；重复读取不延长到期时间。 |
| 退出和重启 | 关闭窗口可继续访问；完全退出后停止访问，重启不恢复旧凭据能力。 |
| 批准竞争 | 已过期、取消或已处理的请求不能再次批准；结束和批准并发仍有唯一有效结果。 |
| 录入与修改 | 提交仅产生提案；确认前不入库；没有读授权不能通过差异或错误响应取得已有内容。 |
| 并发变更 | 过时提案不能静默覆盖新值；预览与提交之间变化得到可解释的处理。 |
| 删除与恢复 | 删除后旧授权失效；恢复后旧授权仍不可读，新批准才可读。 |
| 版本保留 | 用户能查看及恢复保留期内版本；agent 不能用当前授权读取历史；按受控时间验证保留策略。 |
| 历史与记录 | 批准范围、状态变化及访问结果可关联，记录及诊断输出不含内容值、token 或密钥。 |
| 审批入口 | agent 公共接口无法自行批准或撤销他人权限、永久写入或导出全库。 |
| 备份恢复 | 加密备份和恢复密钥可在独立环境恢复；损坏、错误密钥及不兼容版本不破坏原资料。 |
| 恢复权限 | 备份恢复后没有可复活的 token、待审批请求或有效历史授权。 |

### 少量跨边界验收

- 真实 CLI：检索目录、请求并等待、领取范围、读取及提交提案；验证机器可读结果、错误状态、进程等待超时和凭据不进入通用日志。
- 真实桌面：部分批准与补选、差异确认、授权历史及撤销、回收站恢复、备份导出与导入。
- Windows 与 macOS：安装运行、关闭窗口后后台保留、完全退出、桌面通知、自动密钥获取和跨设备恢复，分别提供实际验证证据。
- Codex 桌面端：聊天关联、主子 agent 共享、不同聊天独立、正常结束、恢复聊天及异常结束兜底。不能仅凭官方文档就报告集成验收通过。
- 加密存储：验证静态文件及辅助文件中不出现测试敏感值，密钥缺失时失败可解释；此测试不替代所选加密实现的正确性和安全依据。
- 发布构建与升级：验证两平台实际加载 SQLCipher；加密引擎缺失、错误或缺失密钥均不导致明文回退或原库覆盖；验证应用升级后的系统密钥读取及数据库结构迁移。

## Out of Scope

- 服务器职责选择、远程信息服务、同步传输实现、跨设备审批及同步冲突策略。
- 家庭、团队和多人共享，预配置 agent 权限等级或按命名空间自动授权。
- 单独为同一聊天中的每个子 agent 建立权限体系。
- 原基线不包含SSH私钥保管及凭据使用代理；后续升级 #21 新增本机托管字符串/文件与获批CLI启动。远程代理、签名服务、浏览器填充、无人审批自动执行仍不在此次升级范围。
- 任意文件格式的解析、OCR及自动填表。普通附件原字节的加密存储、授权读取与本机交付已按2026-10-18修订纳入#34，不再整体排除附件存储。
- 应用主密码、密码解锁、应用锁和自动备份。
- 对已控制本机或窃取有效凭据的攻击者提供强隔离保证；收回 agent 已读取的内容。
- 在桌面应用内额外接入模型来完成录入；当前流程由外部 agent 提交提案。
