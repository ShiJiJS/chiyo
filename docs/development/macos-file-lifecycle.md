2026-10-21，QA 最终源码 `72863c8`。只有原生验收脚本与证据变更；生产代码、

## 行为与证据

- 同一文件字段从 1,024 字节的 v1 替换为不同的 2,049 字节 v2，附件身份、字段身份和授权截止保持。
  新操作领取 v2；原 operationId 重查仍返回同一 v1 副本和原文。
- 取消文件选择、选取新文件后放弃未保存更改、取消版本恢复、取消删除及保留授权均保持原状态。
  放弃草稿后暂存计数归零，两个输入源文件字节始终未变。
- 正式版本差异预览显示两个版本的名称、大小与版本号。确认恢复建立信息版本 3，
  当前附件回到 v1；新操作领取 v1，已交付 v2 副本保持 v2，不被替换或重写。
- 界面删除整条信息后，三个活副本被回收，公开目录为空；新操作与原操作重查均以
  `conflict/field_removed` 拒绝，不产生新交付。取消删除时此前副本仍能正常读取。
- 回收恢复建立信息版本 5，信息及附件身份保留、文字/文件字段使用新身份。
  原授权不能读取旧字段，也不能按新字段或同名恢复内容补领。重新批准文件后才能领取，
  同项文字始终未批准，独立 CLI 读取被拒绝。
- 从历史页面实际选择该授权并确认撤销后，副本回收，新领取被拒绝；取消撤销时可继续使用原副本。
- 另一次夹具审批使用正式 API 的最短一分钟期限。父进程按 CLI 返回的真实 expiresAt 等待，
  不改系统时间或注入时钟；到期返回 `expired/grant_expired`，副本回收。
  正常切换页面后选中该到期记录，界面显示“已到期”，不存在虚假的未关联交付条目。
- 同进程关闭服务和加密库再重开：信息版本 5、当前文件 v1 与原字节保持；
  三份旧授权全部结束，五条交付均无活副本，每条仍关联原授权历史。
  新会话不能使用旧关联；重新批准后第六份交付可读，显式释放后路径消失。

六份独立交付均由系统 curl 实际上传到只监听回环地址的接收端，原字节精确匹配。
删除、撤销、到期或释放后，六次继续使用旧路径上传均退出 26，接收端无新增成功接收。
已经上传的字节不会因此撤回。旧操作/新操作版本断言独立于接收端；不将同机路径宣传为远端可访问。

Flutter 和三个 CLI 进程均退出 0，接收端关闭，成功合成根清理。
严格分析、原生 Debug 沙盒/签名及恢复普通 main.dart Debug 后的严格验签通过。

## 保留的失败与范围

第一轮在删除后收到正确 `field_removed`，测试误要求普通 `unauthorized`；
第二轮自然到期返回正确 `grant_expired`，测试同样遗漏其独立 `expired` 状态。
两轮均保持失败，父进程停止自己的等待宿主，未伪造正常退出码；失败根仅本机保留。
修正测试按正式协议精确检查状态与错误码，没有放宽产品拒绝规则。

第三轮完整数据/授权流程通过；视觉复核发现到期后的截图仍选着上一条已撤销记录，
夹具审批发生在已打开的历史页中，不能把该截图当作新到期记录的界面证据。
第四轮增加普通导航刷新后明确选中到期记录，并核对持久化的授权与交付关联。
各轮保留各自源码与结果，不累计重叠通过计数，不把测试夹具快照现象报告为已确认产品缺陷。
