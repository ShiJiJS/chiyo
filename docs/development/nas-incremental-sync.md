# NAS 浏览缓存与增量更新（#106）

实现位于 `codex/nas-sync`。服务器仍为正式保存位置，App 只在当前连接的内存中保留用户浏览内容，不新增离线库或延迟上传队列。当前正式 NAS 与 `/Applications/chiyo.app` 不随开发检查自动替换。

## 数据流

- Owner `POST /v1/owner/sync` 初次返回目录、模板插件和当前资料的共享展示数据。普通文件仅含说明及版本引用，凭据展示使用原有禁止材料值的编码器。
- 每份资源计算摘要。服务器在加密运行状态的独立 `ownerSync` 部分保存递增更新位置及最近八份摘要清单，不复制正文或附件。普通重启保留更新位置；恢复备份后的新资料库代次使用不同的公开更新位置。
- 后续返回发生变化的资源和已删除身份。客户端位置不在保留范围内时明确返回完整重建。此记录描述两次拉取之间的当前状态差异，不代替资料修订、文件版本或审批历史。
- 响应约按 2 MiB 分页。分页使用最多四个、三分钟有效的内存续读句柄，固定当前投影；分页中发生修改由下一次更新获取。续读失效或恢复备份会要求重建；App 验证完整批次后才同时发布内容和更新位置。
- App 缓存依连接实例隔离。手动与每分钟定时更新合并；同步失败保留上次成功内容及更新时间。身份失效或服务器不匹配清除缓存，不继续展示为当前有效资料。
- 保存、目录变更、模板变更等成功后主动更新缓存。紧接着的编辑等待读取完成，避免刚保存又用旧版本提交；后台读取期间的普通浏览使用已发布缓存。
- `WorkspaceLibraryNotifications` 独立通知资料库，申请变化不再触发资料库的网络重读。申请检查使用 `/v1/owner/updates`，不重新遍历完整授权历史；请求与提案仍及时更新。信息库中的搜索、筛选、排序和正文浏览复用既有展示与查询逻辑。

## 保存与持久化

原保存版本检查、操作回执、提案整体入库和文件历史不变。缓存不是写入依据；表单仍携带原始版本，旧版本提交会被服务器拒绝，不按电脑时钟挑选覆盖者。

仅明确列出的 Owner 查询可在全部运行状态不变时省略新 checkpoint。仍运行到期、决定和审计维护，再比较实际状态；发生变化继续持久化。Agent 路由保留原有必须完成 checkpoint 才发布结果的行为，相关故障注入回归继续通过。后台审批列表刷新保留现有可操作状态；用户提交决定会使并行旧读取失效，避免刷新期间吞掉点击或旧结果覆盖已提交决定。

Owner 请求采用整体十五秒期限，Agent 保留默认十五秒及显式短期限；超时中止对应 HTTP 请求，持续发送少量数据不能无限延长期限。不自动重试写入。服务器可通过 `CHIYO_REQUEST_TIMINGS=1` 开启结构化耗时记录，含路由类别、状态、进入路由前、路由处理和 checkpoint 耗时，不记录对象编号、请求正文或凭据。

## 验证与实际限制

新增合成 HTTPS 测试验证完整拉取、增量删除、正常重启、两个客户端版本冲突、失败不改变已发布缓存，以及后台读取等待期间继续浏览。共享路由测试验证无变化不写盘、续读冻结、更新位置过期重建、写入失败及资料库代次变化。持续响应测试验证整个响应期限。

同一合成资料连续三轮读取目录、查询及详情：原客户端路径 21 个请求，内存缓存路径 0 个；一次本机测量约 173 毫秒与 1 毫秒。无变化的同步没有新增运行状态 revision。这是本机合成测试，不能代替繁忙机械硬盘 NAS 的实测数值。

自动界面回归曾发现目录保存后旧分类版本及插件变更后旧详情的问题，已修正为等待本机修改后的缓存更新。完整服务端检查的首次运行缺少合成 SSH 镜像，以及一次既有测试材料文件的时序失败；补建镜像后独立重跑三项通过，完整服务端检查重跑后 78 项全部通过。资料库及刷新控制器 11 项、插件与缓存 2 项、相关文件/提案/审批/备份界面均通过（前一组合运行的目录失败已修复，并在后一组重新验证）。最终测试、候选包及部署状态以 GitHub #106 后续记录为准。

最终候选包统一构建并检查签名、解包、配套 CLI/worker 和实际编译版 Linux 容器；NAS 发布后的实际耗时仍需集中检查，不将源码测试通过写成正式安装已更新。Windows 实机、第二台电脑审批及手机继续后置。
