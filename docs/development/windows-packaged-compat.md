## 夹具来源和实际结果

格式1–4明确是**格式兼容夹具**：用当前SQLCipher快照，按既有自动测试投影移除旧版本
不支持的表、日期等信息，再以相应版本校验；不冒充真正旧发行程序写出的备份。
真实旧源码2918010生成的schema16/格式5，由
[旧源升级和格式5原生恢复](windows-packaged-upgrade-format5.md)单独证明。
格式8由当前正式Owner文件草稿/保存/导出接口生成，含两份保留原文及空文件模板，
没有文件交付事实；此前格式9的完整事实往返见[联合验收](windows-packaged-joint.md)。

| 格式 | 发行程序实际UI与退出后加密重开结果 |
| --- | --- |
| 1 | 信息及字段身份、当前原文、版本2保持；无修改历史；缺失日期仍为未知 |

每种格式使用独立SQLCipher/当前用户DPAPI目标库，初始只有17分钟请求等待设置；
原程序的系统Open对话框分别选择备份与恢复密钥文件，实际查看预览、确认恢复到空库。
界面显示恢复成功、Agent需重新申请、非空库不能覆盖或合并。恢复前已连接的独立AOT
CLI会话随后返回unauthorized，服务仍可查询能力。正常退出后SDK仓储只负责检查结果，
不是替主程序执行恢复；目标等待设置均恢复为源23分钟，无请求/凭据/活跃授权/活副本。
通过各格式的原备份及恢复密钥文件SHA256比较保持不变。

本轮没有打开或显示恢复密钥原文。原生系统文件确认共12次（包含格式8的一次重复
恢复），六个实际Release进程均由CLI按自身PID正常退出0；不把窗口消失当作退出成功。
Computer Use只输入虚构文件路径，观察回执表示实际操作员看过对应UI，不是自动识图。
所有测试窗口/CLI/专属虚构库已经清理，47125无监听，CU会话已reset。
