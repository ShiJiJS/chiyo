# 托管凭据窗口的 Escape 取消与加密保存（#48 / #50）

2026-10-22，独立 `codex/macos-adaptation`，基于 `df8d565e8f60b936d35098684f6050b9e410a144`。
在最新原生安全输入的实际键盘验收中发现：添加凭据与更换版本窗口按 Escape 无效，
但取消按钮工作。现补齐本地取消动作和初始焦点，保存/授权/存储规则保持原有行为。
[79 份原始资料、分轮结果和校验](evidence/macos-credential-escape/verification.json)。

## 原因和修正

凭据列表使用 `showDialog(barrierDismissible: false)`，Flutter 默认 Dismiss 动作也因此
不可用。信息编辑器已有自己的受保护 DismissIntent，CredentialEditor 和
CredentialManagement 漏了这一层。实际基线的 Escape keyCode 53 已送达；不能把它与
Shift-Tab 修饰键状态异常混为一谈。

两个窗口现用局部 Actions 把 DismissIntent 交给已有取消路径：添加窗口保留未保存确认，
管理窗口沿用其取消按钮的行为。保存忙碌期间拒绝关闭。只加 Actions 的首次尝试能处理
已聚焦字段，但刚打开且尚未点击的窗口仍由外层路由作用域持有焦点；新增 autofocus、
skipTraversal 的内部 Focus 才覆盖该状态，不引入多余 Tab 停靠点。管理窗口的标题关闭、
取消和 Escape 共用同一 `_close`，避免忙碌检查不同步。

未改变背景点击限制、凭据写入、旧版保留、OwnerAccess 或 Agent 接口。共享 Dart 文件
只在 Mac 独立分支提交；Windows 模式回归是在 Mac 执行 widget 测试，没有 Windows
实机或 CI 验收，也没有修改 Windows 分支。

## 自动与实际 Mac 验收

新增 3 个场景 × Mac/Windows 两平台模式，共 6 项：

- 添加窗口的 Escape 确认、取消保留、明确放弃及空白窗口直接关闭。
- 元数据、轮换、停用和删除窗口沿用取消行为，名称、版本、修订和启用/删除状态不变。
- 真实仓库提交 Future 尚未完成时 Escape 不关闭管理窗口，完成后保存并正常返回。

正确准备后的旧源码结果为 2 通过、4 失败，失败对应两个平台的取消缺口；修正后 6 通过。
完整桌面最终 221 通过、2 条件跳过，严格分析无问题，三文件格式检查无变化。不将 6 项与
221 项相加，也不将条件跳过当通过。早期遗漏测试仓库参数、误把到期字段当名称的测试
准备错误，以及只有 Actions 的不完整修正日志保留；它们不是产品的不同独立缺陷。

实际基线使用可选被动键盘诊断，最终轮使用普通 WidgetsFlutterBinding，未启用该包装。
两轮均为生产 DesktopLauncher/Bootstrap/UI、真正 SQLCipher、独立合成资料库和内存测试
密钥，所有按钮/按键由 CUA 操作，没有 tester 或控制器写入替代实际界面。原生副本只有
读取输入源 ID 和文件面板被动日志；最终没有按键监视器、输入注入或修改系统偏好。

## 独立加密字节核对与限制

只读诊断严格限制在本轮 `.qa-owner` 匹配的合成临时目录，使用公开 QA 固定内存密钥，
不读取普通资料库或 Keychain。它以 SQLITE_OPEN_READONLY 打开真实 library.db，确认
`sqlite3_db_readonly == 1`，核对 SQLCipher 4.19.0、唯一凭据名、版本和两个已知合成
字节；每次读取前后数据库/WAL 摘要一致，只输出布尔值及摘要。

最终分别核对放弃后为零、创建为版本 1、取消轮换后仍为版本 1、保存为版本 2、独立
重开后仍为版本 2。第一次诊断误用 passphrase 形式而产品使用原始十六进制 key，查询
失败；另误以为材料存储为字节列表，实际为 base64。修正诊断后通过，没有改产品来适配
错误检查。初始脚本和明确标记的失败观察说明保留，不称初次读取成功。

按钮上的 CUA Shift-Tab 仍未通过：原生 Shift flags 为 131072，flagsChanged keyCode
为 0，而 Flutter 硬件状态 shift=false；`Shift_L+Tab` 仍向前进入绑定框。
文本框的 250ms Shift-Tab 则由原生 insertBacktab 正确返回安全按钮；ISO_Left_Tab 被
工具拒绝，没有产生该按键。未全局拦截 Tab、伪造修饰键或据此宣布物理键盘有同一缺陷。
基线中完成原生 sheet 后立即批量发出的第一个 Tab 未推进，下一次稳定 Tab 正常；
没有把这一时序观察写成所有快速键盘输入已通过。

CUA AX 曾将其他字段值映射错位，部分按 AX 按钮的首次动作未执行，改用已观察截图的
坐标完成；以焦点控件键、实际保存和独立加密字节核对，而非单凭 AX 成功回执。原生
AX/截图保存在会话中，归档为明确标识的转录，没有伪称另存完整系统截图。没有实际
中文 IME、VoiceOver、四主题全键盘矩阵、真实睡眠或最终普通安装 GUI 验收。
