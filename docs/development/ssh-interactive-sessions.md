# SSH 持续交互会话设计

状态：用户已批准产品行为，等待实现与双平台验收。日期：2026-11-14。

## 需求与已确认范围

Agent 使用知予保存的凭据连接任意获批 SSH 目标（例如阿里云），连续执行命令，保留同一 Shell 的目录和环境变量，并能回答安装确认、完成 sudo 密码认证。目标机器不必部署知予，和保存知予资料库的 NAS 是不同角色。

- Mac 和 Windows 本机后台程序维护 SSH；本地模式、服务器模式均如此。CLI 调用退出不关闭连接，不弹终端、不控制鼠标或前台焦点。
- 本地模式在本地审批；服务器模式在 NAS 审批、核验授权。本轮不增加 NAS 托管 SSH，不将连接从本机自动迁移到 NAS。
- 保留 `chiyo exec request/run` 单次程序执行及 stdin/env/file 交付。env 只注入获批子进程，不修改 Agent Shell 或全局环境，不自动传到远端；远端敏感环境变量注入不是已有功能，本轮不借普通 export 传秘密。
- 新 SSH 模式支持密码和私钥登录，共享会话管理；不得要求 Agent 自写 Expect 登录脚本。通用 exec 能力继续保留。
- 保留同一个远端 Shell，而非仅复用 TCP 连接。`cd`、`export` 在后续命令生效。
- 首版包括普通交互输入、回车、安装确认、sudo 凭据交付及中断。不能把“只支持非交互命令”作为完成标准。全屏编辑器的完整屏幕渲染不在此验收范围。
- 不按服务器品牌、应用名单或操作系统名称设白名单。识别实际 Shell/协议能力；无法支持时明确报错。Windows 本机支持不等同于任意远端 Shell 均已通过验收。
- 撤销后拒绝新命令，让当前命令自然结束后关闭连接。保留明确的中断/强制关闭入口；不宣称断开 SSH 能杀死所有远端后代。

## 架构与复用

CLI → 本机 SSH 会话模块 → OpenSSH/终端通道 → 目标机器 Shell。
本机模块 → 当前资料库服务 → 申请、授权、凭据使用记录。

复用 credential execution host 的本机常驻、私有入口、进程身份核验、凭据交付、操作防重放和输出过滤。现有执行器会关闭 stdin 并等待整个进程退出，不能直接冒充持续 SSH 执行器。实现独立 SSH 会话模块，由 CLI 和资料库授权层调用；保持远端连接、逐次命令和认证交付的内部职责清楚。

延续 ADR0009/0010/0024/0031 的执行归属与授权边界；扩展为可持续输入的会话。旧授权“聊天有效”不等于存在 SSH 连接，不恢复已丢失的活动连接。记录格式若新增持久事实，遵循现有版本迁移和旧版本拒绝规则，不提前臆造版本号。

## 对外操作契约（语义固定，最终命名在公共实现中统一）

| 操作 | 输入与结果 |
| --- | --- |
| ssh request | 目标 host/port、user、认证方式、凭据 ID/版本、用途及有效期；返回申请编号，等待批准 |
| ssh open | 申请编号、幂等 operationId；后台核验授权和服务器身份，连接成功且 Shell 就绪后返回 sessionId |
| ssh run | sessionId、operationId、命令；返回当前运行编号及状态，同一 Shell 执行 |
| ssh status/output | sessionId、运行编号、输出游标；只查询，不启动或重放操作 |
| ssh input | sessionId、运行编号、inputId、普通文字或按键；确认接收结果，禁止过期输入落到下一条命令 |
| ssh credential request/use | 绑定当前运行、用途和接收动作的凭据 ID/版本；已有范围可复用，否则申请追加授权。结果不包含秘密 |
| ssh interrupt | 绑定当前运行，请求中断；随后查询实际结束状态，不能把发送信号成功当作程序已停止 |
| ssh close | 正常关闭先停止新命令并等待当前结束；明确 force 关闭连接，报告未完成运行的结果未知 |

只准同一授权会话、原设备和对应资料库使用 sessionId；编号本身不是通行证。当前运行已结束、目标变化或授权失效后，旧输入/旧凭据申请不能转用于新运行。

会话 ready 时才接受新 run；busy 时返回 busy，不隐式排队。运行期间可以 input、查询、interrupt；输入不是新 Shell 命令。并发写入串行化，每次 inputId 防重放；响应丢失查询原操作，不盲目重送 y、回车或密码。CLI 等待超时不取消远端命令。

## 交互与每条命令的结果

申请远端 PTY（后台终端），处理连续输出、换行、UTF-8 分块、ANSI 控制符及终端尺寸。PTY 输出可能合并 stdout/stderr，结果中如实标识，不虚构分离流。

建立同 Shell 下的明确运行边界协议；不能靠 `$` 提示符、静默时间或整个 ssh 退出判断命令结束，也不能为每条命令新建 Shell。`exit`、`exec`、语法错误、信号及嵌套交互可能改变 Shell 生命周期，必须正确结束会话或报告未知。输出里伪造结束标记不能把后续输入错误投递；若所选协议不能保证隔离，必须改执行结构，不能只随机化字符串后宣称可靠。

“正在等待输入”不能仅根据暂时无输出推断。普通场景 Agent 读取实际提示并决定回复；知予保留输入能力，但不自动对任何提示回答 yes。每次写入前检查所属运行，执行结构须阻止进程结束到 Shell 恢复之间的竞态误投。此项和 sudo 接收确认是首轮实现验证门槛。

输出采用有界缓冲和游标；丢弃旧片段时明确返回缺口。正常输出过滤已知秘密（包括跨分块），输入日志只记录长度/类别/凭据引用，不能保留密码原文、私钥、认证能力、完整敏感环境。

## 密码认证和 sudo

登录密码与 sudo 密码可不同；私钥登录也可能需要 sudo 密码。审批须分别描述用途，不能把登录许可默认为 sudo 密码使用许可。已批准相同版本、接收范围和有效期时可复用，避免每次重复批准。知予控制凭据交付，远端账号能否 sudo 由远端系统决定。

登录优先评估 OpenSSH + 随包 ASKPASS，使用私有通道绑定本次认证与进程身份；不得把密码放到命令参数、Agent 输入文件或普通环境变量中。现有 exec env 接口仍允许用户批准支持环境变量的业务程序，不被此 SSH 专用约束删除。

sudo 必须有明确、可核验的密码接收动作，不能仅匹配任意 `Password:` 自动注入。评估 sudo 的专用输入/ASKPASS 机制与受控远端运行结构，明确输入只交给该次认证而非后续业务程序或 Shell。开发先证明这个性质，再接入真实材料交付；禁止把本地 SSH ASKPASS 当成远端 sudo ASKPASS。不得默默部署永久远端服务、修改 sudoers、关闭 SSH 主机核验或绕过系统认证。必要的会话级远端辅助代码须可审查、无秘密落盘并在设计中说明。

如当前交互无法可靠确认接收位置，明确失败或请求用户处理，不自动降级为读取凭据原文。审批等待后必须重新验证原运行与接收动作仍有效。私钥有口令、多因素和特殊 PAM 提示需能力检测，未适配时明确返回不支持，不能循环提交密码或误送登录密码。

服务器指纹使用已有信任记录；未知/变更身份须按既有信任流程处理。不会自动接受新主机指纹。正常流程隐藏凭据不等于能防范已获准远端程序主动窃取或变换输出秘密。

## 生命周期与撤销

会话：opening → ready ↔ busy → draining → closed；异常连接丢失为 lost。
运行：accepted → running → exited；可能 failed/unknown。可信的认证步骤可标 awaiting_credential；普通提示只作为输出，不伪造可靠等待状态。

- 沿用批准有效期或会话内不限时；不额外增加固定闲置断开期限。聊天明确结束、撤销、停用、凭据变更后停止新运行及新的凭据交付。
- 撤销后既有命令可自然结束；不能用“继续当前任务”为理由接受任意新输入或交付秘密。若卡在等输入，状态明确提示可中断/关闭，不自动输入 yes、不无限重试、不偷偷强杀。清理/中断入口不依赖已撤销的执行权限，但仍须验证原控制者。
- 终端窗口关闭/一次 CLI 退出不影响后台会话。后台程序退出、机器关机、休眠导致断线后明确 lost/unknown；不自动新建 Shell 或补发命令。
- 资料库服务不可达时，拒绝新的有副作用操作；已发出的远端运行可以继续，输出查询不伪造成功。不把另一资料库许可代用。
- 正常关闭释放本机进程、连接及受管材料；敏感材料清理按实际进程寿命，不因 CLI 返回提前删除。

## 分工与实施顺序

统筹维护本规格、公共接口合并、审批/记录/兼容性及最终验收。Mac 与 Windows 使用独立工作树，基于同一规格提交，禁止交叉覆盖已有原生填写、bugfix、说明页工作树。

公共实现负责 CLI 契约、会话/输入操作状态、授权范围、宿主路由和测试夹具；平台实现负责 OpenSSH/PTY、ASKPASS、进程寿命、私有通道及随包集成。平台适配尽量共用核心，差异集中在明确模块中，禁止分别实现两套不兼容 CLI。

先完成运行边界和 sudo 密码接收验证，再完成端到端实现。平台未实测不得标完成；无法远程连接 Windows 时可先实现可审查代码，但如实标 Windows 验收阻塞。只使用自制测试程序、隔离 SSH 测试环境、合成凭据；不下载第三方桌面软件、不操作真实云服务器、不更改系统安全设置、不替换正式 App/NAS、不发 Release。

## 必须通过的验收

1. Mac/Windows 本地模式与服务器模式：CLI 多次退出后仍是同一 Shell；cd、export 连贯，输入确认成功；后台无窗口/焦点变化。
2. 密码与私钥认证；严格主机核验；失败、口令/多因素不支持有明确错误。
3. sudo 需要密码、不需要密码、错误密码、密码与登录凭据不同；安装确认与 sudo 同一运行串联。凭据在日志/输出/参数/历史中不泄露。
4. 原运行结束后才到达的输入、重复输入ID、并发 run/input、审批期间程序变化、伪提示、伪结束标记、UTF-8分块、大量输出、非零退出、EOF/exit/exec、Ctrl+C。
5. 未批准、跨聊天、跨设备、凭据换版、授权撤销、到期、服务失联；当前运行按既定撤销规则处理，新输入和凭据不能越权。
6. 本机后台异常、网络断开、CLI超时/响应丢失均不重放，不宣称未知命令成功；资源和临时材料清理正确。
7. 旧 exec stdin/env/file（尤其环境变量注入）、现有 SSH 单次执行、浏览器/原生填写不回归；新记录兼容及旧版拒绝行为经验证。
