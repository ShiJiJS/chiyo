# 当前批次的手动验收

覆盖基础信息库、审批与接入的初始检查，以及后续已集成功能的手动入口。自动化测试及构建结果见 [实施进度](../planning/implementation-status.md)；本清单尚未执行，不能据此关闭任务。操作由用户安排，Agent 不自动启动或控制桌面，也不自动安装 Codex hook。

## 先验证 Windows 资料库

1. 如旧的“开发演示”仍在运行，先手动关闭它，避免占用端口 47125。启动当前工作区 `apps/desktop/build/windows/x64/runner/Release/info_desktop.exe`，保留同目录 DLL 和 `data` 文件夹，不单独搬走 exe。
2. 应至少显示“访问审批”“我的信息”和“录入提案”入口。首次使用时资料库为空。在“我的信息”新建“测试服务器”，公开描述填“仅用于演示”，添加“地址”和“用户名”两字段，值分别使用虚构的 `demo.example.invalid` 和 `demo-user`。
3. 保存后展开信息，确认两个字段可见。将地址修正为 `updated.example.invalid`，确认保存成功。
4. 使用“完全退出”按钮或托盘/菜单栏的退出项，再重新启动，确认资料与修正值保留。关闭窗口现在会保留后台服务；不要用关闭窗口代替完全退出。正常打开无需输入应用密码。
5. 记录是否启动成功、保存是否成功、重启后是否保留，以及错误提示原文。截图只包含虚构资料；不要分享密钥文件或会话凭据。

原库或密钥出现错误时应显示失败并保留文件，不应自动重建成空库。不要为手动验证删除或破坏正常资料库；缺失、错误密钥和明文 SQLite 引擎已通过隔离测试覆盖。

## 再验证桌面审批和等待

这一步由 Agent 运行通用 CLI、用户操作审批窗口配合。CLI 保持同一进程，先查询目录获得实际随机 ID，再提交上述两个字段的请求。

1. CLI 等待短时间后应返回原请求仍待审批，桌面只出现一个待办。Agent 稍后查询同一个请求，不重提。
2. 用户只批准“地址”，CLI 再查应得到批准结果；领取后可读地址，读取“用户名”被拒绝。
3. 用户撤销后再次读取失败；重新打开应用也不能复活旧授权。
4. 新建另一请求并拒绝，CLI 应显示 `denied`，不自动创建第三个请求。
5. 在桌面调整待审批有效期，重启后设置应保留；修改不延长已经提交的请求。自动化测试覆盖到期及并发处理，无需手动等待默认 30 分钟。

CLI 协议见 [说明](../cli.md)。此次校验不需要安装 Codex 接入，也不要求用户复制 token。

## 后续功能入口

- 审批范围与时长：按 [#5 清单](adjusted-approval.md) 改选其他信息项、只批准部分字段并设置时长，再由 CLI 验证实际范围。
- 目录、标签与检索：按 [#9 清单](organized-catalog.md) 整理虚构资料、保存公开描述并通过 CLI 分页检索；移动信息不能使旧授权扩张。
- 字段模板：按 [#10 清单](field-templates.md) 创建、使用和扩展模板，确认旧资料不被改写。
- 后台与通知：按 [#8 清单](background-runtime.md) 从应用内明确启用通知，提交新请求后关窗、从托盘/菜单栏重开，最后完全退出。系统通知权限和实际显示需在各平台观察。
- 批量录入：按 [#11 清单](import-proposals.md) 先拒绝一批虚构提案，再确认另一批；未确认内容不应出现在公开目录，确认后读取仍需单独审批。
- 备份当前资料：按 [#12 清单](independent-encrypted-backup.md) 另存独立恢复密钥、导出备份，并在空测试资料库中恢复；密钥与备份分开保管。
- 审阅修改：按 [#13 清单](reviewed-updates.md) 检查版本差异、修正和替换含义，再由 CLI 检查授权范围及冲突响应。
- 删除与回收：按 [#14 清单](../implementation-ticket-14.md) 确认删除提案、恢复字段，验证旧授权仍不能读已恢复字段；其他已授权字段不受影响。
- 授权与访问记录：按 [#16 清单](../implementation-ticket-16.md) 查看批准范围、访问结果和历史撤销；缩短保留时长应预览清理范围并确认。
