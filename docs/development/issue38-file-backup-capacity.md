## 行为与接口

设置的“备份与恢复”沿用原卡片、恢复入口、设置行与四主题，下方增加普通附件用量。当前与保留原件、未保存草稿共用100MiB预算；受管副本单列32份/100MiB，包括准备中和待回收，历史归档不计活副本。注明单文件10MiB、版本/回收至少保留30天、删除不立即释放容量。初次加载失败不伪造零，刷新失败保留上次值并明确未更新，可显式刷新。错误提示指向实际用量和保留期，未展示源路径或私有原名称。

Owner新增`informationAttachmentUsage`只读统计；Memory与SQLCipher仓库均实现，SQL使用同一只读事务核对版本元数据与暂存计数，不加载BLOB正文。统计区分版本记录、可用原文版本、原文字节和草稿数量/字节，回收与替换不会被误算成释放正文。

`InformationBackups.exportTo`成功发布后返回不带密钥、路径或可重用快照句柄的`BackupExportSummary`。导出界面的附件数量/大小来自这次真实导出的快照，避免以导出前后另一次统计充当结果。恢复预览同样列当前文件字段、可恢复原文版本（含保留版本）、合计字节和交付事实数；旧格式明确不含普通附件。交付事实不等于活副本，恢复需重新申请。检查后备份变化、原文缺失/校验失败、容量/格式错误有对应反馈。schema21、备份9/8/7和Agent协议不变。
