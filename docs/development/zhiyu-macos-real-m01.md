## 2026-10-30：组合入口与持久保存回执

代码提交 `9894f060`。

- 将 `WorkspaceApp` 从 `PreviewWorkspace` 分离。正式入口可以提供自己的 `WorkspaceSource` 和桌面桥；共享界面不构造示例来源、不打开数据库。预览根继续持有原示例来源，现有预览 App 未替换。
- 同一来源的普通重建保持控制器；更换来源/桌面桥时销毁旧页面投影和订阅。旧页面销毁不能清除新页面注册的菜单回调；来源与桌面服务的销毁仍由组合根负责。
- `OwnerAccess.saveInformationRecord` 复用现有完整表单事务、字段身份、版本检查、修订与回收规则，提供跨表单/重开可查询的操作结果。新文件仍走原暂存表单，当前入口只处理文字与未变的附件引用。
- `information_record_operations` 与资料在同一 SQLCipher 事务内写入，仅保留操作编号、输入摘要、信息项身份、前后版本；没有正文快照。原临时表单回执继续按原生命周期清理。重复操作不会再次创建或修改资料，改变输入复用操作编号会拒绝。
- 普通库格式 22 升级至 24；带可移植焦点填充数据的格式 23 升级至 25。保留普通/可移植格式边界，实际存储可移植数据时 24 转 25。旧读者不能读新的数据库格式。操作回执不进入备份，备份内容格式本次未改变。
- 恢复事务将接收库中的旧回执标为失效，查询/重放返回 `library_changed`；失败恢复回滚该变化。资料删除及保留期清理后，重放原保存仅返回原操作元数据，不重新创建资料。

## 2026-10-30：资料结构进入同一持久模型

## 2026-10-30：表单编解码与真实库验证

新增 `WorkspaceInformationCodec`，将新界面创建/编辑表单转换为现有核心保存输入，并从实际信息项还原详情。普通文本、文档格式/正文、独立经历叶、实例描述及关联引用保存在同一持久模型中；布局只放描述和顺序，正文保留在核心字段。编解码本身不打开库、不构造示例来源、不向 Agent 提供正文。

- 新经历的 UI 临时 ID 不作为核心字段 ID；再次保存和排序使用真实不透明身份。实际 SQLCipher 测试发现核心 ID 的 base64url 填充不符合临时 ID 语法，已区分两者，避免正常再次编辑失败。借用已有身份、重复叶身份和重用删除经历均拒绝。
- 未映射旧字段在详情中保留，连续编辑及删除恢复后仍可保存。未知字段类型可原样保留，禁止改写；未知布局版本只读。已有普通附件可原样保留身份、版本和字节，本票没有因此开放新文件导入。
- 已有资料的字段被全部删除后，允许继续修改名称等元数据；新建空字段资料仍拒绝。文档格式字段已被删除时，不再用其旧模板要求阻止保存。字段名为 `name` 的校验错误与资料名称错误分别呈现。
- `LibraryController` 默认使用全部真实资料范围，不再硬编码 `selfhost`/`azure`。预览组合入口显式传入自己的初始查询和选择，正式组合默认不依赖示例身份。相关预览重置测试改为显式声明示例初始选择。

## 2026-10-30：真实资料读写适配与原操作核对

新增 `OwnerWorkspaceInformation`，作为正式来源中的普通资料模块，直接使用现有 OwnerAccess。定义由组合根提供，没有导入示例来源或创建第二套存储。它实现真实新建/编辑/详情、元数据列表与目录后代/标签/类型筛选、分组分页及跨页选择、关联候选和身份摘要查询。

- 创建要求模板版本/摘要与提供的定义一致；旧模板采用和文件导入明确返回未接入。编辑验证实际资料版本及字段身份。新关联核对当前目标和模板类型，已有失效关联在无关编辑时保留；关联仅为 owner 元数据，不授予读取权限。候选查询只读取来源关系描述及目标元数据，不解码来源字段正文；不在列表关键词查询中搜索正文。
- `InformationRecordCommand` 只保留原资料类型和规范化表单摘要，与输入、资料、回执同事务提交；不是正文副本。输入映射键排序后计算摘要，标签顺序不改变意图，字段/经历顺序保持其业务含义。核心拒绝命令类型与提交布局类型不符。
- UI 回执现在能在资料被修改、彻底删除并重开后，准确还原 create/edit 的原类型、预期版本和提交版本。重复原命令进入结果核对，不再次写入；同操作编号的新内容明确冲突。写入后通知/详情读取失败统一保持未知结果，查询失败不会被吞成“从未提交”。不完整的旧回执保持可读，但不能被适配器猜成完整 UI 回执。

## 2026-10-30：目录和标签真实事务接入

新增核心分类操作合同、SQLCipher事务实现和 `OwnerWorkspaceClassification`。新界面的目录/标签命令使用真实原子提交与持久原回执；未改既有分类语义，也没有通过内存列表变化猜测成功。

- 分类版本由数据库触发器维护，目录/标签的插入、更新和删除都推进版本，包括旧Owner入口、录入提案等已有写入路径。此版本覆盖分类状态，模板仍按自身版本/摘要核对。MemoryRepository提供对应的状态变化检测，产品持久性由SQLCipher实现。
- 创建、改名和移动复用核心名称、同级重名、现存父目录及循环检查。目录只允许空删除。标签删除需要当前影响预览，预览摘要包含标签、分类版本及受影响信息项/版本；资料关系或内容变化后须重新核对，不能仅凭旧数量继续。
- 标签删除将当前信息标签关系、修订和分类原回执同事务提交；字段正文、身份及历史原标签引用保持不变，符合ADR0014。回执失败导致分类、统一版本、资料关系、修订全部回滚。重开后可核对创建时原名称，即使分类后来已改名或删除；重复命令不重复创建，不同意图复用编号冲突。
- 新界面适配包含真实目录后代计数、标签计数、创建类型和回收数量；资料模块明确拒绝将托管凭据作为普通信息创建。分类提交后的刷新失败保持未知结果，原回执查询失败不能返回空值。
- 新增本机分类状态及回执表，普通格式为 **30**、可移植填充格式为 **31**；旧28/29迁移保留原分类身份。分类回执及本机版本不写入备份。成功恢复使本机旧回执失效并推进版本，失败恢复不改变它们；目录标签本身仍按既有备份内容恢复，无需改变备份格式。
