# Mac预览：跨页导航与弹窗保护

源码`0efa4b34afd26e6c71a6a0814fa65f7b0568819d`，独立`codex/zhiyu-macos`分支。进入#67多页面流程前完成的保护修复；提案/历史界面尚未实现，#67仍0/7，完整S5/实际OS输入门槛不变。

原有审批后台刷新、各页弹窗和设计说明各自调用setNavigationEnabled。三个定向检查复现：本机侧仍会转发关闭导航后到达的已排队原生事件；后台刷新会解除未保存表单的导航锁；晚到弹窗关闭会在审批结果仍未知时重开原生菜单。

现在根入口把弹窗计数和未决审批汇总为同一个导航状态；所有弹窗生产者释放自己的计数，后台读取不会覆盖它。原生菜单与Flutter顶栏使用相同状态，本机侧也检查当前标记，已排队的系统事件直接丢弃、不留待以后执行。锁定时不触发信息库搜索焦点等附带行为。

Owner在弹窗中明确选择的“查看资料/前往审批”与外部排队事件不同：该目标保留到所有弹窗完全关闭后执行一次。showDesktopDialog等待退场完成，不能用第一帧或已看不到控件推断它已经完成；更早的post-frame回调可能仍在关闭阶段。若期间审批提交进入未决状态，丢弃等待的跳转，保留当前核对。新建/旧模板保存后的资料跳转也在释放自有弹窗锁后进行。

设计说明按钮在弹窗期间禁用，因此关闭后先释放锁、等待按钮重新可聚焦，再恢复焦点；不能在按钮仍禁用时请求焦点。持续等待的恢复检查按实际按钮重新可操作来等待，不以固定延时或提高测试超时绕过。
