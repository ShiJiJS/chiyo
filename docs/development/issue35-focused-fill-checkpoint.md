# #35 焦点填充原型与只读识别检查点

2026-10-19，基线3d31604。**本票继续OPEN，尚不能通过正式CLI填充密码。**本次完成第一项原型和原生只读识别基础，接续核心/CLI/宿主/Flutter/迁移及实际输入验证，不改变#35的完整范围。

## 已落地

- 同一个Round05入口增加填充申请/确认/批准结果、tips和逐次填充历史。固定凭据版本、应用、方式及15/30分钟期限；批准不会输入，之后Agent点击密码框并后台调用CLI。同范围内复用，不逐次审批。
- 填充有sent/refused/partial/unknown/checking状态，记录与命令执行分开，无虚构exitCode/cleanup。重复操作ID返回原事实；部分/未知不自动重填，撤销阻止后续操作。
- 凭据管理中的建议环境变量对字符串可留空。密码框填充不要求无关变量名，也不trim秘密输入。
- [目标合同](../design/local-focused-fill-contract.md)补齐类型、应用身份/焦点、审计、私密管道、输入结果及恢复边界；其中正式接口仍标为待实现。更新ADR0012及原型README，纠正旧的“#33仍待实现”描述。
- Windows `focused_input`模块只读技术焦点属性，不读控件值/窗口标题/剪贴板，不发送输入。EXCLUDE_FROM_ALL且未链接/安装到正式应用，只有显式构建的检查器/测试。

## 发现、修正与未通过项

1. 实际空密码框测试时，浏览器工具报告DOM焦点在密码框，Windows原生前台却是LockApp。未发送按键、未读密码。由此补WTS会话解锁检查，不能只根据桌面名Default或浏览器工具“已点击”放行。之后一次只读捕获为普通Chrome非密码控件，仍不列为内置浏览器兼容通过。
2. 看图发现初始化的page/request监听提前关闭确认/保存失败弹窗，模型检查没有捕获。将关闭监听延后到初始状态稳定后注册，增加实际浏览器`waitfor .focused-fill-modal`门槛；确认/失败在1440×900、1280×800均可见。
3. 截图工具最初点被裁切的历史行，提示中心点受底栏遮挡；其页面滚动不能替代内层滚动。这些尝试不计通过。随后用内置浏览器对该元素实际滚动、点击并取得FILL-01选中/正确内容的AX及截图；无须更改现有滚动布局。
4. 初始tips正文偏长，限制阅读宽度后复测无提示。步骤编号是实际01/02/03操作次序，保留；无新眉标/装饰卡片，未加入图片或新字体。界面说明只保留决定凭据、目标、期限及异常处理所需内容。
5. 动效取证环境缺ffmpeg，录制步骤非零退出，只取得出场三帧和探测结果，不声称有MP4。静态/交互检查单独通过。三帧沿用同一出场样式，不用于证明正式输入。
