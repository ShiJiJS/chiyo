# 完整资料库备份与恢复（#17）

本任务扩展 #12 的独立恢复密钥备份，保留 SQLCipher 4 加密信封和 `aim-recovery-v1:` 密钥格式。内部逻辑快照版本为 2，读取器仍支持版本 1 的当前资料快照。未知版本、表、列或无效嵌套历史在接触目标资料前拒绝。数据库仍为 schema 10，此次不需要迁移表。

## 覆盖范围

- 当前信息、字段及类型、目录树、标签、模板和设置，保留原标识、版本及关系。
- 替换时间仍在 30 天内的内容版本，以及尚未达到原到期时间的回收站内容。版本恰好 30 天时清理；回收站达到到期时间时不可恢复。
- 在用户设置的 30/90/180/365 天期限内的授权历史及访问记录，默认 90 天。两者按各自批准或访问时间筛选，允许访问记录的原授权历史已经清理。
- 不含字段值的删除、恢复、清理事实及版本标识，维持后续恢复的单调版本号。这些事实不采用内容的 30 天期限。

排除所有录入、修改、删除提案，待审批请求，运行中授权、访问 token、会话证明、主子 agent 关联与仅撤销凭据、hook 私有索引、本机系统密钥、备份设置中的恢复密钥。备份本身必须和恢复密钥分开保存。

导出只产生一个一致的逻辑快照；不会为备份先清理用户的资料库。历史保留筛选在导出、预览和实际恢复时分别执行，延迟确认恢复不能延长任何内容的期限。离线备份的字节不会随应用清理而改变，需用户自行删除旧备份。

## 运行中恢复的边界

桌面通过 `OwnerAccess.exportLibrary` / `restoreLibrary` 调用可信存储能力，Agent HTTP 接口不提供这些入口。操作与资料写入串行：暂缓新内容访问及同步审批，等待已进入的读取完成拒绝记录，并保存此前排队的授权/访问事实。记录无法保存时操作停止，保留失败队列供修复后重试。导出期间已有授权仍保留，完成后可重试读取。

恢复仅允许空接收库；设置和本机备份配置可以已存在，任何其他持久记录（包括提案和无内容的历史事实）都会使恢复拒绝。验证、空库检查及全部插入受一个事务保护，所有内存模型在提交前准备好，提交后同步发布缓存，避免半恢复或因再次读取失败而报告错误结果。失败保留原设置、运行中会话及记录队列。

恢复成功后清空旧实例的请求、读取 token、会话私密证明和仅撤销凭据；排在恢复之后、仍基于旧资料库的写操作也会拒绝。桌面保留原服务与请求通知订阅，新申请仍可正常审批。目标使用其正常初始化时新生成、由本机系统保管的数据库密钥，不导入源设备密钥。

导入的 `GrantHistory.restoredAt` 仅标记本机恢复事实，保留源记录中的批准及结束事件原样，不伪造源设备已撤销事件。该记录永远不视为当前有效授权，界面明确标注且不提供撤销按钮。公开历史标识不能领取任何权限。

- `backup_coordinator_test.dart`：排队审批/资料修正先于导出；读取等待期间恢复阻止交付；成功清空旧会话与仅撤销能力；失败保留旧授权和失败记录；旧库排队写入拒绝，退出等待恢复结束。

- `backup_widget_test.dart`：完整应用内预览覆盖范围及计数，用户确认后恢复，已打开的信息/历史页面刷新，历史只作为事实展示，旧会话及仅撤销凭据失效。原生文件选择框不由此测试操作。
