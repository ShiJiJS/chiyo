# #35 加密存储与备份检查点

2026-10-19，接续299a8b1的核心/CLI检查点。实际实现SQLCipher填充请求和独立操作的事务保存、重开归档、保留清理及完整备份，不将其当作整个#35完成。输入端仍为受控测试驱动，生产能力关闭，没有更改Round05界面。

## 实现与边界

- 数据库升级至schema18，独立`credential_focused_fills`保存类型化输入事实；命令操作、填充操作及其请求保持同一事务中的关联。任一种提交保留另一种，混合清理可原子删除，校验/审计失败回滚数据库和缓存。
- 校验请求类型/协议、批准事实、应用身份、操作ID、指纹、行身份与载荷关联，不将命令记录关联到填充请求。输入已放行必须有检查记录；不把墙上时钟的先后当作操作顺序，系统时间回拨不让真实事实无法持久化。
- 重开取消待审批、使旧使用许可失效；checking归为unknown并保留放行事实，sent/refused/partial/unknown终态及人工确认事实不改写成未输入。未解决的输入结果不随普通保留清理丢弃；人工确认后再按记录时间保留，确认不延长或复活授权。
- 完整备份升级为格式7，独立保存填充结果，无秘密输入缓冲、控制句柄、进程身份、输入长度或假命令退出码。真实凭据材料仍由既有凭据表随完整加密备份保护，不从本机填充记录复制。
- 备份排除待审批，进行中输入按未知事实归档，但不修改源库的运行事实。恢复只恢复过去结果和凭据，不恢复会话、授权或输入端；恢复时间有明确记录。
- schema18/格式7允许凭据的建议绑定为空，填充不强制环境变量名；格式1–6仍执行原来的严格约束。填充申请用途长度/版本上限与共享历史合同对齐，拒绝会导致无法备份的输入。
- 独立`library_format`在Drift前拒绝未来版本。旧程序改写header时，以已知独立标记选择迁移起点；目标表冲突完整回滚。已归档的真正schema17源码读取器用于验证旧库/格式6升级及旧读取器拒绝新库/格式7，数据库字节不被拒绝读取改写；已有实际schema16/格式5兼容验证保留。
