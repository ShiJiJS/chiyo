# Agent 录入提案（Issue #11）

新增 `import-submit`、`import-status` CLI 命令。会话先通过原有接入建立，凭据只在 CLI 内存或 Codex 私密关联中使用。以下 JSON 为虚构例子，通过标准输入传入，不将真实资料写到命令行参数：

```json
{"command":"import-submit","items":[{"name":"虚构测试机","description":"测试环境的连接资料","suggestedDirectory":"服务器","suggestedTags":["测试"],"suggestedTemplate":"服务器模板","fields":[{"name":"地址","description":"服务器主机名","value":"fictional.invalid","kind":"structured"},{"name":"备注","description":"操作说明","value":"虚构私有说明","kind":"textNote"}]}]}
{"command":"import-status","proposalId":"返回的提案标识"}
```

提交仅创建加密保存的待确认提案，不进入公开目录。状态只向创建提案的仍有效私密授权会话返回；公开聊天标识或提案标识不足以查询。持久化的是独立随机会话关联标识，不保存会话秘密或授权 token。重启后原会话不能查询，用户仍可在桌面处理待确认提案。

“录入提案”页整批预览，用户可以改信息名称、公开描述、字段名称/说明/类型/值，增减字段，选择现有目录和标签。Agent 建议分类和模板只作参考，不自动建立标签、套用模板或复用字段身份。用户确认后整批正式信息与提案终态在同一事务提交；重复确认返回原批信息，不重复建项。拒绝不会写入正式信息。导入只新增，不修改同名旧信息；新信息及字段拥有全新随机标识，原有授权不会扩大。

公开目录仅含用户确认的公开元数据。录入方已经看到原始资料，软件不能令其遗忘；正式入库不授予读取、审批、覆盖或备份导出能力，后续读取仍需正常申请。

单批最多 20 项、每项 50 字段、共 200 字段；单字段值 64000 字符，整批条目 JSON 最多 240000 UTF-8 字节；每个会话最多 20 个待确认提案。仅 `/import/submit` 请求体上限为 256 KiB，其余接口仍为 16 KiB，并保留原有 Host、Origin、内容类型和超时检查。错误不回显提交内容或内部异常。CLI 同样按命令限制输入大小。

Schema 6 增加加密提案存储。独立备份只覆盖正式信息，排除提案内容及其会话关联；已确认条目通过普通信息快照备份。现有待处理提案不作为恢复权限或待审批状态恢复。

自动验证覆盖核心服务私密隔离、拒绝、全批校验与单次入库、正常新授权读取，真实 CLI 大于 16 KiB 的批量提交和状态查询、不可直接读取/确认，加密重启和静态内容检查，以及完整桌面组件“确认提案 → 切换我的信息后可见”。未启动真实桌面窗口；Windows/macOS 实机批量预览、确认、拒绝仍待用户验收。
