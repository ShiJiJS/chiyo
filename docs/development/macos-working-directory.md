## 实现与兼容

- 读取范围继续创建 `.securityScopeAllowOnlyReadAccess` 书签；只有主人明确选择
  “选择工作目录（读写）”或“重新选择为读写…”后，才创建读写书签。
- 行内“重新选择”保留原保存范围；切换范围同样先说明、再由系统选择准确目录。
  取消或保存失败不更新列表/原归档，移除只忘记访问记录，不删除主人文件。
- v1 归档中的旧书签按读取解释，加载不重写或重新创建 token；主人修改列表时才
  迁移至 v2，并原样保留旧 token。v2 每条明确保存 `readOnly` / `readWrite`；
  缺范围、未知范围、格式不符保留原文件并拒绝写入。
- **降级旧应用的限制**：旧版只识别 v1，会将 v2 目录设置显示为不可用并保留原文件，
  避免把读写 token 错标为读取。数据库格式、密钥、凭据使用授权和备份格式均未改变。
- 系统面板在当次进程可能授予临时写入，不能以应用内标记宣称即时收窄这些权限。
  说明和行内状态均指“重开后恢复”的保存范围；降级和移除后以退出重开验证。
  保存范围不会赋予外部程序执行权限，GH/AWS 继续使用固定随包入口。
- 原生书签只保存在本机原生存储，响应仅含 ID、路径、可用状态及范围，不包含 token；
  没有增加 Agent 接口、沙盒例外或新的 entitlements。
