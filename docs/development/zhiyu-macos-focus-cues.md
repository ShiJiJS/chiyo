# 共享键盘焦点 · UI正式验收收尾第一段

源码`b9160aa5bd7c21dd6df8109ca4db5401b6c0cab3`，独立`codex/zhiyu-macos`分支。当前排期统一在[#62顶部](https://github.com/ShiJiJS/agent-info-manage/issues/62)；首候选交付已经结束，本段继续七张UI票的正式验收，不启动真实服务。

已修复两个实际问题：普通按钮原来把原边框改成2px焦点边框，且菜单项也描边；现在Round09沿用原边框，按冻结CSS在外侧保留3px间隙、绘制2px描边，菜单以背景和文字表示焦点。描边不扩张点击区、不改变布局，按下仍沿用原1px位移和150ms反馈。旧主题保留原边框处理。

从键盘切回鼠标时，旧的焦点表现仍会保留。现在原DesktopInteractionHost统一提供输入方式，鼠标按下收起装饰性描边，非修饰键恢复键盘提示；在子控件处理Enter/Space前只观察、不消费事件。原快捷键、激活、导航、Tooltip规则和销毁清理保留，没有第二套控件或新的系统输入能力。

实际像素回归先复现8组外描边/菜单差异，以及键盘→鼠标切换的一组失败。最终18项焦点检查包含实际导航栏的两尺寸、明暗、100%/200%文字，原边框、3px间隙、选中与焦点区分、禁用、旧主题及激活次数；连同现有菜单/动效/页面检查共84项通过，严格分析通过。

同条件冻结HTML的四组最终计算样式确认为2px/3px，并保留原参考PNG、Mac字体来源及实际PNG。四对原尺寸顶栏已经逐对查看；浏览器PNG包含ICC编码，拼图显示时转换到sRGB。没有把编码RGB差异误算成产品颜色错误，也没有将不可靠的精确色连通域尝试计为几何验收。当前证明焦点规则和可见性，不接受全部字形、基线或整页S5。

当前Profile原生检查1项/10条功能断言及六组原时钟/位移门槛通过，普通arm64预览恢复。首轮在800×600内容窗口定位尚未构建的惰性列表行失败；检查入口现先用已有原生接口固定1440×900，再检查原行。失败日志保留，不计为产品通过，也没有改变列表或放宽容差。最终帧预算仍有build两帧、raster三帧超时，最坏24.346/28.959ms；不宣称完整流畅度或冷启动稳定。

本段只接受共享焦点这一小段。#62仍10/12，#63/#64/#65/#67各6/7，#66/#68各7/8，全部OPEN。接着复核各页面的具体表单/菜单上下文及其余视觉与动效；完整S5不能因共享控件通过而自动关闭。
