## 复现与修复

初轮六类通过、一类失败：撤销、到期、轮换、会话结束、真实宿主终止后重开、交付前审计失败已通过；实际目标退出后，结束回执遇到 SQLCipher `BEGIN IMMEDIATE` 写锁，CLI 的退出和降级 unknown 两次写入均失败。解除写锁再重试审计仍显示 running，exitCode 为 null，清理 pending，凭据文件仍存在。0.4.0+9 源码有此问题，已有包不能被称为修复后包。红测原始结果保留，不覆盖。

修复集中在 Core 的执行回执处理：先完成私密能力和状态校验，再将写失败的第一份结束元数据纳入现有有序审计恢复队列。队列不保存凭据或整个请求/执行快照，不重放启动；后续 fallback unknown 不能覆盖已收到的退出事实。CLI 状态、操作重查和所有者的执行列表在补记前统一投影 unknown/audit_unavailable，不声称有持久化退出码。

恢复时只将该份结束元数据合并到最新登记，保留清理/材料身份和其他操作；命令、焦点与保留清理共用内部写入顺序，避免整个列表提交相互覆盖。恢复不获取 owner 锁，因此导出/恢复备份持有 owner 锁排空审计时不会互锁。关闭服务可排空已校验的结束事实；替换库清除旧关联。补记前拒绝迟到 worker/材料登记及清理，保留历史；补记后仍实际核查 Job，再按原身份清理材料。

这些只是存储故障期间当前服务实例收到的结果。若进程死亡而未保存回执，重开仍保守记录 unknown，不编造退出码、不恢复授权。
