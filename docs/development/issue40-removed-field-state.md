# 删除字段后的审批名称和历史可用范围（#40）

2026-10-20，缺陷来自[原0.4.0+11实际包的删除恢复验收](windows-packaged-recycle-delete.md)。
旧字段实际已经无法领取，Owner界面却显示内部ID及可读取。当前修复不改变授权规则、
公开协议v2、schema21、备份7/8/9或已确认Round05布局；新版本号0.4.0+12。

## 修复含义

Owner请求快照增加只读的已记录名称集合，合并原申请字段和实际批准的补选字段；
不含旧字段正文、会话秘密或授权凭证，不加入Agent传输。旧审批在当前字段不存在时
使用这些名称；名称确实未保留时显示“字段名称未记录/信息名称未记录”，不显示内部ID。
已处理请求明确提示旧授权不可读取，不再提示用户取消一个已经禁用的选择框。

Owner历史范围调用既有后端读取判断的只读投影：核对实际运行请求与历史grant身份，
复用会话状态、期限、原批准字段、已移除标记及当前字段存在性，不按同名重新匹配。
恢复归档或审计不可用不显示可读取。历史记录/公开ID本身不能产生授权。

历史范围保留当时名称，并注明全部/部分原字段移除、授权已结束或历史归档未授权。
全部字段都不再可用的旧许可不进入“有效”筛选，显示范围已失效或当前不可读取；
部分删除时其余真实可读字段继续可用，不修改后端原批准范围、截止时间或历史事实。
文字和状态沿用现有徽标、主题、列表与三栏结构，没有重做版式。
