## 另存与保留语义

`OwnerAccess.exportInformationFile(ref,path)`是用户明确另存，不是Agent领取。通过可信存储Interface在同一来源事务读取固定版本，分块校验完整长度及SHA-256，在目标同卷写入临时文件；来源事务成功结束、Owner仍可用后才不覆盖发布。既有目标、发布竞争、摘要错误、读取/事务结束失败及关闭前取消均不截断已有文件。临时清理只删除本次已知部分文件和空文件夹；不遍历任意目录。另存输出不随授权撤销回收。

备份和另存共用原有原生不覆盖发布实现，Windows仍为MoveFileExW WRITE_THROUGH，无覆盖或跨卷复制降级；Mac已有备份分支只做代码搬迁，本轮没有Mac实测。Agent受管副本将走独立登记及清理流程，不把Owner路径作为其授权内容。

当前字段引用的原文件一直保留，不按文件创建年龄删除。替换/删除使它脱离当前内容时，记录退役时间；退役满30天且修改历史、回收站快照均无引用后才清理BLOB。恢复旧文件为当前内容会清除退役状态；字段恢复继续用原有新身份规则，不能复活旧授权。已清理版本保留显式不可用元数据，时钟回拨不会重新出现正文。旧中间schema20库没有退役时间时，从首次核对开始保守保留，不伪造历史日期。

正式变更事务同时核对引用/退役状态；到期修订删除及对应正文清理共享事务，失败保留快照与正文，允许重试。Owner清理先处理到期修订/回收快照，再核对正文；读取仍存在的快照不会拿到已清理文件。导出和延后恢复在筛掉过期快照后使用同一策略；延后恢复不把备份中的已过期无引用正文重新保存为可用。恢复过程中仍保持同一验证句柄及接收事务。

文件摄入检查额度前会先处理到期保留内容，避免已经到期的BLOB长期占住100MiB候选额度。桌面启动及原有每分钟维护增加附件核对，失败保留内容并通过现有QuietNotice样式提示，后续重试。#38文件编辑器/另存系统对话框仍未接入，不把此提示当作完整客户端交付。
