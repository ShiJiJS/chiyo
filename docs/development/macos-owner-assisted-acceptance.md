2026-10-22，关联 #42/#44–#48/#50。此表安排人工动作，不表示已经通过；各 Issue 原验收条件保持。
先完成编辑器当前自动/原生检查，再准备同一份新版集中验收，避免每个测试复制一个应用、重复请求钥匙串。

## 建议集中做的一轮

预计 25–40 分钟；遇到产品问题先停止该项、记录并修复，不要求反复输入密码重试。
我负责准备合成资料、发起请求、核对日志和保存结果，你只需做下列人工动作。

| 项目 | 要确认什么 | 需要你做什么 | 时间 |
| --- | --- | --- | --- |
| 新版启动和旧库升级（#42/#50） | 同一普通安装位置换入新版后，能读取原有加密资料、附件和设置；退出再开仍可用。先保存备份、核对版本，不能直接把新库交给旧版打开。 | 若 macOS 弹出明确对应本应用的钥匙串提示，输入本机密码并选择允许／始终允许；密码由你输入。此次只验允许路径。 | 5–10 分钟 |

## 不必现在集中配合的补充项

| 条件 | 原因和处理方式 |
| --- | --- |
| 已有干净 Mac 用户或另一台 ARM Mac（#50） | 验证没有开发 SDK／缓存／原 Keychain 环境时，普通安装包能否用。临时 QA 目录不算干净用户；不会自行创建系统账号。有现成环境时再安排，约 10–15 分钟。 |
| Windows 双向迁移（#45） | 验证真实跨系统备份与恢复、路径和工具重新绑定。需要 Windows 侧空闲窗口；保持独立分支，不干扰正在开发的新功能。本轮不要求你跑 Windows CI。 |
| GitHub 工具成功场景（#44） | 现有真实 GitHub 证据是无效合成 Token 被 HTTP401 拒绝；成功认证需要专门测试账号／最小范围凭据。不会读取个人 Token 或把无认证响应冒充成功；准备凭据前单独确定具体范围。 |

## 为什么“始终允许”之后还可能提示

“始终允许”针对钥匙串项目和被系统识别的应用身份，不是对所有后续测试副本、签名或新版的总授权。先前多个独立 QA 应用和重新签名可能被视为不同应用，因此旧决定不一定沿用。最终稳定签名及跨版本自动读取仍是 #42 的待验部分，不能承诺一次授权永久免提示。

后续集中使用一个固定普通入口和一份一致新版，尽量减少身份变化；不再为非钥匙串测试反复创建系统密钥，不通过放宽钥匙串访问规则来消除提示。系统密码仍需要本人输入。

临时 QA 应用、调试符号和合成资料在记录完结果后清理；保留当前可用预览、明确标注版本的候选 ZIP、开发工具、验收证据和升级恢复备份。截图里的重复 `info_desktop` 多为测试构建副本，`FlutterMacOS.framework.dSYM` 是用于定位崩溃的调试符号，不是个人文档。清理按实际路径与归属核对，不按同名全盘删除。
