# 字段模板录入（Issue #10）

模板辅助用户填写新信息。模板字段定义具有自己的稳定标识，与保存后新生成的信息字段标识分离；模板不代表权限等级，不赋予任何读取能力。

用户可以创建、修改、扩展模板，选择结构化字段或文本说明。使用模板先打开填写界面，点击“保存信息”后才创建资料；取消不会入库。每次使用模板创建独立信息项及独立字段，名称和字段说明作为公开目录元数据，字段值和文本说明均需要授权。

模板修改只影响后续填写。原信息不引用可变的模板定义，因此不会被模板修改、删减或扩展覆盖。未改变的模板定义保留标识；名称、说明或内容形式改变后分配新定义标识，避免用旧身份表达不同含义。信息字段始终获得新标识，新增字段不会自动进入已有授权。填写期间模板若已被修改，保存会拒绝过时草稿，界面保留输入并提示重新打开模板。

模板通过现有 SQLCipher 资料库保存，schema 4 增加模板表和信息字段内容形式。已有字段迁移为结构化字段，原值及身份保留。模板和信息不会产生额外的明文索引或模板文件。CLI 不获得模板管理入口，仍通过公开目录发现保存后的字段并提交访问请求；公开字段元数据新增 `kind`（`structured` / `textNote`），值不会包含在目录中。

## 自动验证

按已确认的主要测试边界，在核心公开接口上验证：模板尚未应用时没有正式信息；明确保存后出现独立字段；模板扩展、替换不改写旧信息和授权；过时草稿不写入。

加密存储测试由 v2 SQLCipher 资料库迁移、保存并修改模板、创建包含文本说明的信息、关闭并重新打开，通过服务公开接口验证定义身份、版本、内容形式及值保留，并检查磁盘文件不含虚构测试标记。真实 CLI 子进程从重开后的模板信息目录发现字段标识和内容形式，申请并领取批准范围，确认获批字段可读而未获批说明不可读。

Flutter widget 测试从“我的信息 → 字段模板”创建模板，填写后确认保存信息，再修改模板，观察旧信息仍保持原字段含义。测试为无界面运行；未启动真实桌面、未安装 Codex hook、未变更用户配置。

## 待真实桌面验收

1. 使用虚构资料，在“字段模板”新建模板，添加一个结构化地址字段和一个文本说明字段。
2. 点击“使用模板”，填入虚构值；先取消，确认资料库未新增，再重新填写并保存。
3. 修改模板、增加字段并改变一个字段说明，确认旧信息的内容和字段列表保持原样；再次使用模板，确认新表单使用最新结构。
4. 通过运行中的 CLI `catalog` 发现新信息，申请字段，在桌面批准部分范围；确认只有批准部分可读。CLI 用法见 `docs/cli.md`。
5. 完全退出并重新打开应用，确认模板和文本说明仍存在；旧运行中的临时授权不应恢复。
