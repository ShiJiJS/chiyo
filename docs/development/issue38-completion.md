## 实际使用流程

1. 在信息库新建“求职资料”，保留姓名/受控说明并增加文件字段。取消真实系统选择器后其余输入保留；选文件并保存后关闭、重开同一隔离加密库，原字节一致。
2. 独立 AOT CLI 从公开目录申请三个字段；界面只批准姓名和简历。公开目录没有原文件名或源路径，姓名可读、说明拒绝，文件通过专门领取命令取得。
3. 同一授权中领 v1、替换后领 v2，重试原操作仍返回原 v1 副本；主人通过系统对话框另存的字节也一致。交付历史分别显示 v1/v2 及释放事实。
4. 从修订恢复 v1，新的领取使用恢复后的当前版本；移入回收站再恢复取得新字段身份，原字段授权不能继续领取。
5. 通过系统对话框导出备份，在另一份空库、新 DPAPI 包装中选择备份和测试恢复密钥。两份原文分别一致，未恢复旧请求、活动授权、草稿或活动副本。
6. 恢复后再经真实系统选择器导入一份 **169 字节的可读 UTF-8 虚构简历**，建立新会话，并通过实际审批界面重新批准。新 CLI 取得的受管路径直接交给当前内置浏览器文件控件；浏览器读出中文内容并上传至同源 loopback 接收器，原字节、字节数和交付文件名均一致。浏览器关闭后释放副本，服务/窗口退出；独立检查确认副本、该轮隔离库目录和本机接收端已消失/关闭。

前五步使用带 PDF 名称的 3/4 字节不透明二进制夹具验证保存、版本和备份完整性，不冒充有效 PDF 或 PDF 预览。第六步另外验证可读简历、恢复后新授权及真实工具消费。当前浏览器证据只覆盖这台机器的内置浏览器和本机接收器，不声称远程浏览器传文件、任意网站或 PDF/Word 解析已支持。

受管副本路径使用应用生成的安全 basename，本轮是 `attachment.txt`；原始文件名是独立元数据。工具使用 CLI 返回的真实 `path`，不能按原文件名重拼路径。没有改产品命名规则迎合测试。

## 失败、修正与复验

- 首轮默认测试框架先启用语义，随后外部 UIA 接入，在 `flutter_windows.dll+0x3c1ea` 发生 AV。保存本轮 Windows 1000 事件元数据，偏移与 #35 已有最小复现相同；没有取得/重新符号化本轮 dump，也不把相同偏移当作唯一根因证明。新测试沿用 #35 由 Windows 初始化原生桥的方式及严格语义句柄检查。
- `live-02` 因用户物理 Esc 停止 Computer Use，主动终止独立测试窗口；退出 79 不计第二次引擎崩溃。用户旧窗口始终未操作。
- `live-03` 未滚动到惰性列表内的审批字段；排练又暴露提示条遮挡导致点击未命中。修正测试滚动与实际命中等待，不改批准范围/版本断言，也不静默忽略失败。
- 键盘新测试发现禁止外部点按关闭也禁用了默认 Esc，以及异步禁用控件后的焦点交接问题。生产编辑器增加本地 Dismiss 动作，复用现有关闭/放弃确认/暂存清理，并恢复取消选择/取消确认后的焦点；保存和选择期间仍阻止关闭。原有样式未改变。
- 排练最初使用测试字体导致 200% 页脚溢出；改用应用字体和 Windows 字体，不缩小文字或降低缩放。加载真实字体后同样视口通过。忙碌状态按可观察控件等待，不靠固定延时。
- 浏览器排练的原字节检查通过，但脚本错误要求接收原始文件名。按实际受管路径 basename 修正验证，同时要求外部浏览器关闭后再释放副本。最终原生全流程通过；失败日志、当时源文件、实际浏览器读回与最终接收事实保留。

固定证据包含 187 份日志/元数据/脚本/代表图、36 份 Git 源文件/锁摘要及全部渲染图哈希。旧失败不改记为通过；19 个 opt-in 跳过也不改记为零跳过。后续依次继续 #30、#23、#18，不把本票完成等同于整个 Windows 交付完成。
