## 用户任务与实现

用户在原收件箱中看清凭据、应用和期限，批准后由 Agent 重新点击密码框，
后台调用 CLI。批准本身不发送按键。历史记录逐次输入事实，部分/未知时由
用户亲自检查并处理输入框，再决定解除后续使用的暂停。

- 审批接真实 OwnerAccess 决定，显示固定凭据版本、程序位置/SHA-256、
  自述页面、当前前台密码框、15/30 分钟期限及三步使用说明。
  三处 tips 可展开；保存中防重复提交，失败保留选择与确认框。
- 申请、历史搜索和共享交付说明在读取 command plan 前区分 focused_fill；
  填充没有命令、环境变量、退出码或文件清理状态，不再被旧命令界面误读。
- 历史使用独立填充操作，最近操作优先，每页最多 8 项；切页和选择不会发送输入。
  checking/sent/refused/partial/unknown 分开显示，sent 不表示已读回完整内容或登录成功。
- 人工确认冻结所选操作身份，确认只保存 attentionAcknowledgedAt；
  原 partial/unknown 不改写、授权不续期、不自动重新输入。保存失败保留暂停。
  活动操作不能人工清除；终态审计写入失败时诚实显示未知，并在任务结束后提供恢复入口。
  已知输入结果与“当前能否恢复”分开查询，服务暂不可用时不退回“正在核验”。
- 字符串凭据可留空建议绑定名；新建默认用途改为“字符串凭据”，覆盖 Token 与密码。
  黑白主题错误提示使用灰阶；其余主题保留原有提示风格。

布局继续使用顶部导航、请求栏、纸张和右侧决定栏，详情/决定分别滚动。
先在 HTML 补人工确认和分页，再落到 Flutter。沿用主按钮 120ms 反馈，
150ms 首次进入和展开过渡，尊重系统减少动画设置。

### 主 Agent 自检，未独立评审

按用户要求未启动子 Agent。对照原型截图，修正了目标行过疏、提示按钮靠右、
缺少会话头像、编号占位、历史摘要分栏及默认展开图标等差异；检查最终全部
主题/状态总览，并放大核对代表性审批、历史、确认和黑白失败画面。
现有测试覆盖 200% 换行/溢出，普通渲染不证明原生窗口的键盘、焦点和动效。
字体使用本地 Windows 字体及产品随包字体；Chromium 与 Flutter 字形栅格差异
不作为逐像素相同的证明。正式 Windows 原生界面的最终原型对照仍保留。
