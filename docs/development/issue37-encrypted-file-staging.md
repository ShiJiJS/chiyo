2026-10-19，实施源码 `e55b640b07f1570997cbd834d5c22cd6f3fd11d7`。本次接续[文件字段类型基础](issue37-typed-file-fields.md)，实现 Owner 文件草稿、原文件有界读取及 SQLCipher 暂存 BLOB。**这是 #37 的中间检查点，全部 7 项整体验收仍未勾选。** schema19、完整备份格式仍为7；尚未宣告 `information-attachments.v1`，旧正式文件字段/模板写入口继续拒绝，不把不可完整备份的文件升为正式信息。用户包未更新。

## 已实现的边界

- `beginInformationFileDraft` 建立绑定当前 Owner、资料库代际和表单生命周期的句柄；`stageInformationFile` 只在 Owner 侧接收源路径。返回文件名、MIME、大小及 SHA-256，源路径不进入描述或持久化记录，不自动删除来源文件。MIME 是展示提示，不是内容安全证明。
- 普通文件按小块有界读取，检测可见的大小/时间变化；目录、链接、读取失败、控制字符元数据及超限明确拒绝，失败不替换已有暂存。此检查不承诺对恶意并发改写提供原子文件快照。
- 暂存正文以独立 BLOB 存入同一个 SQLCipher 库；写入前复制并拥有输入字节，调用者之后改写缓冲不改变已登记摘要/正文。元数据/容量查询不读取 BLOB，信息项启动缓存、公开目录和普通 read 没有暂存内容或源路径。
- 同暂存 ID/相同内容重试返回原描述，异内容冲突；按草稿释放、取消及正常服务关闭清理。正在写入的草稿在关闭时排空；**没有文件草稿时直接沿用原关闭路径，不等待无关 Owner 写入。** 新进程打开库会清理没有有效表单句柄的孤立暂存。
- 成功恢复在同一事务内清除接收库的暂存，旧表单代际失效；错误密钥/失败恢复保留原暂存。暂存不是正式资料，不进入便携备份，不能通过恢复复活。旧库升级按独立 `library_format` 标记执行，发现新表冲突回滚，不放宽未知格式检查。

当前摄入边界暂按单文件10MiB、暂存合计100MiB、200份暂存及32个同时打开的Owner表单保护资源。实测同时预留最后两份10MiB时只允许一份成功。**这只是暂存预算验证，最终保留版本总量、备份大小和峰值内存仍须测量后冻结**，不将候选100MiB声称为完整附件容量验收。
