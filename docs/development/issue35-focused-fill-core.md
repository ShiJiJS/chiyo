# #35 核心授权与CLI检查点

2026-10-19，接续381f3f2的原型/只读识别。[目标合同](../design/local-focused-fill-contract.md)继续作为完整范围，**#35保持OPEN**。本次落地类型化授权/操作、Memory事务审计、服务端调度和CLI；实际输入端在测试中使用受控驱动，不冒充原生Windows填充通过。

## 已实现

- `CredentialUseRequest`以sealed specification区分命令/填充。填充没有LaunchPlan；误用旧命令入口明确拒绝。独立`FocusedFillOperation`保留输入事实，不带命令/退出码/文件清理、秘密或输入长度。
- `request-use`的fill规格仅接受一个字符串凭据及应用路径/字节摘要/自述目标；与launch互斥，不附带普通字段许可。实际文件字节检查不启动目标程序；请求和审批只检查凭据元数据，不取材料。
- 共用#33的私密会话、凭据版本/使用代际、固定15/30分钟及撤销/到期/会话结束检查。普通字段许可不被消费。不同方式不能互用，同一会话的操作ID在命令/填充之间也防冲突。
- `fill-use`先审计、占用本机服务串行槽位，异步准备宿主；输入前持久化放行事实。每批检查最新授权，Unicode不拆分代理对，不trim，不解释控制字符或提交登录。只在宿主接口内传递秘密，CLI仅请求/查询原操作。
- 同ID先查旧记录，撤销后查询也不重发；忙时不排队等待未来焦点。已知拒绝、部分发送和未知分开；驱动响应丢失不当作未输入。部分/未知阻止新ID，所有者确认检查目标后才允许明确重做，不续期、不重放旧ID、不清空目标。
- 原生等待期间不占所有者队列，因此撤销/轮换可及时生效。关闭取消已准备端并排空任务；恢复先停输入，旧任务按资料库代际隔离，不能覆盖新恢复库的同名记录。历史清理保留未解决未知事实，并原子删除可清理的请求/填充操作；预览包含填充操作数。
- HTTP/CLI需要协议2及`credential-focused-fill.v1`。源程序的开关默认关闭，且同时要求原生驱动与专门仓储能力；现有SQLCipher仓储尚未实现该接口，不接受新填充数据。没有把Memory测试通过当生产持久化完成。

## 本轮关键发现与处理

1. 旧资格检查会查看凭据材料是否存在。填充改用元数据检查，只有检查/目标审计提交后才取材料；审计intent/checked/released三处故障分别验证不放行未审计输入。
2. 输入等待若持有所有者锁，撤销会迟到。现在只有短的鉴权/审计阶段持锁，驱动等待在锁外；撤销、结束、到期和轮换在第一批等待期间生效，后续批次停止。
3. 关闭与异步任务登记存在窗口，任务现在和审计占用在同一序列内登记。关闭重复调用也等待任务完成，不在关闭之后新建输入宿主。
4. 仅检查恢复前的资料库代际不足，已在最终写入的所有者序列内再次检查。恢复含同名历史的回归验证旧任务不覆盖恢复事实。
5. “终态审计失败”不能返回成功。保存的checking/放行意图保留，查询明确返回unknown/audit_unavailable；人工恢复必须成功写审计才能继续。未知不是“未输入”。
6. 公开合同示例顶层误写`version`，改为真实`protocolVersion`，增加直接读取文档并交给实际解析器的测试；不是仅验证JSON语法。

早期测试入口名称写错、一次编译错误和格式lint均已纠正；最初存储运行少配置编译CLI而跳过2项，补齐后77项全部运行。SQLCipher错误密钥/HMAC负例及独立测试库的Drift提示保留原始日志，不当作实际数据损坏或新迁移通过。未使用子Agent、Computer Use或真实秘密；loopback服务/CLI子进程由测试关闭，没有改用户Codex配置或服务器同步。
