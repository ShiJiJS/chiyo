# Mac 编辑取消后的原控件焦点恢复（#48 / #50）

2026-10-22，独立 `codex/macos-adaptation`。实际原生文件面板取消后复现输入焦点丢失，
现保留表单内最近的实际控件；原生/辅助功能激活先落到对话框作用域时，不再把作用域
当作取消后的输入目标。忙碌状态下的重复文件选择直接返回，不再排队恢复错误焦点。
[分轮记录与摘要](evidence/macos-editor-focus/verification.json)。

## 定位与实现

基线第二轮真实 CUA：公开说明输入、Escape确认/取消、⌘A全文替换均正常；
原生NSOpenPanel取消后，primaryFocus落到无控件键的作用域，直接续写没有进入字段。
从可见文件名称输入框再单击选择文件，也出现同样结果；不是只凭AX没有焦点提示推断。
保存标记及7字节原附件经SQLCipher独立进程重开保持，但这不使焦点失败变成通过。

第三轮只在源码副本加被动诊断。第一次单击捕获实际编辑节点5167363，取消后可恢复；
随后双击场景在 `_chooseFile` 入口已捕获作用域254169997，恢复时各项条件均允许，
却仍恢复同一作用域。两条分支证明原逻辑记录的节点本身会错误，不以任意延时修补。
诊断不请求焦点、不改变文件面板回调或返回路径，没有修改原生输入方式。

生产 `InformationEditor` 现在在自身存活期间监听焦点变化，只记住本表单内非作用域
节点；忙碌时不覆盖记录。确认或文件选择开始时优先取当前真实控件，否则取最近控件。
沿用现有的路由、挂载、可请求焦点和下一帧检查，既不强抢其他对话框焦点，也不恢复
已移除字段；卸载时移除监听。没有改变保存、字段身份、授权、附件或Agent协议。
