# Windows 联网版 Codex 接入

先使用同包 App 打开本地资料库，或在设置中连接现有 NAS。服务准备成功后，CLI 默认发现当前模式的连接；审批仍由用户在 App 完成。“本地模式”使用本机审批，“服务器同步”使用 NAS 审批。切换模式只影响新聊天的默认连接，已有聊天保留原服务和许可范围。

## 准备运行目录

从完整同版本包调用，选择一个全新且稳定的输出目录：

```powershell
& 'C:\知予完整包\cli\info-prepare-codex.exe' --state-root 'C:\本机私有状态\codex' 'C:\知予运行目录'
```

生成器复制实际 Codex CLI、hook、worker，生成 hooks.json 和 skills/agent-info-access 下的模板及引用，拒绝覆盖已有目录。它不会安装、合并个人配置或自动授予 hook 信任。GH/AWS 工具保留在原完整包；准备目录通过公开指针核对匹配的完整包和二进制，保留原完整包的位置。

用户准备接入后审查准确的路径和 hook 定义，按当前 Codex 正式入口安装/信任，保留已有配置。Windows 私有状态由当前用户 DPAPI/ACL 保护；不能复制其他设备的状态代替本机登记。

## 能力和使用

统一入口可在没有聊天上下文时查看各级帮助：

```powershell
chiyo --help
chiyo fill request --help
chiyo chat start --help
```

宿主通过当前聊天的 `CHIYO_CONTEXT` 提供私有文件引用，或通过独立 stdin 使用 `--context-stdin`；该 stdin 不能同时用于业务 `--input -`。聊天配置由当前用户 DPAPI 和私有 ACL 保护，不能当成普通 JSON 文本阅读或移到其他设备使用。不同终端/聊天分别持有自己的配置；重开进程继续使用明确给出的同一引用，不依赖“最近聊天”文件。

普通终端需要新聊天时，按 `chiyo chat start --help` 明确给出 `--context-out` 和 Agent/聊天信息；初始没有资料访问或凭据使用许可。上下文文件写入全新的专用目录或已经私有的目录，不覆盖已有文件或收紧普通资料目录权限。只使用本聊天已收到的引用，公开聊天 ID 不能找回已有许可。

Chrome 表单填写需要调用方明确提供可用的回环 CDP 入口、标签页、完整 URL、唯一表单区域及区域内密码字段。CLI 不自动为日常 Chrome 打开调试端口，不扫描其他实例，不将 `--via chrome` 静默改为 `--via focus`。独立合成 Chrome 的自动测试结果与日常浏览器是否提供控制入口分别记录。Ego 也以实际能力检查为准。

公开能力查询不创建批准范围：

```powershell
'{"command":"capabilities"}' | & 'C:\知予完整包\cli\info.exe'
```

联网版的 credentialToolScope=current_device 表示工具观察来自当前电脑。GH/AWS 使用返回的完整随包路径，SSH 使用返回的系统路径；不可用或版本不符时先修复工具，不退回个人登录配置。

正式宿主启动事件或显式接入为新聊天建立未批准的关联；主/子身份按原会话范围核对。访问或凭据使用仍须申请和用户批准，提交提案不等于已保存。NAS 模式下 App 关闭后 CLI 仍连接 NAS；本地模式完全退出 App 会关闭本机服务，重开后旧本地会话不能复用原连接。

关联引用是该聊天的私密能力，只使用当前上下文已经收到的引用，并通过受保护环境或独立 stdin 交给 CLI。不要放入 shell 命令、argv、日志或仓库。引用丢失或确认会话无效时，由用户或宿主重新接入；不搜索文件或按聊天 ID 恢复。明确新建聊天时初始未授权，旧批准不继承，公开聊天 ID、请求 ID 或结束索引不能恢复读取关联。

结束只使用原 end-only 能力；普通 CLI 退出、切换聊天和子调用结束不自动结束根聊天。两秒结束回调未确认时保留 end_pending，按原结束索引核对，不把超时当成功或生成新的读取关联。恢复或 NAS 正常重启不会延长原期限。

当前模板位于 [cli/template](cli/template/)，实际能力说明随生成目录一并提供。正式安装/信任、真实宿主启动和结束事件的验收，与受控 CLI 检查分别记录；待办见 [ACCEPTANCE.md](ACCEPTANCE.md)。
