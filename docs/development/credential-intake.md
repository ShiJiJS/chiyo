# 凭据录入

对应 [#79](https://github.com/ShiJiJS/agent-info-manage/issues/79)。Mac 分支主流程已通过首轮整包和同模型独立新聊天试用；正常Release启动与真实资料重新录入仍待完成。

## 当前改造（2026-11-04，优先于下方旧验收记录）

当前要求见ADR0020和GitHub #78／#67／#79：用户直接在提案里输入密码、显示或隐藏，最后整份一次保存，没有密码弹窗及第二次密码审批。同一提案缺少任意必填材料时整份不入库；旧的逐条批准或部分入库不是目标。

账号是受保护提案内单独的非密码元数据，由App动态查询返回填写位置和例子。CLI透传并校验，App直接显示账号；旧资料未记账号时明确标“未注明”，不从AI用途描述中猜。用户名、Token、密码及来源文件分别表达，用户只需填写尚未给AI看的登录密码。用户已填写值由Host保管，不进入普通提案模型和AI回执。

新提案入库时只保留凭据当时的名称、账号、类型和关联说明，不含密码材料或后加私有备注；后续改名不会改写原操作的展示。老提案没有这份说明时，仅在当前准确版本仍可核对的情况下显示，不冒充历史原文。新元数据使用按内容触发的资料库格式49；旧程序拒绝打开，防止丢字段。有账号的完整加密备份使用格式19，普通旧库和旧备份仍可读，恢复保留账号及原材料。活动提案仍不进入便携备份。

这些改造已通过合成库、CLI、App组件与备份恢复检查，尚未完成统一打包、正常Release和新聊天集中验收。当前安装包和真实库没有修改。

## 历史流程与验收（保留当时事实，不作为当前交互规格）

App 提供当前凭据模板及例子，CLI 和 Skill 不另存清单。模板标记 `recordKind: credential`，声明宿主管理的字符串或文件材料；外部插件可以声明这些形式，但不能把凭据材料声明成普通字段。安装、更新、启停与移除通过原模板查询立即反映，提交和批准都核对版本。

未见的人设账号密码由主人在提案中私下填写，包括密码管理器生成后设为登录密码的情况。已从指定资料看到的密码、来源不明的密码及 API Key／Token 由 Agent 填写，提案说明已接触。整份凭据文件由 CLI 接收用户给定的路径，不要求主人重选；程序读取文件不等于 AI 已看到。没有增加 JSON 字段提取或混合文件隐藏协议。

三种材料输入分别是 `owner`、`agentString`、`agentFile`，具体结构由 `template-read` 返回。`agentString` 必须声明已进入上下文；`owner` 不能携带 Agent 伪造的主人材料。文件路径只在 CLI 本机使用，服务收到文件名和有界材料，不保留原路径。字符串最多65536字节，凭据文件最多1 MiB，凭据提案传输上限6 MB；常规 stdin JSON 继续保持原有上限。材料放在加密提案，普通字段、工作区模型、目录和状态回执不包含秘密。

`import-submit` 可附唯一 `operationId`。同一会话、编号和原内容的重试返回原提案；同编号换内容报冲突。未取得提案ID时，可用 `import-status` 携原 `operationId` 找回同会话的状态，不必再读原文件。未提供编号的凭据提交按同一会话中的完整原内容去重。修订仍修改原提案，清除相应批准；已经入库或拒绝的秘密正文从提案中清除。

主人在真实审批页中填写密码，只返回完成标志；保存到提案后仍须批准。缺材料时不能确认，批量操作也不能绕过。其余材料显示来源与暴露提示，不显示原文。主人编辑名称、用途、分类和关联后再批准；自己的密码补填不会丢掉同份提案中尚未提交的元数据编辑。

凭据与普通资料、其他凭据的待入库关联使用共同流程：独立项可先保存，未获批引用继续等，已批准的循环一起保存；引用被拒保留待处理，修订后重新审批。已有普通资料的修改也可以等凭据获准，期间原文不变。凭据和资料、提案状态及主人回执在同一次数据库事务中保存。保存凭据不授予使用许可。

凭据保留不可变模板定义及当前关联，已保存记录不因插件停用或移除而丢失。资料库含凭据提案时使用格式45，阻止旧程序错误处理；包含凭据模板的完整加密备份使用格式16，保留原材料和关联。普通附件的长期历史仍由 #80 完成，不改变凭据旧材料的既有保留规则。

## 已验证与待验证

- 核心：主人补填、已见密码、Token、整份文件、材料完整性、源类型与上下文提示要求、会话隔离、模板变化、普通资料与凭据循环、凭据互相引用、拒绝后修订以及修改等待凭据。
- CLI：真实本机服务，直接提交含中文和 shell 字符路径的1 MiB合成文件；重复提交、批准后重试、同编号内容冲突；缺失、空或超限文件不生成提案、不回显内容。
- 加密存储：重开恢复主人填写及批准；模拟回执保存失败，相关资料、凭据和材料全部回滚；重开后重试、格式45保持、完整备份恢复与磁盘不含秘密明文／Base64。
- App：真实加密库、CLI 与审批组件；私下填写后批准，状态不返回秘密；已见字符串显示暴露提示，文件不要求重选；插件的凭据模板动态查询、停用拒绝入库、升级／移除不改旧记录；凭据模板不进入普通资料编辑器。

首轮 f88c78fe 整包及正式 Skill 的同模型新聊天已通过，见[合成试用记录](evidence/ai-intake-synthetic-20261103/summary.json)。新聊天自己选择Agent填Token、已见密码、整份私钥及配置文件、主人补填未提供的登录密码；材料未作为普通字段保存，关联正确入库。主人补填的合成材料通过现有Owner API进入待审提案，原生NSSecureTextField物理输入不在此证据范围。仍需追加修复后的最终包、正常Release启动及真实资料重录；不提前关闭验收要求。
