## 本机另存和打开已连接（后续阶段）

原 InformationFileOutputs / InformationFileOpens 改依赖最小私有操作日志接口，旧资料库仍使用原加密私有日志。联网客户端使用独立 DeviceFileOperations：仅保存本机输出路径、原生访问证明、操作结果及清理责任；库表没有资料、文件原文、凭据或授权，不是本机资料副本。日志使用 SQLCipher 和独立本机密钥文件，目录700、文件600，与服务器密钥、接入Token分开；更换Token不要求重新加密操作记录。按服务器身份隔离，错误身份、丢失密钥、宽权限密钥及链接路径拒绝，不能自动重置成空记录。开发与默认联网接入均不调用个人钥匙串。

另存和打开主体流程继续复用原协调器、原路径身份/字节验证、no-replace 发布、未确认操作及清理规则。OwnerFileActionContext保留旧单机快照屏障，远程实现读取实际服务器原文并在本机写入前再次核对字段和版本；不伪造OwnerAccess、资料库或服务器路径。本机操作串行，App完全退出前清理打开副本；中断或清理失败的记录留待重开处理。用户选择另存的文件不纳入副本清理。

RemoteWorkspaceSource接同一文件菜单、另存、打开、结果查询、重新选择原输出核对，以及副本结束使用和重试清理。关闭使用同一个完成Future，界面与外层同时收尾不会重复关闭资源。

## 服务端文件领取和授权恢复已接通（CLI本机执行未完成）

InformationFileDelivery增加明确的设备交付标记，服务器不建立本机lease、不返回主机路径，也不放假路径满足原ready状态。复用原批准字段、整份决定、授权会话、原操作编号、期限和文件版本记录；本机声明校验完成之前保持preparing，确认后才ready。释放、撤销、结束或到期后保留cleanup_pending，只有设备实际清理后的确认才能结束，服务器不会假装已替设备删掉文件。已结束会话只能用原设备/会话证明确认自己的清理，不能读取、下载或确认新领取；其他设备及聊天不能借此操作。

原文读取与本机交付共用同一个字节验证函数：核对不可变附件版本、长度、SHA256与读取末尾的授权状态。普通服务器重启保留原会话和原交付记录，不改批准范围或期限；准备中的设备交付也可继续核对。观察到失效后不因时间回拨复活。结束服务器前先排完既有文件核对任务，再保存原运行状态；服务关闭不虚构设备文件已清理。

设备交付字段仅进入服务器私有SQLCipher记录，写入后格式标记54，旧读者在加载前拒绝。历史与可移植备份继续使用原白名单，既没有设备路径/证明，也不恢复可用许可。标记54只用于真正包含设备交付的服务库；原本机日志与普通资料库不因此无条件升级。

## CLI本机领取与清理：最终自动检查

正式`info --connection`和Codex一次命令封装均提供准确配置旁的私有本机登记目录。`DeviceInformationFiles`用原`NativeInformationDeliveryFiles`创建真实保护目录/文件；先持久登记空副本身份，再写原文字节并核对长度、摘要，服务器complete和返回路径前再次核对原许可。设备登记不保存原文、可读聊天证明或管理Token。它不是第二份信息库，内容是仅本机可读的操作/副本身份和清理/控制证明。

现有`info-runtime-worker`新增内部看护参数，保持原凭据执行模式。一次CLI退出后看护仍运行，不要求App在线；到期、撤销、聊天结束或网络状态无法确认时清理副本。它只持有这份副本的清理证明作长期核对，不能靠它重新读取或创建交付。仅实际物理清理成功后才确认服务端终止；失败保留待清理记录，不假装已清理。未知进程/超时不触发另一份副本；已确认看护死亡时，下一次普通CLI维护用原文件身份完成清理，即使原聊天已经结束。身份不符不删除文件，也不阻断无关目录查询。

服务器`watch/discard`仅接受该副本清理证明并核对原设备，回复只有最小状态；不能读取原文、恢复会话或变成其他副本的证明。普通status、历史、目录与便携备份不含此证明；正常会话fetch及内部download/complete才交付它。格式55保留证明不可轮换；格式54已有非终态交付可经正常fetch一次补入，操作、版本与期限不变。端点和私有格式说明见`apps/server/README.md`及ADR0027。
