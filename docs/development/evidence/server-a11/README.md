## 当前实现

- `OwnerBackupRoutes` 使用正常用户身份，支持分块上传加密备份、检查恢复预览、原恢复操作及查询原回执。复用 `InformationBackups.inspectRestore/restoreWithReceipt` 和 `OwnerAccess.restoreLibraryOnce`，未修改备份格式、原件校验或非空目标拒绝规则。Agent 设备凭证不能访问用户备份接口。
- 分块上限 512 KiB，单份及同时保留的声明总量不超过原容器 256 MiB，上限 4 份上传、16 个预览、固定 30 分钟暂存。相同分块可安全重传；不同内容、错误顺序/长度或完整摘要不符不能作为有效备份。用户资源及回执只含名称和随机身份，不含客户端或服务器路径。
- 服务器只暂存加密备份。恢复密钥只在受认证请求和原存储预览内存中使用，不落入文件、回执、公开目录或运行状态。取消、到期、成功换库或正常关闭释放这次登记的暂存和预览。
- 原 Owner 恢复成功后，在线运行状态只接受原屏障实际产生的新空身份代次，再保存已清除旧聊天的状态。外部换库、未改变存储代次、非空/非初始状态均拒绝接续。恢复失败不切换原身份。普通运行和重启逻辑不变。
- 原服务器目录、审批、插件、提案、文件、凭据及历史投影在换库后重新绑定，避免数据已恢复但旧页面持续报“资料库已变化”。重复原恢复只读原回执，不再清理新建身份。
- 新 `backup_transport.dart` 严格传递现有工作区的状态、资源、命令、预览和回执，核对操作/版本/类型与完整统计字段；拒绝额外原文、路径、密钥字段、负数及未知格式。
