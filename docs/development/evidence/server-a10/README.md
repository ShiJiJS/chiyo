共享规则在纯Dart info_workspace，App只保留原构造封装及本机文件显示。历史文件先按共享历史范围解析准确原附件；服务器核对历史交付的摘要/名称/类型/长度，再交付原字节，由同一WorkspaceAttachmentRenderer显示；不打开客户端路径，不在Linux渲染原生PDF。

新增受认证/v1/owner/history和/v1/owner/grant-history，凭据changes及recycled接原凭据管理源。明确wireVersion=1，严格检查已知字段、类型、版本/范围及回执对应；Owner路径不接受Agent设备凭证。普通保存回执与生命周期回执都要成功查询，不能一次失败便称没提交。服务变化标记加入回收批次、回收凭据及访问/授权历史，正常页面能刷新。

## 实际发现的问题与修正

- 正常恢复对话框刚取到预览，延迟抵达的广义刷新通知却要求重新核对。原批次控制器现重新读取并比较准确范围token：完全相同才保留已核对预览，变化/失败不自动接纳或写入；Core提交仍原子核对实际范围。正常App的首次失败和修复后完整流程均有日志。
- 原在线目录Widget回归在新增联网历史订阅后，退出时未等待异步source.dispose，遗留HTTP超时假时钟；按已有SSH试用的收尾方式显式等待原数据源销毁，保留原业务断言，复验通过。
- 早期合成测试遗漏文件协议版本/批准版本、误用内部layout字段key及把已恢复的审计批次当作应物理删除，均已按正式协议/原codec/当前Owner可见状态修正。补关联时也改用当前服务器模板创建资料，未放松旧格式校验。早期失败日志未算通过。

所有库、文件、密钥和用户/设备身份为隔离合成；测试进程和容器已结束。系统文件面板/PDF原生能力、个人钥匙串及正式安装仍按后置范围记录，不把替代的系统边界或Linux跳过算通过。#99执行历史继续按工单安排在#101、#102完整备份与最终候选中联合核对。下一步#101完整备份/旧库迁入演练，然后#102统一候选和无开发上下文Agent试用。
