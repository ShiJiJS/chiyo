## Windows 安全另存

原流程的 Windows prepareStaging 返回 null，公共发布器实际只有 Darwin 后端。本次为原协调器增加 Windows 后端，保持 Mac 私有记录格式与原生实现；没有以普通 File.copy/rename 绕过持久操作记录。

Windows 在所选输出的同卷创建当前用户/SYSTEM 专用目录，核对规范路径、目录/文件 ID、ACL、链接数和原文 SHA-256。发布保留私有原件，通过单独硬链接及不覆盖的 MoveFileExW WRITE_THROUGH 交出输出，SQL 成功后再清理原件。普通配置/受管材料仍要求单一链接，只有发布器持有的原生句柄允许原件加发布链接。UNC、ADS、保留 DOS 名称、穿越/重解析别名、既有输出、跨卷、变化身份/字节均拒绝。清理使用已核对的句柄，只处理登记名称，不递归扫描或删除用户输出。

真实面板暴露了一项自动夹具未涵盖的 NTFS 行为：GetSaveFileName 默认先创建/删除同名探测文件，之后的链接重命名可能继承它的创建时间。旧身份将创建时间一起比较，导致已成功输出被误判变化，清理保留原件。新增回归先复现 prepared_file_changed，再修正文件身份为卷+文件 ID；保留链接让该 ID 在回执确认期间仍分配，另独立核对哈希/ACL/路径/链接数。目录继续保留创建时间核对。对话框增加 OFN_NOTESTFILECREATE，实际写入失败由发布协调器报告，不能只靠取消探测掩盖同名旧文件场景。

依据：[微软 NTFS tunneling 说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fltkernel/nf-fltkernel-fltgettunneledname)、[原生文件面板标志](https://learn.microsoft.com/en-us/windows/win32/api/commdlg/ns-commdlg-openfilenamea)。

7 项 Windows 发布检查覆盖实际原文、既有输出、变更字节、未知目录项/替换目录、Windows 路径、NTFS 同名缓存，以及真实 SQLCipher 关闭重开。丢失发布回复后仅观察原操作；输出匹配才确认，输出被删除则保持未知，原件保留且同编号不重放。已确认成功后用户改动或删除输出，也不重新发布。

## Windows 系统打开

新增 owner_file_open 原生通道，接原 WorkspaceFileOpens 和加密设备操作记录。原生接收端验证唯一受管 Temp 目录、当前用户/SYSTEM 保护 ACL、卷/文件 ID、单一链接、长度与哈希，固定允许附件扩展名，再通过 ShellExecuteExW 的 open 动词交给系统。不会接收任意程序或任意文件名。原生缓存最多 256 个完整意图，不驱逐旧结果；同编号不同意图拒绝，接收结果不明保留 pending，不重复启动。新进程无原生缓存时不推断从未打开，持久协调器保留未知事实。

实际 C++ 接收端与 Dart 正式保护副本组合检查通过：有效副本只启动一次、错误身份/哈希/路径/后缀拒绝、不同意图冲突、异常保持未知且不重放、重开没有缓存、256 容量和满额拒绝。该单测用注入接收器；另由下述实际 Flutter 通道与记事本观察证明系统接收。opened 表示 Windows 接受打开请求，不宣称主人已阅读。
