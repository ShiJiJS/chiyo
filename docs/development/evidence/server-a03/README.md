## 实际流程

- 正常 App 连接页面、编辑页面及审批页面沿用原工作区；“AI 接入”生成受限设备配置，后续打开复用它，不把用户管理 Token 写入配置。
- 正式 info、info-codex、info-codex-hook 接口完成目录查询、一次申请、等待、批准范围核对与读取；私密关联与读取凭证不进入普通输出。
- 独立 CLI 进程使用同一聊天关联；同根子聊天共享原范围。普通服务重启保留原有效许可，根聊天结束、撤销或到期后不恢复。
- 用户审批仍走正常接口；没有新增演示或自动批准产品开关。首轮范围为文字，远程文件与凭据分别由 #97/#99 接续。

## 独立 Agent

两次均使用 fork_turns=none 的新 Agent，任务只给正式运行包、合成资料名称、要取得的内容及文件范围，没有给命令答案、字段 ID 或预期结果。原文反馈见 [试用记录](independent-agent-feedback.md)。

首轮完成了业务流程，但发现 Node REPL 不提供 process 全局对象，原示例不能直接运行。已改为通过 /usr/bin/env 继承正常环境并设置当前真实聊天标识。第二个全新 Agent 仅按修正后的配套说明，顺利完成完整目录查询、最小字段申请、等待、领取及读取，没有另行补充操作提示。

两份申请由协调方通过正常用户 HTTPS 接口分别批准，只批准“访问地址”。结束后停止服务器，再独立打开加密仓库核对 [持久审计](independent-agent-audit.json)：两个不同请求各一次成功读取、只含访问地址字段，其他字段成功读取为0；两个根会话均记录 ended，剩余有效授权为0。合成私有库、配置、关联和重复运行包随后清理，保留反馈、审计及可重建脚本。
