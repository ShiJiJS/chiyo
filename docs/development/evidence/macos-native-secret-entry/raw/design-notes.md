# Mac 托管凭据安全输入

任务是新增或轮换托管凭据：输入名称和秘密内容，检查绑定名称，最后保存。结果仍由既有 OwnerAccess 写入；原生弹层只改表单草稿。产品颜色、字体、布局和最终保存位置沿用当前项目。

旧表单中直接输入秘密值。Mac Flutter 遮蔽字段存在已复现的辅助功能明文异常，因此改为“未填写 / 已填写”和“填写 / 修改”，点击后在 NSSecureTextField 系统 sheet 内输入，完成后返回同一表单。代表性新建路径约由四次交互增加至五次，增加一次“完成”和一个短输入 sheet；这是防错取舍，不声称减少步骤。系统控件可预填草稿，取消不丢失原值，用户无需记住或复制其他页面的数据。

不增加独立业务页；自动推断秘密内容也不适合此任务。此前嵌入式 AppKitView 方案破坏 Flutter 控件的辅助功能树，已拒绝，见上一轮诊断。本轮采用范围较小的原生输入组件，不开展无人确认的视觉重设计，也不创建代表用户认可的新 DESIGN.md。

状态覆盖：空、已填、编辑中、取消、清空、超过长度、平台失败、禁用、保存失败重试、窗口关闭和退出。正文不显示秘密值或长度，错误不回显原文。按钮沿用既有 hover/focus 状态，过渡使用系统 sheet 动画，无新增装饰动效。

同类资料仅作只读参考：1Password Mac 入门页和 Apple 密码使用手册的概览，不曾完整走查其编辑流程，不据此编造点击数或通用最佳实践。

验收使用实际 CUA 的系统输入 sheet 和真实 CredentialEditor/CredentialManagement，另做四主题 × 两字号的 Flutter 截图对照。100% 和 200% 对照图已逐张目测：状态和修改入口可读，底部保存可见；200% 内容使用现有滚动区，环境变量说明在下方，不要求取消滚动。系统 sheet 遵循 macOS 自身外观，不声称受 Flutter 四主题或字号设置控制。没有进行独立设计评审；由本 agent 自查任务路径、渲染和原生操作。
