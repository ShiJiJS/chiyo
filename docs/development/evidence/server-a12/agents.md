# #102：联网 Agent 接入状态

2026-11-09。原接入页面、会话选择及诊断已接到真实服务；窗口、通知与退出仍需接续，#102 保持打开。本轮只有隔离合成资料，没有替换日常 App、读取个人聊天或处理系统信任。

## 实现

- 将原 OwnerWorkspaceAgents 中的会话/申请统计移到纯 Dart `OwnerAgentSessions`，单机和服务器共用。原统计仍包含文字、文件、凭据及分类整理申请，同名聊天按公开会话身份区分；没有申请的聊天也可见。
- 新增受用户管理身份保护的 GET `/v1/owner/agent-sessions`，只返回会话及申请摘要。Agent 设备凭证不能访问；没有资料字段、凭据、聊天私密证明、结束能力、管理 Token 或本机路径。摘要序列化继续复用原审批传输，解析拒绝额外字段、重复身份和矛盾统计。
- `WorkspaceAgentObservations` 保留原观察版本、明确选择聊天、重新检测及过期详情拒绝规则。`OwnerWorkspaceAgents` 和 `RemoteWorkspaceAgents` 使用同一逻辑，没有另建一套诊断页面或凭空生成已关联聊天。
- 服务端恢复后重新绑定观察；服务重开或恢复后的旧观察不能继续作为当前详情。便携恢复保留历史，不恢复活跃聊天或授权。
- 配套文件核对仍由当前 Mac 上的 `MacAgentBundle` 读取当前包清单并计算摘要，服务器不检查客户端文件，也不按服务器 PID 或路径操作客户端。核对通过只代表配套文件一致，Skill 安装、hooks 信任和独立 CLI 网络连接仍明确不能由此推断。
- 正常 `OnlineDesktopLauncher` 经 `RemoteWorkspaceSource.agents` 接入原控制器/页面。补上 `/v1/server` 变化标记中的空会话建立和结束；否则原来的周期刷新看不到没有申请的新聊天。接入页统一称“资料服务”，避免把独立服务器叫成本机服务。

正常 App 自动操作原设置入口，选择聊天、打开会话与诊断对话框；随后从真实 Agent 接口建立新空聊天，原轮询使它自动出现在页面，没有直接调用控制器刷新掩盖问题。失败读取时保留上次观察而禁止使用它作为当前详情；恢复网络后重新查询。

配套工具检查使用实际 MacAgentBundle 读取一套合成文件及清单，未执行这些文件；篡改其中 CLI 文件后原诊断被拒，重新观察显示无法核对。即使清单匹配，Skill 和 hooks 仍未声称已安装/信任。此检查不是最终候选的签名、执行或宿主接入验收。

早期缺导入、测试枚举名及重复转发参数的编译失败已修正。凭据恢复测试最初对非空接收库恢复，被原规则正确拒绝；改为保留合成加密备份、关闭源库后在另一空服务器恢复，没有放宽接收库规则。失败保留，未算通过。最终 App 组中原备份界面测试会同时打开两个不同路径的加密库，Drift输出通用的多实例调试提示；检查其夹具为独立数据库文件与连接，未关闭警告或共用执行器。
