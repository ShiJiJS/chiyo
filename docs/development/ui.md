# 界面约定

[开发指南](README.md) · [使用指南](../usage.md) · [领域决策](../adr/)

桌面 App 使用同一套 Flutter 页面与控件，平台差异集中在 macOS / Windows 原生接口。当前可运行界面和共用组件是样式来源；不再并列维护一套 HTML 原型或已完成的分阶段任务规格。

## 页面职责

信息库左侧放目录、标签和回收站，中间是筛选后的资料列表，右侧阅读详情。各栏独立滚动；正文不堆叠成整页固定高度卡片。资料与凭据可以出现在同一列表，但凭据继续使用独立的保存、展示和使用接口。

访问审批展示聊天来源、用途、范围、期限和结果；申请由 AI 发起。录入提案展示类型、归属和完整内容，修改展示差异；条目切换只是阅读，整份提案一次保存。提案预览、信息库详情和历史快照复用插件展示组件，不能复制另一套字段渲染规则。

提案标题由 AI 描述本批主题，不只显示“x 项新增资料”。新增及关联内容在提案内预览，尚未入库时不跳转到信息库。密码输入和显示按钮放在同一输入框内，不另开多层填写流程。

授权历史以右侧详情为主。筛选通过右上角气泡完成，应用后的条件以可移除标签展示。历史内容与当前资料要有明确标题，不用“当时保存 v1”代替内容说明。

存储与同步是本地 / 服务器二选一。资料可以在本机浏览，申请、提案和授权历史始终来自当前模式对应的服务；不能将另一处空列表冒充当前服务的结果。

服务器连接放在设置中，连接与断线页面沿用主界面样式，提供返回设置或原页面的路径。等待只显示加载状态，不堆叠重复提示。Mac 菜单栏明确区分访问申请和录入提案，沿用 App 的字体、颜色和按钮层级；原生能力按平台适配。

设置不保留旧版模板、手动 Agent 接入或“AI 接入”生成入口及其专属废弃逻辑。受限连接由 App 与 CLI 自动准备，不要求用户逐家适配 Agent。名称和聊天标识用于申请与历史，不能当作已验证身份；页面不反复标注“自述”，不显示没有操作意义的技术说明。

## 共用样式和控件

- 颜色使用 `ui_palette.dart`，动效使用 `desktop_motion.dart`，字体由 `desktop_fonts.dart` 加载。明暗主题保留相同层级；状态同时用文字和图标表达。
- 按钮、输入、选择、浮层和对话框复用 `desktop_*`、`anchored_surface.dart` 及 workspace 组件。共用图标和绘制保持一个来源，不按页面复制实现。
- 不通过缩小字体、缩放截图或裁切内容解决布局问题。长名称、无内容、错误、加载和 200% 文字尺寸应能阅读和操作。
- 搜索与筛选保留明确范围和选择。后台刷新不抢焦点、不重放当前详情动画、不丢失草稿；旧异步结果不能覆盖新选择。

## 浮层、滚动与输入

锚定菜单从触发器一侧展开，空间不足时整体翻向；内部可以滚动。滚动或缩放后关闭或重新定位，不悬空。Escape 和外部点击可以关闭，焦点应能回到触发器。弹窗标题、底部动作和可滚动正文各司其职。

滚动轨道不占用选中背景、树箭头、行尾操作或按钮点击区。Hover、选中和键盘焦点应可区分，避免叠出错位背景或下拉框白边。

密码输入旁用眼睛图标查看和隐藏。提交中显示等待状态并防止重复提交；失败保留输入、光标、选择和滚动位置。只有真实操作完成才显示成功。

## 插件与安全边界

模板描述类型、字段、章节、关联和填写示例，不包含用户实际值；目录不决定模板或授权。现有资料保留使用时的模板快照，缺少插件时仍能按受支持的通用方式查看，不改写旧内容。

普通字段、普通附件、托管凭据和聊天许可分别处理。展示章节、关联和重复条目不扩大已批准范围；新增字段不进入旧授权。禁止把密码、私钥或 Token 放进列表、普通内容预览、说明或错误日志。

Markdown 由宿主安全渲染，不执行 HTML/脚本或自动请求远程图片。文件预览使用实际附件与保留版本，缺失时显示不可用，不用固定样例代替真实原文。

模板插件仍采用有限的声明式格式，不加载任意脚本或界面代码。安装插件、录入资料和批准 AI 使用是不同决定。当前格式见 [JSON Schema](../design/zhiyu-template-package.schema.json)，取舍见 [ADR0016](../adr/0016-declarative-template-plugins.md)。

## 验证

`apps/desktop/test/` 中的控件、信息库、提案和历史测试保护共享行为；`integration_test/approved_workspace_native_test.dart` 等在隔离原生窗口检查实际组件。常用覆盖包括 1000 / 1440 宽度、明暗主题、文字放大、键盘与输入焦点。

Sample 数据和隔离预览是测试工具，不是产品演示模式，也不是保存成功的证据。涉及资料写入、权限、备份或同步的改动，使用临时加密库和真实传输验证。截图放在 `build/`，不提交私人资料截图；需要用户配合的系统检查集中安排，避免逐项反复换包。
