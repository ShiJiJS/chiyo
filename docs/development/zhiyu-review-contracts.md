# U06前端交接：提案、整理结果与授权历史

范围为冻结R11/R12的正式Flutter工作台、控制器和集中可重置合成来源。UI已具备新增、字段意图、经历叶、整条/字段删除、逐项混合批量、只读新整理结果、旧版整批审阅和分层授权/操作历史。没有接真实Owner服务。完整S5、实际OS输入和录屏继续开放；本文件不将这些门槛判为通过。

## 提案来源

| 调用 | 页面需要的输入与结果 | 失败和边界 |
| --- | --- | --- |
| `query(query, keepSelection)` | 关键词、全部/待确认/已处理、种类、offset/limit；身份、名称、用途、版本、时间、计数与选中项全局位置 | 关键词不超过2000字符，limit1–100；不按字段正文检索；分页选择按ID，不能按标题/行号关联 |
| `read(proposalId)` | 明确选中的待审内容、提交时定义快照/字段身份/范围、审阅token；终态只读无正文结果；整理仅分类元数据 | 读失败保留输入但禁用旧决定；新定义不重解释旧提案；清理先撤去派生Owner旧值，不从当前值补原值 |
| `catalog()` | 当前目录/标签和分类版本 | 分类变化使原观察失效，不静默变更所选范围 |
| `relations(proposalId,itemId,version)` | 按固定提交定义的关系候选元数据 | 来源代次/提案/资料版本固定；不读取关系正文；缺包不换成新模板 |
| `currentTarget(proposalId)` | Owner明确比较时的准确当前普通资料 | 只读，不把旧草稿自动套到新身份；不存在反馈不可用 |
| `snapshot(proposalId, typedRecord)` | Owner明确点击结果后读取准确保存/删除前版本 | 核对提案结果身份与版本；保留修订/回收已清理则不可用，不回退同名或当前资料；不提供凭据秘密 |
| `change(command)` | operationId、提案版本、审阅token、动作、选中且明确审阅的输入；返回无正文回执和准确结果身份/版本 | 确认/拒绝分开。版本/语义冲突保留输入；确定失败不写入；结果未知冻结原意图并只查原操作 |
| `receipt(operationId)` | 原命令的无正文提交事实，或来源明确确认未提交 | 错回执、查询失败、仍执行中都不等于未提交；无自动重放；确认未提交后明确操作才生成新身份 |

回执同时核对operationId、proposalId、动作、审阅版本/token、命令摘要、结果数量、kind+ID唯一性和版本。修改/删除/旧版整理还核对原目标身份及版本递增；删除必须有回收身份。终态来源、控制器草稿及批量提交正文一并清除；读回失败也不恢复它们。名字和版本摘要不是原内容备份。

新增的一份提案内先校验全部选中资料，再一次写入；核心当前新增预算20项、每项50字段、总计200叶、240000 UTF-8字节、每值64000字符及100标签，经历按实际叶字段计数。页面名称160与核心200的差异仍需真实适配明确映射。普通附件走既有Owner文件事务，凭据走专用材料流程，不将它们展开为此端口的普通文本或原字节。

修改遵循correct保留原实例fieldId、add/replace由来源分配新身份、remove进入同一部分回收；经历保留entryId并逐叶修改/替换/移除，新增经历由来源分配身份。实例字段描述/移除覆盖与不可变模板快照分别保存，不能因同key就把新含义当原插件字段。部分回收恢复核对当前资料和回收条目两个版本；碰撞保留为独立内容，不覆盖新含义，也不复活旧授权。准确修订/部分清理合同见[字段与提案合同](zhiyu-macos-proposals.md)。

## 混合队列

一个UI清单最多100份提案；与单新增提案内20项的原子预算不同。各份确认或拒绝在加入时冻结明确审阅，后续单独编辑必须明确更新清单。开始前可调整顺序、移出或清空。逐项预检后走各自事务，没有跨提案的全局回滚。

逐项结果区分未开始、处理中、已提交、已拒绝、冲突、确定未提交、未知、已核对未提交、外部已处理。已成功项不重复提交，确定失败仅重试该项；冲突需单独核对。未知停止尾部并冻结根级导航、关闭和Escape，只查询原操作；核对成功不自动运行尾部，Owner明确继续。外部已处理的隐藏项通过纯元数据查询清除提交正文，不读取Owner旧值或冒充自己的回执，晚到元数据不能解除未知锁。结果阅读返回原查询、分页、选择和两侧滚动。

## 新整理结果与旧版方案

`WorkspaceOrganizationReport`只携带固定资料kind+ID、历史名称/版本、整理前后目录和标签、批准/到期时间、原操作及关联历史；没有字段值、字段身份清单、文件字节或凭据材料。当前对象是否存在按同一资料来源投影，不在持久结果里改连同名对象。新任务结果没有确认、拒绝、编辑或加入批量入口。

已应用结果来自同一合成分类事务，资料正文、定义、字段实例身份和凭据关联保持。整批预检包括批准范围内未发生分类变化的成员；任一固定版本冲突则整个整理不应用。界面显示分类无变化、保存失败、冲突、未知、撤销、到期和会话结束；未知只读原结果且不显示已确认结果版本，也不会因刷新重新执行。新的原结果观察只更新同一operationId的元数据，不制造第二次整理。失败/未应用的建议使用普通底色，不以成功配色表达已应用。

整理授权与结果/操作历史共享原决定事实。成功或版本冲突后整理能力结束，确定存储失败而授权仍有效时保持有效范围与固定到期，不伪造任务完成或延长期限。撤销/到期/会话结束阻止后续写入。示例双击共享一次操作，来源重置/关闭后晚到准备不会继续。真实服务仍须在异步提交前重新验证会话、期限和完整范围，并按核心事务提交任务状态、资料修订及结果。

旧版已保存待确认方案明确标为旧版，保留整批确认或拒绝语义，不能升级为自动写入许可。旧版审阅也只含分类元数据；拒绝不改资料，确认不得夹带名称、字段值、额外范围或部分选择。全部成员版本及当前目录/标签核对成功后才原子应用；失败不部分写，未知复用原操作回执核对，终态清除待提交输入。Owner可通过准确结果版本查看仍保留的内容，清理后仍不可用。

真实核心允许在原范围内提出目录/标签名称并原子解析/创建；当前示例采用现有分类来演示，不宣称已新增真实分类创建接口。真实适配应核对200项/240000字节、每名称200字符、每项最多100标签及完整批准范围版本；页面回执和示例ID不能当核心持久格式。新整理请求/任务/结果仍排除离线备份，旧方案兼容按ADR0007处理，不能混入普通资料备份。

## 授权历史来源

| 调用 | 输入与结果 | 失败和边界 |
| --- | --- | --- |
| `query(query, keepSelection)` | 类型、全部/有效/结束、最近1/7/30天、关键词、分页及稳定选择位置 | 只查元数据，不索引正文；limit1–100、关键词不超过1000字符 |
| `read(historyId)` | 固定批准成员、版本、分路期限、决定/结束原因及多次独立操作摘要 | 复用原审批/凭据/整理事实，不独立维护第二套授权；旧摘要没有原操作就不伪造 |
| `filePreview(historyId,scopeId,page)` | Owner明确读取批准的准确普通附件版本 | 不替换为当前版本；版本清理或来源变动后旧图像/正文失效；不读取凭据材料 |
| `snapshot(historyId,typedRecord)` | Owner明确查看批准时的准确普通资料版本 | 同kind+ID和版本核对，准确版本已清理则不可用；无凭据秘密快照 |
| 原审批撤销及凭据操作查询 | 原requestId/token/命令摘要和独立operationId | 未决冻结根导航，先查原操作；查询不是重新执行、填充或清理的能力 |

一次授权可以有多次普通访问、文件交付或凭据使用，不把批准当成执行。普通字段读取固定成员的最新值，普通附件固定批准版本，凭据固定材料版本/使用代次和接收配置；到期不续期。整理记录链接原授权/操作，历史可反向进入准确整理结果。当前资料/旧内容/原申请跳转和根级返回保留原查询、页码、选择及滚动。对象删除后保留名称/版本/身份记录，不能自动改连同名对象。

## 真实接入与仍开放的门槛

合成来源的内存成功、去重、暂存、reviewToken和`request:`/`legacy:`都不是生产事务、真正会话身份或持久日志。F01在全部七项UI完成后，映射现有Owner核心、持久无正文回执、待提交新输入的安全暂存/到期清理、导航/进程重启找回、准确修订/回收保留/清理、普通文件事务和完整混合备份恢复。不得把未知列表终态当自己的原操作回执。

本轮不改变Mac固定预览身份、技术路径、CLI/hooks/Skill协议或Windows。无computer use、子Agent、Windows CI或真实系统权限；隔离组成守卫覆盖提案/批量未知、自动整理结果到历史及旧版确认，生产通道/HTTP/越界文件访问应为0。实际OS输入、Cocoa菜单、辅助功能、正常速度录屏和完整S5矩阵仍开放；200%顶栏徽标裁切尚未处理。检查点与当前准确测试数量见[提案实施记录](zhiyu-macos-proposals.md)及其中r6证据。
