# #13 修改提案与当前字段读取

修改入口使用目标 ID、基础版本和显式 correct/add/replace/remove 操作。公开目录返回当前信息项版本，Agent 不必读取原值便可提交用户给定修正。提案提交、状态和错误均不回传原值；修改前后预览仅由桌面持有的 OwnerAccess 提供。没有 Agent 预览、确认、拒绝或历史读取路由。

用户确认通过核心写队列重新校验版本，SQLCipher 事务同时写入新信息、变更前快照及终态提案。版本过时会成为 conflicted，不覆盖当前资料；重复确认返回第一次确认的结果，不产生第二次写入。用户拒绝也进入终态。手动值修正、公开元数据及分类修改同时保存修改前快照和替换时间，为 #15 的用户历史和保留策略提供数据；本票尚不实现历史页面或 30 天清理。

普通值修正保留字段身份。新增、替换业务含义生成新身份，旧授权不会扩大。移除和替换会在各既有授权中记录该字段的永久失效事实，其他字段继续可读；即使之后恢复同一字段 ID，旧授权也不会复活。授权能力和失效事实只留在运行内存，重启后全部旧授权失效。字段持久化先移除旧字段行再写当前集合，重开资料库不会出现已移除字段。

数据库结构版本 8 新增修改提案和修改历史快照，保持其他并行迁移位置。快照、提案内容、旧值及公开元数据均在 SQLCipher 内；不会创建明文差异文件。#12 的当前资料快照应包含修改后的当前字段和组织数据；旧历史和提案不因此成为已承诺的备份范围，完整历史恢复由 #17 验证。修改提案进入确认、拒绝或冲突终态后即清空提交内容，只保存身份、状态、基础版本和确认版本回执；幂等确认返回不含内容的同一回执。#15 还需落实 30 天历史清理，#14 删除不能通过终态提案恢复旧值。尚未处理的待确认提案保留用户待审核内容，本票不增加自动过期规则。

验证使用核心公开 API、真实 CLI 子进程、加密库重开和无窗口 Flutter 组件测试。包含审批前不变、确认后读取最新值、跨会话隔离、无 Agent 确认/预览能力、过时冲突、并发确认唯一结果、拒绝、幂等重试、新身份不扩大授权、移除/重现不复活旧授权、加密旧版本重开和磁盘敏感标记扫描。

未启动用户桌面程序或修改 Codex 配置。真实 Windows 桌面差异确认后由真实 CLI 读取、macOS 发布包及升级仍待用户/平台验收；组件与 CLI 自动化不能替代这些证据。

审查修正：修改提案允许移除最后一个字段并保留信息项名称、描述，也允许继续修正此类零字段信息项的公开描述。新建信息与模板的非空字段要求不变。核心回归测试先复现 `invalid_proposal`，修正后验证预览、确认、版本冲突、回收恢复及旧授权不复活；SQLCipher 重开测试验证空字段集合、描述、确认回执和回收内容均持久保存。手动修正与提案修正共用 `InformationField.correctValue` 保留字段身份和含义；业务含义替换仍生成新身份。
