# 普通文件录入与历史版本

对应 [#80](https://github.com/ShiJiJS/agent-info-manage/issues/80)。Mac 分支开发中；已接入普通文件新建提案、加密待审原文、CLI与主人审批；已有资料新增附件、附件新版本和修改审批也已接入。未替换本机预览，也未清空真实资料。

## 已接入：仍保管的附件历史原文长期保留

一个普通附件仍被当前资料引用时，它的所有尚存版本长期保留；资料旧快照超过原保留期限被清理，也不会带走这些原文。恢复某个旧版本作为当前文件后，其他版本同样保持可用。这个规则由本机存储与完整加密备份共用。

用户删除附件或整条资料后，回收快照和仍保留的旧资料快照继续保护这组原文；这些恢复范围也已清理后，沿用删除后的清理规则。已经清理掉的原文不会凭空恢复。临时交付副本、暂存文件与托管凭据的旧材料没有改成永久保存。

普通附件启用这项规则时将资料库标为46，防止旧程序重新按30天清理仍保管的历史文件。含普通附件版本的完整备份使用格式17，旧备份仍可读取；不把新规则默默放进旧格式。

开发检查使用合成文件和受控时间：超过两年、旧资料快照清除、重开后，所有版本仍可读取；导出备份，再在三年后的时间恢复，原文和当前选择仍正确。已删除系列的清理、保存失败回滚、另存、空文件及旧备份容器检查继续保留。

## 已接入：新建文件资料及审批

CLI按动态模板例子接收原文件路径，单份上限10MiB、空普通文件可保管。CLI私下有界读取并上传，不在响应里返回路径或原文。每次新建文件录入使用稳定operationId，原文上传与提案都有同会话查询和重试核对；同编号换内容会冲突。

待审原文使用加密库中独立持久暂存，不混用重开即清理的主人表单暂存。未审批不生成正式资料与附件；已批准待关联时保留原文；拒绝或成功入库后按剩余引用清理待审副本。新资料、全部原文、版本选择与决定回执在同一事务中保存，失败整组回滚。

同一附件可提交多个原文，明确选择当前版本，并填写来源版本标签及判断依据；其他相关附件保留为独立字段。审批页显示材料名称、分类、文件名、大小、当前选择和来源说明，支持直接核对文本、图片和Mac PDF原文，不要求重新选文件。主人修改名称、说明及分类后仍保留文件。受支持格式以外的原文可保管，但内嵌预览仍受已有阅读器支持范围限制。

新安装的声明式插件可声明file字段；本机服务为当前模板生成对应CLI路径例子，无须修改CLI或Skill。文件原文仍由宿主管理。带版本标签及来源说明的完整备份为18，库格式为47，旧格式可读取；待审上传不作为正式资料导出。

开发检查：核心文件与引用14项、实际CLI普通/凭据回归5项、加密持久化与决定回滚3项通过；真实主人审批组件已验证待审原文预览、独立附件、主人改名与批准，另验证内置及新安装插件模板的动态例子、批准和重开。最终整包和新聊天尚未运行。

## 已接入：已有资料的文件修改

`update-submit`沿用主人修改审批。文件修改指定准确itemId和baseVersion；新独立附件不带fieldId，已有附件新版本指定现有文件字段。新原文追加在全部已存版本之后，不从当前选择的旧版本开始覆盖；只补历史时currentVersion为null，原当前选择保持。新附件与旧文件字段不合并授权身份。

只补文件无需重新读取或填写无关正文。完整模板修改用查询返回的retainFileValue明确保留已有文件，省略或空文字不能悄悄删除原文。正文修改、独立补充字段和引用继续保留；批准等待引用时，新原文也持久保管，引用获准后共同保存。

审批页显示补到哪个已有附件、原当前文件、新交原文与版本依据，并可分别预览。主人改名后批准保留文件计划；目标版本变化则冲突，原资料与原文不覆盖。修改支持稳定operationId和update-status查询，重试不增加记录或版本。待审文件修改及其操作记录使用库格式48，便携备份仍按正式内容选择17/18，不导出待审原文。

开发检查已覆盖待审重开、回执写入失败整组回滚、原操作重试、补历史保持当前、独立新附件、明确保留文件的模板修改、引用等待及目标冲突。存储满时返回明确容量错误，保留历史原文；静默清理历史不作为导入手段。版本阅读器展示保存的来源标签及说明。

这轮针对性检查通过：核心25项、真实CLI6项、加密持久化4项及App67项；App检查含旧当前稿与新稿分别预览、改名后批准、新独立附件及完整模板修改保留文件。仍未将这些开发检查当作最终打包和独立聊天试用。

## 完整检查发现的后续修正

首轮四包完整检查发现：若干旧测试仍预期普通文件使用备份8/9/11，或启动后清理满30天的仍保管历史。当前导出与保留预期已按17和长期保留调整；Mac的80MiB进程中断恢复检查仍生成真实8/9旧格式夹具，并补充17，保留旧备份兼容验证。

另发现一处实际撤销问题：混合凭据申请中的普通字段在撤销事务里先禁止读取，审批核对又把这个临时屏障当成范围变化，导致决定无法保存。现在只让同一次主人撤销的审阅核对忽略其自身屏障，Agent读取仍保持禁止；其他期限、会话、字段和资料变化检查继续生效。两个混合撤销屏障测试及11项实际审批/历史回归通过。首轮打包因完整检查失败而未进入Release构建，最终整包尚待重跑，当前安装没有改变。
