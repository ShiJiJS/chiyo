# 普通文件录入与历史版本

对应 [#80](https://github.com/ShiJiJS/agent-info-manage/issues/80)。Mac 分支开发中；已接入普通文件新建提案、加密待审原文、CLI与主人审批；已有资料的附件修改尚未接完。未替换本机预览，也未清空真实资料。

## 已接入：仍保管的附件历史原文长期保留

一个普通附件仍被当前资料引用时，它的所有尚存版本长期保留；资料旧快照超过原保留期限被清理，也不会带走这些原文。恢复某个旧版本作为当前文件后，其他版本同样保持可用。这个规则由本机存储与完整加密备份共用。

用户删除附件或整条资料后，回收快照和仍保留的旧资料快照继续保护这组原文；这些恢复范围也已清理后，沿用删除后的清理规则。已经清理掉的原文不会凭空恢复。临时交付副本、暂存文件与托管凭据的旧材料没有改成永久保存。

普通附件启用这项规则时将资料库标为46，防止旧程序重新按30天清理仍保管的历史文件。含普通附件版本的完整备份使用格式17，旧备份仍可读取；不把新规则默默放进旧格式。

开发检查使用合成文件和受控时间：超过两年、旧资料快照清除、重开后，所有版本仍可读取；导出备份，再在三年后的时间恢复，原文和当前选择仍正确。已删除系列的清理、保存失败回滚、另存、空文件及旧备份容器检查继续保留。

## 已接入：新建文件资料及审批

CLI按动态模板例子接收原文件路径，单份上限10MiB、空普通文件可保管。CLI私下有界读取并上传，不在响应里返回路径或原文。每次新建文件录入使用稳定operationId，原文上传与提案都有同会话查询和重试核对；同编号换内容会冲突。

待审原文使用加密库中独立持久暂存，不混用重开即清理的主人表单暂存。未审批不生成正式资料与附件；已批准待关联时保留原文；拒绝或成功入库后按剩余引用清理待审副本。新资料、全部原文、版本选择与决定回执在同一事务中保存，失败整组回滚。

同一附件可提交多个原文，明确选择当前版本，并填写来源版本标签及判断依据；其他相关附件保留为独立字段。审批页显示材料名称、分类、文件名、大小、当前选择和来源说明，支持直接核对文本、图片和Mac PDF原文，不要求重新选文件。主人修改名称、说明及分类后仍保留文件。受支持格式以外的原文可保管，但内嵌预览仍受已有阅读器支持范围限制。

新安装的声明式插件可声明file字段；本机服务为当前模板生成对应CLI路径例子，无须修改CLI或Skill。文件原文仍由宿主管理。带版本标签及来源说明的完整备份为18，库格式为47，旧格式可读取；待审上传不作为正式资料导出。

开发检查：核心文件与引用14项、实际CLI普通/凭据回归5项、加密持久化与决定回滚3项通过；真实主人审批组件已验证待审原文预览、独立附件、主人改名与批准，另验证内置及新安装插件模板的动态例子、批准和重开。最终整包和新聊天尚未运行。
