# 飞牛 NAS 首次真实部署（2026-11-09，#103）

用户明确要求将现有 Mac 资料迁入飞牛 NAS，并替换日常 App。本次在 `codex/nas-deployment` 操作；未改 main、Windows 工作目录或其他 NAS 服务。

App 安装在 `/Applications/chiyo.app`，保留原 bundle ID。服务运行在独立 `chiyo` Compose 项目，使用 UID/GID `1000:1000`，监听 NAS 局域网地址的 47126 端口。资料目录可写，配置、运行密钥与 TLS 只读挂载，重启策略为 `unless-stopped`。App 核对私人 CA 和固定服务器身份，没有修改系统全局证书信任。原有 11 个 Docker 容器 ID 与运行状态均保持。

## 迁移与核对

- 通过原 App 的真实文件面板，分别保存原恢复密钥和完整加密备份；没有输出密钥或凭据原文。
- 在独立加密库恢复、正常关闭后重开，比较全部便携表及每份附件字节；没有读取日常数据库密钥。
- 原 App 正常退出后停止旧库写入，通过正式 Owner HTTPS 备份接口恢复到空服务器，核对原操作回执，没有合并 Windows 测试库。
- 备份包含 42 条资料、27 项凭据、27 份凭据版本、12 个目录、29 个标签、1 个模板插件、92 条资料修订、27 个回收对象，以及 30 个附件版本（7,235,435 字节）。这些是完整备份计数，不等同于界面中仅显示的在用条目数。
- 从 NAS 重新导出加密备份，在内存中比较所有便携表和全部附件原文。旧授权只保留历史，恢复后的旧凭据使用许可失效。
- 新版 App 自动连接 NAS，能看到资料、分类和关联，并实际收到、批准本聊天的一字段读取申请。CLI 取得批准地址；App 关闭后仍可读取。服务升级和正常重启保持原截止时间，过期后原读取不再返回内容。
- 最终 App 通过真实 macOS 另存面板导出 `nas-final-native.aimbackup`。重新认证、解密检查，资料、凭据材料、目录、关联、版本等与源备份一致；历史保留原记录并增加本轮实际访问记录；30 个附件版本逐字节一致。

最终版正常退出后再打开，自动连接 NAS 并显示完整信息库。退出控制曾等待超过 15 秒，但随后原进程正常结束，没有强杀 App。

一次原生导出进入结果待确认，使用原操作核对后确认未提交，随后明确重新提交并成功。没有凭超时重复导出或覆盖已有文件。

## 本轮修正与检查

1. Mac 增加局域网用途说明和明确的连接失败提示。按 bundle ID 区分 Swift 模块，避免不同测试应用共用主程序 UUID；用户在系统提示允许局域网访问后连接成功。不将结果归因于某一个单独改动。依据：[Apple TN3178](https://developer.apple.com/documentation/technotes/tn3178-checking-for-and-resolving-build-uuid-problems)、[TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)。
2. 备份恢复后重新绑定 Agent 的动态模板读取器。HTTPS 回归先重现 `service_unavailable`，修复后插件列表、模板列表和模板详情均通过，不再依赖重启解除旧作用域。
3. 联网 Agent 默认响应期限由 5 秒改为 15 秒，保留显式短期限和本机旧接口的默认期限；不延长访问许可。6 秒延迟 HTTPS 回归和完整 CLI 重启/结束回归通过，显式 30 毫秒期限仍生效。
4. 个人 Skill 定位器兼容新版公开 `macos-tools-source.json`，仍核对文件摘要并拒绝符号链接和未知元数据。10 个隔离测试和真实公开描述检查通过；原有其他 Skill 的未提交改动保留。

最终 Mac 包的 25 个打包检查阶段均成功，签名、归档、解包、独立存储检查和配套 CLI/worker 检查通过。两个实际 AMD64 镜像均完成编译版 HTTPS 初始化、持久资料重开及禁止替换已有运行密钥检查。服务修复回归、延迟/正式 CLI 回归通过；`info_remote` 和 `info_cli` 严格静态检查通过。

服务更新前正常停止，完整复制持久目录、对应密钥、配置和 TLS；独立检查容器逐文件核对核心目录字节、收紧备份权限，并检查数据库不是明文 SQLite 头。临时检查容器已移除，日常只保留一个 `chiyo-server` 容器。

## 保留与限制

恢复材料留在被 Git 忽略的 `local/private/chiyo-nas-deployment-20261109/`，说明见其中 `README.md`。原程序压缩归档、停止写入的原资料库和独立密钥/加密备份保留，不能把程序包备份当作资料备份。迁移后新资料以 NAS 为准；直接恢复旧单机库不会包含迁移后的修改。

当前聊天显式连接新服务器，公开运行包登记已更新；没有修改个人 Codex 的全局 hooks 安装及信任状态，也没有把手动连接算作新聊天自动生命周期验收。第二台电脑、跨电脑审批、Windows 和手机均未实测，#104、#105 仍后置。

NAS 部分调用仍需数秒，实际模板查询约 9 秒，过期访问核对约 13 秒。延长有限等待解决了原 5 秒误报，但不等于性能已优化；原生导出也经历过一次结果核对，已单独记录为 [#106](https://github.com/ShiJiJS/chiyo/issues/106)。另外一次只读元数据 CLI 超过两分钟未结束，安全终止该查询后重复成功，原因尚未确定；不能把增加响应期限当作全部修复。

最新交付集中保留在 `build/macos-adaptation/nas-delivery-20261109/`：一个 Mac DMG、一个 AMD64 服务镜像归档以及对应摘要和验证结果。本轮中间 App、重复构建目录、未使用的连接配置和旧 CLI 运行副本已移除；恢复材料按独立 README 保留。NAS 运行目录中已导入的镜像上传包与旧引导 Compose 文件已移除，现行 Compose 和持久目录保留。
