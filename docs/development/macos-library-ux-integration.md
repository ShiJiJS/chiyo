## 短窗口修正

意图：修复既有界面的可达性；阶段：实现完成、自检。沿用现有四主题、字号、三栏、
组件和北极星“位置清楚、筛选可见、一次操作一次提交”，不重新选择设计方向。
实际 Mac 窗口为 800×600 逻辑像素，原测试首个进入信息库即报告底部溢出；新增同尺寸
回归又发现空列表、200% 侧栏和详情横排问题，失败日志保留。

父容器剩余高度不足时，目录标题/快捷入口与树共用一个滚动区，回收站仍置底；
列表标题/筛选与结果共用 sliver 滚动区，分页仍置底；详情标题、正文和底部动作
共用一个滚动区，避免只给正文零高度。充分高度时沿用原固定标题/底部布局。
短高度阈值按当前文字比例计算（侧栏 440、列表/详情 480 逻辑像素），包含操作区和
内容空间预算。狭窄详情字段上下排，内容/凭据标题操作换行。共享 EmptyWorkspace
内容本身在空间不足时滚动，不缩小文字或屏蔽 overflow。

这是防止内容不可达的取舍：正常窗口业务步骤不变，短窗口会增加滚动；没有新增
业务决定、保存或确认。2 项回归覆盖 100%/200% 的实际字段值、修改历史、30 个目录
末项、新建目录入口和回收站均可达。初版测试误用不可实例化的 lazy child 和 Dialog
类型的准备错误也保留，未作为产品缺陷或通过结果。详情值不可达的中间修正失败保留。

主 Agent 按原设计自检，不冒称独立视觉评审。四主题各 100%/200% 保留前后同视口图；
截图工具显式注册本机 Georgia/Courier New，初版未注册系统字体的方块图不是原生
字体缺陷。视口横向小于产品原定 940 时沿用横向滚动；图像是 tester 渲染，非 CUA
或物理 IME。详情滚动后的字段图及实际操作断言用于区分暂时在视口外和永久不可达。
