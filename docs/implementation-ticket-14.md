# #14 确认删除、回收站恢复与重新授权

实现范围：用户可明确删除整条信息或选定字段；Agent 只能提交删除提案和查询其状态，不能确认删除、查看回收站或恢复内容。提案审核只显示选定目标，提交本身不影响资料。

## 接口与一致性

- `OwnerAccess.deleteInformation(itemId, expectedVersion, fieldId: ...)` 校验版本，删除成功后才返回；版本冲突不覆盖资料。
- `submitDelete` / `deleteStatus` 以私有会话能力隔离提案，不回传旧值、回收站内容或内部错误。CLI 对应 `delete-submit` / `delete-status`，通过 stdin JSON 提交 `itemId`、`baseVersion` 和可选 `fieldId`。
- `confirmDelete` / `rejectDelete` 只有 Owner 能力；重复确认返回原回收站条目，不再次删除。目标版本变化会进入冲突终态。
- `restoreRecycled(entryId)` 恢复原信息与字段标识，提高版本。恢复会消费回收站条目，重复或冲突恢复失败。整条信息删除前的版本水位由无字段值的删除、恢复事实保存，避免物理删除后版本回到 1。
- 既有修改提案的移除和业务替换也在同一事务内写入回收站，避免只支持某一个删除按钮。
- 删除只使相关字段从既有授权失效，其他字段仍可读取；即使恢复同一标识，旧授权也不会重新提供恢复的字段。恢复后用户新批准的授权才可读取。
- 核心 Owner 写操作串行；删除、恢复、修改使用事务更新当前内容、前版本、回收站和事实。提交成功之后发起的新读取拒绝已删目标；删除前已开始的读取按当时已生效状态处理，已披露内容不能收回。

## 保存与保留

SQLCipher schema 9 新增加密回收站、删除提案、无内容值的删除及恢复事实。兼容既有 schema 1–8 的升级，并保留 schema 7 审计与 schema 8 修改提案迁移。

回收站默认保留 30 天。恢复时和打开回收站时先清理到期内容，桌面后台启动时及每分钟也会清理；失败会显示提示，下一轮重试。到期条目不能恢复；清理完成后即使系统时间回拨也不能复活。恢复和清理都移除该回收站条目的内容快照，留下状态和必要同步事实，不声称安全擦除操作系统残留或离线备份。内容修改历史另由 #15 按自己的 30 天期限管理，回收站清理不等于所有历史副本已清理。

补齐录入提案终态：确认或拒绝后不再保留提交值；确认返回不含内容的 `ImportReceipt(id, version)`，保留条数供 UI 显示。重复确认使用稳定回执，不依赖当前信息仍存在，也不会重建已删除资料。旧开发库加载时清除终态提案历史遗留值，保留待确认提案原内容。该清理不新增待确认提案过期规则。

## 验证

通过已约定的核心服务公开接口验证：部分删除、旧授权拒绝、同授权其他字段继续读取、同 ID 恢复与新批准、整条删除/恢复循环版本递增、默认 30 天清理、时间回拨不复活、并发删除与更新单一胜者、并发恢复只应用一次、存储失败保留当前资料与授权、录入回执在删除后仍幂等。

真实 CLI 子进程覆盖提交删除、不能自己批准/列出回收站、Owner 确认、恢复后旧 token 拒绝、新批准后读取。SQLCipher 临时资料库覆盖删除后重开、恢复后再次删除/清理、再次重开不复活、磁盘测试标记不可直接检索；schema 8 夹具覆盖升级、终态提案清理与待确认提案保留。Flutter 无窗口 widget 测试覆盖显式确认、字段范围展示、回收站恢复，后台接口测试覆盖启动清理。

本票没有启动或操作用户桌面、没有使用真实资料，也没有执行原生 UI 或 macOS 测试。Windows/macOS 实际客户端与 CLI 联合验收仍需用户配合：手动删除字段后确认旧授权拒绝，打开回收站恢复并确认仍拒绝，重新批准后读取；同时检查同授权其他字段不受影响。
