## Parent

[单机信息访问授权软件：第一版规格 · Issue #1](https://github.com/ShiJiJS/agent-info-manage/issues/1)

## What to build

从零建立一个最小可运行的桌面应用与通用 CLI：agent 查询一条虚构信息，用户在桌面端批准一个字段，CLI 随后只能读取该字段。通过这一条流程验证技术栈、本地通信和审批入口的可行性，不接入真实资料。

关联规格用户故事：16、18、28、30、34、39、54、56。

## Acceptance criteria

- [ ] 选择并记录能支持 Windows/macOS 的桌面、核心服务和 CLI 技术组合，依据官方资料验证关键能力；给出可复现的开发运行方法，不将技术选型单独做成没有可运行结果的任务。
- [ ] 桌面界面、核心服务和真实 CLI 跑通公开描述查询、申请、用户批准、领取临时凭据及读取一个字段；演示数据限定为虚构资料，可先使用内存存储。
- [ ] 批准范围是明确的信息项和字段标识集合，临时凭据默认最长 8 小时有效且重复读取不延长；未授权字段、被篡改的标识和过期凭据无法读取。
- [ ] 桌面审批能力不出现在普通 agent 调用面；申请者仅凭请求 ID、聊天 ID 或用途文字不能领取其他申请的凭据，CLI 不取得全库密钥。
- [ ] CLI 为成功、待处理、未授权和服务不可用返回稳定机器可读结果，凭据不进入诊断日志；为后续请求状态和可控时间测试保留公开用例接口。
- [ ] 主要通过核心服务公开接口验证正向流程和跨范围拒绝，并完成一次真实桌面与 CLI 联调；这一任务完成不代表加密存储或 Codex 集成已完成。
