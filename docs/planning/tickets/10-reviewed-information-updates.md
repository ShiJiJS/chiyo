## Parent

[单机信息访问授权软件：第一版规格 · Issue #1](https://github.com/ShiJiJS/agent-info-manage/issues/1)

## What to build

agent 提交对已有信息的修改提案，用户查看差异后确认；原会话可直接读取已授权字段的新值，而新增字段仍需要授权。

关联规格用户故事：14、36、38、39。

## Acceptance criteria

- [ ] 修改提案携带目标和所依据的版本；桌面展示新增、修改、删除字段及公开描述差异，用户确认前正式资料不变。
- [ ] 读取现有内容或差异中旧值需要相应权限；提交接口和错误响应不能借机把原有资料返回给无读取权限的 agent。
- [ ] 资料在提案生成后发生变化时展示冲突或要求重新预览，不静默覆盖；确认和正式变更有一致结果。
- [ ] 同一字段的普通值修正保持身份及已有授权，新字段或新业务含义按新身份处理，不用自然语言语义识别代替明确操作规则。
- [ ] 确认后原授权读取最新值，不重复审批；新字段不可读，旧值不自动对 agent 开放。
- [ ] 通过核心接口验证差异确认、并发冲突和授权范围不扩张，并完成一次真实修改提案到 CLI 读取新值的演示。
