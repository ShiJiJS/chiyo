## What to build

用户在桌面待办中处理申请；agent 可以等待或先做其他工作，等待超时后继续查询原请求，不会重复创建申请或反复催促。

关联规格用户故事：17、22、23、24、25、26、27、54。

## Acceptance criteria

- [ ] 桌面待办展示请求的聊天关联、自述用途、候选范围和剩余有效期，并支持批准及拒绝；用途仅作为判断信息。
- [ ] 待审批默认 30 分钟有效且可在设置中调整；明确区分待处理、批准、拒绝、过期及取消，终态请求不能再次批准。
- [ ] CLI 支持提交后查询及有界等待，单次等待超时不取消原请求；重试状态查询不新增申请或产生重复通知事件。
- [ ] Skill 说明用户拒绝或请求过期后不自动重提相同申请；申请者可以继续无依赖工作，再查询原请求。
- [ ] 通过可控时间的核心接口测试到期、并发批准、结束与批准竞争和等待超时；桌面待办与真实 CLI 的结果一致。系统通知及关窗行为由后台运行任务完成。
