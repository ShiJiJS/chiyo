## What to build

用户将含组织信息及已确认历史范围的资料库在 Windows/macOS 间恢复，数据关系保留，但所有访问重新申请。

关联规格用户故事：50、51、53、57。当前为待确认的正文草案，尚未发布。

实施约束：Flutter 客户端、Dart 核心与 CLI；持久化使用 SQLite + Drift + SQLCipher，系统保管随机本机数据库密钥，备份采用独立恢复密钥。遵循已确认的固定字段授权、免应用密码及应用层安全边界；不引入云端、手机审批或 SSH 代理。具体通信、凭据和插件配置在相关任务内确定；共享语言不等于共享权限。主要测试边界为核心服务公开接口，并补本票相关的真实接入验证。

## Acceptance criteria

- [ ] 在本票对齐并明确展示备份覆盖的信息、目录、标签、模板、版本、回收站及授权/访问历史范围；未确认录入或修改提案不自动执行。
- [ ] 扩展已有备份格式以覆盖承诺范围，保持稳定标识、版本和关系；验证早期受支持备份升级恢复，不能只用单字段演示替代完整数据集。
- [ ] 活跃凭据及待审批状态排除，历史只能作为过去事实恢复；目标生成新的本机密钥，旧运行实例权限全部无效。
- [ ] 真实验证 Windows 导出到 macOS 恢复及反向流程，不依赖原设备密钥或服务器。
- [ ] 错误密钥、损坏、不支持格式、恢复中断不破坏已有库，不出现半恢复却报告成功。
- [ ] 核心接口测试完整数据往返、格式演进和权限清空，补真实桌面双向恢复证据；缺失平台验证应保持未完成，不以模拟替代。
