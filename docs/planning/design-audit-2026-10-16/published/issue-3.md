## What to build

用户手动保存结构化字段和文本说明，重启后免应用密码查看资料，CLI 重新获批后读取；密钥异常时保留原库并明确报错。

关联规格用户故事：1、2、10、11、38、48、57。

实施约束：Flutter 客户端、Dart 核心与 CLI；持久化使用 SQLite + Drift + SQLCipher，系统保管随机本机数据库密钥，备份采用独立恢复密钥。遵循已确认的固定字段授权、免应用密码及应用层安全边界；不引入云端、手机审批或 SSH 代理。具体通信、凭据和插件配置在相关任务内确定；共享语言不等于共享权限。主要测试边界为核心服务公开接口，并补本票相关的真实接入验证。

## Acceptance criteria

- [ ] 使用 SQLite + Drift + SQLCipher 持久化信息项、字段、公开描述及文本说明；支持手动创建、查看和普通值修正，公开说明与受控内容分开。
- [ ] 信息项与字段具有稳定身份和版本，不以本机路径为身份；已授权字段普通值修正后读取最新值。字段语义替换和完整变更确认在后续任务扩展。
- [ ] 安全随机生成数据库密钥并由系统保管，应用日常自动获取；在本票确定适配及依赖版本，优先验证 flutter_secure_storage，不在 CLI、公开配置或日志保存全库密钥。
- [ ] 发布模式验证实际加载 SQLCipher；缺失加密能力、错误密钥或密钥不可用时拒绝访问，不回退明文、不覆盖现有资料；临时存储采用内存策略。
- [ ] 应用重启后资料保留，旧 token 不恢复。检查数据库、辅助文件和错误输出不含测试敏感值；在 Windows/macOS 验证最小发布构建的密钥获取、重开及一次结构迁移。
- [ ] 核心服务测试覆盖保存、修正、重开及拒绝越权，并有真实桌面、CLI、数据库和密钥适配证据；恢复链路验证前只用虚构资料。
