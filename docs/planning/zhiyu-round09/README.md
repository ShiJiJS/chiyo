## 每项任务做什么

1. **[T01 先整理信息库现有代码](issues/01.md)** — 需要先完成：无。

   把“搜索、选中资料、打开详情、返回列表”这几段代码的职责分清楚，避免改一个地方影响另一个地方。这一步主要为后面的改版做准备，现有界面和功能先保持不变；同时检查快速切换时不会显示错资料。

2. **[T02 换成知予的新外观](issues/02.md)** — 需要先完成：T01。

   把软件展示名改成知予，按照原型统一顶栏、字体、按钮、菜单、提示和动画，只保留明亮、黑暗两种主题。选好主题后，下次打开仍保持；现有资料位置和Agent接入不因改名失效。

3. **[T03 重做信息库的三栏浏览](issues/03.md)** — 需要先完成：T02。

   左边选目录和标签，中间找资料，右边看详情，保留你要求的中间列表。查找只用关键词、类型和标签，分组与排序各用一个小按钮；普通信息、文件资料和凭据都能在同一列表找到。

4. **[T04 做好服务器资料的录入和展示](issues/04.md)** — 需要先完成：T03。

   软件预装服务器模板，填写主机地址、端口、登录用户、用途等信息后，按原型分区展示，不再把所有字段平铺成长表。保存并重新打开后内容完整；Agent申请其中某个字段时，仍只得到你批准的部分。

5. **[T05 做好应用资料和资料之间的关联](issues/05.md)** — 需要先完成：T04。

   录入一个应用或服务时，可以指出它运行在哪台服务器上、对应哪份维护文档、使用哪个凭据。例如打开Blinko能找到它的服务器；打开服务器也能找到关联的应用。点进关联资料后能返回原来的位置，关联本身不会自动授权。

6. **[T06 做好个人档案中的多段经历](issues/06.md)** — 需要先完成：T04。

   教育经历、工作经历等可以一段一段添加、修改和排序，不用手工建立“经历1、经历2”这种字段。审批时也能按经历展开查看；新增经历不会因为以前批过另一段，就自动交给Agent。

7. **[T07 做好文档和文件的阅读界面](issues/07.md)** — 需要先完成：T03。

   文字说明按文档方式阅读，PDF等支持的文件可以预览，并显示文件格式、用途、大小和版本。还要能替换文件、看旧版本、恢复版本和另存；Agent领取文件继续沿用现有审批流程。

8. **[T08 让软件能够安装新的模板插件](issues/08.md)** — 需要先完成：T05、T06。

   在设置里选择Agent制作的模板文件，先看到它会增加什么资料类型、包含哪些字段，再确认安装。安装后新建资料时就能选这个类型，例如增加“域名资料”；不需要你自己逐项搭建模板。

9. **[T09 让插件更新或删除时不影响旧资料](issues/09.md)** — 需要先完成：T08。

   插件更新后，新建资料可以使用新版，旧资料不会被偷偷改成另一种格式。停用或移除插件时，已有资料仍能查看和编辑，软件会提前说明影响，不会连资料一起删除。

10. **[T10 把SSH主机信任放到服务器插件里](issues/10.md)** — 需要先完成：T08。

   全局设置里不再单独放SSH主机信任，而是在服务器插件自己的设置中管理。查看某台服务器时，也能直接核对它的身份；没有专属设置的插件就不显示这个入口。

11. **[T11 把已录入资料整理成新模板的样子](issues/11.md)** — 需要先完成：T09。

   你现在已经存进去的资料不用重新录入。选择一个合适模板后，先预览旧字段分别放到哪里、哪些暂时无法对应，确认后再调整；无法对应的内容也保留，不直接丢掉。

12. **[T12 让Agent会查资料，也会准备新模板](issues/12.md)** — 需要先完成：T08。

   Agent可以直接看到标签，并用关键词、类型和标签找资料；找到条目之后，读取内容仍要申请。同时告诉Agent如何查看已有模板，确实缺少类型时制作一个模板文件、检查格式，再交给你安装。

13. **[T13 让Agent按模板提交录入和修改请求](issues/13.md)** — 需要先完成：T12。

   例如让Agent整理一台新服务器，它会按服务器模板准备资料，并提交给你审阅；你同意后才保存。修改已有资料时，也能明确说明改哪个字段、增加哪段经历或添加哪个关联，避免整份资料被莫名覆盖。

14. **[T14 重做普通信息的访问审批页面](issues/14.md)** — 需要先完成：T06、T07。

   按照原型的收件箱加详情卡片展示请求，请求变多后也能搜索、翻页和切换处理状态。你可以清楚选择提供哪些字段、哪份文件、允许多久，并处理拒绝、到期和撤销等情况；资料整理请求也放在这里。

15. **[T15 重做密钥使用的申请和审批页面](issues/15.md)** — 需要先完成：T02。

   页面明确显示：用哪个密钥、交给哪个程序、以什么方式使用。例如SSH使用临时密钥文件，或把token交给指定程序；浏览器填充则展示目标应用。还要说明有效期内可以重复使用，不会每条命令都重新审批。

16. **[T16 重做录入提案的审阅页面](issues/16.md)** — 需要先完成：T13。

   把Agent准备新增、修改、删除的内容展示清楚，修改前后能对着看，多条提案也能一起处理。如果你已经改过同一份资料，就提示双方修改有冲突，而不是直接覆盖；处理完成后可以跳到对应资料。

17. **[T17 重做授权历史页面](issues/17.md)** — 需要先完成：T05、T06。

   你能查清哪次授权给了谁、允许什么、何时到期，以及这次授权后来被用了几次。读取文件、使用密钥成功或失败、撤销等结果分别展示；资料被删掉后，过去的记录也仍能看懂。

18. **[T18 把其余设置页按原型改完](issues/18.md)** — 需要先完成：T10。

   把通知、请求期限、记录保留、目录标签、备份恢复、后台运行、材料清理和Agent接入等现有功能都放回新界面。按钮必须真的完成对应操作，保存后再次打开也有效，不能停留在原型里的提示演示。

19. **[T19 确认新旧资料都能完整备份和恢复](issues/19.md)** — 需要先完成：T07、T11、T16、T18。

   把旧资料、新模板资料、关联、档案经历、文件版本和凭据一起备份，再恢复出来，检查没有漏内容。缺少某个插件时资料仍能打开；旧的手工模板入口逐步退出主流程，但已有模板仍能查看和转换。

20. **[T20 打包并替换到你的Windows安装位置](issues/20.md)** — 需要先完成：T14、T15、T17、T19。

   生成可用的知予Windows程序，按照之前约定放到C:\Software并更新桌面快捷方式，清理多余旧构建。检查升级后资料和Agent接入仍能用，失败时可以退回；尚未完成的验收会明确列出来。

## 实施节奏

先做T01–T04，形成一条真实服务器资料的完整路径并完成原型对照，再向其他类型和页面扩展。T05–T07验证关联、重复条目及文件，T08/T09接外部包与生命周期；其他票只有列出的真依赖，不要求全部串行。无依赖阻挡不代表可以调用子Agent：用户明确要求由主Agent执行。

T12是模板发现/包验证与Skill制作指引；T13是资料提案协议；T16是完整提案工作台，三者分别负责不同交付，不重复实现审批事务。T14/T15分别使用现有普通信息和凭据授权路径。每张票都有自己的真实业务/视觉验收，T20只整合候选包及安装兼容，不代替前面的证据。
