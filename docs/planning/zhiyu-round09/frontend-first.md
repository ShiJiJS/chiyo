# 按用户要求：先把整套界面做完整，再逐项接功能

2026-10-25修订。此前“先做完服务器的前后端，再扩展其他页面”的顺序取消。用户希望先看完整软件的样子，随后按模块做服务和测试。本次仍只修改计划，未开发、未发布GitHub issues。

## 第一阶段：可以完整操作的界面预览

使用正式客户端的Flutter组件完成全部页面，不再另外写一套HTML原型。用固定示例资料填充界面：能搜索、打开详情、编辑、切换类型、打开菜单、查看审批、演示失败等；这些操作只影响预览数据。

T01只做必要的代码准备。随后7张UI票按模块完成界面：

1. **[U01 软件外壳和通用控件](issues/U01.md)**。先完成T01；提供知予顶栏、五个主页面入口、明暗外观、按钮/菜单/提示/弹窗和动画。
2. **[U02 三栏信息库及服务器、应用资料](issues/U02.md)**。先完成U01；用示例数据完成目录、关键词/类型/标签查找、列表、服务器/应用详情及编辑、关联跳转。
3. **[U03 档案、文档、文件和凭据资料](issues/U03.md)**。先完成U02；在同一信息库里完成其余资料的详情、表单、版本及使用入口。
4. **[U04 插件和旧资料套用模板](issues/U04.md)**。先完成U01；完成插件安装预览、更新/停用/移除、服务器插件设置、旧资料改用模板的预览。
5. **[U05 访问审批](issues/U05.md)**。先完成U01；完成普通信息、文件、密钥使用和整理请求的完整页面、提示与处理状态。
6. **[U06 录入提案与授权历史](issues/U06.md)**。先完成U01；能查看新增/修改/删除的差别、批量提案、冲突以及一次授权下的多次操作。
7. **[U07 其余设置](issues/U07.md)**。先完成U01；完成通知、期限、备份恢复、运行维护、目录标签管理和Agent接入界面。

这些UI票不被新数据库、新插件后台或新CLI接口阻塞。只先商定页面需要哪些数据、操作和错误结果，示例数据与正式数据使用同一个调用方式。

全部页面接在同一个预览程序中，不允许各自做互不相连的演示。跨页关系要能走通，例如服务器→凭据→申请使用→审批→历史，或者新增提案→示例批准→信息库中看到新资料。由一个集中管理的示例数据来源协调，不能每页维护一套互不一致的记录。

第一阶段结束提供可运行的Windows界面预览、固定源码及原型对照。视觉与交互检查通过后才进入下一阶段；是否等待用户亲自反馈按当次授权安排，不额外给每一页添加必须人工批准的门槛。

## 第二阶段：按功能模块接入本地服务

原有T02–T20保留功能范围，但改为接入已经做好的界面，不重新绘制。每张票依次记录三个检查点：

- **界面**：相关UI票已完成，本模块需要的数据及正常/失败状态齐全。
- **接入**：优先调用现有本地服务；确实缺少的接口、存储或业务规则才新增。
- **测试**：使用真实隔离资料库验证操作、保存、重启、授权和错误处理，再检查样式与动画未因接入而改变。

例如服务器模块：前端先能用示例服务器完成查看、编辑和关联跳转；再接真实读取与保存；最后验证保存后重启仍在、Agent只能读取获批字段、保存失败不丢输入。接入真实数据时应主要替换数据来源，不能重写页面。

“服务端”指软件现有的本地核心和数据接口，不是新增云端服务器。服务器同步仍不做。

## 第三阶段：整体检查和打包

各模块完成后检查真实跨页流程、旧资料升级、备份恢复及Windows安装更新，按既有T19/T20和旧验收票执行。不能仅凭整套界面都能点就宣布全部功能完成。
