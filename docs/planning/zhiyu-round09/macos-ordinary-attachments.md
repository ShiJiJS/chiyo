## M06：主人管理普通附件

用户结果：新版信息库能打开旧资料中的普通附件，查看准确文件名、大小、当前版本及保留版本，按需预览；主人能够从原生面板导入、替换、恢复保留版本和另存原文。复用 #64 页面合同、ADR0011和已有SQLCipher附件/草稿事务，不改成外部文件库，不凭文件名创建“简历”业务身份。

实施顺序：
1. Owner-only有界原文读取，验证准确版本、长度及摘要，事务完成后才返回；真实版本列表及文字/图片预览接OwnerWorkspaceSource。普通列表/公开目录不读原文。
2. PDF分页预览与不可预览/损坏/已清理原文的明确状态；不执行HTML/外链，不自动打开外部程序。
3. 原生输入选择映射不透明句柄，草稿暂存/取消清理；普通文件导入、混合字段编辑、替换与保留版本恢复接现有持久事务及准确原操作核对。
4. 主人明确另存，使用原生选择/同卷私有暂存与不覆盖发布；成功和清理分别报告，关闭/换库后迟到操作失效。
5. 真实SQLCipher重开、旧资料兼容、错误原文/容量/冲突/发布与回执失败、正常控件联合检查；同候选原生面板/沙箱验收另留证据。

验收：
- [ ] 旧资料附件字段通过稳定字段映射显示真实文件元数据和当前/保留版本，伪造/跨资料字段拒绝；版本记录不等于原文可用。
- [ ] 文字、受限图片、PDF真实原文按需预览；损坏、摘要不符、已清理及不可预览有准确状态，不以样本替代。
- [ ] 导入/混合字段保存/替换/恢复版本持久化，取消不改变正式资料，保留其他字段和原文件，重开可读。
- [ ] 重复同意图幂等，冲突/回执丢失核对原操作，不自动重写或生成重复附件；换库、关闭和过期草稿不能继续操作。
- [ ] 另存原文逐字节一致、不覆盖已有文件；未知发布不猜成功，暂存仅清理本次登记对象。
- [ ] 真存储、完整控件、独立重开与正式沙箱面板证据对应同源候选；未验项保留。

不包含凭据原文、AI申请发起按钮、演示模式或AI文件领取；后者独立由M07完成。原 #34/#37/#38 为底层及历史交付事实，#44/#48/#50继续负责原系统/旧客户端范围，不重复关闭。

## M07：AI普通附件申请、审批与交付

用户结果：AI通过正式CLI请求文件字段，主人在新版收件箱核对准确文件版本后批准或拒绝；AI只能领取获批范围的受管副本，主人能看交付事实和回收状态。

复用 #66/#67 界面合同、已有文件请求/授权/交付协议、固定期限与共享授权会话。依赖M06准确元数据/预览及 #71/#72 真实申请/审批接缝；不依赖M06所有导入/另存控件完成才开始。普通文字读取批准不得当作凭据使用批准。

验收：
- [ ] 文件申请只由AI正式入口发起；主人页面仅审批和管理，无演示/手动申请入口。
- [ ] 审批核对准确信息字段/附件版本/文件元数据，批准前版本变化或原文不可用拒绝旧决定；允许部分范围或拒绝。
- [ ] 包内独立CLI真实领取原文，未批/越界/跨会话/过期/撤销/会话结束均拒绝；重复操作不重放，恢复历史不复活能力。
- [ ] 历史与受管副本结果为真实事实，清理失败/未知保持准确；主人另存文件与AI受管副本分开，不承诺收回已读取内容。
- [ ] 独立进程重开、故障/回执丢失、真实沙箱App→配套worker/CLI联合证据；真实聊天与原生权限未验项如实保留。

#44 旧普通包的工具/附件系统证据继续保留，本任务只补Round09新版页面到真实协议的适配，不重做或改写旧验收，不扩大托管凭据能力。
