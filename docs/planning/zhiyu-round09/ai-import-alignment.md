## 已确认

- Skill 是 App 和 CLI 的使用手册；插件提供模板的具体格式、说明和例子，CLI 负责让 Agent 查询。插件变化不修改 Skill。
- App／本机服务统一管理插件及模板，CLI 通过通信查询实际已安装插件、启停状态和模板格式，不在 CLI 或 Skill 里写死另一份清单。安装、更新、启停和移除插件后，后续查询反映实际状态；提交时核对所用模板仍可用且版本一致。见 [ADR0019](../../adr/0019-discover-plugin-templates-from-running-app.md)。
- 用户给文件和录入要求，由 Agent 自己判断模板、分类、描述、关联和文件组织。验收者只扮演用户，不能在会话中反复指导 Agent 怎样填才算通过。
- 凭据录入的目的是尽量避免秘密新进入 Agent 上下文。先判断 Agent 是否已经实际看到了秘密：已经看到的，允许 Agent 直接填入凭据提案，并说明秘密可能已进入上下文，不让用户重复填写。这个例外也适用于人设定的密码，以及从文件看到了但不知由谁设定的密码；不能为了套用例外，专门先读取原本可以由用户私下填写的密码。
- 对尚未进入 Agent 上下文的秘密，人设定的账号密码由用户在 App 中填写；用户通过密码管理器生成并设为账号登录密码的，也归这一类。API 密钥、Token 等其他凭据由 Agent 录入，不要求用户复制；整份凭据文件由 Agent 提交文件交给程序保管，不要求用户再次手动选择，也不要求 Agent 为导入而读取原文。
- 不为配置里的 Token 新增 CLI JSON 字段提取协议，也暂不增加混合文件的秘密预先隐藏流程。Agent 可以按用户给定资料完成非人工设定凭据的录入，同时说明秘密可能已经进入 Agent 上下文；这不允许秘密进入公开名称、普通资料字段、日志或 GitHub。
- 没有合适模板时，Agent 只能建议用户需要什么模板，暂缓相关信息的录入；不能自行生成并安装新模板。其他信息是否能先入库，要服从引用关系。
- 修改已有资料仍须提出修改申请，用户查看前后变化并批准。现有 CLI 的 update-submit 以及核心修改预览已经实现，不需要新造一个平行流程；模板、关联和附件写入的缺口另行补齐。
- 普通附件历史版本长期保留，见 [ADR0017](../../adr/0017-retain-ordinary-attachment-versions.md)。不能再用拆成多条信息的方式规避历史清理。
- 不同投递方向的简历属于不同材料，各建一条信息；不是同一条信息下的两个并列附件。同一材料自身的前后修订仍可以组织成文件版本。由 Agent 根据来源自行判断，不要求用户逐份指定组织方式。
- 用户批准的信息如引用尚未批准的待录入内容，先保留为“已批准待入库”；等引用内容也获准后一起保存。不能先保存成引用缺失的正式信息。这是新要求，当前普通新增提案确认流程尚未支持。
- 引用目标被拒绝时，相关的已批准待入库资料保留为需要处理，说明阻塞原因；不自动一起拒绝。修改引用后重新审批。
- 待录入资料互相引用时，全部获准后一起入库，不能互相等待到永远。与该引用组无关的其他资料仍按自身审批和引用状态处理。见 [ADR0018](../../adr/0018-admit-related-information-together.md)。

## 各票负责什么

- #78 由 App／本机服务提供动态插件、模板及示例查询；CLI 不保留硬编码模板清单。负责实际模板类型、字段、关联、Markdown，以及批准等待引用的共同流程。
- #79 首先按秘密是否已经实际进入上下文处理：已见秘密由 Agent 填并说明；未见的人设登录密码（含密码管理器生成）由人填；API 密钥、Token 等其他凭据由 Agent 填。整份凭据文件不再要求用户重选，不新增 JSON 字段提取功能，不增加混合文件预先隐藏流程。
- #80 的普通附件历史版本从“待选择保留方式”改为长期保留；不同方向材料各建一条，不默认合成一条资料中的多个附件。
- #78 和 #73 要明确无模板时只能建议并暂缓，不能将自动创建新模板算作正常录入或验收要求。
- #78/#79/#80 的普通项可先保存说法要服从引用要求；支持已批准待入库、引用被拒后的待处理，以及互相引用内容全部批准后一起保存。#73 相应验证，不能提前报告完成。
