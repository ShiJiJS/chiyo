# T06：个人档案重复条目及稳定字段授权

状态：draft-awaiting-approval。确认拆分后才发布并添加 ready-for-agent。

## What to build

教育经历、工作经历等可以一段一段添加、修改和排序，不用手工建立“经历1、经历2”这种字段。审批时也能按经历展开查看；新增经历不会因为以前批过另一段，就自动交给Agent。

## 开发顺序

本票复用已完成的[U03](U03.md)、[U05](U05.md)界面，不再另外画一套。

- [ ] 先复核前端：正常和异常状态齐全，若有遗漏先在同一套界面补好。
- [ ] 再接真实本地服务：替换示例数据来源，优先复用现有接口，缺失能力才新增。
- [ ] 最后验证：真实隔离资料库/CLI走通本票流程，检查保存、重启、权限及失败恢复，再对比样式和动画。

下方原有界面要求作为复核标准，不重复实现。UI票完成不等于本票完成。

## Acceptance criteria

- [ ] entries首版三子字段和稳定entry/field身份落地，不将整段JSON作为一个绕过粒度的大字段。
- [ ] 普通扁平协议兼容；公开元数据不含实际学校/公司等值，新增条目不加入旧授权，重新排序不换身份。
- [ ] 编辑冲突、删除/恢复、修订、重启和备份往返保持结构，旧已失效授权不复活。
- [ ] R05分组阅读和表单、字段选择完整可用，长经历与200%文字不重叠，失败保留草稿。
- [ ] 提交固定源码、受影响测试、同场景视觉/动效证据及未通过项；实际Windows、离屏和原型证据分开标注。没有业务或布局差异被“编译通过”替代。
- [ ] 无关行为不回退；涉及持久化的新增内容在本票即支持重启和备份/恢复，权限用核心公开接口验证。仅使用隔离虚构数据。

## Demo

新建档案两段经历→仅批准第一段一个字段→新增/排序第二段→验证旧grant范围固定。
