## What to build

把“搜索、选中资料、打开详情、返回列表”这几段代码的职责分清楚，避免改一个地方影响另一个地方。这一步主要为后面的改版做准备，现有界面和功能先保持不变；同时检查快速切换时不会显示错资料。

给前端准备可替换的数据入口和明确的查询/操作结果结构。这里只确定必要接口和隔离预览的启动方式，不先开发全部新数据库和服务；后续U票用示例数据完成界面。

## Acceptance criteria

- [ ] 只做必要预重构：抽出查询、选择、返回位置与带种类的列表摘要；权限、存储语义及外观保持。
- [ ] 至少普通信息、凭据两种真实摘要适配器使用同一状态接口；不把秘密或文件正文放入列表状态。
- [ ] 搜索后快速换范围、异步结果倒序、对象删除后刷新及跨页返回都不显示错误对象；重复导航不靠销毁整页同步。
- [ ] 既有目录/标签、附件和凭据入口回归通过，留下固定基线画面；不顺手重写审批/历史或全仓part结构。
- [ ] 提交固定源码、受影响测试、同场景视觉/动效证据及未通过项；实际Windows、离屏和原型证据分开标注。没有业务或布局差异被“编译通过”替代。
- [ ] 无关行为不回退；涉及持久化的新增内容在本票即支持重启和备份/恢复，权限用核心公开接口验证。仅使用隔离虚构数据。

## Demo

隔离虚构库搜索→选中→打开凭据→返回→修改资料后刷新，界面与操作结果保持原样。
