# T13：按模板提交新增和修改资料提案

状态：draft-awaiting-approval。确认拆分后才发布并添加 ready-for-agent。

## What to build

例如让Agent整理一台新服务器，它会按服务器模板准备资料，并提交给你审阅；你同意后才保存。修改已有资料时，也能明确说明改哪个字段、增加哪段经历或添加哪个关联，避免整份资料被莫名覆盖。

## Specification

[S4](../../../specs/zhiyu-round09/04-flows.md)、[S1](../../../specs/zhiyu-round09/01-domain-and-data.md)；要求：S4-A04、S1-D02、S1-D03、S1-D04。所有票同时遵守 S5-V06、S6 的实现与证据约束。以冻结 Round09 为参照，原型演示数据/假成功不得进入正式代码。

## Acceptance criteria

- [ ] 提案引用固定模板版本/快照及实例身份，明确新字段、条目和关系；并发更新或包变化不静默换定义。
- [ ] 新增与修改均由Owner一次确认原子保存；模板停用/缺失走通用预览，不兼容保留草稿并提示重新生成。
- [ ] 通用提案不提供展开凭据材料或上传附件原字节的能力；普通文本仍需Owner审阅，不声称能自动识别任意秘密；标签可直接发现，但实际写入分类建议仍需相应批准。
- [ ] 独立CLI真实端到端跑新增→部分字段修改→重启→读取，备份/修订一致；不只测JSON序列化。
- [ ] 提交固定源码、受影响测试、同场景视觉/动效证据及未通过项；实际Windows、离屏和原型证据分开标注。没有业务或布局差异被“编译通过”替代。
- [ ] 无关行为不回退；涉及持久化的新增内容在本票即支持重启和备份/恢复，权限用核心公开接口验证。仅使用隔离虚构数据。

## Demo

Agent生成应用+关联及档案条目提案→审阅→保存→再次修改→冲突提示与重提。
