## What to build

按照原型的收件箱加详情卡片展示请求，请求变多后也能搜索、翻页和切换处理状态。你可以清楚选择提供哪些字段、哪份文件、允许多久，并处理拒绝、到期和撤销等情况；资料整理请求也放在这里。

## 开发顺序

本票复用已完成的[U05](U05.md)界面，不再另外画一套。

- [ ] 先复核前端：正常和异常状态齐全，若有遗漏先在同一套界面补好。
- [ ] 再接真实本地服务：替换示例数据来源，优先复用现有接口，缺失能力才新增。
- [ ] 最后验证：真实隔离资料库/CLI走通本票流程，检查保存、重启、权限及失败恢复，再对比样式和动画。

下方原有界面要求作为复核标准，不重复实现。UI票完成不等于本票完成。

## Acceptance criteria

- [ ] R09的列表、详情卡和决定区与原型一致；请求不是无限tabs，可搜索/分页/切状态，详情与当前请求一致。
- [ ] 补选/减选、条目展开、文件版本及固定授权集合真实接入；重复提交受控，失败保留选择。
- [ ] 拒绝、到期、对象删除、会话结束和撤销均覆盖；整理仍是固定元数据范围最长30分钟，完成结果无第二次批准。
- [ ] 以实际Core/CLI驱动普通和文件请求；现有通知路由不退化，系统通知真实点击未通过仍归#23。
- [ ] 提交固定源码、受影响测试、同场景视觉/动效证据及未通过项；实际Windows、离屏和原型证据分开标注。没有业务或布局差异被“编译通过”替代。
- [ ] 无关行为不回退；涉及持久化的新增内容在本票即支持重启和备份/恢复，权限用核心公开接口验证。仅使用隔离虚构数据。
