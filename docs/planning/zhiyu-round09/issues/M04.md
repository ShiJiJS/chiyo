# 知予 Mac M04：验收保存—AI申请—审批闭环并交付可用候选

## 目标与依赖

依赖 M01（#70）、M02（#71）、M03（#72）。从同一固定 Mac ARM64 候选验证主人保存、AI 申请、主人审批、AI 限定读取及失效，再交付可实际使用的 App。此票只验首批业务接缝和形成候选，不重复创建 #50 的全平台安装交付总验收，也不把“最小可用”称为完整产品。本轮仅拆分，未运行验证或重新打包。

## 验收路径

1. 固定源码、App/CLI/核心版本和稳定安装目录；普通入口启动实际 SQLCipher/本机服务，新界面不带预置示例资料，不回退内存源。隔离项目使用合成资料和独立库，不触碰个人资料。
2. 主人从新界面录入一条普通资料，编辑并正常退出；独立重开确认准确内容与身份。通过现有备份能力验证该首批数据可恢复，不以未来备份 UI 延后数据可恢复性。
3. 同一个真实 AI 宿主聊天通过正式 CLI/接入路径发现元数据并申请；App 收件箱显示准确申请；批准部分字段后真实 AI 只读到这些字段。另一个请求验证拒绝；无审批时读不到正文。
4. 分别验证撤销、固定期限和根会话结束失效、重开不复活，至少一次跨进程核对。若需主/子 Agent 场景，应在明确安排且受限的合成项目中复用 #49 的标准，不能凭过往授权扩展个人环境。
5. 覆盖服务中断、并发修改、提交后响应丢失、退出保存失败与重启核对；错误不能造成资料丢失、重复请求或重复批准。
6. 同一候选复查保存、申请定位、审批和历史的可操作性；系统密码/中文输入/通知点击/睡眠等需要本人环节集中列清用途，不能拆成反复确认或用模拟宣告通过。

## 交付物与集中配合安排

- 固定位置保留一个当前 Mac ARM64 App，附同版本 CLI/接入说明、源码版本、已支持功能和剩余问题清单；普通启动不带预置样例。
- 一份完整流程记录：新建和重开资料 → 真实 AI 发现并申请 → 主人部分批准或拒绝 → AI 限定读取 → 撤销/到期/会话结束失效。每个结果能对应同一请求与授权。
- 先完成可自动化准备，再一次性列明需要主人参与的项目及目的：钥匙串用于本机密钥访问，中文输入用于实际编辑；通知点击和睡眠唤醒分别回填 #47/#46。非阻塞的系统专项未验项保留原票，不混称首批已全量验收。
- 验收结束清理本轮过期 App、dSYM 和可重建过程文件，保留当前候选、必要证据、源码和接入文档；不动个人库或来源不明的文件。

## 完成标准

- [ ] 同一个候选完成真实加密保存及独立重开，资料恢复结果准确，源码/载荷/CLI一致。
- [ ] 真实 AI 宿主经正式入口提出请求，主人新界面审批、AI 读取和历史查询形成可追溯同源闭环；不是仅测试进程直接调用服务。
- [ ] 拒绝、越界、撤销、到期、结束和恢复不复活的关键负向检查通过，故障路径有确定结果或可恢复的未知状态。
- [ ] 固定 App/CLI 构建、架构、运行依赖、sandbox、深度签名和启动通过；明确正式身份/密钥兼容、签名分发限制及实际验证的系统版本。
- [ ] 给用户一个固定位置可打开的候选及支持/不支持清单、接入步骤；保留必要源码/证据，清理本轮多余 App/dSYM/过程副本，不删未知文件或个人库。
- [ ] 向 #46/#47/#48/#50 回填本候选证据与尚缺范围；未完成的系统输入、通知、睡眠、干净用户/其他机器安装保持未验，不提前关闭旧票。

## 首批可用边界

允许通过 App 收件箱接收/处理申请，系统通知缺失不丢请求；系统通知完整能力仍归 #47。首批不承诺附件交付、凭据执行、插件包迁移、提案整理、完整备份 UI、焦点填充或 Windows 适配。保留已有 UI 管理结构，未接入按钮如实不可用，无另外的演示模式。实际系统验证不能永远省略；本人暂不在时可完成准备并列明剩余条件，不能伪造完成。
