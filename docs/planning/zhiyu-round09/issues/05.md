## What to build

录入一个应用或服务时，可以指出它运行在哪台服务器上、对应哪份维护文档、使用哪个凭据。例如打开Blinko能找到它的服务器；打开服务器也能找到关联的应用。点进关联资料后能返回原来的位置，关联本身不会自动授权。

## 开发顺序

本票复用已完成的[U02](U02.md)界面，不再另外画一套。

- [ ] 先复核前端：正常和异常状态齐全，若有遗漏先在同一套界面补好。
- [ ] 再接真实本地服务：替换示例数据来源，优先复用现有接口，缺失能力才新增。
- [ ] 最后验证：真实隔离资料库/CLI走通本票流程，检查保存、重启、权限及失败恢复，再对比样式和动画。

下方原有界面要求作为复核标准，不重复实现。UI票完成不等于本票完成。

## Acceptance criteria

- [ ] 应用模板与服务器共享定义/渲染接口，关系持久化为同一事实，反向展示无双份可冲突数据。
- [ ] 凭据关系复用既有关联事实；读源资料不能读取目标资料或密钥，Agent普通catalog不返回私人关系图。
- [ ] 支持选择/移除关系、并发冲突、目标回收/恢复和历史查看；禁止重复/自指，普通资料互链不误当目录防环。
- [ ] 关联参与修订/回收和备份；跨筛选跳转及返回可解释，R04长关联列表不压缩正文。
- [ ] 提交固定源码、受影响测试、同场景视觉/动效证据及未通过项；实际Windows、离屏和原型证据分开标注。没有业务或布局差异被“编译通过”替代。
- [ ] 无关行为不回退；涉及持久化的新增内容在本票即支持重启和备份/恢复，权限用核心公开接口验证。仅使用隔离虚构数据。
