## 已确认的实施基线

- Flutter 桌面客户端；Dart 本地核心和独立 CLI；SQLite + Drift + SQLCipher；安全随机生成本机数据库密钥并由系统保管，备份采用独立恢复密钥。
- Windows/macOS 单机版；未来 Spring Boot 云端、手机确认、同步及 SSH 代理不在本轮任务内。
- 通信协议、会话凭据和平台配置在相关任务内设计、验证并记录，不另设阻塞所有实施的技术设计阶段；改变产品、安全边界或主要选型时再对齐。
- 每票交付可演示的用户流程，主要通过核心服务公开接口测试，补相关真实 CLI/桌面/平台验收。每票可在新上下文中读取父规格、相关 ADR 和直接依赖成果后实施。
- T01 限于内存虚构资料；T02 起新增的敏感持久化数据均沿用加密契约，不出现功能临时使用明文的旁路。T11 起新增数据应维持已承诺备份兼容性，T16 验收最终覆盖范围及跨平台恢复。
- 加密、系统密钥及恢复链路验证前不迁移真实资料。平台实测不足必须明确留为未完成，不能把文档查阅当作验收。

## 已发布任务

1. **[T01 / #2：跑通一次申请、桌面批准与限定字段读取](https://github.com/ShiJiJS/agent-info-manage/issues/2)**  
   阻塞：无。交付：用虚构信息从真实 Dart CLI 发起申请，在 Flutter 桌面端批准一个字段，CLI 领取凭据后只能读取该字段；桌面撤销后再次读取失败。

2. **[T02 / #3：手动录入并在重启后安全读取信息](https://github.com/ShiJiJS/agent-info-manage/issues/3)**  
   阻塞：T01。交付：用户手动保存结构化字段和文本说明，重启后免应用密码查看资料，CLI 重新获批后读取；密钥异常时保留原库并明确报错。

3. **[T03 / #4：等待、拒绝或过期后查询原申请](https://github.com/ShiJiJS/agent-info-manage/issues/4)**  
   阻塞：T01。交付：申请进入桌面待办，agent 可等待或先做其他工作；超时后继续查询同一申请，用户可拒绝，过期申请不能批准。

4. **[T04 / #5：一次审批调整字段范围和有效期](https://github.com/ShiJiJS/agent-info-manage/issues/5)**  
   阻塞：T02。交付：用户在一次审批中取消、补选或改选字段并调整有效期，CLI 获得实际批准范围；新增信息不会自动加入旧授权。

5. **[T05 / #6：让一个 Codex 聊天自动关联并复用授权](https://github.com/ShiJiJS/agent-info-manage/issues/6)**  
   阻塞：T01。交付：Codex 在同一聊天中多次调用 CLI 能复用已获准范围，其他聊天独立申请，用户不用手动维护聊天凭据。

6. **[T06 / #7：共享主子 Agent 授权并在聊天结束时失效](https://github.com/ShiJiJS/agent-info-manage/issues/7)**  
   阻塞：T05、T03。交付：同聊天主 agent 与子 agent 复用授权，聊天正常结束后撤销授权并取消待审批；异常结束和恢复聊天也不会复活旧权限。

7. **[T07 / #8：关窗后继续服务并通知新申请](https://github.com/ShiJiJS/agent-info-manage/issues/8)**  
   阻塞：T03。交付：窗口关闭后 CLI 仍能访问有效授权；新申请通过系统通知提醒，用户从托盘或菜单栏打开待办，完全退出后停止访问。

8. **[T08 / #9：整理目录与标签，让 Agent 检索公开目录](https://github.com/ShiJiJS/agent-info-manage/issues/9)**  
   阻塞：T02。交付：用户按目录和标签整理资料、审阅公开说明，agent 搜索和分页发现可以申请的信息。

9. **[T09 / #10：使用可扩展字段模板录入信息](https://github.com/ShiJiJS/agent-info-manage/issues/10)**  
   阻塞：T02。交付：用户定义并应用字段模板来创建信息；扩展模板后新增字段仍需授权，原有资料及授权不会被静默改写。

10. **[T10 / #11：批量预览并确认 Agent 的录入提案](https://github.com/ShiJiJS/agent-info-manage/issues/11)**  
   阻塞：T08、T09。交付：agent 将用户指定资料整理成录入提案，用户批量调整分类、字段和公开描述后确认，信息才正式入库。

11. **[T11 / #12：导出加密备份并在独立密钥环境恢复](https://github.com/ShiJiJS/agent-info-manage/issues/12)**  
   阻塞：T02。交付：用户启用备份、另存恢复密钥并手动导出；没有原电脑密钥时仍能恢复当前信息，日常打开应用无需密码。

12. **[T12 / #13：确认修改差异并读取已授权字段的新值](https://github.com/ShiJiJS/agent-info-manage/issues/13)**  
   阻塞：T04、T10。交付：agent 提交修改提案，用户查看差异并确认；原授权立即读到修正值，新字段仍需批准，过时提案不会覆盖新内容。

13. **[T13 / #14：确认删除、回收站恢复与重新授权](https://github.com/ShiJiJS/agent-info-manage/issues/14)**  
   阻塞：T12。交付：用户确认删除后，信息进入回收站且旧授权立即不能读取；恢复资料后需要重新批准访问。

14. **[T14 / #15：查看和恢复修改历史，保持旧值仅用户可见](https://github.com/ShiJiJS/agent-info-manage/issues/15)**  
   阻塞：T13。交付：用户查看最近 30 天的修改版本，将旧版本恢复成新的当前内容；agent 仍只能读取当前获准字段。

15. **[T15 / #16：查看授权历史与访问记录，并从历史撤销](https://github.com/ShiJiJS/agent-info-manage/issues/16)**  
   阻塞：T03、T04。交付：用户查看曾批准的范围及实际成功、失败访问，从历史入口撤销有效授权后，CLI 的后续读取立即失败。

16. **[T16 / #17：将完整支持范围的资料恢复到另一平台](https://github.com/ShiJiJS/agent-info-manage/issues/17)**  
   阻塞：T11、T14、T15。交付：用户将含组织信息及已确认历史范围的资料库在 Windows/macOS 间恢复，数据关系保留，但所有访问重新申请。

17. **[T17 / #18：在干净 Windows 环境安装并完成单机流程](https://github.com/ShiJiJS/agent-info-manage/issues/18)**  
   阻塞：T06、T07、T16。交付：用户安装 Windows 应用和 CLI、接入 Codex 后，能完成录入、审批、后台运行、变更、历史与恢复，并能升级继续使用资料。

18. **[T18 / #19：在干净 macOS 环境安装并完成单机流程](https://github.com/ShiJiJS/agent-info-manage/issues/19)**  
   阻塞：T06、T07、T16。交付：用户安装 macOS 应用和 CLI、接入 Codex 后，获得一致的单机流程，菜单栏、钥匙串及升级在实际分发环境中可用。

## 依赖说明与可启动任务

只列直接的必需依赖，不重复列出传递依赖。T01 是初始唯一可启动任务；其完成后，T02（持久化）、T03（请求处理）和 T05（Codex 基本接入）可分别开展。后续按阻塞任务全部完成的前沿推进，而非按编号强制串行。

- T04 需要 T02 的可编辑信息库；无需等待 Codex 或目录模板。
- T06 需要 T05 的聊天凭据关联与 T03 的完整待审批终态，才能验证子 agent 及结束时取消。
- T08 与 T09 分别依赖基础信息录入，彼此不阻塞；T10 需要二者以完成带组织信息和模板的批量录入。
- T15 需要 T03 的完整请求状态和 T04 的最终批准范围；无需等待 Codex，其历史可以用通用 CLI 演示，后续适配使用同一契约。
- T11 较早提供基础信息恢复，T16 汇合变更、组织和历史后验证最终备份范围；两者各自有完整可演示成果。
- T17 与 T18 分别验收实际发行物，均依赖 Codex 生命周期、后台通知和完整恢复，互不阻塞。

相对旧稿，将 Codex 接入拆成基本会话关联与主子 agent/生命周期两票；将目录标签检索与字段模板拆成两票；移除授权历史对 Codex 专用适配的不必要依赖。未拆出只有框架搭建、数据库建表或研究报告的横向任务。
