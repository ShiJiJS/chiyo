# 开发复盘：减少返工和等待用户

2026-11-08。复盘本聊天关键阶段、已提交开发记录和交付说明，用于调整服务端方案。抽查了 UI 原型、功能接入、实际录入、资料管理及交付阶段的聊天；没有逐字读取全部历史，不对每轮耗时或返工比例作统计。历史陈述与当时源码/安装版本分别看待，不把过去计划当成本轮执行指令。

## 1. 业务规则没有先用具体例子钉住

曾把一份提案理解为可逐条处理，允许部分凭据先入库，另一部分等密码。用户需要的是“一份提案一次保存”。后来需要同时修改保存、预览、CLI 和状态展示，而不是只改按钮。决定和旧行为见 [ADR0020](../../adr/0020-save-whole-import-proposal.md)。

原型阶段还加入用户没有要求的演示申请入口，用户查看后要求删除。资料录入阶段也出现分类、版本、应用与设备配置混放；保留了来源副本，却没有达到用户需要的清晰资料组织。问题在于对实际使用结果理解不准确，测试数量不能弥补。

**调整：** 开发前先固定少量完整场景及预期结果。沿用已经确认的产品规则；发现未定且会改变用户操作的规则时，集中问清楚，不自行补演示入口或新模式。对资料整理的验证看类型、目录、关联、版本和实际用途，不只看文件字节有没有丢。

## 2. 测试环境与正式 App 不一致

[0.4.4 来源清理记录](../../development/macos-source-cleanup-044.md) 明确记录：拆分文件的入口只查询插件，漏了内置文件模板；测试人为提供文件插件，因此未发现正常安装无法使用。实际操作还发现凭据被打开到普通资料编辑器，导致保存失败。

[独立 Agent 试用记录](../../development/skill-guidance-20261107.md) 记录了另一类问题：隔离宿主没有文件交付驱动，提案能保存，但后续文件查询失败。这是测试装配缺口，不能用来证明正式 App 失败，也不能宣称完整录入已验完。

**调整：** 用生产装配和正常入口，只替换测试数据及必要系统依赖；模板目录、文件驱动和加密库应与候选一致。服务抽离第一步就验证一次实际写入、重启、新客户端读取，随功能逐步扩充。人工模拟的系统面板单独标记，不代替原生验收。

## 3. 小改动频繁安装，反复要求系统确认

本聊天多次出现更新后再次钥匙串授权。固定包名和位置并没有解决，因为不同 ad-hoc 构建改变签名识别条件，见[交付记录的升级授权说明](../../development/macos-latest-delivery.md#后续升级的授权提示)。有些票同时包括开发、系统授权、真实资料处理和另一平台验证，一项等待便使整票长时间无法结束。

**调整：** 开发与自动测试都在合成库中进行，使用隔离密钥，不触碰日常安装。自动阶段完成后集中交付一个候选，把真实安装、系统确认、原生面板和迁移安排在 L01；第二平台放 L02。固定签名改进可继续按已有交付事项处理，但不能承诺任意新版本永久免系统确认。

## 4. 按票号全串行，把晚期条件放到了前面

旧阶段曾把视觉检查与后端接通连在很长的顺序上，后来需要调整。上一版服务端草案又把“另一电脑审批”作为目录和模板的前置，并在多个功能票中要求双平台实机。这会让当前电脑上能做的开发也等用户或另一台设备。

**调整：** 只保留真实依赖。目录管理无需先完成跨电脑审批；提案需要目录查询，不需要先验完整拖动排序；文件与凭据在文字提案完成后可分别推进。每票的合成检查独立完成，正式交付另列。跨电脑审批是后续体验与验证，不倒逼第一阶段增加设备限制。

## 5. 过晚连续试用，早期测试只证明局部

[2026-11-02 实际试用](../../development/macos-app-trial-20261102.md) 集中发现预览漏展示实际修改、默认目录不符、标签管理跳错页、前一请求成功提示残留等问题。它们涉及连续操作和正式入口，单独模型测试难以覆盖。

**调整：** 不等所有功能写完才进行第一次完整操作。A02 就从 App 保存再取回；A03 让新 Agent 按正式说明申请；后续每票补一条正常使用流程。A12 再集中连续试用和修正。测试采用合成材料，可以自动走正常用户接口审批，不要求用户每次坐在电脑前。

## 6. 重复检查和大量中间包增加负担

[0.4.3 交付记录](../../development/macos-library-management-043.md) 中部分失败源自旧测试路径/格式假设，并非每次都是新功能故障；它也记录了源码检查不重复跑、交付后清理约 2.7 GB 可重建产物的做法。说明后期已有可复用的改进，不必推翻全部流程。

**调整：** 先核对失败来自产品还是旧测试，既不放宽业务约束迁就测试，也不人为补齐不存在的生产能力。每票跑相关检查；候选阶段跑适当全量与打包检查，无新改动不反复重跑。延用已有隔离打包和进程核对后清理的做法，保留最新候选及必要证据，不累积每次的 App 和 dSYM。

## 这次对完成标准的调整

第一轮完成的是：**当前电脑的 App、CLI 和独立服务能完成既有主要业务；资料确实保存到服务器，并可由全新客户端取回；有一致候选和自动验收结果。**

不把“本票自动通过”“已安装日常版本”“真实资料已迁移”“第二平台已验证”混成一个状态。需要系统密码、用户手工输入法操作或另一电脑的事项单独保留，避免 Agent 为一个外部条件停止所有可做任务；但不能把首轮功能缺陷临时划为后置来凑完成。

后续执行以[修订方案](README.md)及其工单依赖为准。本复盘没有启动开发，也没有操作真实资料。
