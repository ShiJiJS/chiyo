# 服务端 A11：完整备份恢复，并演练旧版资料迁入

已确认的方案编号。阶段：首轮自动开发与合成验收。

## 要实现什么

App 导出服务端完整加密备份，在空服务器恢复；现有单机格式的合成资料也能完整迁入。

## 验收条件

- [ ] 正常 App 导出加密备份及单独恢复材料，恢复到不同密钥的空服务器；沿用手动备份，不加调度产品。
- [ ] 覆盖资料、全部文件版本、凭据、关联、目录、标签、顺序、回收站、模板插件及历史；核对内容与原字节，不只比条数。
- [ ] 用现有单机格式生成合成备份迁入，保留身份和关联；目标已有资料时不静默覆盖或自动合并。
- [ ] 普通重启可延续有效许可；备份恢复和首次迁入重新建立接入身份，历史不变成有效旧授权，待处理状态按实际备份范围显示。
- [ ] 坏备份、错误密钥、中断或磁盘失败不破坏当前库，可重试；以合成资料演练回退。
- [ ] 容器升级、持久数据与运行密钥恢复说明可执行，不把密钥放进镜像或公共配置。
- [ ] 对照正式入口表检查备份、进度和错误反馈；这里只演练，不迁移用户真实资料。


## 本票范围

真实迁移留 [#103](https://github.com/ShiJiJS/chiyo/issues/103)，本票无需用户提供个人恢复密钥。

## 执行约定

本阶段为单用户、局域网、必须联网使用；不开发离线同步、手机或网页管理端。

复用现有 Dart 业务规则和加密存储，先验证当前电脑连接独立服务器；跨电脑审批后置。开发与自动验收使用隔离合成资料、正常产品入口及实际内置能力，不逐票替换日常 App 或访问个人钥匙串。相关检查随开发完成，正式安装和必要人工操作集中安排；实际未验证的平台与系统项目如实记录。
