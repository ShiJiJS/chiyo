# 服务端 A09：服务器批准凭据使用，本机执行 SSH 和命令

已确认的方案编号。阶段：首轮自动开发与合成验收。

## 要实现什么

App 批准后，CLI 在 AI 所在电脑执行 SSH、Token 注入和凭据文件使用，服务端只核对与交付。

## 验收条件

- [ ] 复用现有本机执行程序，以服务器许可接通当前平台已支持的 SSH、Token 注入及凭据文件交付；App 退出仍可工作。
- [ ] 用独立合成 SSH 服务和无外部权限的接收程序验证，命令在客户端工作目录及网络环境运行，不在资料服务器代执行。
- [ ] 材料只进入获准本机执行流程，不返回普通 CLI 响应或日志；成功失败均按原规则清理临时材料。
- [ ] 普通重启保留原聊天有效授权；固定期限和会话内不限时分别验证，不延长、不复活结束/撤销/停用/材料变更后的许可。
- [ ] 断线重试先查原操作结果，不重复启动命令；未知执行结果如实反馈，不猜成功或直接重跑。
- [ ] 区分聊天结束、客户端断线与服务重启；撤销阻止后续使用，不承诺收回已交付内容或外部结果。
- [ ] 逐项记录当前平台使用方式；Mac 原生密码填充继续按已有 #51 单独处理，Windows 原生填充与另一平台执行放 [#104](https://github.com/ShiJiJS/chiyo/issues/104)，不宣称全部迁完。


## 本票范围

改造同一套许可和本机交付流程，不扩展浏览器填充、服务器代执行或新凭据类型。

## 执行约定

本阶段为单用户、局域网、必须联网使用；不开发离线同步、手机或网页管理端。

复用现有 Dart 业务规则和加密存储，先验证当前电脑连接独立服务器；跨电脑审批后置。开发与自动验收使用隔离合成资料、正常产品入口及实际内置能力，不逐票替换日常 App 或访问个人钥匙串。相关检查随开发完成，正式安装和必要人工操作集中安排；实际未验证的平台与系统项目如实记录。
