# 服务端 A03：同一电脑完成 AI 申请、审批和读取

已确认的方案编号。阶段：首轮自动开发与合成验收。

## 要实现什么

AI 用正式 CLI 申请文字资料，用户在同机 App 批准；App 关闭或服务重启后仍可使用原有效许可。

## 验收条件

- [ ] CLI 按配套说明接入，能在读取内容前查询允许公开的资料说明与完整目录；不获得管理 Token 或审批能力。
- [ ] 正常 App 展示待办并批准或拒绝；CLI 仅能读获批字段，撤销、到期、聊天结束后拒绝新访问。
- [ ] App 关闭仍可提交申请，重开可查询有效待办；处理结果可查询，重复提交、重复批准不重复产生授权。
- [ ] 先验证文字授权普通重启后延续：原聊天、设备、范围与期限保持，已结束或撤销的不恢复；备份恢复不同于普通重启。
- [ ] 统一用户审批接口不限制只能由申请电脑处理；跨端提醒和双端实测留给 [#105](https://github.com/ShiJiJS/chiyo/issues/105)。
- [ ] 合成审批由正常用户接口或 App 自动驱动，不增加自动批准产品开关；现有主/子 Agent 授权规则保持。
- [ ] 提前让无开发上下文的独立 Agent 只按正式说明完成查询、申请、等待及获批读取，记录卡点并修正；不给命令答案。


## 本票范围

文件和凭据授权分别随 [#97](https://github.com/ShiJiJS/chiyo/issues/97)、[#99](https://github.com/ShiJiJS/chiyo/issues/99) 验证，本票不宣称全部授权方式已完成。

## 执行约定

本阶段为单用户、局域网、必须联网使用；不开发离线同步、手机或网页管理端。

复用现有 Dart 业务规则和加密存储，先验证当前电脑连接独立服务器；跨电脑审批后置。开发与自动验收使用隔离合成资料、正常产品入口及实际内置能力，不逐票替换日常 App 或访问个人钥匙串。相关检查随开发完成，正式安装和必要人工操作集中安排；实际未验证的平台与系统项目如实记录。
