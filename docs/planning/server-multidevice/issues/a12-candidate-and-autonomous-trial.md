# 服务端 A12：统一打包并自动试用当前电脑的联网版

已确认的方案编号。阶段：首轮自动开发与合成验收。

## 要实现什么

形成匹配的服务端、当前平台 App、CLI 和说明，用合成资料连续试用并修正问题。

## 验收条件

- [ ] 同一源码交付 Docker 镜像或可复现构建、当前平台 App、CLI、本机执行程序及说明；新版只走服务器，未配置时引导连接，不暗中开旧本机库。
- [ ] 连续试用录入、修改、申请、审批、文件、凭据、目录、回收、恢复及重连，集中修正问题；功能级检查随改动做，最终候选再做适当整体检查。
- [ ] 全新客户端配置重新拉取核对，正式装配的模板、文件驱动和入口齐全，不以内存库或额外测试插件替代。
- [ ] 无开发上下文的独立 Agent 只按正式说明和合成来源整理、申请；不给分类、数量、关联、版本或命令答案，核对实际结果并修正。
- [ ] 保留整份提案一次保存、用户手动编辑直接保存、插件展示共用、CLI 不能审批等规则；合成审批可自动调用正常用户接口。
- [ ] 分别列出当前平台已验证项、需系统操作的未测项、第二平台未验证项及明确后置能力，不把测试数当正式安装完成。
- [ ] 开发期间用隔离库、密钥和端口，不替换日常 App；结束测试后清理副本、dSYM、重复包和临时库，仅留最新候选、必要故障证据及恢复材料。
- [ ] 核对全部正式入口，首轮范围缺项必须修好，不通过临时扩大后置范围来完成本票。


## 本票范围

完成仅表示当前电脑首轮开发与自动验收完成，不表示正式切换、第二平台或跨电脑审批已交付。

## 执行约定

本阶段为单用户、局域网、必须联网使用；不开发离线同步、手机或网页管理端。

复用现有 Dart 业务规则和加密存储，先验证当前电脑连接独立服务器；跨电脑审批后置。开发与自动验收使用隔离合成资料、正常产品入口及实际内置能力，不逐票替换日常 App 或访问个人钥匙串。相关检查随开发完成，正式安装和必要人工操作集中安排；实际未验证的平台与系统项目如实记录。
