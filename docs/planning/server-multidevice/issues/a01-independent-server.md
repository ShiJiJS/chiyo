# 服务端 A01：独立服务保存资料，重开后仍能取回

已确认的方案编号。阶段：首轮自动开发与合成验收。

## 要实现什么

独立 Dart/Linux 服务保存一条合成资料，重启容器后从全新客户端进程取回。

## 验收条件

- [ ] 服务在当前开发电脑的 Docker 环境启动；只拆出所需启动和平台依赖，复用现有资料规则及加密存储，不先重写全部核心。
- [ ] 实际受认证接口可写入、读取、修改资料；资料、请求和服务器有稳定身份，丢失响应后重试能查原结果，不重复创建。明确接口版本及错误反馈。
- [ ] 用户管理身份与受限 Agent 身份分开；错误 Token 或 Agent 身份不能管理和审批。局域网连接保护 Token 和正文，并核验服务器身份，不靠跳过证书校验。
- [ ] 真实 Linux SQLCipher 可用，容器重建保留资料及密钥；缺失或错误密钥拒绝开库且不覆盖旧库；镜像与日志不含密钥或正文。
- [ ] 提前验证单条资料的加密备份恢复，以及现有单机格式的最小合成备份导入；新服务恢复值相同，旧访问身份不复活。全部类型和完整恢复界面由 [#101](https://github.com/ShiJiJS/chiyo/issues/101) 完成。
- [ ] 验收使用正式服务装配、内置能力及隔离配置，记录实际 Linux 架构；测试身份不改全局系统信任，结束后清理可重建副本。


## 本票范围

必要的独立服务准备步骤，不增加演示入口，不替换日常 App。

## 执行约定

本阶段为单用户、局域网、必须联网使用；不开发离线同步、手机或网页管理端。

复用现有 Dart 业务规则和加密存储，先验证当前电脑连接独立服务器；跨电脑审批后置。开发与自动验收使用隔离合成资料、正常产品入口及实际内置能力，不逐票替换日常 App 或访问个人钥匙串。相关检查随开发完成，正式安装和必要人工操作集中安排；实际未验证的平台与系统项目如实记录。
