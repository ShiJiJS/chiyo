# 服务端 A06：AI 提交新增和修改，App 一次保存整份提案

已确认的方案编号。阶段：首轮自动开发与合成验收。

## 要实现什么

AI 查看目录和模板后提交文字资料，App 展示新增或修改对比，一次保存整份提案。

## 验收条件

- [ ] 新增、修改均经正式 CLI 提交，使用当前目录和模板；Agent 不绕过提案直接修改。
- [ ] App 展示类型、保存目录、内容和关联；新增复用插件预览，修改展示前后对比。逐条切换阅读，一份提案一次保存。
- [ ] 多条资料与相互引用在同一提案完整保存；任一条缺内容或存储失败，整份不部分入库。
- [ ] App 核对修正后保存；重复确认、超时查询和重连不生成重复资料或版本。
- [ ] 保留原有版本检查与待处理状态，不静默覆盖；用户本人手动编辑仍直接保存。
- [ ] 独立客户端查询结果和关联，预览与实际值一致，不跳转到尚未入库的信息库对象。
- [ ] 目录查询已由前置票提供，不等待 [#94](https://github.com/ShiJiJS/chiyo/issues/94) 的完整移动、排序或人工验收。


## 本票范围

文件和待填密码按 [#97](https://github.com/ShiJiJS/chiyo/issues/97)、[#98](https://github.com/ShiJiJS/chiyo/issues/98) 接续，不伪造材料或忽略必填项。

## 执行约定

本阶段为单用户、局域网、必须联网使用；不开发离线同步、手机或网页管理端。

复用现有 Dart 业务规则和加密存储，先验证当前电脑连接独立服务器；跨电脑审批后置。开发与自动验收使用隔离合成资料、正常产品入口及实际内置能力，不逐票替换日常 App 或访问个人钥匙串。相关检查随开发完成，正式安装和必要人工操作集中安排；实际未验证的平台与系统项目如实记录。
