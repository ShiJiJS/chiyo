# 实现Windows客户端文件字段编辑、审批、历史与恢复界面

父任务#34。前置为#36原型/字段合同和#37附件核心实现子票。将已确认新增HTML状态落到现有Flutter客户端，依据[客户端改动清单](https://github.com/ShiJiJS/agent-info-manage/blob/codex/round05-windows-sync/docs/design/windows-attachment-client-plan.md)，复用Round05风格；不能以核心和CLI已支持为本票完成。

## 范围与验收

- [ ] 新建/编辑信息字段类型增加“文件”；用Windows系统选择器选择原文件、展示私有摘要、更换/移除，保存真实导入；取消或失败保留其他字段草稿，未保存暂存清理；文件控件不复用String value输入框。
- [ ] 信息库保留目录树、中间列表、右侧详情；支持混合/纯文件项、长名称、真实更换/另存/删除、版本/回收；仅改普通字段不丢附件。列表分页不触发全量文件读取。
- [ ] 模板可定义空文件字段，套用时重新选文件，模板不携带文件/路径；文本↔文件的含义变化取得新身份，同用途替换只递增版本，旧授权不因转换扩大。
- [ ] 公开预览、附件独立勾选审批、决定栏和历史消费真实服务；区分普通读取与凭据使用，部分批准/拒绝和版本变化正确，历史不含正文/失效临时路径。
- [ ] 录入提案/整理和其他普通编辑保留已有文件，支持当前许可的删除差异；Agent新文件写入明确不支持，不误报成功；未知类型不降级为空文本覆盖。
- [ ] 设置容量反馈、备份/恢复数量体积预览和错误状态均接真实新格式；系统文件对话框、错误/忙/取消及再次尝试可用，恢复后新授权才可领取。
- [ ] 使用虚构简历完成Windows真实GUI→保存重开→混合部分审批→独立CLI取文件→另存/替换→回收恢复→备份到空库的闭环；验证原字节与授权边界，不接触真实简历/用户库。
- [ ] 按新增原型在1440×900/1280×800和四主题对照，关键弹窗/错误/长名称、键盘/缩放可用；无模拟成功，记录实际Flutter及原生证据，不启动子Agent。

本票含功能自身Windows验收；#30的真实Codex联调和#18最终整包/干净环境仍单独保留。本轮不做PDF/Word内嵌全文预览、OCR、浏览器插件、Mac或服务器同步。
