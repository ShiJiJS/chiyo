# 设计普通文件字段、客户端全流程原型与接口合同

父任务#34。用户要求文件入库必须体现为客户端可用的新信息类型；当前仅structured/textNote和字符串value。本票交付设计与契约，不交付生产业务代码。依据[客户端补充规划](https://github.com/ShiJiJS/agent-info-manage/blob/codex/round05-windows-sync/docs/design/windows-attachment-client-plan.md)及ADR0011。

## 范围与验收

- [x] 沿用Round05四主题、顶部导航和信息库三栏，在新建/编辑字段类型中增加“文件”；一字段一文件，混合信息及仅含文件的信息项均可表达，不另建文件库导航。
- [x] 完成文件选择前后、类型转换、同用途替换、取消/保存失败、长文件名/超限等HTML状态；沿用现有控件/弹窗/过渡，保留其他草稿，未保存选择不成为正式附件。
- [x] 补模板文件字段（不保存实际文件/路径）、信息库列表/详情/公开预览、部分审批决定栏、交付历史、版本/回收及备份恢复预览；明确录入提案/整理保留附件及不支持的Agent文件写入如何反馈。
- [x] 冻结字段判别联合/私有摘要/版本引用、所有者导入替换事务、目录/read边界、交付/释放、错误和桌面投影接口；不把路径/Base64硬塞String value。命名与#33新协议协商一致，旧客户端明确拒绝新能力。
- [x] 列出实际受影响模块：核心字段、模板、提案、历史、回收、序列化、公开目录、存储/备份、CLI、桌面草稿和各消费者；旧文本兼容及未修改附件保留引用有具体合同。
- [x] 固定虚构“求职资料”混合样本，1440×900/1280×800四主题逐状态验证；自检视觉及交互、失败保留草稿，记录原型证据，用户不允许子Agent。未渲染/未实测部分不得计通过。

完成后交给#37核心与#38客户端实施子票；不能因写完说明关闭实现票。普通文件正文可授权Agent阅读，凭据文件保持独立；不增加OCR、Agent附件导入、远程传输或服务器同步。
