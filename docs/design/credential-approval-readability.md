# 凭据申请与使用历史的阅读顺序

用户已确认此方向：先说明用途、实际程序或服务器、所用凭据及允许范围，再按需展开完整命令。覆盖既有程序使用（环境变量、标准输入、临时文件）及 SSH 交互会话。沿用知予现有主题、控件与审批外壳，不改变授权规则。

## 申请

- 用途标为「Agent 说明」。它是申请者的解释，不能当成程序只会进行某种操作的保证；不能从任意脚本猜出可信用途。
- 程序使用先显示可执行程序、运行位置与工作目录。凭据按保存的名称和版本显示，说明交给哪个环境变量、输入位置或文件参数。绝不显示密钥原文或内部领取证明。
- SSH 单独显示服务器、端口、登录账号、登录凭据及其版本，区分登录和提供 sudo 密码；结构化字段来自申请目标，不从说明文字中解析。
- 允许范围常驻可见。程序许可允许调整业务参数和目录，不能把首个命令说成整个授权期唯一允许的命令。SSH 登录许可允许以该账号连续运行命令，不把「检查状态」的用途说成只读限制。sudo 密码另行申请，但已有免密码权限仍由远端账号决定。
- 完整命令、参数和脚本默认收起，展开区域限高并允许滚动和选取文字。完整内容可查看，不靠截断掩盖具体执行内容；不把单个长参数摊成整页正文。
- 保留部分批准、有效期、拒绝及撤销；批准不是执行，知予不因用户点击批准而自动运行命令。

## 历史与结果

- 授权是否有效和每次操作的状态分开显示；单次失败不会被误说成整个许可失效。
- 「刷新状态」只读取原操作，不重放、不再次领取凭据，也不延长授权；就地显示读取中、更新成功、暂无变化或读取失败。不能让没有变化的按钮看起来失灵。
- 普通程序显示是否启动、是否结束、退出码与必要的临时文件状态。退出码 0 表示程序未报告执行错误，不等于业务目标一定达成。
- SSH 按登录、发送命令、发送交互输入、提供 sudo 密码分别命名。已发送不表示命令完成，凭据交给连接程序也不表示登录成功。
- 发送命令与普通输入沿用原登录许可，不说成重新领取了登录密钥。公开历史只保存上下文、摘要及结果，不新增命令正文、输入正文或终端输出的持久保存。
- 对状态未知、部分完成、备份中的历史保留必要解释和原有处理入口，不因精简样式去掉事实或恢复约束。

## 实现与验证

颜色、字体和按钮复用 UiPalette、libraryText、DesktopButton、DesktopSelect；重复的摘要、命令折叠、刷新反馈做成共享展示组件。没有新依赖。桌面布局保留项目导航和审批决定栏，宽度不足时按内容顺序纵向排列。

用虚构资料验证长脚本、命名凭据、SSH 登录与 sudo、刷新未变化和失败、已发送而未确认完成的状态。截图与一次性产物放忽略的 build 目录，不接触真实资料库、不在界面录入真实密钥。正常审批、部分批准、撤销与历史翻页仍使用原有业务入口。

## 标题、概要与命令分开

申请与授权历史采用[结构化申请](structured-approval-requests.md)：title 识别任务，summary 解释用途，实际程序、凭据版本与接收位置单独展示。完整命令、参数及脚本默认折叠。标题和概要由 Agent 填写，批准范围仍由实际请求参数决定。CLI 的 exec、ssh、fill template 提供可直接填写并提交的业务 JSON。
