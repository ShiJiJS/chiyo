# 桌面产品界面设计记录 · 0.2.2

本轮由用户授权 Agent 自主设计、实际迁移整个 Flutter 产品。此前 A「审批收件箱」只是试做，原布局、字体、配色、控件及弹窗约束已解除；此前记录属于历史参考。用户随后明确反馈新版“要好太多了”，本轮沿用当前 LIMS 风格，并按具体反馈修复导航与页面对齐、调整设置入口。此前的重塑评分记录保留为历史，不再对已选方向重新打分。原生窗口与手感由用户打开新版包验收。CLI/hook、核心授权规则、数据库、系统密钥与数据目录均未改变。

## 问题与方向

旧页面和旧视觉规范都有问题：大面积同质白框、较松的列表与粗细不一的默认控件使对象关系不清；移动端表单语法与桌面任务的密度不符。不能只修改单页间距或主色，需要在共享变量、控件和页面骨架上重做。

北极星：每一次提供信息，都让用户看清当前对象、最终范围和决定。

内部以同一份虚构业务事实，分别独立编写、渲染「审阅工作台」「个人档案」「权限台账」三个真实首屏，并在各自原尺寸及 480px 并排检查。选定审阅工作台：对象清单与决定相邻，复杂编辑明确分开公开元数据和需授权内容。个人档案的长文书会拉长决定路径；权限台账会压缩个体申请与长字段名。完整过程与图片只留在本地任务目录 `.scratch/product-reshape-2026-10-16/`，不向用户发送截图集合。

初步采用顶部模块导航，之后用户提供 [GridStore / LIMS](https://ui.oiloil.org/en/works/lims/) 并明确喜欢其样式。实际查看官方完整画面及公开示例，提取稳定的导航/清单/详情关系、灰白表面层次、紧凑记录行与少量蓝色焦点。最终常规桌面使用侧边导航，窄窗口和大字体使用紧凑顶栏。该调整延续审阅工作台的对象与决定关系，不移植实验室图表、虚构数量、账户或已验证身份模型。

其他真实参考：[Bitwarden 桌面](https://bitwarden.com/help/getting-started-desktop/) 的对象列表与字段分组；[Little Snitch](https://www.obdev.at/products/littlesnitch/index.html) 的范围、期限与决定邻近关系。保留本产品名称和绿色叠层标志，未借用参考的图标资产、品牌名称、账户、主密码或自动允许规则。

## 当前共享语言

- 同一 AppSans 字族覆盖中文与西文，随包附带 Noto Sans SC Regular/Medium 与许可证。正文 14、辅助 13、分区 16、页面与对象 20–22，实际字重 400/500；用位置、尺度和分组建立层级。
- 墨灰文字 #26343A、辅助 #61717B、灰白表面 #F7F9FA、细线 #E1E7EB、动作蓝 #285AB0、选中 #EAF0FA。绿色保留品牌/有效状态，红色用于错误/删除语义，琥珀用于待处理。
- 普通按钮高 36px、圆角 6px，常驻输入标签；输入、菜单、焦点、错误、禁用及进度统一主题。公开说明与需授权值在实际编辑界面分区，需授权值使用一致的浅灰输入组。
- 高宽约束与自然换行优先，记录行在窄窗口自动堆叠，复杂表单在窄窗口/大字下转为纵向。长值默认预览并有明确完整展开入口，保存不会截断原值。
- 导航选中即时切换，不在旧菜单与新菜单之间交叉渐变；其余沿用 120ms 控件反馈、150ms 工作区进入、短促的路由/展开过渡；保留减少动态效果支持。离屏静态图不能证明原生动效、窗口或触控板手感通过。

| --- | --- |

| 模板/目录标签/回收站/修改版本 | 统一子页面返回栏、记录与弹窗；模板直接显示字段定义，字段管理动作靠近字段组；目录标签分组；恢复前差异/范围明确。 |
| 启动失败 | 有界阅读宽度，说明保留原资料与系统密钥，提供重试。 |

## 视觉与交互验收

主 Agent 实际查看真实 Flutter headless engine 渲染：1440×900、1280×800、200% 系统字体、空列表、已有内容、24 个长中文字段、多行私有值、无效期限、保存失败、记录存储异常、启动错误；另看修改/删除/恢复范围及复杂模板/批量录入。图片生成成功和测试通过没有当作视觉验收。所有数据为测试夹具；不读取用户真实库、不打开原生窗口、不触发真实文件选择框或安装 hook。

Pro 独立评审三轮：7 → 8 → 8/10，达到三轮上限后停止继续换标准。第一轮指出的保存失败歧义、审批首屏空程、长摘要重复/碎断行已修复；第二轮要求的提案动作距离、模板主体层级和大字操作尺度在第三轮确认落实，未发现本批新问题。保留：编辑弹窗公开目录与需授权字段值的清楚分区；审批页最终字段与有效期围绕决定展开，批准、拒绝及异常语义克制清楚。

尚未达到评审目标 9 分的差距：提案与模板在密度上升时的对象识别、局部字号/字重及组内节奏仍可精修。本轮已尝试收近动作、直接呈现模板字段定义、压缩组内距离及按大字缩放图标；不把静态评审分数等同于用户认可。原生 Windows 窗口、动画/焦点/滚动手感、真实文件对话框、托盘通知与 macOS 运行效果均留待用户验收。

界面测试覆盖原有授权/拒绝/撤销、范围调整、会话结束、公开目录、模板、提案、回收站、版本、历史与真实合成加密备份。新增覆盖：修正值失败保留草稿并按原身份重试；新建有效内容遇存储失败保留输入并成功重试；大字体多聊天切换与完整范围核对只批准当前聊天字段。


## 0.2.1 用户反馈修正

- **用户确认**：沿用当前 LIMS 风格；菜单不能出现双重选中，页面标题与资料库对齐。所有主页面使用共同左边距与标题行高度，移除部分页面独立居中的限宽布局。
- **用户要求**：备份与恢复、完全退出收进独立“设置”。设置保留“通知与应用 / 备份与恢复”两个分区；不再占主导航和侧栏底部。
- **Agent 推断**：将“字段模板”改为“录入模板”，放在设置中，明确只保存空白字段结构、不保存字段值；管理页返回设置。原有创建、使用、修改模板功能保留。
- **用户要求**：移除“开发预览 / 请使用虚构资料”等静态开发提示。保留与当前真实状态相关的存储失败、安全范围和关闭行为说明。
- **Agent 推断**：通知展示当前应用/系统权限状态、开启/检查后的持久反馈及主动测试入口。提交成功只说明系统接受，不声称通知已经显示；拒绝、不可用和提交失败分别可见。测试通知采用固定文本，无资料值。

## 0.3.0 阅读式录入与限定整理

用户要求将批量录入由默认表单改为先读后改，分类交给 Agent 提出默认值；本轮沿用
已确认的 LIMS 字体、颜色和控件语法。正常路径仍为打开提案、确认整批两次操作，
每条手动分类从必做改为只改例外。列表呈现自述提交者、聊天、目的、条数和标题摘要。
每项内容使用只读卡片，编辑另开弹窗；保存编辑只回到预览，确认才入库。已确认提案
仍可查看当前资料详情，入口只读；已删除资料不会从历史提案中重现其旧值。

录入建议的分类和标签与资料在同一事务应用，复用同名分类，减少空分类及重复标签。

复用现有控件悬停/焦点反馈、弹窗路由和长内容展开动效；未新增交叉选中动画。
