# 普通附件完整备份格式8

2026-10-19，#37的实现合同，沿用ADR0011和已有SQLCipher4恢复密钥封装。格式冻结先于正式附件写入启用。格式1–7读取和旧数据库迁移继续保留；新格式不是现有用户包已经可用的能力。

schema20检查点已将本容器接到正式草稿保存及完整库备份/恢复。含附件版本或文件模板输出8，其他库仍输出7。`tables`在格式7全部行之外增加`information_file_fields(field_id,attachment_id,attachment_version)`；每个当前文件字段必须有且仅有一份可用版本引用，文本字段不得带该关系。历史/回收快照使用类型化`content`引用，同样不得悬空。旧SQL文本列对文件仅保留未使用的空槽，类型化模型及备份关系才是内容，不能把空槽返回为文件值。

Owner的恢复预览只持有元数据及私有来源关联，不加载全部BLOB。确认时重新完整认证来源，比较与原预览的完整逻辑文档摘要；不一致返回`backup_changed`。相同来源的全程安装使用这次验证的同一句柄；接收数据库的正文、关系、信息/历史在同一事务内提交，失败保留原设置和未提交草稿。来源路径和恢复密钥仅驻留Owner内存，不进便携文档或Agent响应。

容器保留唯一`backup_snapshot`行，文本JSON为`format: agent-info-manage-current-data`、`version:8`、UTC `createdAt`、`tables`和`attachments`五个成员。`tables`承载当前资料/历史的行和附件关系，不含BLOB、源路径、交付路径或执行能力；行/引用合法性由完整备份的领域验证执行。`attachments`是普通附件版本的私有元数据：不可变引用、原文件名、MIME、原始大小/SHA-256及创建/退役/清理时间。已清理正文的版本保留元数据并显式不可用，不能伪装成空文件。

正文只存于`attachment_chunks(attachment_id,attachment_version,chunk_index,body)`；复合主键，正文BLOB，每块最大1MiB、从0连续排列，末块长度由原始大小决定。可用零字节文件有0块且摘要等于空文件；不可用版本没有块。来源通过有界范围读取，不把多份正文装入快照或Base64。当前保护界限：单版本10MiB、可用正文合计100MiB、最多10000份版本元数据、文本JSON64MiB、容器256MiB；最终连同正式保存/保留版本的峰值内存及磁盘余量实测后冻结。

SQLCipher逐页认证后，验证SQLite完整性、仅允许的两个表、单行文本类型/大小、严格JSON及版本/重复键、附件身份唯一、块总数/编号/类型/长度/归属和每个完整文件的SHA-256。全部附件验证后才给出可读句柄；任一缺块、额外块、拼接/摘要变化、未知对象、超限、错误密钥或截断均失败。逐块解密成功不能替代整容器验证，旧读取器必须拒绝格式8。

容器固定使用DELETE日志模式和本格式的规范DDL，拒绝WAL、生成列、额外约束/触发器或其他SQL对象。附件时间戳使用1970–9999年的规范UTC ISO字符串；空值成员不能被未知成员替代。JSON检查保留重复键、UTF-8字节上限和嵌套深度约束，不为长度检查复制整段UTF-8，也不重复解码已验证的字符串值。

校验句柄持有原只读连接及读事务。恢复通过同一句柄分块读取，不先检查路径再重新打开另一个文件；读取时仍核验长度和完整摘要，任何后续IO错误使接收库事务回滚。正式信息项、文件关系、保留版本及正文在同一接收事务安装，恢复不复活授权或临时材料。仅完成容器校验模块不能宣称资料库关系或原子恢复已完成。

保留策略与正式库共用：当前字段引用的原文件不因创建时间已过30天而清理。脱离当前内容时记录退役时间；退役满30天且修订/回收快照均不再引用后，清理正文并保留显式不可用的版本元数据。恢复旧版本成为当前内容会清除退役状态；已清理正文不因系统时间回拨而重新可用。导出及延后恢复先筛掉到期快照，再执行同一策略；延后恢复不能把备份中的过期正文重新放回保留期。旧中间库缺少退役时间时从首次核对开始保守保留，不伪造历史退役日期。

导出先在目标同卷临时目录写加密容器，完整关闭、重新校验，再以既有不覆盖发布方式生成目标。来源读取失败/变化、校验失败、目标已存在或发布竞争不截断已有目标；清理只处理本次已知加密临时文件。导出调用方须在同一资料库快照中固定文本与版本来源，不能把元数据和后续另一版本正文混用。
