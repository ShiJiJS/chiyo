## 产品任务和对象

用户把简历原文件保存到信息库，以后可单独批准Agent读取或使用该文件。产出物是经批准领取的、与导入字节一致的同机文件副本；客户端要能完成导入、找回、替换、授权、查看交付记录及备份恢复。

“文件”是信息字段的新类型，和“结构化字段”“受控说明”并列；不是新增顶层信息库导航。一个信息项可同时含姓名、邮箱和简历文件；只有一份文件时，可建立仅含一个文件字段的信息项。一个文件字段对应一份当前文件，多份文件使用多个字段，各自授权。SSH私钥等仍放在凭据管理。

采用“顺手”立场：在现有新建/编辑信息的字段类型里增加“文件”，切换后显示文件选择控件及私有摘要；保存后原地显示结果，保留目录树、中间列表和右详情。专用文件库会割裂混合信息项与逐字段授权；自动判断文件是否为凭据不能可靠代替用户选择，因此不采用这两种做法。

主路径：信息库→新建/编辑→添加字段并选“文件”→系统选择器选简历→检查摘要并保存→Agent从公开字段目录发现并申请→用户勾选该附件→Agent领取受管副本。不会让用户先把文件变成路径字符串或粘贴Base64。

文件选择时不提交正式对象；保存才原子提交信息项与附件关系。取消选择保留原草稿；取消编辑清理本表单暂存，保存失败保留暂存供原操作重试，二者都不替换正式文件。更换文件后其他字段草稿、目录与标签不丢失。类型转换涉及含义变化时使用新字段身份，不能自动继承旧授权；替换同一用途文件则保留字段身份并递增版本，已有副本不变。

## 客户端改动清单

| 页面/入口 | 必须具备的行为 | 失败与兼容 |
| --- | --- | --- |
| 新建/编辑信息 | 类型选择增加“文件”；文件控件显示已选文件名、格式、大小、选择/更换/移除；字段名和公开说明独立 | 未选文件、超限、无权限、文件消失/读取失败在字段处报错；保存失败保留草稿；不显示字符串值输入框 |
| 信息库三栏 | 中栏标识含附件/纯文件信息；右侧字段显示名称、私有文件摘要、版本及更换/另存/删除 | 长文件名可完整查看、空状态明确；切换选中和分页不读全量正文；无内置PDF/Word全文预览承诺 |
| 模板 | 模板可声明文件字段，套用后等待用户选文件 | 模板不保存实际文件、附件ID、源路径或上次选择；不同信息项不因此共用文件身份 |
| 公开预览 | 展示用户允许的字段名、说明和文件类型标识 | 不带源路径、正文、摘要哈希及默认私有原文件名；不因“文件类型”暴露本机文件位置 |
| 访问审批 | 文件字段独立勾选，主人可看文件摘要与版本；决定栏明确允许“领取原文件”及普通读取期限 | 附件与文本混合申请可部分批准；不套用凭据注入或15分钟使用期限；处理期间替换/删除要按现有版本校验提示刷新 |
| 授权历史 | 批准范围标识文件；实际交付记录操作、时间、版本及可解释状态 | 不显示文件内容或失效临时路径；撤销停止新领取，不暗示已交付副本可被远端收回 |
| 历史版本/回收站 | 显示附件版本和可恢复状态，恢复与信息字段身份规则一致 | 保留期清理和占用失败可解释；恢复不恢复旧授权；新正文与历史不可错配 |
| 设置/备份恢复 | 容量反馈、备份预览/恢复预览包括附件数量、大小及相关错误 | 不是新建一个附件存储模式；新格式往返和旧格式迁移需有真实字节证据 |
| 录入提案/整理 | 保留原附件及身份，普通文字/元数据修改、删除提案差异能表达文件字段 | 首版不收Agent上传新附件；明确拒绝不支持的文件写入，不能忽略后显示成功；未知字段类型不得降级成空字符串并覆盖已有文件 |

## 字段和接口合同先于实现

先定义带类型的字段载荷、私有附件摘要、版本引用、所有者导入/替换事务、文件交付/释放结果和错误投影，再分别实现服务与客户端。不得只在FieldKind添加枚举就把路径或二进制硬塞String value；正文不能流入公开目录或普通read响应。具体Dart类型和协议字段由设计子票冻结，不在此假称已经实现。

旧库的两类字段和值原样保留；模板、提案、历史、回收、公开投影、快照及备份每一处穷举/序列化都列入兼容清单。旧客户端遇到新类型明确不支持，不回写删掉附件；编辑一条包含附件的信息时，未变附件保留引用，不随普通字段完整快照复制BLOB或意外丢失。

完整例子采用虚构资料“求职资料”：姓名（结构化字段）、求职说明（受控说明）、简历（文件，resume.pdf）。验收先批准姓名和简历、拒绝说明；Agent能领到原文件，不能读说明。用户仅修改姓名后附件仍完整；替换简历产生新版本，历史领取的旧副本不被换掉；备份到空库后文件逐字节一致且授权不复活。
