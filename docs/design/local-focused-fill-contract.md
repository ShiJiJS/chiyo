# 本机焦点填充合同（#35）

2026-10-19，沿用Round05，基线为#33提交3d31604。本文区分目标合同和已实现检查点：HTML、类型化核心、CLI和SQLCipher后已接通真实Windows输入端及安全目标发现，用独立CLI/Win32假密码控件验证。Flutter页、正式bootstrap/打包及内置浏览器兼容仍待；生产客户端继续关闭填充能力。

## 用户任务与设计

用户允许当前Agent使用一个密码登录指定本机应用中的网站，正常流程不把密码原文交给模型。产出是固定凭据版本/应用/方式/期限的使用授权，以及每次输入的独立事实记录；不是密码文本、登录成功证明或浏览器来源证明。

沿用请求收件箱、纸张详情、右侧决定栏、650px确认弹窗和四主题；不新增“密码填充”顶级导航。凭据仍在凭据管理，关联信息不自动授予使用。命令执行与填充共用授权概念，操作结果用不同类型。填充页不显示业务命令、退出码或文件清理。

新增路径沿用既有审批确认习惯：打开请求→核对凭据与应用→批准→确认；Agent再点击密码框并后台调用CLI。正常每次使用不让所有者再次确认。异常只查询原操作，不悄悄提交新ID。

计数口径：所有者点击与Agent动作分开，默认15分钟且凭据勾选时计数；不把阅读/滚动算点击。以下是原型路径，不冒充实际Windows计时。

| 路径 | 所有者点击 | 页面切换 | 所有者决定 | 需记忆/复制 | 失败后 |
| --- | --- | --- | --- | --- | --- |
| 邻近命令注入审批 | 打开请求、批准、确认，3次 | 仍在审批页 | 凭据、方式/目标、期限 | 不复制秘密 | 保存失败保留选择 |
| 理想填充路径/本次原型 | 打开请求、批准、确认，3次 | 仍在审批页 | 凭据、应用、期限 | 不复制秘密或输入目标 | 保存失败保留选择；输入异常不重放 |

Agent在批准后点击密码框一次、后台调用一次；这是新增使用方式必要步骤，不算所有者审批点击。已批准同范围后续操作不重复以上3次所有者点击。确认后原地显示“等待Agent点击密码框”，不在所有者应用提供会抢焦点的“立即填充”。

出场/确认沿用现有180–200ms动效，tips沿用原地展开；按钮按压、焦点和reduced-motion继续使用共用样式。不引入新字体、图标库或浏览器插件。模拟凭据仅在HTML内存，无真实秘密和本机输入。

## 请求、授权与能力

公开v1命令合同不变。v2 `request-use`扩展为互斥的两种使用规格：原`launch`与新`fill`；缺少fill仍按命令规格解析。两种同时提供、未知方式或旧客户端尝试填充均明确拒绝，不用虚构LaunchPlan兼容。

请求形状（已通过核心及独立编译CLI的受控宿主测试；当前生产客户端尚不支持）：

```json
{
  "protocolVersion": 2,
  "command": "request-use",
  "purpose": "登录工作台继续填写项目发布资料",
  "credentials": [{"alias": "portal_password", "credentialId": "portal-password", "version": 1}],
  "fill": {
    "application": {
      "executable": "C:\\Apps\\WorkBrowser\\WorkBrowser.exe",
      "sha256": "8b31313131313131313131313131313131313131313131313131313131313131"
    },
    "targetHint": "https://portal.beichen.example/login"
  }
}
```

第一版fill恰好使用一个字符串凭据；文件拒绝。建议环境变量可留空，密码填充不要求变量名。批准固定凭据身份/版本、应用规范路径/可执行字节摘要、focused_fill方式、同一私密授权会话、15或30分钟截止；不因使用续期。没有普通字段读取的附带许可；如需读其他字段另走现有普通授权，默认8小时。

可提供私密会话内的`focus-target`发现接口，只返回可公开的应用身份与目标就绪状态。此观测不签发授权、不固定之后的焦点，不返回网页标题、字段名/值、DOM、窗口句柄或UIA RuntimeId。请求中的目标网址仅是自述，不做域名自动匹配或网站来源保证。

批准后目标调用`fill-use`只接受requestId/operationId与私密会话证明。服务根据授权捕获当前目标；不接受Agent指定任意HWND或秘密文本。操作ID相同先返回原记录，即使后来撤销也不重发；命令执行的run-use不能消费fill授权，fill-use也不能消费命令授权。所有新接口在端到端可用前保持未宣告。

## 操作与原生输入

1. 统一检查私密会话、请求类型、授权状态和固定凭据版本。按桌面串行；其他操作返回busy，不排队等待未知未来焦点。
2. 原子登记操作意图并持久化审计，失败不读取秘密；冻结本次应用进程PID/创建时间、前台窗口、原生焦点、UIA控件身份和核验时间。公共记录仅投影应用身份/目标类型等安全事实。
3. 核验同会话活动且解锁的交互桌面、非安全桌面、实际前台应用及已批准可执行字节、进程创建身份/提供者归属、UIA密码Edit控件、可写/启用/可见/有键盘焦点、原生与UIA窗口祖先、修饰键全部释放。任何不可核验属性明确拒绝；不降级盲填普通文本框或剪贴板。
4. 秘密只经宿主到原生接收器的私有管道进入内存，不放argv/env、普通stdout/stderr、临时明文脚本/文件或持久化日志。固定二进制身份/私有通道和宿主租约沿用现有原则，不能让不可信请求自行启动一个任意填充程序。
5. 输入前再次核验授权及同一目标，按小批Unicode按键发送；每批前复核。保持原字节代表的文本，不trim/规范化；拒绝NUL、换行、制表及其他控制字符，不解释快捷键/Enter。不自动清空已有值、不自动按登录，也不读取密码框值验证。
6. 取消、撤销、期限/版本变化或宿主失联停止尚未放行的批次；已放行结果保留，不自动重放。全局串行锁和UIA潜在阻塞由受限生命周期的独立进程隔离，超时不阻塞整个授权服务。

SendInput不是向某个HWND原子定向输入；最终复核和Windows接受按键之间仍有竞态。检测到变化就停止余下输入并诚实返回部分/未知，不能宣称原子锁住目标或抵御刻意抢焦点。这与用户选择的不抵御恶意回读的第一版目标一致，但仍要用实际焦点变化测试验证。

## 结果、重复调用和恢复

| 状态 | 已知事实 | 后续 |
| --- | --- | --- |
| checking | 正在核验，尚无终态 | 查询原操作，不新建替代操作 |
| sent | Windows接受了完整输入事件 | 不读回确认，不声称目标完整接收或登录成功 |
| refused | 可以确定未发送任何按键 | 显示原因；修正后可明确提交新操作 |
| partial | 确定只发送部分事件 | 停止自动填充，用户检查/清空目标后才决定重新操作 |
| unknown | 输入放行后结果无法确认 | 只查原操作，不自动换ID重填 |

拒绝原因分开投影desktop_locked、unsupported_target、focus_changed、modifier_active、application_changed、access_denied、audit_unavailable、busy、grant_expired/revoked等；不把所有失败都写成“密码错误”。部分/未知的原记录不可改成未输入。用户确认目标后重新使用的显式恢复入口须在正式实现时留审计，不能由Agent自动确认。

公共填充记录无exitCode、cleanup、秘密、字符长度、按键缓冲或截图。共用操作查询按类型返回结果，不把空退出码当填充成功。命令输出和填充输入事实不能混流。

存储已从schema17/备份6升级为schema18/备份7，填充有独立表与类型化归档，不伪装成command、不丢弃原有命令记录。独立library_format及物理表规则延续#33，迁移以独立标记为准，不被旧程序改写的header触发重复迁移。旧库/备份1–6仍可读，真实schema17/格式6读取器拒绝新格式，冲突迁移回滚。恢复不复活授权、私密会话、PID/句柄或输入能力，进行中/已放行未确认转unknown，已终结输入事实保留。建议绑定在格式7可空，旧格式仍按原约束验证。系统时间回拨不阻止保存实际输入事实。
