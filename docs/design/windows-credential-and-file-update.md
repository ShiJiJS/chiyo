## 2. 授权与每次操作分离

凭据使用授权固定：私密授权会话、一个凭据ID及不可变版本、批准的接收配置/使用方式、固定到期时间。它不再冻结整个授权期内唯一的一条命令，也不再在第一次操作后标记为consumed。不增加“单次/多次”选择：批准后默认可在期限内复用。

初始接收配置沿用已支持的gh Token、非交互SSH文件、AWS文件，并增加本机焦点填充；可用配置受凭据形式及现有接收器校验限制。不同接收配置必须在批准范围内，不能把获准使用gh Token解释为任意程序、任意位置读取秘密。当前工具路径、SSH主机确认、严格参数校验等仍逐次执行；不扩大为通用shell。

保留凭据使用默认15分钟、可选30分钟；普通信息独立读取默认8小时，组合申请的普通字段仍单独显示范围和到期时间。使用不续期、不自动扩范围；换凭据、换版本或增加未批准的使用方式需要新申请，同一范围内的新命令不需要。

### 2.1 每次使用

1. Agent提交获批授权的引用、一个新的操作ID，以及本次启动计划或本机填充操作。
2. 服务逐次检查会话、期限、凭据版本/状态、接收配置及现有平台约束，先持久化不含秘密的操作记录，再交付材料。
3. 命令执行时，每次独立冻结绝对exe、argv、cwd、env及材料映射；同一操作不能在提交后换命令。真实秘密仍只送入执行端。
4. 同一操作ID的重复提交只返回原结果/状态；同ID不同内容报冲突，不重复启动或输入。新命令使用新操作ID。
5. 准备/启动/输入失败只结束本次操作，不消费整个授权。结果未知时先查原操作；若需重做，由Agent明确提交新的操作，不因超时自动创建第二次执行。

这保留“每次操作至多执行一次”的规则，移除“整个授权只准启动一次”的规则。历史按一个授权关联多次操作展示；撤销授权阻止后续操作，单次进程非零退出不能把授权显示为已撤销。

### 2.2 失效与运行中的任务

撤销、到期、会话结束、应用完全退出/服务重启、凭据轮换/停用/删除均阻止新的使用。尚未放行的操作不得在重启后迟到启动；历史恢复不恢复有效授权。

已经开始的命令沿用现有Job/身份核查与清理规则；到期或撤销不默认杀进程。每次文件执行产生独立材料及租约，必须等对应进程组结束后清理。重复使用授权不等于跨执行共享同一路径，也不恢复旧的启动能力。正在发送的本机输入不承诺可撤回；状态未知时不得自动再填一次。

### 2.3 协议与兼容

现有[协议v1](runtime-protocol-v1.md)与一次启动证据保留，不能把旧的一次性证明静默变成多次使用许可。#33先冻结新增协议版本/能力协商以及授权ID、操作ID、逐次计划的schema，再实施；#30同步CLI、私密接续、Skill和随包材料。旧客户端遇到新能力明确不支持，旧授权不迁移为可复用授权。

类型化引用继续使用env里的`{"secret":"alias"}`、argv完整参数或env里的`{"file":"alias"}`。UI的`{{file:alias}}`仍只是显示形式，普通字符串不做全局替换。焦点填充直接引用获准凭据，不把密码作为CLI参数或占位符值返回。

## 3. 普通附件：存储、授权和交付

普通附件是信息内容，Agent获准后可以阅读原文；SSH私钥等凭据文件仍是独立托管凭据，不能通过普通附件接口取得。初版普通附件由用户在桌面导入；Agent提交附件录入提案、通用OCR和任意格式解析不纳入本轮。

### 3.1 信息模型和界面

普通附件作为可单独勾选授权的信息字段类型；一份独立文件可建立一个仅含附件字段的信息项，也可作为服务器/个人资料信息项的附件字段。沿用稳定信息项/字段身份、目录和标签，不另做平铺的文件库导航。

信息库中间列表保留，右侧详情展示文件名称、格式、体积、版本和导入/替换/导出动作。公开目录只提供用户允许的显示名称、说明和附件类型标识；原文、提取文本、导入源路径、本机存储位置不公开。原文件名作为受控交付元数据，文件系统路径不得用其直接拼接。

### 3.2 加密数据库

元数据与原文件二进制内容放在现有SQLCipher中，新增按版本引用的附件BLOB，不将文件转成大段Base64塞入普通字段或全库JSON快照。信息/附件关系与导入、替换必须事务提交；写入失败保留原版本，不出现目录可见而文件缺失的正式对象。

目录、分页和启动恢复只读元数据，正文按需读取。保存原始字节并记录私有长度/摘要用于完整性核验，取出应与导入逐字节一致。导入不自动删除或加密源文件；不对PDF/Word另设一种格式密码，不建立独立外部加密附件目录。

本轮工程默认候选：单文件10MiB、全部保留附件字节100MiB（含历史/回收站）。这是实施采用的容量预算，不是用户提出的固定数值；#34须测量峰值内存与最坏备份体积后冻结最终常量，变更同步该票和本文。超限明确拒绝，不截断，也不让已保存资料陷入无法导出的状态。

### 3.3 Agent读取与文件交付

1. `catalog`发现附件字段，沿用普通信息申请、批准及私密会话鉴权；批准后期限内可重复领取。
2. 通过专用文件交付接口取得可供文档/浏览器工具读取的本机副本及交付身份；不把二进制或Base64正文打印到普通工具响应。
3. 普通附件副本路径可以交给Agent，因为这里本来就授权其读取；与不会作为普通响应返回的凭据临时路径分开处理。
4. 每次交付记录具体版本，文件替换沿用稳定字段读取当前值的规则；已交付副本保持原版本，不在原路径悄悄换内容。新字段或无关文件不得借旧身份扩大授权。
5. 到期、撤销、会话结束或显式释放后停止新交付并回收登记副本；文件占用时显示待清理并安全重试。删除/恢复不复活旧授权。不能收回Agent已经阅读、复制或上传的内容，也不承诺同用户强文件隔离。

本轮只交付同机工具能访问的文件。远程浏览器需要额外传输接入，不把一个本机路径宣称为远端可用文件；上传目标依据用户的实际任务授权，不能把读取附件解释为向任意网站上传的许可。解析由已有文档工具承担，保管原文件不等于软件已支持所有格式预览。

### 3.4 版本、删除与完整备份

附件进入信息项已有的版本/回收站关系，保留期沿用普通资料30天；容量计入保留版本及回收对象。删除或恢复的身份与授权规则不变。只导出元数据而漏掉BLOB不能称为完整备份。

#34负责数据库迁移和新的完整备份格式，复用#31已验证的加密/恢复框架。新增备份版本包含附件元数据、原字节、保留关系与私有摘要，并包含#33/#35不含秘密的历史投影；排除活跃授权、待处理申请、执行/输入能力和交付临时路径。

备份按附件分块处理，不能沿用“所有文件字节先转Base64再jsonEncode整库”的内存路径。保留64MiB文本payload限制，新备份总大小预算候选256MiB；#34须在上述附件容量上限和历史对象组合下验证余量，再冻结格式限制。新读取器兼容现有1–5格式；旧读取器拒绝新版本，不能忽略附件后报告完整恢复。恢复预览显示附件数量、体积及秘密范围，空库恢复生成新本机密钥，不复活任何授权。

## 4. 本机焦点填充

用户的保护目标是正常使用时尽量使密码不进入模型上下文/工具输出，不要求抵御Agent蓄意回读。当前内置浏览器的[假密码实测](https://github.com/ShiJiJS/agent-info-manage/issues/35#issuecomment-6249832356)证明本机可见页面可接收临时CLI的直接Unicode键盘输入；正常快照和显式读取脱敏，但“显示明文”截图泄漏。该结论不推广到所有内置浏览器或所有控件。

### 4.1 流程和目标

先申请并获得允许焦点填充的凭据使用授权，再由Agent点击目标密码框，最后后台调用CLI。CLI只提交凭据引用/授权引用和操作ID；服务在本机校验授权、串行捕获及复核前台窗口/进程创建身份/焦点句柄，执行输入。审批弹窗、终端窗口或通知不得在该阶段抢焦点。

使用Windows直接输入接口，初始以Unicode键盘输入为候选，复用本机应用宿主保管材料。秘密不进入CLI参数、普通stdout/stderr、日志、历史、明文脚本或普通剪贴板；首轮测试工具出现paste事件的结果不能当作无剪贴板验证。

一台交互桌面同时只允许一个填充操作，其他返回busy。目标变化、修饰键按下、桌面锁定/安全桌面、权限不足、授权失效或审计保存失败时中止，不向其他窗口重试。能取得控件身份/密码类型时纳入核验；第一阶段支持清单须通过实际密码控件验证，无法可靠确定目标时明确unsupported_target，不盲填或自动切换剪贴板。

本机目标核验不等于网页来源核验，Agent自述网址只用于判断。后台/无头/远程浏览器不在覆盖范围；可见内置浏览器能否支持取决于真实系统焦点及控件识别，不能只凭工具返回“已点击”认定。

### 4.2 结果、历史及上下文

返回“输入已发送”、拒绝、部分发送/结果未知等真实事实，不读取密码验证、不自动点击登录、不把SendInput成功当登录成功。记录授权、操作、应用身份、时间、输入结果和可安全披露的错误；不记录秘密、输入缓冲、剪贴板内容或截图。成功后的页面结果由Agent继续判断。

申请页明确显示：哪个凭据、允许本机焦点填充、授权期限、Agent自述用途和目标应用；原命令展示区域在此模式变为输入目标说明。tips解释“先批准再点框”“不负责登录提交”“网页来源未独立验证”“明文显示会通过截图泄漏”。历史把进程执行与填充结果分开显示，填充没有虚构的退出码或文件清理状态。

正常流程要求保持密码遮挡，Agent不点显示明文、不读取或打印密码，结果检查优先看登录后的页面。当前浏览器工具的`<redacted>`是工具自身的保护，其他工具需用虚构数据验证；不得保证所有第三方截图/录屏/DOM采集都不带出密码，亦未检查模型服务实际网络载荷或内部遥测。

## 5. 实施与验收边界

| 场景 | 必须观察的结果 |
| --- | --- |
| 授权复用 | 一次批准后运行多条不同合法命令；截止时间不延长；另一会话/版本/未批方式拒绝 |
| 重复调用 | 同操作ID不重复执行；不同操作独立记录；失败不废弃授权，未知不自动重放 |
| 文件多次执行 | 每次独立材料；并发/撤销/宿主死亡不误删其他活动材料；重启不恢复能力 |
| 普通附件 | 原字节一致；批准前不可读、范围外不可读；替换/删除/恢复及副本清理可解释 |
| 完整备份 | 附件原字节及关系往返；兼容旧格式；损坏/错误密钥/中断不改原库；不复活授权 |
| 焦点填充 | 独立CLI真实输入、特殊字符、无粘贴、目标变化拒绝、结果未知不重填；正常工具返回/截图不含假密码 |
| 明文对照 | 显示明文后的截图泄漏必须如实记录，不能因文字脱敏就声称整个链路安全 |
| 最终Windows | 新功能与原型一致；实际通知点击、真实Codex信任/生命周期、干净用户安装及整包升级分项留证 |

核心服务公开接口为主要测试边界，补存储/备份、实际CLI及必要的隔离Windows原生验证。只使用虚构材料，不借此修改用户实际Codex配置或迁移真实资料。开发与验收证据逐票更新，不用旧版351项通过数字证明新增功能完成。
