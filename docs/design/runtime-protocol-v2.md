# 凭据复用协议v2 · #33实施合同

2026-10-19，实施合同，核心操作账本、CLI、schema17/备份6及Flutter复用流程已接通，Windows功能验收已完成，见[完成记录](../development/issue33-completion.md)；v1历史事实保留。Windows生产DesktopBootstrap显式启用v2，新CLI省略版本时的申请/操作默认使用2；AgentServer的底层测试入口仍可不启用，以验证旧服务明确拒绝。以实际capabilities为准，不把旧0.4.0+8预览当成新包。#36已冻结普通附件合同，附件能力在#37实施，不提前宣告附件或焦点填充可用。

## 协商与旧客户端

新增`capabilities`命令返回服务/随包CLI实际共同支持的`protocolVersions`和能力标识。v2复用能力标识为`credential-use-reuse.v1`；`information-attachments.v1`、`local-focused-fill.v1`在对应票通过并接入后才出现。新CLI先协商，未支持时返回`unsupported_capability`，不得偷偷降级为一次性申请或自行生成新的审批。

v2请求包含整数`protocolVersion:2`，字段类型、未知key、重复key、输入字节上限、标识/UTC沿用v1。旧的v1请求/许可保持v1单次语义，不能仅凭公开requestId或改变请求版本把旧许可升级。程序中新请求默认使用v2，旧格式记录和旧请求必须明确标记其原语义；不增加用户“单次/多次”开关。旧客户端请求v2专有能力明确失败。

## 授权范围与逐次计划

`request-use`保留凭据数组（首版一个凭据）、用途、首条launch和可选readFields，增加v2封套。批准绑定私密会话、凭据ID及固定版本/使用代际、批准的接收配置和固定截止；首条launch作为用途参考，不能被解释为此授权唯一允许的命令。首版接收配置仍为gh_token、ssh_identity、aws_shared_credentials，并按凭据形式和既有接收器约束验证；未批准配置不能借新命令进入。

```json
{"protocolVersion":2,"command":"run-use","requestId":"opaque-request","operationId":"operation-1","launch":{"receiver":"gh_token","executable":"C:\\Program Files\\GitHub CLI\\gh.exe","argv":["repo","view","northstar/agent-skills"],"cwd":"C:\\Work\\northstar","env":{"GH_TOKEN":{"secret":"github_token"}}}}
```

每次run-use都由Agent显式提供operationId和本次完整launch，凭据alias由获准申请固定。每次检查真实接收程序、类型化引用、argv/env/cwd及已有SSH主机规则，不开放通用shell。exe身份在该次计划中捕获并在真正启动前重新核验。第一条命令也要提交自己的操作ID，批准不自动执行。

操作去重键为`(私密会话,operationId)`，另绑定requestId与规范化原输入指纹；一个会话内不能将同ID改绑另一授权。指纹覆盖完整调用launch（字典键排序、数组顺序保留）与requestId，不能只比较最终exe或命令字符串；服务附加材料及exe身份另形成有效planHash，均不可变。响应丢失重试相同ID只返回原事实，不提供第二份启动材料。同ID改变任意输入为`operation_conflict`；新操作用新ID。

`operation-status`使用与`run-use`相同的v2请求字段（仅command改名），按同一指纹查询：未登记返回`not_found`，已登记只返回公开事实，不领取材料、不启动。可在未拿到executionId时查询原操作；即使宿主16个槽位已满，查询也不占新槽。重复run-use首先查询，真正领取时仍在核心原子去重，不能靠前置查询代替事务。会话证明失效时查询不能恢复许可。

服务原子持久化操作/有效计划之后才交付秘密。第一次私密领取返回执行记录及一次启动材料；重复领取返回原记录和`newlyClaimed:false`，不再次返回材料或重新启动。未能确认首次领取是否启动时查询原executionId；超时不是新执行许可。新run-use响应包含`protocolVersion:2, requestId, operationId, executionId, executionState, grantState, duplicate`，没有外部秘密、能力证明或材料路径。

私密领取响应还须匹配调用方的requestId、operationId与原输入指纹，并核对记录计划和材料计划一致；格式损坏、重复JSON成员或身份错配均按领取结果未知处理，不自动启动或改ID。持续宿主处理run-use后若抛出异常，也只能返回`execution_unknown,operationClaimed:true,retryable:false`，不能标成未占用的新执行许可。v2错误的`operationClaimed`仅指这次操作，不能解释为整个授权已消费；v1的attemptConsumed保持旧语义。

单次操作的准备失败、启动失败、非零退出不使整个授权consumed；同ID仍不能重做。修正后使用新的ID，在有效授权内不再审批。结果未知不能自动换ID重放；CLI只报告事实，由Agent核查后明确决定是否提交新的操作。

授权默认15分钟、可选30分钟，使用不续期。普通字段独立默认8小时（可按普通读取选项缩短）；组合申请批准/撤销/期限分别记录，不把普通字段误绑到凭据15分钟。轮换、停用、删除、撤销、到期、会话结束和服务重启阻止新操作；历史恢复不恢复许可。重试查询不能绕失效重新交付材料。

## 执行、清理与历史

每个操作有独立executionId、冻结计划、材料租约、worker/Job及身份事实。旧v1的request.executionId仅代表单次执行；v2的执行集合必须按requestId查询，不能以“最后一条执行”替代全部事实。历史先展示授权固定范围及期限，再列各次操作、命令、状态和清理；填充稍后会有独立结果类型。

新登记的v2操作保存不可变UTC createdAt（操作登记时间），随公开事实、数据库及格式6归档往返；后续报告和重复查询不得改写。早期内部v2检查点可能没有此字段，仍可读入，界面明确显示“时间未记录”，不以申请的最后attemptedAt替代每次操作时间。保留检查纳入createdAt。客户端将v2凭据使用与连接字段列为独立历史记录，分别显示固定截止；操作列表每页五条，按操作身份保留选择，执行详情只展示该操作冻结计划。

撤销不默认终止已运行命令；一个操作结束只清理其自己的材料。相同授权下同时运行的任务互不误删；宿主崩溃/恢复保留现有Job事实和unknown，不重放。审计保留/备份选择必须检查该授权下全部执行：任一仍运行、结果无法确立或清理未完成均阻止整体删除，不能只看最后一条。输出继续有界、只在持有授权的本机执行宿主内保管并脱敏，不写入执行历史/备份。

v2在输出进入保留缓冲和Base64响应前，按stdout/stderr独立进行流式字节匹配，遮挡已知材料的直接回显，跨块亦匹配。范围为完整字符串/完整文件字节、AWS静态配置中的已知键值，以及不超过128行的PEM文件完整正文行；任意二进制文件只有完整原字节匹配，不声称识别所有格式内部秘密。输入与保留输出均有4MiB总量上限，超过后仍排空管道；未完成的匹配前缀只在确知不匹配或管道结束时释放。v1保留原有输出行为，不能把旧证据当成v2脱敏通过。

该措施用于减少直接意外回显，不防编码、拆分后重排、截图、外部文件或接收程序主动外传；授权接收程序仍会接触原文。运行结果默认以退出状态和非秘密结果判断，不以输出可查推断执行环境强隔离。

## 持久化兼容与测试门槛

请求持久化显式保存protocolVersion，旧缺失值解作1；执行记录为v2时保存operationId、输入指纹、有效计划及协议版本。旧单次attemptConsumed信息保留，v2不得借该位推导整个授权已用完。JSON虽可扩字段，旧程序会误读其含义，因此数据库从schema16升级17、新完整备份从5升级6；旧读取器须明确拒绝新库/新格式，而非丢字段后报告恢复成功。

实际旧schema16读取器会经Drift把更高user_version重写为16再加载，单纯版本号不能提供拒绝。schema17因此在一笔事务中将物理表改为credential_runtime_requests/credential_operations，外键随重命名保留；旧读取器缺少原表而失败，不能加载或重写运行时事实。独立library_format标记在交给Drift之前检查，新结构缺失标记或未知未来格式拒绝；已知17结构被旧程序改写头部后，新程序可以安全恢复版本头。标记已等于目标格式时跳过旧DDL，只由Drift修复版本头，不重复已完成的迁移；真实旧结构没有新标记，仍正常执行升级。旧读取器失败可能已经改了版本头，不宣称数据库文件逐字节未变；已验证领域记录及标记保留。新迁移也显式拒绝from大于to。

本机完整存储保留每次操作的Job、材料租约与进程身份；可移植归档仅保留公开执行事实、操作ID/输入指纹及完整冻结计划，不保存私密能力或临时材料路径。恢复逐操作将preparing/running改为unknown，已结束结果各自保留，所有许可失效、清理为not_needed，不在另一设备套用原租约。保留期限对该授权全部操作检查，任一未结束/未知未核实/未完成清理均不能因最后一条较早而丢弃。

新读取器兼容旧备份1–5，并将v2完整历史投影写入6，恢复时许可/私密会话/执行能力全部失效。便携table keys保持原有credential_use_requests/credential_executions，由存储层映射到新物理表，避免把物理改名误作旧备份不兼容。#37附件须兼容1–6并继续保留全部操作；进一步升级schema时同时更新library_format，先接受已支持的旧标记、在迁移事务完成后递增。不得为了避免格式升级而把新操作历史丢出“完整备份”。

完成需真实核心公开接口、CLI、存储重开/迁移/备份、Windows多次启动/独立材料与桌面状态证据。用v2独立操作测试两条不同命令、同ID并发/响应丢失、失败后继续、跨会话/未批配置/失效、审计失败及恢复不复活；v1旧证据不计作v2通过。合同和原型本身不构成完成证明；#33的Windows完成证据见[逐项验收记录](../development/issue33-completion.md)，真实Codex/通知/新整包和干净环境仍由后续工单跟踪。


## #89：SSH会话内不限时（2026-11-07）

新服务增加 `credential-ssh-session-validity.v1` 能力。申请仍由AI发起，期限由用户在App审批时选择；仅v2命令方式的 `ssh_identity` 可选不限时。Owner决定中 `lifetime: null` 表示本聊天内不限时，其他接收方式、焦点填充和v1不接受；普通字段保留独立时长。旧记录没有新标志时始终解释为原限时记录，不因缺少截止推断不限时。

已批准SSH的 `use-status` 在 `decision.credentialUse` 中返回 `validity: "session"`、`expiresAt: null` 和非私密的 `sessionId`。有效状态仍由 `state` 给出，不能仅凭空截止判断可用。持久请求显式保存 `credentialValidity: "session"`；只有符合SSH方式、原v2语义且已经批准的记录可使用此值。未批准、未知值、同时带固定截止或其他接收器都拒绝，不把它解释成任意永久授权。

等待审批的 `requestExpiresAt` 仍独立生效；原会话、凭据版本／使用代次、接收方式、主机信任和逐次操作编号继续检查。到期后的旧限时记录不会变成不限时。手动撤销、真实聊天结束、凭据停用／更换和App重启阻止新的使用；历史查询不会恢复使用能力。每条本机命令及已建立的SSH连接有各自运行生命周期，撤销不自动终止，已完成的远端操作不会回滚；CLI等待结束或响应丢失也不能据此重复执行。

保存新事实才要求资料库52；完整备份中有此历史使用格式22，仍兼容1—21。备份恢复与重开保留“不限时”的历史含义，但所有原许可失效。新字段不能放进低格式备份或低标记库后被忽略。App审批、凭据使用历史及授权历史均显示“不限时（限本聊天）”，并保留真实有效／撤销等状态。
