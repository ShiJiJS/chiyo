占位符属于启动计划

{{file:ssh_key}} 是界面上的文件引用写法。结构化参数用 {"file":"ssh_key"} 表达，由 CLI 在启动前解析为完整路径参数；不交给 shell 做字符串替换。Token 原文不拼到命令中。环境变量必须是目标工具认识的名字；没有命令占位符也可以注入。

Agent 提交凭据引用与启动计划 → 用户审批 → Agent 调用 CLI 执行已批准的请求 → CLI 校验、准备凭据并启动子进程 → 记录结果并清理临时文件。

批准不自动启动。凭据版本、程序、参数、工作目录和注入位置改变需重新申请。原型展示的 request-use / run-use 是拟议接口，尚未实现。

验证与边界

  • 三种注入示例、申请明细和问号提示已截图检查；1440×900 与 1280×800 无控制台错误、横向溢出或图片加载失败。
  • 实际点击走查申请明细、结构化内容、问号提示、批准确认和授权历史。记录保持 0 / 1 次及等待 CLI 启动，未误报已执行。
  • 一次独立视觉评审，无必须修改项；已采纳精简文件注入说明的建议。较小窗口收紧局部间距，保持完整命令可见。
  • 沿用轻量进入与展开反馈和减少动态效果设置。动效证据以关键帧为准；本机缺少 ffmpeg，未完成视频验收。
  • 命令长行的静态提示保留：命令是需要完整核对的内容，实际截图没有截断或横向溢出。
  • 全部虚构数据，刷新重置；不读取秘密文件，不执行命令，不保存真实凭据。目标程序可接触原文，运行时注入不构成强隔离。

后续实现应以扩展设计为依据，先验证结构化启动和进程生命周期，再连接真实凭据。本轮只交付界面及方案。
