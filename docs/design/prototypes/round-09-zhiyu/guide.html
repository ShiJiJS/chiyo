几种组织方式同时保留，各自解决一个问题

概念作用例子
目录决定资料归放在哪，一个资料对应一个位置；可有父子层级。自托管服务、个人资料 / 求职材料

目录决定当前范围。类型和标签各有一个直接点选的菜单，可以单独使用，也可以一起使用；关键词搜索名称、用途和标签，多个词按同时匹配查找。不再提供字段条件、逻辑组合或保存视图。模板新增字段也不会增加筛选负担。

推荐体验路线

服务器插件的专属设置

信息库 → Azure 日本服务器 → 主机身份 → 管理全部主机信任。进入服务器插件的“插件设置”页。应用与服务等没有配置项的插件不显示这个页签。插件停用后仍可查看和撤销已有信任；安装或启用插件不会自动信任主机。

快速找到资料

信息库 → 全部资料 → 类型选择服务器 → 标签选择生产环境 → 输入日本。选择即生效，不需要填写条件表单。分组与排序是列表上方的两个小按钮。

审批后查看使用记录

访问审批 → 查看项目仓库 → 查看 GH_TOKEN 注入位置与 CLI 命令 → 批准 → 授权历史 → 撤销。另有 SSH 文件、普通简历文件、焦点填充与分类整理的不同审批内容。

核对 Agent 的录入与变更

录入提案 → 编辑名称并确认新增 → 查看入库资料。修改提案有前后差异；分类整理结果标明已依据先前授权自动应用，避免重复确认。

管理低频功能

设置 → 外观 / 通知 / 请求与记录 / 插件 / 目录与标签 / 备份与恢复 / 应用运行 / Agent 接入。

外观、通知、期限设置对应分区。明亮 / 黑暗主题、开关、等待时间、保留期限可保存；测试通知只预览外观和入口。
录入模板设置 → 插件。保留上一轮安装、启停、更新、移除、通用回退。普通使用只选模板，不要求手工定义模板。
备份与恢复、恢复密钥设置 → 备份与恢复。范围、文件选择、密钥输入、确认流程布局；不执行加密、导出或恢复。
临时材料、附件清理、后台与退出设置 → 应用运行。状态与检查入口、退出确认布局；不影响真实服务或电脑进程。
SSH 主机信任设置 → 插件 → 服务器信息 → 插件设置；服务器详情另有单台入口。逐主机指纹核对、确认与撤销、导入流程入口；未取得指纹时不能确认。信任状态按地址和端口保存，不修改真实 known_hosts。
Agent 接入与 Skill 说明设置 → Agent 接入。状态展示、接入步骤、模板/目录/标签约定；不修改 Skill 或宿主配置。

本轮取舍与后续验证

保留五个一级导航；插件从顶部和信息库左下角移除，仅在设置及相关对象操作中出现。类型和标签是直接选择的菜单；分组、排序各自独立。主题使用浅灰与深灰层次，保留克制的紫色强调和资料类型识别色。目录、列表、详情独立滚动，弹窗只滚正文。

插件设置面板由知予提供，当前只有服务器插件挂接内置 SSH 能力；插件包没有任意代码执行能力。导入主机文件仅演示操作流程。
本轮核对了现有桌面源码中的设置、提案、历史、资料与凭据管理入口。仍是设计评审原型，不宣称等同正式客户端的全部异常处理。下一轮可继续细化目录重组、批量录入、文件版本和真实备份的长流程；服务器同步未纳入。

验证：1440 × 900 与 1280 × 800；关键词/类型/标签、明暗主题、入库与变更、回收、审批与撤销、插件接入、设置持久化、存储失败保留输入。由主 Agent 自检，遵循用户要求未使用子 Agent，未独立评审。
