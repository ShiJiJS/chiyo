更新：2026-11-10。

状态：问题分析与需求对齐。本文不表示功能已修改，也不授权按建议直接开发。

## 本轮范围与依据

- 已拉取主分支 `4d3ee072`。相对当前安装版本，最近提交仅修改测试和开发文档，界面代码一致。

## 整体判断

资料管理、AI 申请、用户审批、授权记录、模板与备份都有实际用途。主要问题是技术说明太多、入口与下一步不清楚，以及列表、详情、表单的空间分配不合理。

评审建议保留现有品牌、紫色与目录—列表—详情结构；先整理任务流程、文案和共用组件，不默认重做全部视觉。此为评审建议，并非用户已经选择的新设计规范。

## 用户补充与确认

### U01 移除设置里的旧版模板

- 用户明确：这个功能入口没有用，应移除，不只是空时隐藏。
- 从设置导航中移除“旧版模板”，不再让用户选择旧版模板作为日常操作。
- 这不等于授权删除已有资料或破坏旧资料读取。底层兼容代码是否仍有实际使用，实施前另外核实；不能把“移除入口”直接解释成“删除旧数据”。
- 本条替代上一轮“没有旧模板时隐藏入口”的较弱建议。

### U02 移除设置里的 Agent 接入及专属无用逻辑（已确认）

- 用户反馈：完全看不懂这个页面做什么，也看不出存在意义。
- 当前功能：检查资料服务、配套 CLI、Skill 等状态；选择聊天查看关联、待处理申请与有效授权；提供接入流程和录入约定说明。它本身不是一键完成安装或接入的操作。
- 问题：页面面向工具配置和故障排查，却作为普通设置常驻；大量 hooks、关联、CLI 等术语，状态异常后缺少清楚的下一步。
- 用户在解释后明确确认移除。不是只隐藏入口：删除该页面及仅服务于它、已无实际用途的状态检查、控制器、说明、专属数据接口和测试；逐项核实调用关系后清理，不能留下孤立实现让后续 Agent 再接回界面。
- 审批和授权历史仍需要的来源、聊天、授权数据，以及 CLI 实际连接、会话授权校验能力保留。不以删除页面为由删除共用业务能力。
- 不再为每家 Agent 建独立接入管理页；有用的来源信息归入审批和历史。

### U03 未分类支持清理，空时隐藏

- 用户已确认：右键删除是删除“未分类”中的资料，不是删除一个真实目录。
- “未分类”属于没有目录的资料集合，不作为真实目录删除。
- 有内容时显示入口，提供右键批量移到回收站的操作；操作前展示实际涉及资料范围。
- 没有内容时隐藏入口；之后出现未分类资料时重新显示。
- 不影响添加资料时暂不指定目录的能力。

### U04 资料目录与标签标题的视觉层级不合理

- 用户反馈：左侧“资料目录”“标签”标题难看，字号居然比下面条目小。
- 改动方向：让分组标题在字号、字重、颜色和间距上清楚统领下面的条目；两个标题使用同一套样式。
- 不通过单纯缩小目录条目来解决。具体字号和间距待设计时按实际画面确定。

### U05 目录 hover 区域与展开箭头不对齐

- 用户反馈：悬停背景位置奇怪，展开箭头落在背景外面。
- 改动方向：图标、名称、数量、展开箭头使用同一行布局；悬停、选中、键盘焦点与点击区域对齐。子目录缩进不能把箭头挤出背景。
- 该项目前是用户实际反馈，尚未在本轮单独重现 hover 动态；实施前按当前窗口尺寸核对。

### U06 录入提案需要有意义的标题

- 用户明确：“x 项新增资料”不能当主要标题，应由提交提案的 Agent 给出概括主题，例如“NAS 相关应用信息新增”。
- 提案列表和详情主标题显示这个主题；“新增 7 条／修改 2 条”等数量与动作作为辅助信息。
- 标题描述整份提案，不把同一提案拆成逐条保存。
- 涉及 Agent 提交说明、CLI／服务端提案数据和 App 展示，不能只在 App 拼接名称。
- 实施建议：旧提案缺少标题时使用诚实的回退显示；标题不填写密码、Token 等凭据内容。是否允许用户改标题不在本轮新增范围中。

### U07 移除右上角 AI 接入及手动生成流程（已确认）

- 用户反馈：看不懂，且没有提出过增加这个入口的需求。
- 当前功能：给这台电脑的 AI 工具生成独立的服务器连接配置，以便 CLI 提交申请；它不会自动安装 Skill，也不直接授予资料读取或凭据使用许可。
- 与 U02 的区别：这里创建连接配置，设置页主要检查状态和给出说明。当前两者名字相近、步骤断开，用户不知道是否都要操作。
- 用户在解释后明确确认移除。清理按钮、弹窗和仅为这个手动流程存在的逻辑、文案及测试，不以另一个名字保留同样的日常入口。
- CLI 必需的设备连接配置改为首次可信配置时准备，已有有效配置复用；自动化触发点与失败处理在实施前明确。共用的设备注册、连接配置存储和凭证校验不能未经检查一起删掉。
- 清理后检查死代码、仅测试引用和旧说明，更新相关使用文档，防止后续 Agent 根据遗留描述恢复入口。

### U08 连接与断线页面需要统一设计及返回路径

- 用户明确：连接服务器、断开后重连等非正常界面的样式难看；查看服务器信息后没有返回按钮。
- 已复现：点击右上连接设置图标会立即离开信息库，展示连接页；没有取消／返回，Escape 也不能回到原页。源码确认进入设置即释放原连接和工作区。
- 改动方向：打开连接设置时保留当前连接和页面；提供取消／返回；只有用户确认切换且连接成功后才替换。
- 首次连接、连接中、断线、重试、证书或地址错误沿用 App 的字体、按钮、间距和品牌样式。错误给出具体可执行的下一步。
- 遵循之前确认：正常等待显示加载动画，不增加“服务器响应较慢”提示。并非所有慢请求都应显示全屏断线。

### U09 授权历史与其他页面不统一

- 用户反馈：背景、标题位置等明显不同。
- 改动方向：统一主页面背景、标题起点、顶部间距、筛选区域和详情容器样式，复用共用组件。
- 上轮同时发现：历史列表占据过宽空间，详情过窄，应重新分配宽度，考虑可调整分栏。
- 用户再次强调：右侧记录详情才是重点，当前左右主次颠倒；顶部搜索和筛选又占掉大量纵向空间。
- 方案建议：左侧紧凑历史列表，右侧详情占主要宽度；搜索与常用筛选收成紧凑工具栏，次要条件放展开筛选。详情优先显示申请用途、来源、批准范围及实际使用结果，不让控件占据内容首屏。

### U10 右键菜单仍有白边与样式问题

- 用户反馈指目录右键菜单（“邮件”按上下文理解为“右键”）：外围多一圈白边，部分菜单样式难看。
- 改动方向：统一菜单背景、外围留白、圆角、阴影、菜单项高度及 hover；排查菜单容器与菜单项各自绘制背景导致的多层边缘。
- 对资料、目录及其他同类右键菜单一起检查，修共用组件，不只给某个菜单覆盖样式。
- 用户报告的是视觉问题，白边的具体实现原因尚未确认。

### U11 Mac 菜单栏状态与快速审批

- 用户已确认：指 **Mac 屏幕顶部、时钟旁边的系统菜单栏**，不是 App 窗口内右上角。
- 需要菜单栏图标及配套弹出界面，能查看待审批事项、打开详情、直接批准或拒绝，减少切回主窗口的次数。
- 现有 Mac 实现有基础菜单栏入口，但主要是打开窗口和退出，不等于已提供所需状态面板与快速审批。
- Windows 暂不做这个界面；实现采用平台区分，保留 Windows 现有流程，不让 Mac 专属实现造成 Windows 构建或运行问题。
- 方案建议（尚非完整规格）：显示连接状态和待处理数量；快速审批仍需展示谁申请、用途、资料范围及期限，复用现有审批规则，不增加一键全部批准。
- 密码未填齐、内容较多的提案等不能因快速入口跳过必要审阅；详细面板范围需在设计时与主窗口审批共用逻辑一起明确。

### U12 目录位置直接展示，减少单独打开目录树的操作

- 用户反馈：审批区域的“查看目录层级”按钮令人困惑，希望有更自然的方式了解目录位置。
- 代码定位到提案目录组件的“查看完整目录树／查看目录树 / 更换位置”和通用目录选择组件的“浏览完整目录树”。不能把访问审批与录入提案的业务目的混为一谈；具体页面实施时按入口核对。
- 方案建议：资料旁直接显示完整目录路径；点击路径或展开箭头，在当前区域展开目录树并高亮所在位置，保留上下级上下文，不另跳页面。
- 录入提案明确标“将保存到”，允许更换位置；访问审批只表示资料所在位置，不让用户误以为是在批准整个目录。
- 整理申请若有移动目录，则直接展示原位置与目标位置。详细目录树用于按需核对，不作为理解当前位置的必经步骤。
- 以上为交互建议，尚未制作或确认具体设计稿。

### U13 “未提供 Agent 名称”不是都因为 Agent 没填

- 用户反馈：授权历史里几乎都是“未提供 Agent 名称”，无法识别来源。
- 本轮源码确认：普通资料审批与授权历史，以及凭据使用的来源投影，多处直接写死 `agentClaim: '未提供 Agent 名称'`，并不是先读到名称再判断为空。整理申请部分则确实根据 `agentName` 是否为空回退。
- 证据：`packages/info_workspace/lib/owner_workspace_approvals.dart` 的 `summaryOf`、`owner_workspace_grant_history.dart` 的 `_summary`、`owner_credential_use_projection.dart` 的 `request`。
- 修改需贯通 CLI 提交、服务端保存、历史记录与 App 展示，支持通用 Agent 名称、任务用途和外部聊天标识；不只改占位文字，也不直接替所有旧记录填上 Codex。
- 旧记录无法确认名称时保留事实，优先展示已有聊天说明、用途及时间，避免一屏重复未知名称。显示信息仍是自述，不代替实际授权凭证校验。

### U14 历史资料入口要说明时间与动作，按钮要可识别

- 用户截图：关联资料下并排显示“查看当前资料”和“查看当时资料v4”，看不懂“当时”是什么时间，两处按钮又像普通正文。
- 本轮核实：前者打开信息库中的现有资料；后者读取这项授权记录在批准时关联的资料版本，不等于 AI 某次实际读到的内容。
- 方案建议：历史详情直接展示批准范围，必要时原地展开审批时的内容。去信息库的独立动作写“在信息库中打开”；历史内容写“展开审批时的内容”，附审批日期。版本编号作为次要信息，不嵌进含糊的按钮名。
- 若要比较审批时与目前内容，提供明确的“对比后来修改”，复用版本对比组件；不要求用户分别打开两份资料自己记忆比对。
- 按钮使用可识别的边框／背景、图标、hover 和焦点样式；普通静态文字不采用相同外观。展开按钮与跨页跳转也需区分。
- 展示历史内容复用模板组件；历史缺失时明确说明，不用最新内容冒充历史，也不标成“AI 已读取内容”。

### AI 申请与资料变更

| 功能 | 判断 | 问题与建议 |
| --- | --- | --- |
| 访问审批 | 核心功能 | 无待办时写“暂无待处理申请”，不要显示像筛选失败的“没有匹配的请求”。 |
| 申请来源与用途 | 优先改 | 多条申请同名且都写“未提供 Agent 名称”；以用途、资料、设备及聊天标识帮助识别。名称仍是自述，不能当身份保证。 |
| 批准范围与期限 | 保留 | 说明当前申请实际允许什么；字段内容、普通附件和凭据的版本规则分别解释。 |
| 已批准请求展示 | 调整 | 已处理范围使用清楚的静态结果，避免像仍能勾选修改。 |
| 授权使用说明 | 重写 | 实际观察到固定范围、最新内容、附件快照等泛化说明混杂；按当前申请类型显示。不能据文案直接断言后端授权错误。 |
| 录入提案 | 核心功能 | 含新增、修改、删除和整理，上一轮建议考虑“资料变更”命名；用户尚未确认改名。先落实有意义的提案标题。 |
| 提案预览与修改对比 | 保留 | 已处理提案显示类型和完整目录是正确方向；待处理密码输入和对比缺现场样本，未算实测通过。 |
| 批量提案处理 | 降低干扰 | 无待处理内容时不突出空批次；批量处理单位仍为整份提案，不部分入库。 |
| 授权历史与实际使用 | 保留 | “已批准不代表已经读取”的区分有用；突出操作结果，统一视觉和加宽详情。 |

## 文案与组件共用原则（评审建议）

### 追加对齐：AI 接入不是面向每家 Agent 的管理产品

- 用户明确不希望为每家 Agent 做专门适配；希望通过通用 Skill 和 CLI 使用，来源与聊天信息在审批及授权历史里查看。
- 右上角实际生成的是给本机 CLI 使用的私有连接文件，包含服务器地址、设备接入 Token、服务器身份与证书信息；不是给 Codex 本身生成账号，也不是某份资料已经批准的读取凭证。
- 设备接入配置允许 CLI 连接服务器、查可发现的目录并发起申请；实际资料读取和凭据使用仍需要对应审批许可。
- 评审建议：这类配置并入可信的首次安装／连接设置过程，已有有效配置直接复用，不要求日常手动点“生成”。不能改为让任意未配置的 CLI 自行领取管理权限或免审批读资料。
- 设置里的 Agent 接入是状态检查、会话列表和技术说明页面，不是区分会话所必需的界面。可以移除该页面，把有用的来源与会话信息放在审批和历史；异常诊断按需提供，而不另做每家 Agent 的控制台。
- Agent 名称、任务用途、外部聊天标识可以由 Agent／调用工具提供，属于来源说明。实际承接批准许可的会话凭证仍由软件生成和核验；不能仅凭自报名称或复制聊天 ID 继承别的聊天授权。
- 当前状态：用户已确认移除两个入口，并要求清理专属无用逻辑，不只删按钮。独立原型已去掉入口，正式版本的专属逻辑清理及配置自动化尚未实施；准确触发位置待后续方案确定。

- 对用户说资料、密码、凭据、文件；避免把“材料、注入、固定成员、原操作核对”等实现词当作日常动作名称。
- “公开”需说明是对接入的 AI 可见，不是发布到互联网。
- 列表简明，详情完整；高级说明按需展开，不把所有限制平铺在每页。
- 提案、信息库、回收站等预览复用对应模板的展示逻辑，不能正常页有排版、其他页退回 JSON。
- 页面标题、导航、按钮、右键菜单、状态页从共用组件统一，避免逐页补丁。
- 不为讲解增加演示申请、演示模式或假成功入口。

## 原生 App 原型的确认范围

用户选择直接在现有 Flutter App 上确认设计，不另做 HTML 原型。原型使用独立分支 `codex/ui-prototype-20261110`、独立应用标识和现有 `preview_main.dart` 入口。正式 App、服务器和真实资料不参与原型；假资料只保存在内存，退出重开即可恢复初始示例。

原型复用页面、模板渲染、主题和菜单组件，主要用于确认以下交互：

- 信息库：目录与标签标题、整行悬停与选中效果、右键菜单；未分类可回收其中资料，清空后隐藏，恢复资料后重新出现。回收站预览复用模板展示。
- 访问审批：申请用途与 Agent 名称、资料所在的完整路径；可以原地展开目录树。
- 录入提案：有意义的标题、各条资料的类型和分项预览、保存目录和展开的目录树；整份提案的处理方式不变。
- 授权历史：缩小左侧列表、扩大右侧内容，搜索与筛选收紧；用“展开审批时的内容”原地展示审批快照，用“在信息库中打开”区分当前资料。审批快照不代表 AI 实际读取记录。
- 设置：移除旧版模板、Agent 接入和顶部 AI 接入入口，去掉外观中的设计说明；创建资料先填写内容，再选择目录与标签，标签支持搜索。
- 连接状态：统一连接、加载和断开页面；保留返回入口；原型中的地址、Token、同步和重新连接仅用于展示，不发起网络连接。
- Mac 菜单栏：查看待处理申请；普通资料申请可直接批准或拒绝，其他类型打开主窗口详情。示例快捷批准明确显示范围及 2 小时期限；正式服务的授权规则待后续实现。

服务器连接统一从设置进入。通过 macOS 顶部“原型状态”菜单可模拟断线、打开菜单栏审批面板；该菜单仅供这个独立原型使用，不进入正式版。

本轮不实施服务器改造、CLI 自动配置、Agent 名称的全流程补齐，或两个旧接入功能的后台逻辑清理。菜单栏真实后台生命周期、完整的目录恢复和排序行为也不以原型代替正式开发。待外观和交互确认后，继续使用本轮共用 UI 改动，补齐真实行为，并移除不再需要的旧逻辑。

原型使用 Flutter 静态检查、现有工作区组件测试及实际 Mac 窗口检查。独立视觉评审指出授权范围缺资料名、菜单栏范围文案重复，已据此调整；这些检查不代表真实服务器或真实资料验收。

### 第二轮原型反馈

- Agent 名称只显示名称，去掉“（自述）”和重复解释；名称仍不能作为访问凭证，底层身份核验不变。
- 下拉框与列表不再为滚动条固定空出一条白边，使用覆盖式滚动条；列表内容本身保留正常边距。
- 授权历史时间线的圆点、连线均在内容区域内对齐，去掉旧记录实现说明和“重新读取记录”按钮；数据变化仍可正常更新页面。
- 移除跨页面遗留的“返回录入提案／返回授权历史／返回访问审批”等快捷按钮。编辑取消、弹窗关闭和断线恢复等必要操作保留。
- 删除选择资料类型时的“保存到某目录”提示，正式填写和提案预览中的目录字段仍显示；清掉重复来源说明和已处理后的旁白提示，保留错误、范围、期限及未保存内容等必要信息。
- 服务器连接放到设置中，去掉顶部连接图标和原型菜单里的连接设置入口；断线页可进入设置中的连接页。
- 菜单栏复用 Flutter 主题的颜色值，采用相同的紫色主按钮、描边次要按钮、正文颜色及间距；深色主题同步更新。不裁切可以直接批准的申请范围。
- 用户确认新的时间要求：授权默认 2 小时，可选 2、4、8、24 小时；原有 SSH 会话内不限时能力保留。新申请默认等待 2 小时，设置中可选择 30 分钟、1、2、4、8、24 小时。等待期限只影响新申请，不修改已有批准结果。

本轮时间选择和设置保存已接入原型的内存数据。真实服务当前仍有普通范围、凭据和整理各自的旧时长校验；正式实施时需同步修改服务端校验、默认值及 CLI 引导，再测试，不能把此原型作为已部署的新授权规则。

### 补充：本地使用与可选同步

用户新增要求：不连接服务器时，资料保存在本机，软件可独立使用；连接服务器作为可选的资料同步方式。设置入口调整为“存储与同步”，可关闭“同步到服务器”，确认后显示本地模式，隐藏地址、Token 和同步按钮；开启时填写地址和 Token。

本地模式仍需要支持保存普通资料、附件、凭据，以及本机 AI 发起申请和用户审批。切换模式不应清空资料，也不因关闭同步删除服务器上的内容。原型沿用同一份内存示例资料，只改变设置和状态展示，没有打开真实本地库、下载服务器资料或实现双向同步。

代码核对结果：`main.dart` 的默认入口目前是 `OnlineDesktopLauncher`；同一文件仍保留 `DesktopLauncher`，`desktop_bootstrap.dart` 仍包含打开本地库、启动 `AgentServer` 和本机运行控制的路径。因此本地能力并非全部删除，但也不能只加一个开关就宣称恢复。

此要求调整了 ADR0024 中“只保留服务器模式、断网不可用”的原先方向。正式开发前需更新该决定并设计：本地服务恢复、CLI 如何跟随当前资料库、服务器资料如何完整落到本机、首次同步如何处理两端已有内容，以及离线修改后的冲突处理。已有版本和提案核对逻辑应复用，不能默认用最后保存时间静默覆盖另一端。

### 菜单栏分类与证书区域调整

- 菜单栏弹窗按“访问审批”和“录入提案”两个标签分开，各自显示待处理数量；顶部为两类合计。录入提案显示标题、申请方、用途和条目数量，点击后打开对应提案，不跳到访问审批。提案仍在完整预览页整体保存，不提供跳过核对的快捷批准。
- 服务器设置里的证书状态改为紧凑的单行边框区域：“服务器证书 · 已信任”。移除原先空白较多的展开层和重复说明，沿用设置页字体、颜色和间距。
- 本轮仍为隔离原型，菜单栏内容来自同一份示例资料，未连接真实服务。

### 提案密码与多条资料切换

- 密码的显示/隐藏改为输入框右侧的小眼睛，沿用同一个受保护输入控件；移除框外的文字按钮，避免与输入框错位。明文切换不清空已输入内容，不改变密码保存或提案审批方式。
- 待确认提案和已保存提案共用横向标签栏。当前资料用底部紫色线标明，不再使用筛选按钮式的 ChoiceChip；长名称省略并提供完整名称提示，条目较多时横向滚动，缺少密码的条目保留“待填密码”。
- 原型使用已有多资料提案检查标签切换；密码样式修改落在正式界面共用组件中，通过合成密码录入测试检查对齐、显示/隐藏和整份入库。未为此读取真实提案或真实密码，也未替换正式 App。

### 授权历史关联资料行

关联资料从“名称 + 大号打开按钮”改为一行可点击的资料入口：左侧为资料/凭据图标，中间是名称，右侧为打开图标，悬停提示“在信息库中打开”。删除后的资料显示不可用并禁用跳转；普通资料的审批时内容仍可单独展开，改为次要文字操作。保持现有访问范围和历史内容读取逻辑。
