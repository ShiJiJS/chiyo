## 用户任务与界面

北极星：批准前，用户能看清使用哪个凭据、凭据交给哪里、由 CLI 启动什么程序。

保留第五轮之前已确认的顶部导航、审批收件箱与文档决策栏、信息库三栏，以及紫棠、
松石、雾蓝和灰底黑白主题。用户管理凭据；Agent 在外部聊天提交使用申请，桌面不新增
一个要求用户手工编写命令的主流程。

| 位置 | 常驻内容 | 点击问号后解释 |
| --- | --- | --- |
| 使用哪个凭据 | 名称、形式、版本、可用状态 | 请求携带引用，不包含秘密原文；关联信息不等于授权 |
| 注入到哪里 | 接收方式、参数位置或环境变量名、程序收到值还是路径 | 谁生成文件、谁设置变量、是否需要占位符 |
| 由 CLI 启动什么命令 | 完整可读命令、本机与工作目录；可展开程序绝对路径 | 批准不自动执行；CLI 准备凭据并启动，操作系统不识别文件引用 |
| 申请明细 | 原始申请的凭据、注入位置和启动内容 | 结构化请求与 run-use 调用按需展开 |
| 右侧决定 | 一次启动、启动有效期、另行批准的普通字段 | 原文接触边界常驻，不隐藏进 tips |
| 使用历史 | 批准快照、启动次数、命令、注入方式、清理结果 | 批准与启动分开；待清理在列表即可辨认 |

三个问号是可点击、可键盘聚焦的展开控件，带展开状态；不依赖悬停，不遮住批准按钮。
原型中的结构化示例用于评审接口设计，具体字段与命令名未实现。

## 与原模型的关系

- 信息字段仍按既有批准范围返回值。托管凭据是独立对象：字符串或文件，包含不可变版本。
- 信息项通过凭据 ID 关联，可多对多；关联不复制秘密，不自动批准使用。
- 使用授权绑定一次启动；不同于原来默认八小时、可重复读取的字段授权。两者共享授权会话，
  但能力类型分离，领取读取凭证不能调用凭据注入接口。
- 临时授权凭证是调用许可；托管凭据是目标服务的 Token/密钥；文件引用是启动计划中的
  命名标识。请求 ID、会话 ID、凭据 ID 或别名都不是鉴权秘密。
- 保留 ADR 0002 的同用户无强隔离边界。CLI 执行本机程序并接触获批秘密是本扩展新增职责，
  不意味着 CLI 能打开数据库或取得全库解密密钥。
- Agent 可见目录只提供用户允许披露的名称、说明、形式和引用信息；文件内容、秘密值、
  原始导入路径不进入目录或普通读取接口。初版由用户在桌面录入凭据，不经 Agent 聊天导入原文。

## 三种交付方式

| 交付类型 | 来源 | 去向 | 展示例子 |
| --- | --- | --- | --- |
| env_value | 字符串凭据的原文 | 新启动进程的环境变量 | GitHub Token → GH_TOKEN；gh repo view northstar/agent-skills |
| file_arg | 文件凭据生成的临时文件路径 | 一个完整命令参数 | SSH 私钥 → ssh 的 -i 后一个参数 |
| file_env | 文件凭据生成的临时文件路径 | 新启动进程的环境变量 | AWS 配置文件 → AWS_SHARED_CREDENTIALS_FILE |

设置进程环境变量不改变系统全局环境，也不修改 Agent 已运行的父进程。目标工具必须认识
指定变量或文件参数；没有通用的自动识别规则。GH_TOKEN 与 AWS_SHARED_CREDENTIALS_FILE
分别是工具自己的接口，不是本软件发明的变量。

文件保存为加密库中的独立内容副本，文件名仅作显示元数据。不能默认依赖源路径，也不自动
删除源文件；运行前由执行器生成受管临时副本。文件可能含二进制，不隐式按字符串处理。
多行文本也不自动猜测成 SSH 私钥或配置格式，须声明接收工具与格式。

## 文件占位符与参数规则

**规范数据使用类型化引用，UI 才显示占位符。** 展示语法固定为 `{{file:ssh_key}}`，
规范参数是 `{"file":"ssh_key"}`。初版不接受一条任意 shell 字符串再做全局文本替换。

1. `launch.executable` 是本机解析、核对后的绝对程序路径；`argv` 是有序参数数组；
   `cwd` 是明确的绝对工作目录；`env` 是明确的注入映射。启动使用直接进程 API，不经 shell。
2. 文件别名采用 `[A-Za-z_][A-Za-z0-9_]{0,63}`，区分大小写，在本请求内唯一。
   同一文件引用出现多次时复用本次运行的同一受管文件；不接受路径穿越或用户指定落盘路径。
3. 一个 file 引用占用一个完整参数，不支持前后缀拼接、嵌套、递归替换或任意表达式。
   `--key={{file:x}}` 第一版不支持；工具若允许则改成 `--key` 与文件引用两个参数。
4. env_value 中使用 `{"secret":"alias"}`；file_env 中使用 `{"file":"alias"}`。
   字符串秘密不支持塞入 argv，UI 不产生 `{{secret:...}}` 命令占位符。
5. 路径含空格时仍传为一个参数，不能先拼完整命令再解析；引号仅用于阅读展示。`$NAME`、
   `%NAME%`、`$env:NAME`、反引号等不触发二次 shell 展开，CLI 不自动执行它们。
6. 未声明引用、未使用的凭据、类型不匹配、重复别名、重复变量绑定一律在提交时拒绝。
   Windows 的环境变量名按大小写不敏感检测冲突。环境变量名限定 ASCII 标识符，不能含 `=` 或 NUL。
7. 原型不提供 shell 管道、重定向、`sh -c` / `cmd /c` / PowerShell 命令字符串模板。
   脚本或复杂工具的内部行为仍不等于获批命令表面内容；不能由此承诺脚本不可读取或外传秘密。
8. 对“字面文本恰好含 {{file:...}}”的参数，明细用 literal 与 file 类型区分，展示不得把
   字面文本伪装成有效文件引用；机器接口不会按字符串内容自动推断类型。

## 兼容现有 CLI 的拟议接口

现有 CLI 是保持进程的逐行 JSON 通道，授权会话凭据留在进程内。沿用这个机制，新增独立
的 `request-use` / `run-use` 能力；此前聊天中的 `info run --request ...` 仅用于解释流程，
不作为已存在的独立命令，也不引入在 shell 参数里传临时 token 的要求。

SSH 申请草案（纯虚构数据；未实现）：

```json
{
  "command": "request-use",
  "purpose": "排查测试环境连接",
  "credentials": [{"alias":"ssh_key","credentialId":"ssh-deploy","version":2}],
  "launch": {
    "executable": "C:\\Windows\\System32\\OpenSSH\\ssh.exe",
    "argv": ["-T", "-o", "BatchMode=yes", "-i", {"file":"ssh_key"}, "-p", "2222", "developer@test.beichen.example", "/usr/bin/true"],
    "cwd": "C:\\Work\\northstar",
    "env": {}
  },
  "readFields": []
}
```

GitHub 使用同样的结构：凭据别名为 `github_token`，`argv` 为
`["repo","view","northstar/agent-skills"]`，`env` 为
`{"GH_TOKEN":{"secret":"github_token"}}`。文件环境变量方式则是
`{"AWS_SHARED_CREDENTIALS_FILE":{"file":"aws_config"}}`，文件格式与工具要求匹配。

批准后在同一 CLI 授权上下文调用：

```json
{"command":"run-use","requestId":"REQ-026"}
```

run-use 不再接收可替换的命令或注入位置。CLI 必须校验私密会话证明和专门的使用授权，
请求编号单独无效。普通 status/claim 结果只暴露状态与批准摘要，不返回长期秘密或注入包。
不能持久化一份可在重启后复活的 run-use 凭证。

## 执行职责与状态

1. 本地核心校验申请，固定凭据版本、程序绝对路径、argv、cwd、env 映射、明确的非秘密
   启动选项与会话。用户可以拒绝凭据或取消附带普通字段，但不得静默重写命令来绕过申请。
2. 桌面批准后进入“已批准，等待 Agent 调用”。待审批期限与批准后的启动窗口分开。
   凭据启动窗口默认 15 分钟，可选 30 分钟，一次授权允许一次启动尝试。
3. run-use 在核心服务中原子占用一次使用额度，复核会话、撤销、到期、凭据版本与可用性。
   并发或重复调用不能再次启动。失败不自动重试、不自动退还次数；返回可解释状态。
4. 受控本机通道只向本次执行器交付获批材料，不进入 CLI 的通用 JSON stdout。执行器不持有
   全库密钥；临时授权凭证不作为子进程环境继承。原型不声称这条通道能抵御同用户攻击者。
5. CLI 生成私有临时目录与文件，使用受限 ACL/权限、独占创建、拒绝符号链接跟随；别名不能
   决定任意输出路径。所有绑定准备成功后才启动进程，中途失败清理已生成材料并记录失败。
6. 子进程环境由明确的基础环境策略和本次映射组成，不能完整继承 Agent/CLI 的秘密环境。
   不允许以注入为由改写 PATH、HOME、加载器变量或本软件内部授权变量。工具适配需核对现有
   登录文件、其他 token、AWS 环境凭据等优先级，避免使用未批准来源或落回另一账号。
7. 直接启动获批程序，记录 executionId、时间、退出码和清理结果。程序路径重新解析、工作
   目录或注入位置变化应拒绝并重新申请；恶意替换同路径程序仍属于本机强隔离边界，不能仅
   通过路径相同就声称已阻止程序篡改。
8. 进程结束后尝试清理受管文件，失败显示“待清理”，下次启动检查残留。只清理受管目录内
   经校验的路径，不清理用户源文件。进程退出并不证明子进程未存活或没有复制内容。
9. 会话结束、到期、撤销、完全退出阻止后续启动，不自动终止已运行进程，不收回已读内容。
   异常退出时保留可审计的“结果未知/待检查”，不能把未收到结束消息当成成功或清理完成。

CLI 的 JSON stdout 继续作为协议通道，子进程输出须作为带 executionId 的事件封装，不能
混入协议行。stdin 不得直接把 CLI 的鉴权消息转给子进程。交互 SSH 需要单独的输入/PTY
适配以及取消、退出和断线处理；首版明确不包含该能力，只支持非交互远程命令；原型中早期裸SSH示例须在D0校正。

输出可按已知秘密做尽力遮盖，但不能承诺编码、拆分、网页回显或自定义脚本不会泄漏。
启动记录不保存秘密值、文件字节、临时授权凭证或完整程序输出。Agent 不应把秘密写在
purpose、argv 或普通 env 文本中，应用也不能声称能检测任意未知秘密字符串。

## 固定快照、存储与兼容

- 获批快照不可变；替换凭据版本或停用凭据后，旧版本尚未启动的使用授权失效，须重新申请。
  历史保留旧名称/版本/接收方式事实；不能因后续重命名而改写过去批准内容。
- 旧信息读取继续固定字段成员、读取当前字段值；不把这个规则套到“凭据版本固定”的使用授权。
- 现有普通字段中即使内容像 Token，也不自动移成凭据。迁移应由用户确认，检查旧版本历史
  和备份中的残留；不承诺改成凭据后能收回已经读取的旧值。
- 后续加密备份应纳入托管凭据及其关联，排除活跃临时授权、未完成申请、执行中状态和临时文件。
  “排除活跃凭据”需明确指临时授权凭证，不能误删用户保存的长期凭据。备份格式须升级并验证
  跨机恢复；旧版本不能静默忽略新对象后报告完整备份成功。
- 只在同一台执行机器注入；不把本机路径交给远程 Agent 使用。远程执行、浏览器自动填充、
  固定用户配置文件覆盖、会话数据库写回、加密私钥交互解锁，均不自动纳入本版。

## 设计验收与后续实现验证

原型验收：三种方式可辨别；问号可开关；申请明细与确认框一致；批准只进入等待启动；
撤销不显示已注入；历史保留方式与命令；1280×800 与 1440×900 下无重叠或横向溢出。

实施时至少验证：参数含空格/Unicode仍为一个参数、未定义引用/类型错/重复绑定拒绝、
Windows变量大小写冲突、无shell二次解释、审批快照不能替换、版本变更与跨会话拒绝、
并发调用仅一次、材料准备/启动失败清理、撤销与启动竞争、异常退出残留、子进程不继承
CLI授权秘密、stdout协议不混流、旧账号凭据优先级、备份恢复不复活使用授权。
这些是待实现的验收要求，不是本轮已通过的安全测试。
