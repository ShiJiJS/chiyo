# Ticket #16 — 授权历史与访问记录

实现的是所有者在桌面查看的过去事实，普通 agent 接口不提供查询、清理、撤销历史的管理能力。

## 行为

- 批准时保存独立的历史 ID、请求关联、非凭据会话 ID、聊天名称、批准与到期时间、实际选择的项/字段 ID 和当时名称。名称或字段值后续变化不会改写这份批准事实。聊天名称由 agent 自述，不承担鉴权。
- 每次到达核心读取接口的操作记录时间、操作、会话/历史关联、可识别的项/字段 ID 与获准、拒绝或记录故障结果。不记录内容值、token、会话 bearer、密钥、请求原文或未知目标文本；不能识别凭据的尝试不关联私有目标。
- SQLCipher 库保存历史和访问记录。重启只恢复过去事实；上次未记终态的批准会记录上次运行结束，或按原到期时间记录过期。没有会话凭据或有效授权被恢复。
- 从“授权历史”撤销对应的实际活动授权。撤销完成后新发起的读取失败；已经开始并获准的读取可在记录保存后完成。撤销不能收回已交付内容。
- 默认保留 90 天，提供 30/90/180/365 天。缩短前预览清理数量并要求所有者确认；延长期限不会找回已清理事实。启动、读取及查看历史时执行清理，清理不改变活动授权。修改历史的 30 天规则独立处理。

## 记录可靠性

读取接口现在返回 `Future<String>`。授权判定和取值在核心的同一执行单元同步完成，随后等待批准事实与访问结果持久化，最后才交付内容。

用户已确认记录保存失败时暂停读取。CLI 返回 `audit_unavailable`，不返回值；桌面显示暂停原因。未保存的事实保留在内存队列，所有者修复存储后可以“重试保存记录”，保存成功才恢复读取，不丢弃事件后直接恢复。

完全退出首先立即失效能力、关闭访问服务，再等待记录保存，最后关闭数据库并退出。保存失败则保留数据库及队列并显示“重试保存并退出”，不会静默退出。异常终止进程、断电或手动结束进程仍可能丢失尚未保存的内存事实；任何已返回的成功读取都已先完成记录持久化。
