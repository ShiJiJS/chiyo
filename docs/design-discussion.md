本文保留设计讨论背景。用户已确认按本方案进入设计，当前产品范围与验收要求以[第一版规格](specs/0001-local-information-access.md)为准；下列未定技术项不构成实现承诺。

第一版规格已发布为 [GitHub Issue #1](https://github.com/ShiJiJS/agent-info-manage/issues/1)，标签为 `ready-for-agent`。后续规格变更应同步本地规格与该 Issue。

## 已明确的方向

- 支持 Windows 和 macOS。第一版可以单机使用，但设计需为后续同步留出空间。
- 信息由应用以加密形式统一保存，并在用户批准后签发只能访问获准内容的临时 token。第一版不要求限制 agent 的运行环境，通过保护密钥、审批入口及逐请求鉴权控制访问；不承诺抵御已控制本机或窃取有效凭据的攻击者。采用 SQLCipher 整库加密，随机数据库密钥由系统保管，具体平台实现待验证。
- 第一版打开客户端即可使用，不设置应用主密码，不要求用户输入密码解锁资料库，也不采用短期免密作为前提。数据库仍加密，密钥由应用自动管理；主密码或应用锁可以后续再考虑，系统密钥保管的具体实现待验证。
- agent 通过 CLI 和配套 skill 提出信息需要，桌面端向用户呈现请求，由用户选择授权范围。
- 未处理的访问请求保留在桌面端待办中并发送通知。agent 可以等待或先处理独立工作，查询状态不重复通知；部分批准返回实际获准范围，拒绝后不得自动重复提交相同申请。待审批默认有效期为 30 分钟，允许设置调整，与批准后的授权有效期分开计算。CLI 等待超时不取消申请；会话结束取消待审批请求。请求过期后不得自动反复申请。
- 关闭客户端窗口后保留托盘或菜单栏后台进程，继续提供有效授权内的访问并通知新请求。用户选择完全退出时停止服务并使当前临时授权失效；重启后需要重新申请。
- agent 可提供用途说明和候选信息，用户在审批界面可取消字段、补选或改选正确的信息，无需退回重新申请。界面展示会话标识、agent 自述用途、申请范围及最终选择；实际授权以用户最终选择为准，自述用途不作为可信身份或授权依据。
- 在录入阶段拆分信息粒度、组织层级并建立索引。避免通过逐步缩小查询范围而反复要求用户授权。
- 信息组织采用目录层级、标签和可扩展字段模板。agent 建议归类和字段，用户批量确认时可以调整；这些组织方式不自动形成授权范围。
- 未授权前只向 agent 提供可公开的目录索引或信息描述，不提供实际信息内容。
- 授权在本次会话内复用。正常收到会话结束事件时撤销，最长有效期默认 8 小时，批准时允许调整，并支持桌面端手动撤销。异常退出或事件丢失依靠到期兜底；隔天恢复同一聊天不意味着自动恢复已失效授权。
- 第一版以整次聊天为授权单位，主 agent 与子 agent 共享本聊天已批准范围，不单独为子 agent 授权。其他聊天独立申请；子 agent 需要超出已有范围的信息时仍需申请。
- 信息的展示形式和最终名称尚未确定；暂称“信息项”，不预设卡片界面。
- 第一版信息内容支持结构化字段和文本说明，图片、PDF 等附件后续扩展。
- 主要由 agent 录入信息，同时提供手动输入入口。agent 自动整理后提交，用户在桌面端批量预览并确认；修改展示差异。提交权限不自动赋予读取或覆盖已有信息的权限。
- 用户接受导入会话的 agent 已经看到其整理的原始资料；入库后的访问控制面向后续访问，不尝试收回导入会话已获知的内容。
- 授权固定为批准当时选中的信息项及字段集合，后续新增信息项和字段不自动获得授权。向 agent 明确说明新增内容需要重新申请访问。
- 已授权字段允许读取最新值，修正资料不重复审批。信息项和字段需要保持语义身份，不能通过复用既有身份将无关内容纳入授权。具体编辑约束尚待设计。
- 删除先进入回收站，立即停止通过既有授权读取；恢复后需要重新授权，不复活旧权限。提供修改历史，回收站和修改历史默认保留 30 天。历史版本由用户在客户端查看和恢复，不自动向 agent 开放；agent 提出的删除需要用户确认。
- 第一版优先验证 Codex 桌面端；CLI 保持通用。会话绑定与生命周期能力需要事实核查，不能把调用者自报的会话 ID 视为可信鉴权依据。
- 优先讨论基础信息；SSH 密钥的保管和使用方式另行设计。
- 后续同步仅面向同一用户的多台设备，暂不设计家庭或团队共享。为信息标识、版本、删除记录和冲突处理预留结构；临时 token 不随资料库同步。未来云端优先考虑 Java + Spring Boot，但具体职责仍延后，不选择同步中转或远程信息服务，亦不将云端作为单机版前提。
- 第一版提供手动加密备份，启用备份时生成供用户另行保存的恢复密钥。恢复密钥仅用于换机或恢复，不用于日常打开客户端；自动备份和设备间同步后续实现。备份中凭据、历史和恢复范围的细节待定。
- 以授权历史为主要入口，展示批准范围、有效期、撤销状态，并关联实际访问和被拒绝的越权请求。记录时间、会话、信息项及字段标识、操作和结果，不复制字段内容或 token；支持从历史入口撤销仍有效的授权。

用户已确认按以下方案进入设计；客户端与本地语言已选定，其他技术项仍需补齐，模块划分与实现顺序不代表应用已完成。

### 已确认的技术选择（2026-10-16）

| 部分 | 选择 | 理由与边界 |
| --- | --- | --- |
| 客户端 | Flutter / Dart | Windows/macOS 优先；用户接受学习成本，并希望将经验用于后续手机授权确认。移动端不加入第一版。 |
| 本地核心服务 | 独立 Dart 业务模块 | 与客户端共用语言，授权规则独立于页面；存储及系统能力通过适配层接入。 |
| 通用 CLI | Dart 独立可执行程序 | 通过受控本机接口请求服务，不直接打开资料库或持有全库密钥。 |
| 本地存储 | SQLite + Drift + SQLCipher | 关系型存储及事务；Drift 管理数据访问与结构升级，SQLCipher 加密数据库；不自行设计字段加密体系。 |
| 本机密钥 | 安全随机生成，操作系统保管 | 日常自动获取；flutter_secure_storage 为优先验证的适配方案，插件版本及平台配置尚未锁定。 |
| 备份密钥 | 独立恢复密钥 | 用户另行保存；换机恢复生成新设备本机密钥，不恢复活跃凭据或待审批状态。 |
| 未来云端 | Java + Spring Boot 为优先方向 | 利用用户已有经验；服务器职责、手机审批与同步另行设计，第一版无云端依赖。 |

选择背景及替代方案见 [ADR 0003](adr/0003-flutter-and-dart-local-stack.md)。本地核心随桌面应用后台运行；具体 isolate 或进程划分、通信协议、插件与原生库、安装更新仍待验证。Flutter 跨平台支持不代表各平台能力已验证，也不自动解决手机与电脑之间的可信审批。

依据：[Flutter 平台支持](https://docs.flutter.dev/reference/supported-platforms)、[Dart 服务与 CLI](https://dart.dev/server)、[Dart 可执行文件](https://dart.dev/tools/dart-compile)。当前只有文档核查，没有运行验证结果。

存储选择见 [ADR 0004](adr/0004-encrypted-sqlite-storage.md)。字段级授权由核心服务执行，agent token 不是数据库解密密钥；公开目录也保存在加密库内，由服务按规则返回。第一版不安装 PostgreSQL/MySQL 等本机数据库服务器，也不为每个字段建立独立密钥体系。

需验证发布包加载的加密引擎与版本、错误或缺失密钥的失败处理、内存临时存储策略、数据库辅助文件及日志、升级后密钥访问和跨设备恢复。不得在加密能力缺失时静默退回明文 SQLite，也不得因密钥缺失而覆盖旧库。备份格式、密钥封装及包含哪些历史数据仍待设计。

存储依据：[SQLite 适用场景](https://www.sqlite.org/whentouse.html)、[Drift](https://drift.simonbinder.eu/)、[SQLCipher 设计](https://www.zetetic.net/sqlcipher/design/)、[Dart sqlite3 更新记录](https://pub.dev/packages/sqlite3/changelog)、[构建选项](https://github.com/simolus3/sqlite3.dart/blob/main/sqlite3/doc/hook.md)、[系统密钥适配候选](https://pub.dev/packages/flutter_secure_storage)。部分 Drift 加密教程与底层 sqlite3 当前支持情况存在差异，应以选定版本和实测结果为准。

### 模块职责

| 模块 | 职责 |
| --- | --- |
| 桌面界面 | 信息浏览和编辑、请求审批、录入提案确认、授权历史、回收站、备份恢复；关闭窗口后保留后台进程。 |
| 本地核心服务 | 管理信息和授权，每次读取验证实际获准范围、有效期、撤销及删除状态；执行批准后的变更，维护历史。 |
| 加密存储与密钥管理 | 保存资料、版本及记录，自动管理本机密钥，支持用恢复密钥保护的可迁移备份。具体技术方案待验证。 |
| 通用 CLI | 提供公开目录查询、访问申请、等待及状态查询、获准内容读取、录入与修改提案提交；输出机器可读结果。 |
| Skill 与 Codex 适配 | 指导 agent 发现、申请和使用信息；关联聊天及生命周期，主子 agent 使用相同授权单位。 |

桌面界面与 CLI 调用同一套业务规则，但管理和审批权限不能因能调用 CLI 而自动获得。CLI 不直接持有全库解密密钥；公开访问接口不提供自我批准能力。后台服务是桌面应用的一部分，不预设需要单独安装系统服务。

### 三条主流程

1. 录入：用户指定资料 → agent 整理为录入提案 → 桌面端展示差异和批量预览 → 用户确认 → 正式入库并更新公开目录。
2. 读取：agent 检索公开目录 → 一次提交用途与候选范围 → 用户调整并批准 → 签发限定范围的临时凭据 → 会话内重复读取已授权字段的最新值。
3. 管理：用户查看授权历史及访问记录 → 可撤销授权；修改、删除或恢复信息按前述规则影响后续访问；已披露内容不尝试收回。

### 建议实现顺序

1. 先用虚构数据跑通桌面审批与 CLI 申请、读取的完整流程，验证跨会话范围、主子 agent 复用和生命周期。
2. 完成加密存储、自动密钥保管及恢复验证后，再接入真实资料；补齐目录、字段模板、批量录入和修改确认。
3. 完成授权历史、访问记录、撤销、回收站、修改历史及加密备份。
4. 在 Windows 与 macOS 验证安装、后台运行、通知和 Codex 接入，交付单机版。

### 必须验证的行为

- 未授权只能看到允许公开的目录；篡改请求中的信息项或字段标识不能扩大访问。
- 同一聊天复用授权，其他聊天不能仅凭猜测会话 ID 取得凭据；主子 agent 共享本聊天范围。
- 批准的范围固定，新增项和字段不自动加入；已授权字段的值更新后可读取最新值。
- 拒绝、部分批准、请求过期、等待超时和会话结束给出不同状态，不产生重复通知。
- 撤销、删除、完全退出或授权到期后，旧凭据不能继续读取；恢复信息不恢复旧授权。
- CLI 不能直接批准自己的申请；日志不包含资料内容或访问凭据。
- 新设备可用备份及恢复密钥恢复资料；恢复不能复活有效 token 或待处理审批。
- 在约定不抵御本机控制及有效凭据失窃的边界内验证，不宣称提供进程之间的强隔离。

## 接入核查（2026-10-15）

[Codex Hooks 官方文档](https://learn.chatgpt.com/docs/hooks) 提供 `session_id`、`SessionStart` 和 `SessionEnd`。切换离开聊天不等于立即结束会话，因此结束事件不能替代凭据到期机制。普通 CLI 的业务接口可以通用；自动关联聊天、接收生命周期事件仍需接入适配。

会话 ID 只作为关联标识，不单独充当访问凭证，这是本项目的安全设计要求。当前文档核查不等于已在 Windows/macOS 两端完成集成验证。
