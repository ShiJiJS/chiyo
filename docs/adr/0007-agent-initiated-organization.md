# Agent 发起整理请求，一次批准后自动调整分类与标签

2026-10-16 用户指出：在应用创建任务再回 Codex 找 Agent，违背按自然语言要求、由 Agent 用 CLI 发起请求的产品模型。整理请求改由当前私密会话发起，在已有访问审批队列中显示用途、来源和候选资料。用户可以缩小范围、拒绝或批准，无需选择 Agent、创建任务或复制提示。

用户进一步明确批准：一次请求获批后，允许 Agent 自动应用分类和标签，无须再次确认方案。批准界面明确说明元数据种类和这项写入能力；批准时固定资料身份及版本，最长30分钟。Agent 只读标题、公开说明、目录树和标签名称，不能读取或修改字段值，也不能扩张普通内容授权。最终提交在同一事务应用分类、标签、资料版本、修改历史和整理结果，任一版本冲突整批不应用。

待审批采用现有请求期限配置；批准不重复生效、不续期，完成后结束本次能力。撤销、会话结束、到期、重启均阻止后续读取/写入；异步存储提交前再次检查会话与期限。所有整理请求、任务和结果仍排除离线备份。旧版已保存的待确认方案保持原审阅语义，不能把旧的元数据授权升级成自动写入许可。本决策替代ADR0006的发起和再次确认流程，其余边界保留。

2026-10-25补充：[ADR0015](0015-default-visible-tags.md)确认标签默认可见；整理任务结束不应阻止Agent继续通过普通发现接口读取标签。它仍不能在整理能力失效后写标签或改资料；目录和其他整理专属元数据按既有规则处理。正式实现随Round09推进。
