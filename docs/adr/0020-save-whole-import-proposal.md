# 一份录入提案整体保存

2026-11-03，用户明确确认一个提案就是一次完整提交、一次整体保存，即使包含多条信息也不能部分入库。旧实现允许先保存七项凭证、剩四项待填密码，这与用户任务不符。本决定替换ADR0018中按条目分别确认、分别入库的含义，不取消关联的准确性校验。

整份必填字段、密码和文件齐全，用户核对后点一次保存；任意一项未齐全或实际保存失败都不留下部分新增或修改。同份待录入关联一起建立，不再用提案内勾选范围作为保存单位。提案中的密码直接填写并支持显示／隐藏，不额外要求用户单独审批自己填写的密码；保存提案仍不授予AI使用资料或凭证的许可。

代价是同一提案中已完整的条目也要等待未完整的条目，因此AI应按用户的实际一次操作组织提案。历史已部分入库事实不能抹掉或重做；只对保留下来的全部待处理内容整体保存，既有正式记录、回执和用户已填密码必须保留。

App、CLI通信和实际保存规则统一；不能只隐藏复选框。新增预览、修改前后展示和信息库共用插件展示逻辑，提案逐条切换阅读但不逐条入库。实现与验收归GitHub #78、#67、#79；本决定记录已确认的目标，不表示全部开发已完成。
