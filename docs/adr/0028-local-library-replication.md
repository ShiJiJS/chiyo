# 资料内容同步与本机授权分别保存

按 #130、#131 已确认的范围，本地库作为独立加密副本，用户可选择连接服务器同步。同步资料库身份与各端副本身份分开：资料、字段、版本、关联和目录等沿用原 ID，各端继续使用自己的数据库密钥、设备接入凭证和聊天授权。关闭同步只停止传输，不删除任何一端资料；恢复备份或选择另一资料库后先重新核对共同基准。

首次传输采用有版本的内容清单、完整性校验和分块文件传输。目标为空才可接收初次内容；已有同库身份按共同基准接续，不同库且双方非空则保留双方并提示使用备份或空目标。接收端先验证隔离暂存内容，完成后原子发布；不直接复制正在使用的数据库文件，也不以覆盖整库充当后续同步。

普通资料、文件所有保留版本、凭据材料、目录/标签/手动顺序、回收事实、插件模板及可保留的历史进入内容同步。界面偏好留在设备，活动聊天许可、待处理审批、进行中的凭据执行、临时明文文件和接入配置留在所属服务。历史记录在另一副本中只表示发生过的事实，不恢复可用许可。

后续变更使用持久同步进度和共同基准核对。每次已提交的关联变化在接收端保持整体可见，消息重试须返回原处理结果。双方分别修改或删改冲突时保留两份候选和原历史，其他不冲突内容继续；用户选择后形成新的同步版本。代价是需要额外保存同步进度和冲突候选，但避免按电脑时间静默覆盖、整库替换导致丢失及把历史授权误当作当前许可。实际协议、存储及界面完成情况以相应 tickets 的实现证据为准。

变更捕获与业务写入放在同一个 SQLCipher 事务中：触发器收集行变化，最外层事务合并重复写入并生成一个稳定的变更编号。嵌套写入和一份提案涉及的多条资料不拆成可分别提交的同步事件；捕获失败时业务写入一起回滚。设备偏好、接入配置、服务心跳不进入内容变化记录。文件只记录已有不可变版本的说明和引用，传输需要原字节时再按块读取，不把附件正文重复写进 JSON 日志或全部预读进内存。

数据库内部的原始行变化不是可直接传输的内容协议，必须先经过现有可移植内容校验及授权剥离。共同基准按资料整体比较，不逐字段合并；删除也有独立版本标记，旧设备不能把“已删除”当成“从未存在”而自动新建。原始变化、每台设备已确认的进度和处理回执均为各端私有状态，不进入手动备份或首次内容复制；恢复或完整接收资料后重新建立基准。新增存储格式标记使旧程序明确拒绝，不能静默忽略这些状态再继续写入。

新副本接入时，需要由同一次一致性快照确定内容版本及源端变化水位，才能从该位置继续接收后续变化；不能给已有版本另算一套不相干的初始编号，也不能从源端第一条旧变化重新播放。这是新连接建立共同基准，不是把源设备的同步进度、操作回执或授权状态复制到另一设备。同步保留独立的协议版本和完整性校验。

增量接收仅更新涉及的资料及其缓存，不调用整库恢复去清空本机审批、聊天许可、提案或偏好。原文按需分块读取；待传版本在本机正常保留策略将要清理其原文时，先在 SQLCipher 中保留该原文，避免断线期间失去仍待交付的版本。接收失败不发布半套缓存；同一消息重试返回原回执。

用户处理冲突时核对整组变化，而不是逐字段合并。选择产生一个带双方父版本的新变更，原冲突回执保持原结果；独立保存的处理记录用于识别已解决候选，重试须核对同一命令。后续设备接收这个新变更后也结束对应冲突；未被这次选择覆盖的更新仍保留待处理。历史按准确内容识别，两端同编号的资料修订可以同时保留；文件读取和恢复使用不可变引用，不只使用界面编号。

凭据的两份材料只在加密存储中归档。普通冲突预览提供凭据名称、账号、用途及修改时间，不带密码、Token、文件字节或可代用的证明。选择后生成新材料版本并使旧使用许可失效；不会因为历史被同步就恢复原聊天许可。

目录及标签依赖随来源变化携带当时的元数据和版本，但不当成普通写入。接收后缺目录或形成循环时，整组暂存为冲突，其他资料继续。用户选择来源内容时同时核对必要目录变化；不会悄悄新建同名目录，也不会为同步失败把资料移入未分类。

内容格式 24 表达准确授权快照，25 保存同编号的独立资料修订，26 保存受保护凭据候选；旧格式仍可读。普通修订继续使用原版本存储，出现分支时再使用独立快照。同步及凭据归档原先使用的本机格式截至63，仍分别记录此前可选功能能力，避免只保存资料历史就误认为服务器或同步表已经存在。

CLI 重构中的多凭据填写批次沿用本机格式65／内容格式28，程序使用沿用本机格式67／内容格式29。同步仅保留只读历史，不复制原聊天批准、材料领取或进程控制能力；旧对端未明确支持相应内容格式时停止上传。申请和每次使用各为独立历史记录，单次变化不反复传输整段历史；同一原始事务中的关联变化仍整体发布和校验。来源设备保留的防重复事实不能被副本历史覆盖，包括不能把原操作改挂到另一份历史申请。接收只更新对应缓存，不清空本机其他待审批工作。已有同步库升级时补记一次以前漏捕获的新历史，正常重启和未变化查询不重复制造变更。
