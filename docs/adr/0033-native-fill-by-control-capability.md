# 原生后台填写按控件能力开放，不按应用名单开放

2026-11-14，用户明确要求通用原生控件后台填写。现有 Mac 实现将一个实测应用的版本、签名、系统构建和控件编号固化为允许名单，混淆了“测试证据”与“可使用条件”；Windows 没有逐应用名单，但把三个框架家族作为硬门槛。这比用户要求的范围更窄。本决定修订 [ADR0032](0032-native-background-credential-fill.md) 的支持资格：对实际目标检查密码语义、系统直接写值能力、对象身份及权限，符合条件即可申请，无须逐应用或逐版本登记。

Mac 使用 AX 密码控件的可写 AXValue，Windows 使用 UIA 密码控件的可写 ValuePattern 并关闭 AutoSetFocus；具体类名、开发者提供的控件编号不作为通用资格。保留实际进程/文件/窗口/字段身份、可信 helper、原设备与聊天、逐项批准及写入前授权检查，失效不改绑。测试应用清单只记录证据；原生接口检查不能保证任意第三方应用的内部实现或业务接收，这一局限由明确的结果语义表达，不靠默认拒绝未知软件掩盖。浏览器继续专用接口，已识别的内嵌网页不进入本路径，不增加聚焦、键盘或剪贴板后备。

不支持在写入前明确报错；setter 已开始而不能确定有无写入时保留 unknown，不能误称未写入或自动重试。通用控件采用新的公开类型与能力版本，旧批准不扩大。完整行为、兼容迁移和验证标准见 [实施合同](../design/native-background-fill-contract.md)，实施跟踪仍为 [#144](https://github.com/ShiJiJS/chiyo/issues/144)。本决策已接受，代码适配与验收待完成。
