# 按实际使用位置选择凭据交付，原文读取单独批准

现有凭据使用仅支持少数固定命令，用户批准之后仍可能无法登录。2026-11-12 用户决定：Agent 先确定凭据用在哪，再查询本机支持的方式，选择密码框填写、程序标准输入、环境变量或临时文件；复用既有申请、授权和使用记录。通用程序交付固定获批程序身份及凭据接收位置，不把服务器的操作系统能力当成 Agent 所在设备的能力。

无法直接使用时，Agent 另行申请读取已保存的字符串凭据，说明不能填写的原因及原文将进入聊天；用户明确批准前不返回原文。原文读取与使用批准分别记录，撤销、有效期和凭据版本仍须检查。用户本人在 App 查看或复制保存的密码不再发起申请。

本决策扩展 [ADR0008](0008-local-credential-runtime-injection.md) 的固定接收工具范围和 [ADR0012](0012-local-focused-credential-fill.md) 的平台范围。Mac 主程序保留沙盒，由独立辅助程序调用系统填写接口；设置提供本机权限检查和主动申请，启动、查询能力不弹权限。Windows 按实际验证结果提供能力，不承诺所有网页、应用或受保护窗口都能填写。不要求在填写时阻止 Agent 观察页面，也不承诺防止获批接收程序主动泄露凭据；正常命令输出仍过滤凭据，未知的填写结果不自动重试。

服务器模式下，批准和持久使用记录仍由服务器管理，实际输入由Agent所在电脑上正在运行的App完成。CLI自动发现与同一服务器及设备配置匹配的App私有入口，只转交请求和查询结果；凭据材料不进入普通Agent响应。App核对实际应用身份，服务器将申请绑定原设备与会话；每次操作持久登记，领取和输入前检查原批准，每批输入前重新检查。App退出、目标变化或连接失效时停止未发送部分，结果不确定时保留原操作，恢复连接不重放输入。设置中的系统权限属于当前电脑，与NAS管理身份分别保管。
