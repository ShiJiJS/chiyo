# Agent Info Manage · Mac 开发预览

本候选用于接通普通资料的本机保存、AI 申请和主人审批，再按字段和期限提供获准内容。
它仍需同候选真实宿主与系统验收，不能把构建或合成测试通过当作已交付可用版本。
这份说明随完整 Mac 包放在根目录，下面的相对链接均以该目录为准。

## 启动

解压并保留完整 `AgentInfoManage` 目录，放在一个稳定位置，打开
[app/info_desktop.app](app/info_desktop.app)。运行 App 和随包命令不需要安装
Xcode、Flutter、Dart 或 Python。完整载荷、来源与摘要见 [manifest.json](manifest.json)。

首次使用需要系统钥匙串保存或读取本机资料库密钥。若出现“无法访问系统钥匙串”，
应用会保留原库；从窗口的“请求钥匙串访问”重试，并由你在系统提示中处理。
只为你确认的这份应用选择“允许”或“始终允许”，系统密码由你自己输入。
同版本重开已有免再次确认的本机验证；升级改变 ad-hoc 签名时仍可能要求重新允许。

红色关窗保留后台服务，菜单栏提供“打开访问审批”。使用应用菜单退出或 ⌘Q
结束服务。新界面的“应用运行”设置尚未接入，请使用应用菜单或 ⌘Q 退出。
退出或重开后，原聊天的许可不会恢复。

同一完整包的 [cli/info](cli/info) 也提供 `app status` 和 `app quit`，可用
`app quit --timeout-ms 15000` 请求正常退出。命令只控制同包应用，超时不会强杀或
重发退出请求；保存失败会明确返回 `shutdown_failed`。Mac 返回 `exited` 时只确认
应用收尾及该进程结束，原生退出码保持 `null`。移动包后从新位置调用随包CLI。

## 当前支持范围与使用路径

1. 在“信息库”新建、编辑和管理普通资料：文字字段、服务器/应用资料、文档正文、
   档案经历的独立字段，以及目录、标签和资料关联。修订与回收使用真实资料来源。
2. 接入的 Agent 先查看公开目录并提出申请；主人在审批收件箱核对用途、字段范围
   和期限，批准需要的部分或拒绝。主人没有创建访问申请的入口。
3. 同一授权会话可在已批范围与固定期限内重复读取，每次读取不会延长期限。未选
   字段和新增字段需要另行批准；普通信息许可不提供关联凭据。
4. 在授权历史查看获批范围、当前状态和实际访问记录。撤销会阻止后续访问，已经
   读取的内容无法收回；重开应用和恢复历史不会恢复旧许可。
5. 新版“备份与恢复”已接入独立恢复密钥、真实加密导出和空库恢复，以及原操作
   核对和暂存清理。当前仍属开发候选，系统面板与沙箱重开验收范围见下方说明。

普通附件版本列表和文字/图片/PDF分页预览已接真实Owner原文服务；原文需完整校验，
过期已清理版本仅保留记录。PDF需要密码、损坏或超出预览范围时会明确提示。
实际原生App端到端验收仍单列，不以独立渲染检查替代。

普通附件导入、替换和保留版本恢复已接真实加密草稿事务；选择后原文进入加密暂存，
取消清理暂存，提交以持久回执核对。恢复保留版本会生成新版本。原生面板验收仍单列。
主人“另存为”先完整校验原文，再以不覆盖方式写出；取消不写文件，另存不修改资料。
结果未知时先核对原操作，重开不自动重写；若需恢复文件访问，点击“重新选择原文件
并核对”，选择原文件。文件已保存但暂存未清理会单独提示，可重试清理，不删除输出。
“用本机程序打开”使用临时副本，支持文字、PDF、图片和Word。修改不会自动写回
资料库，可结束使用并清理，正常退出或下次启动时回收此前副本；路径移除不能收回
外部程序已读取的内容。打开结果未知时先核对，重开不会自动再次打开；可以明确
结束核对并清理副本，原结果仍保留未知。系统接受请求不等于文档已经显示。
同候选真实默认程序、系统面板及外部位置重开验收尚未完成。

以下模块的新界面真实接入仍未完成：AI文件申请/审批与交付、托管凭据、
录入提案与整理、插件、其他完整设置及应用运行设置。相关入口会提示
尚未接入，不能把预览样例或底层协议能力当作这些界面已经可用。本机焦点填充关闭。
随包保留 GH/AWS 和协议模板供后续功能使用，不表示已完成对应管理和审批流程。

接入 Codex 的材料生成和配置说明见 [CODEX-INTEGRATION.md](CODEX-INTEGRATION.md)。
先用合成资料测试；生成文件只是准备步骤，具体 hook 仍须在客户端审查并信任。

## 备份与升级

在“设置 → 备份与恢复”创建恢复密钥并独立另存，再选择归档位置导出；已有输出
不会覆盖。恢复时选择归档和对应密钥文件，先检查范围，再明确提交到空目标库。
操作结果不确定时，使用“核对上次备份操作”，不要把重新导出或恢复当作核对。
成功结果与暂存清理分别显示，清理失败可重试，不删除已保存的备份和密钥。

真实存储、控件和独立测试进程已有验证；本包仍需同候选系统文件面板和沙箱重开
验收，特别是外部目录在重开后的访问。暂不承诺所有外部位置都能自动恢复访问，
核对失败不代表原操作未执行。现阶段先用隔离合成资料完成候选验收，不将本候选
当作个人资料的唯一保管方式。

已有旧版资料的用户，应在仍可正常使用备份功能的旧版中独立保存恢复密钥和加密
备份，分别保管。恢复密钥不同于本机数据库密钥；现有恢复规则只允许空目标库，
不覆盖或合并非空资料库。

升级前在可正常打开的旧版中保存完整备份和恢复密钥，并保留旧 ZIP。完全退出后，
核对新包清单与来源，再整体替换稳定位置的完整目录。安装不需要清理原资料容器。
若新版本无法开库，保留原文件并处理系统提示；旧版能否打开升级后的库需独立核对。

接入材料引用绝对路径。移动目录后，按随包接入说明重新生成并审查准确路径，
保留项目已有配置。不要把需要长期使用的接入材料留在将要清理的构建目录。
