# 普通文件录入

先确认 `capabilities` 包含 `information-file-upload.v1`，读取所选模板本次返回的 `fileInput`、限制与 `submissionExample`。普通文件也由主人批准后入库；文件上传成功只是收件，不是入库，也不授予 AI 读取许可。

用户只给文件时，自行判断材料组织：相同材料的真实前后修订作为版本；不同用途、方向或独立证明分别建资料。有源文明确联系的补充附件可归同一资料，但仍是独立字段。相同原文的重复副本不冒充新的修订。用文件名、文内修订信息或用户说明写清版本标签及来源依据；证据不足时保留未知，不能只按提交顺序或文件修改时间编造先后。

按动态例子把用户给定路径交给 CLI。模板文件值绑定相应附件 key，具体结构以查询为准；本机路径、文件 Base64 与整段原文不写进普通文字字段或公开说明。无需主人在 App 重选。为各版本填写可理解的说明，明确选择哪份是当前原文；较大的软件版本号只是保存次序。已保管材料的历史原文长期保留。

为录入意图保存稳定的 `operationId`。首次提交没收到结果时，新建用 `import-status`、修改用 `update-status`，携原 operationId 查是否已收件；上传结果不明会另给上传 operationId，可用 `import-file-status` 核对。结果不明时保持原编号，不换编号重复创建。缺文件、超限、模板变化或原文已不可用时，修复具体问题再提交，不能把普通文本称为原文备份。

给已有资料添加文件或新版本，先确认 `information-file-update.v1`，读取动态返回的 `fileInput` 和 `fileUpdateExamples`。从公开目录确认准确资料、当前版本及现有文件字段，依据用户来源选择目标；内容相似不足以认定可以覆盖。新增独立附件与给已有附件加版本分别使用查询中的例子，只补历史稿时保留原当前文件。只改文件无需读取、重填无关正文；同时改正文时按模板的完整修改格式，明确保留已有文件。主人可查看原当前文件和新交原文，再批准；原资料变化后重新核对并审批，不能自动换目标。

私钥、登录会话等证明身份的文件使用凭据模板和凭据录入流程。只有上传能力而没有修改能力的旧运行包，暂缓已有资料的文件修改。
