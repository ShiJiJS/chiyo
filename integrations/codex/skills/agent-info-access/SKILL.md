# 知予使用说明

App 管理资料和审批，CLI 查询、提案和使用获准内容。模板格式、说明和例子由实际连接的插件提供，不在 Skill 里固定另一套。连接成功不代表获准，保存资料也不授予 AI 读取或使用许可。

## 入口与当前聊天

本包的 `Bundle executable` 是统一入口 `chiyo`（Windows 为 `chiyo.exe`）。使用定位器已经核对的完整路径，先看 `--help`，再看所用子命令的 `--help`。帮助不需要 App、连接或私有配置。普通任务使用参数，复杂批量内容使用 `--input`；机器结果加 `--json`。凭据使用申请先取 `exec/ssh/fill template`，填写简短 title、用途 summary 与独立执行参数，再 `request --input FILE`；模板离线可用，`--out FILE` 只写新文件。

先读[聊天、连接与恢复](references/remote-connection.md)。已有本聊天私有上下文时复用，没有时 Agent 自动建立一次新的未授权聊天，无需用户单独确认。不能用公开聊天 ID 或最近一次聊天找回权限。配置固定原资料库和执行设备，断网不换库，不随 App 模式切换搬运旧批准。普通终端可接入，不要求安装 Codex hooks。

| 本次工作 | 先看什么、怎么开始 |
| --- | --- |
| 用户给文件，要求新增或更新资料 | 读[来源整理与文件例子](references/information-file-intake.md)，查 `directories list`、`catalog list`、`credentials list`，再查 `templates list/show/examples` |
| 阅读已保存的普通字段 | 从 `catalog list` 选准确资料与字段，用 `access request`；等待原申请后 `access read` |
| 读取或上传已保存的普通附件 | 读[普通附件](references/information-files.md)，用 `access request` 申请 file 字段，获准后 `files fetch/status/release` |
| 持续 SSH、保留目录环境、安装确认或 sudo | 读[SSH 持续交互](references/ssh-sessions.md)，使用 `ssh request/open/run/input/credential` |
| 密码、Token、私钥用于登录或程序 | 读[凭据使用](references/credential-use.md)，先确定真正目的地，再查 `doctor`，使用 `fill` 或 `exec` |
| 继续旧版整理任务 | 按下方兼容说明使用原聊天的旧协议；不要换聊天继承批准 |

## 整理和提交

用户给定文件是来源范围，由 Agent 自行判断条目、分类、关联及版本，不让用户逐条指挥。先完整查看目录和已有同类资料；目录可查不代表正文可读。没有合适模板或缺填写例子时，说明需要什么格式并暂缓该项，不自行装插件或拿通用文字凑数。

1. 选择实际动态模板，读取说明和完整例子。名称写真实对象；应用名用软件名，部署位置可区分名称，设备配置单独关联。描述写简短用途，结构字段写准确值，长正文按模板声明的 plain／markdown 格式填写。公开名称和说明不放密码或私人正文。
2. 同一材料的前后修订保存版本，不同用途分别建资料。完整提取后没有独立用途的原件不再附存；确需保管的原件建文件类型资料并关联，复用同一原件，不加“保留原字段”等额外字段。已由其他 Skill 维护的操作流程不重复保存。
3. 按 `templates examples TEMPLATE_ID` 返回的业务例子准备 JSON。新增包含 title、purpose、items，修改使用 update，删除指明 itemId、baseVersion 和可选 fieldId；不填写内部 command、聊天证明、Agent 别名或模板摘要。CLI 绑定当前聊天并取得实际模板版本。
4. 用 `proposals check --kind import|update|delete --input FILE --json` 预检，再用同来源和 `--check CHECK_ID` 提交。预检不入库、不创建申请、不上传原件。正文、附件或模板变化后重新预检；相对文件路径以 JSON 所在目录解析，stdin 以当前工作目录解析。已存在的私有值若来源里没有，先正常申请读取，不猜填或靠省略清空。
5. 提案标题说明本次工作，例如“补齐 NAS 应用清单”；purpose 解释变化，不写过程日记。新增／修改的一份提案整体保存，多条也是一次操作，切换条目只是预览。全部必填内容、文件、密码及关联齐全后才一起入库；用户在提案里填密码不再单独审批自己的输入。
6. 保存 proposalId 和 operationId，通过 `proposals show/list` 查原提案。待审批、等待关联、已入库分别报告；只有返回正式资料 ID、版本并核对类型、目录和必要关联后才报告完成。来源有用信息都有去向才算整理完成。

模板定义变动时重新查询当前例子。更新需要准确 itemId、baseVersion 和完整有来源的修改内容，用户看前后变化后批准。缺少已有私有值时先申请读取。修订旧提案及尚未迁移的特殊操作继续使用原聊天的兼容入口，不把重新提交当作修订或故障恢复。

## 密码与凭据录入

从动态模板选择 credential 类型，读材料分支及例子，直接关联实际服务器／应用，账号按模板的账号位置保存，不塞进长描述。来源格式是 JSON 或 Markdown 不代表凭据类型是文件；认证程序真正需要整份文件时才用文件凭据。

- 尚未看到的人设密码由用户在 App 补填；密码管理器生成后设置为登录密码的也这样处理。不要为了录入而先读取它。
- 用户指定来源里已实际看到的密码直接由 Agent 填，并说明原文可能已进入上下文；其他 Token、API Key 也由 Agent 填。可在内存中提取明确字段并通过业务 stdin 提交，不必输出原文；CLI 不承担各软件配置字段的提取协议。
- 整份私钥／会话文件直接给 filePath，不必打开或输出原文，不让用户重新选文件。程序读文件不等于 AI 已看过；只有确实读过才标记已接触。
- 只知道账号或 SSH 用户名不能证明需要密码；认证方式未知时保留未知。确认密码登录但缺当前密码时才走用户补填。旧密码、哈希不能冒充当前可登录密码。

密码原文不放普通字段、公开说明或 CLI 参数。批准录入和批准使用是两件事。

## 查询、等待与结果

`requests list/show/wait` 查询当前已认证聊天的申请；`proposals list/show` 只看提案，`operations list/show/retry` 找原提交或执行。列表有分页时按返回信息继续，不能把第一页当全部。正常读取字段先申请准确 itemId/fieldId，用户批准后 `access read --request ID --item ID --field ID`；只读取最终获准字段，拒绝、到期、撤销或聊天结束即停止。

申请收件、获批、实际执行和登录结果分别判断。等待超时不会取消申请或延长许可。回复丢失先按原操作编号查询／恢复，不能换编号重做未知输入；恢复也不继承其他聊天的批准。修改同一操作内容会冲突。确需新的业务动作，明确使用新编号。

## 旧聊天兼容与结束

本包保留 `info-codex` 兼容旧协议与既有授权，位置由已核对描述的 legacyCliPath 给出；不能由改名猜路径。旧协议的 association 通过独立 stdin 传入，仍核对原 CODEX_THREAD_ID，不能把新通用聊天配置冒充旧 association。继续旧 SSH 会话不限时和整理任务时读取相应兼容说明及旧入口 `--help`。普通附件可通过本包的 `files` 命令继续使用原聊天的许可。没有原私有证明就不能继承旧任务，也不为凑功能自动重建申请。

已有 Codex 宿主委托继续使用原 delegate 规则；子聊天必须收到父聊天明确传递的私有委托，公开父聊天 ID 不能代替证明。普通 CLI 退出、子 Agent 完成、切换或归档聊天不等于收到根聊天结束事件。通用聊天实际结束使用 `chat end`；宿主有真实结束事件时由适配器处理。服务器普通重启不延长批准或恢复已结束许可。撤销阻止后续使用，不能追回已经披露的内容或撤销外部程序已经做的事。

下面由打包器提供本机路径；它们是位置资料，不是授权证明。
