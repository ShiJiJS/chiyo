# 备份、升级与恢复

本文用于独立 Dart 服务的维护。先在隔离合成资料中演练，再集中替换匹配版本的服务、App 和 CLI；测试镜像不代表已经部署日常服务。

## 平时备份资料

在联网 App 的「设置 → 备份与恢复」中创建恢复密钥，先将密钥独立另存，再导出加密备份。两份文件分开保管。文件已存在时换一个名称，不能覆盖。

备份包括资料及关联、附件的保留版本、凭据及材料版本、目录标签和手动顺序、回收站、模板插件及填写示例，以及已保存的历史。未处理提案及其中的密码不属于已入库资料，不放进便携备份。已经过期并清理的内容不会重新出现。

服务器生成备份不代表电脑已经保存。App 确认本机文件发布成功后才登记完成。断线或结果待核对时，从原操作核对结果；不要立即换一次操作重做。恢复密钥与备份最多按原 256 MiB 备份限制处理，普通附件仍受自己的 10 MiB 限制。

恢复时连接空服务器，选择备份及单独的恢复密钥，先看预览，再确认。已有资料的服务器会拒绝恢复，不自动合并或覆盖。恢复不带旧设备和聊天的有效许可，Agent 必须重新接入并申请；历史只作为历史保留。正常重启则保持原聊天仍有效、未撤销及未到期的许可。

首次同步与手动备份分别管理：App 会自动准备独立传输密钥，不要求用户复制恢复密钥。关闭同步保留已经完整落地的本地资料，也不删除服务器内容。两边都有不同资料时先保留双方并备份，选择空目标，不直接覆盖或自动合并。恢复备份会清除旧同步身份与进度，重新连接时需再次核对资料库。

## 服务器需要保存哪些文件

配置中的 `dataDirectory` 是完整持久资料目录，`secretsDirectory` 含三份互相独立的私有文件：

| 文件 | 用途 |
|---|---|
| `database.key` | 打开这一份 SQLCipher 资料库。丢失后不能为旧库另生成一个替代密钥。 |
| `owner.token` | 用户 App 的服务接入身份，不给 AI。 |
| `server.id` | 客户端核对连接目标的稳定身份。 |

TLS 证书、私钥、配置和信任的 CA 也需保管。配置只记录路径和监听端口；镜像、仓库和日志中不要放数据库密钥、接入 Token 或 TLS 私钥。私有目录保持 700，私有文件保持 600。服务器运行身份必须能读取它们；正常启动和重启都不运行 `init-secrets`。

数据库密钥丢失时，如果还有完整加密备份和独立恢复密钥，可以向另一空服务器恢复资料；原设备身份重新登记。如果密钥尚在但新容器不能读取，先检查挂载位置、运行身份和权限，不改动库文件或放宽全局权限。

## 升级与失败回退

1. 记下当前镜像的准确版本或 digest，准备匹配版本的 App、CLI 和本机执行程序。先做完整加密备份，确认恢复密钥可用。
2. 暂停使用，等本机文件/凭据操作结束；正常停止服务容器并检查退出码为 0。升级演练期间不接受新的修改或审批。
3. 服务停止后，将**整份持久目录、对应私有密钥及配置**复制到独立私有位置。不要只复制 `library.db`，不要在服务写入时逐文件复制数据库和日志。
4. 新容器挂载原持久目录和原私有密钥，使用新镜像启动。不要重新初始化密钥，也不把库搬进容器临时层。核对服务器身份、资料与原操作结果，再重新开放使用。
5. 如果升级失败，停止新容器。保留失败现场，将第 3 步的停止状态副本恢复到**另一目录**，用原镜像及其配套客户端启动这份旧副本。不要让旧程序强行打开已经升级的库，不覆盖唯一旧副本。
6. 确认回退库、文件、服务器身份与原回执正确后再继续使用。这里只适用于尚未恢复使用的升级窗口；一旦新版已接收新修改，不能直接回退旧快照而丢掉这些修改。

停止状态副本包含当时的设备和运行状态，只用于受控升级回退。它不能用来把较早的授权状态重新带回日常服务。一般灾难恢复优先用 App 的便携加密备份恢复到新空服务并重新登记设备。

升级后若发生异常退出，先让原存储正常重开并恢复日志；不要手动删除 SQLite 的 journal 或 WAL 文件。操作回复丢失时核对原操作结果，不能把断线解释成“没有保存”。

首次启用本地库复制会写入库格式 56，启用变化捕获和增量状态后依次使用 57、58；旧程序会拒绝打开。需要回退时使用升级前停止状态的完整副本，不能让旧程序直接打开这份已升级的库。服务器 `replication-transfers` 及 App `replication-staging` 是加密传输暂存；它们不能代替正常加密备份。

## 可重复的合成演练

从仓库根目录运行以下命令。两个镜像必须真实存在、ID 不同，并兼容脚本使用的正常资料接口；新镜像应来自要检查的源码。

```sh
python3 scripts/qa/check-server-container.py \
  --image chiyo-server-verification:a05 \
  --upgrade-image chiyo-server-verification:a11
```

脚本创建自己的临时目录、TLS 和密钥，通过 HTTPS 保存资料，停止旧容器，再用新镜像挂载原目录。它还把停止状态的资料及密钥复制到另一路径、以新容器恢复，并以旧镜像验证未改动的升级前副本可回退。结束后只清理它自己创建的容器和临时目录。它是实际跨镜像维护演练，不等于真实资料迁移、正式安装或最终候选验证。

真实恢复中断检查在 `apps/server` 运行：

```sh
dart test test/server_backup_interruption_test.dart --reporter expanded
```

测试以现有单机入口生成 80 MiB 合成附件备份，用正式服务启动入口接收上传和恢复。在检测到带有效 journal 的实际未提交写入后 SIGKILL **该测试服务自己的 VM**；重开核对空库回退、原设备仍有效和原恢复未提交，再用新操作恢复并重新启动核对。没有击中真实写入窗口时测试失败，不算中断通过。

App 完整资料检查在 `apps/desktop` 运行：

```sh
flutter test test/remote_backup_recovery_test.dart --reporter expanded
```

它使用真正的 HTTPS、SQLCipher、Mac 文件发布及当前源码编译的本机执行程序；系统文件面板用隔离路径替代。系统真实面板和必要人工操作仍按 #103 集中检查。

## 本地增量同步与冲突处理

本地模式的同步在启动、手动点击和定时检查时进行；点击目录只读本机资料。两端改了同一资料时，工具栏显示需要处理冲突。点击后逐条查看整组的两份内容，选择本机或服务器内容，一次保存整组；其他不冲突的资料继续同步。不根据设备时间自动覆盖。

选择后两端收到相同的新版本，旧的资料修订和准确文件引用仍保留。同一个“第 2 版”可能有两份原文，必须从列表选具体一份，不能靠编号拼出文件引用。凭据只展示管理信息，材料在加密库内保留，选择后原凭据使用许可不再适用。

这一版的 App 与服务器应集中升级。本机和服务器都可能升级至库格式 63，内容传输最高格式 26；升级前正常停机副本及其原密钥必须保留。关闭同步不删除本机或服务器资料。升级失败时使用旧程序和升级前副本恢复，不能让旧程序直接打开已经升级的库。
